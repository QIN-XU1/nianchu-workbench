# 舱壁隔离（Bulkhead）技能

> 舱壁来自船体：一个舱进水，其他舱不受影响，船不沉。
> 软件里：**一个慢依赖/慢接口耗尽共享资源池 → 拖垮所有功能**。
> 判据：**某个功能变慢时，会不会把线程/连接/内存占光，导致别的功能也挂？**

## 什么时候用

- 多个功能共享资源池（线程/连接）
- 一个慢依赖影响全局
- 要故障隔离

## 什么时候**不**用

- 单一功能、无共享资源竞争

## 第 1 步：识别共享资源（会互相拖累的）

| 共享池 | 风险 |
|---|---|
| 线程池 | 慢请求占满线程 |
| DB 连接池 | 慢查询占满连接 |
| HTTP 连接池（到下游） | 下游慢占满 |
| 内存 | 大请求占满 |

⛔ 所有下游共用一个 HTTP 连接池 = 一个慢下游占满池 = 其他下游也调不动。

## 第 2 步：隔离方式

| 方式 | 说明 |
|---|---|
| **按依赖分池** | 每个下游独立连接池/线程池 |
| **按租户/用户分池** | 防单租户占满 |
| **信号量限制** | 每个功能限并发数 |
| **线程池分组** | 不同业务不同池 |

## 第 3 步：池大小（太大太小都不行）

| 太小 | 正常流量就排队 |
| 太大 | 失去隔离意义（等于共享） |

原则：按每个下游「能承受的并发」设，不是按总量。

## 第 4 步：满了怎么办（背压）

| 策略 | 说明 |
|---|---|
| 拒绝（快速失败） | 池满直接拒，别排队 |
| 排队 + 超时 | 有限等待 |
| 降级 | 走兜底 |

⛔ 池满了还无限排队 = 请求越积越多，延迟爆炸。

## 第 5 步：与熔断/限流配合

- 舱壁：**限制并发**（不超过池）
- 熔断：**依赖挂了不再调**
- 限流：**控制速率**

三者互补：舱壁防「慢」，熔断防「挂」，限流防「猛」。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 关键资源分池 + 池大小合理 + 满时快速失败
- WARN = 部分分池但有共享池
- FAIL = 全共享池 / 池无限 / 满了无限排队
- UNKNOWN = 拿不到资源模型

## 假阳性清单（这些不算「有隔离」）

- 有连接池但全共享
- 池无限大（等于没限）

## 假阴性清单（最常漏的 8 类）

1. **所有下游共用一个池**
2. **池无限**（失去隔离）
3. **池满无限排队**（延迟爆）
4. **线程池共享**
5. **DB 连接池不分**
6. **按总量而非按依赖设池**
7. **无快速失败**
8. **不与熔断/限流配合**

## 边界（如实说清）

- 分池增加资源总占用（每个池都要余量）
- 池大小需压测校准
- 本技能不实现，只设计
