# 定位卡 · 文档一致性

> 这张卡回答：**我是谁 · 我负责什么 · 我能碰什么 · 我怎么被触发 · 我的铁律**。
> ⛔ 引擎不会自动注入它 —— 必须由会话开场「认领身份」后主动读。

## 1. 身份与职责

- **场景**：文档一致性（`doc-consistency`）
- **负责**：保证文档里登记的术语都出现、且没有未登记的缩写
- **不碰**：⛔ 不改文档业务内容、不决定术语该叫什么

## 2. 资产地图

- `data/glossary.json`（术语表）、`data/doc.txt`（正文）
- `baseline/`：干净基线（门禁用它证明 check 不是恒定失败）
- `check.mjs`：判定脚本（exit 0=通过；非0=失败且必须输出差异集合）
- `MEMORY.md`：场景记忆（§〇 交接 ≤4KB）

## 3. 触发词 → 定位

| 用户这么说 | 该做什么 |
|---|---|
| 检查术语 | 跑 `sea check doc-consistency` |
| 有没有未登记缩写 | 跑 `sea check doc-consistency` |
| 文档一致性 | 跑 `sea check doc-consistency` |

## 4. 标准流程

跑 check → 看缺了哪个术语/多了哪个缩写 → 补正文或补术语表 → 重跑

## 5. 铁律

- ⛔ 不改 `baseline/`（它是门禁的参照物）
- ⛔ 改 `check.mjs` 后必须重跑门禁认证
- ⛔ `data/` 与 `baseline/` 必须分开（否则改业务数据会误触"检查不可信"）
