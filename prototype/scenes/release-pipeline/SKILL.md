# 端到端发布流水线（深度技能）

> 这是一个**深度技能**（`depth: deep`）：它承载的是一条多阶段、有前置依赖、出错要能回退的真实流程，
> 不是一句话能说清的轻量指南。所有命令都指向本仓库真实存在的脚本，可逐条复算。

## 什么时候用

- 一批改动完成，要交付一个可用版本
- 要给非技术同事解释「这次发布包含什么、有什么风险」
- 线上出问题，要能快速判断「能不能回滚、回滚到哪」

## 0. 先定发布范围（不做这步后面全白做）

发布不是「把 main 推上去」。先写下三件事，缺一条就停下来问：

1. **这次包含哪些改动**（对应台账条目 / 提交范围，而不是「最近改的那些」）
2. **影响面**：哪些模块、哪些用户可见行为变了
3. **不兼容项**：有没有删字段 / 改接口 / 改数据结构（有就必须写迁移与回滚方案）

产出：一段「发布说明草稿」，后续步骤都围绕它。

## 1. 门禁全绿（发布的前置条件，不是可选项）

按 `release-gate` 技能逐条跑，任一 FAIL 停止。这里只强调发布场景特有的一条：

```powershell
node tools\quality\audit-doc-numbers.mjs   # 文档里的数字必须与代码实测一致
```

为什么发布前特别要跑它：发版说明会引用「N 项验证 / N 个技能 / N 个方法」这类数字，
一旦是旧数，发出去就是**对外承诺错误信息**。这个工具会拿代码实测值比对，不符 exit 1。

**判据**：全 PASS，或每个 WARN/UNKNOWN 都能一句话解释清楚为什么可接受。

## 2. 版本号与变更日志

1. 定版本号：**不兼容 → 主版本**；新增能力 → 次版本；纯修复 → 修订号。不许「感觉差不多就 +0.0.1」。
2. 写变更日志（用 `changelog` 技能）：按 新增 / 修复 / 变更 / 移除 / 安全 分类，每条写「对用户的影响」。
3. 不兼容项**单独成节**，放在最前面——藏在细节里就是坑用户。

**判据**：每条变更能追溯到提交或台账 id；读者能据此判断「要不要升、升了会不会坏」。

## 3. 构建产物（不是构建成功，是产物正确）

1. 构建，记录**产物路径、大小、构建时间**。
2. **校验产物本身**，而不是只看「构建 exit 0」：
   - 大小是否异常（突然小一半 = 漏打包；突然大一圈 = 误打包 node_modules）
   - 入口文件是否存在、能否被加载
   - 版本号是否已写进产物（避免「装了新版还是旧行为」）
3. 若产物含多平台/多宿主文件，逐个抽查一个真实文件的内容是否为新版本内容。

**反例（必须试一次）**：故意把某个资源文件挪走再构建，确认构建**会失败**而不是静默产出一个缺资源的包。
若它静默通过，说明校验是假的。

## 4. 回滚预案（在发布之前写好，不是出事再想）

发布前必须能回答：

- **回滚到哪个版本**？（具体版本号，不是「上一个」）
- **回滚怎么做**？（替换产物 / 切 tag / 恢复数据，逐条写命令）
- **数据能不能回滚**？结构变更通常不可逆 → 必须有备份 + 前向兼容方案（旧代码能读新数据）
- **回滚要多久**？（超过 5 分钟就要提前告知）

**判据**：把回滚命令写下来，**在预发环境真跑一次**。没跑过的回滚方案等于没有。

## 5. 发布后验证（发布不是结束，验证才是）

发布后 10 分钟内做：

1. **冒烟**：核心路径能走通（不是「首页能打开」）
2. **数字核对**：版本号、能力数量、关键配置是否为新值
3. **日志与错误率**：有没有新增报错（对比发布前基线）
4. **用户视角**：用真实账号走一遍最关键的一条流程

**判据**：四项都有明确结论（通过/不通过），不通过立即按第 4 步回滚——**不要边观察边修**。

## 6. 记录（让下次发布更省事）

在台账记一条：版本号、范围、遇到的问题、回滚是否演练过。
下次发布前先看上一次的记录——**重复踩同一个坑是最贵的浪费**。

## 常见坑（都是真实踩过的）

- ⛔ **「构建成功」当「产物正确」**：exit 0 只说明编译过了，不说明包里有该有的东西。
- ⛔ **回滚方案没演练**：真出事时才发现命令跑不通，或者回滚后数据不兼容。
- ⛔ **变更日志写实现细节**（「重构了 XxxService」）：用户看不懂，也判断不了要不要升。
- ⛔ **不兼容项没单独标注**：升级后炸了才知道，属于交付事故。
- ⛔ **发布后只盯监控不冒烟**：监控绿但核心路径已经断了的情况很常见。
- ⛔ **文档数字过期**：发版说明里的「N 项」如果是旧数，等于对外发布错误信息。

## 与其他技能的关系

- 前置：`release-gate`（门禁）、`changelog`（变更日志）、`doc-write`（发布说明）
- 数据变更时并行：`data-migration`（备份/dry-run/计数校验）
- 出问题后：`debug-repro`（复现定位）、`docs-index`（文档与索引核对）
