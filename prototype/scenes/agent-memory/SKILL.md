# Agent 记忆设计 技能

> agent「记不住」有三种完全不同的原因，别混：
> ① 会话内忘了（上下文窗口挤掉）② 跨会话不记得（没长期记忆）③ 记了但检索不到（存了没用）。
> 判据：**用户说「上次我们说的那个」，agent 能不能找回来？** 不能就是记忆没设计好。

## 什么时候用

- agent 多轮任务记不住前文
- 要跨会话记住用户偏好
- 记忆太多检索不准

## 什么时候**不**用

- 单轮无状态任务

## 第 1 步：分清三层记忆

| 层 | 存哪 | 生命周期 | 例子 |
|---|---|---|---|
| **工作记忆**（上下文） | prompt 里 | 当前会话 | 最近对话、当前任务 |
| **会话记忆** | 会话存储 | 一次会话/可续 | 本次聊的要点 |
| **长期记忆** | 外部存储+检索 | 跨会话/长期 | 用户偏好、历史决策 |

⛔ 三层混用 = 要么挤爆上下文，要么该记的没记。

## 第 2 步：上下文层（工作记忆）怎么管

见 `context-management`：预算、压缩、按需注入、关键状态重述。

★ 最实用的一条：**长任务定期把「当前目标/已确认约束/已完成步骤」重述进上下文**，别指望早期内容一直在。

## 第 3 步：长期记忆怎么存与取

| 环节 | 要点 |
|---|---|
| **写什么** | 值得跨会话的事实（偏好/决策/关键事实），不是全部对话 |
| **怎么存** | 结构化（键值/条目）优于原始对话堆积 |
| **怎么取** | 按相关性检索（关键词/向量），不是全塞 |
| **去重** | 同一事实不重复存 |
| **冲突** | 新事实覆盖旧事实（带时间戳） |

⛔ 把整段对话原文存进「记忆」= 检索到一堆噪音。要**提炼成事实条目**。

## 第 4 步：遗忘（记忆系统必须有）

| 策略 | 说明 |
|---|---|
| **过期** | 时效性记忆（如临时偏好）到期删 |
| **不重要衰减** | 长期不用的降权 |
| **用户可删** | 尊重隐私（见 `data-retention`） |
| **冲突覆盖** | 新覆盖旧 |

⛔ 只记不忘 = 记忆越积越脏，检索越来越差。

## 第 5 步：验证记忆有效（不是「存了」就行）

| 检查 | 判据 |
|---|---|
| 能召回吗 | 提相关问题，能取到 |
| 取得准吗 | 不是一堆无关记忆 |
| 会过时吗 | 旧事实被更新 |
| 会矛盾吗 | 同一事实多个版本 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 三层分清 + 提炼存 + 按需取 + 有遗忘 + 可召回
- WARN = 有长期记忆但无冲突/过期处理
- FAIL = 三层混用 / 存原始对话 / 只记不忘 / 检索不到
- UNKNOWN = 拿不到记忆实现

## 假阳性清单（这些不算「有记忆」）

- 存了原始对话当记忆
- 有存储但检索不到
- 只记不忘

## 假阴性清单（最常漏的 8 类）

1. **三层混用**（挤爆/遗漏）
2. **存原始对话非提炼**
3. **只写不检索**
4. **无冲突覆盖**（多版本矛盾）
5. **无过期/遗忘**（越积越脏）
6. **长会话不重述状态**
7. **检索返回一堆噪音**
8. **用户无法删记忆**


## 与其他技能的关系

- `context-management`：工作记忆预算
- `data-retention`：遗忘与删除
- `rag-design`：检索
- `prompt-engineering`：记忆注入

## 边界（如实说清）

- 记忆质量取决于「提炼得好不好」
- 长期记忆有成本（存储+检索）
- 本技能不实现存储，只设计
