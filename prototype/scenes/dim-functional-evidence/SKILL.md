# 维度功能实证审计 技能

> 自评「A 维度有」，证据里引的路径**真实存在**——但「存在 ≠ 能用」。第 102 轮就撞到：A 维度自评「有」，界面依赖的 git 集成其实一个方法都没有。
> 判据：**每个自评「有」的维度，都能在验收脚本里找到「有断言覆盖它」吗？**

## 什么时候用

- 多维能力自评
- 要评审「某维度已实现」这类声明
- 发现「文件在但功能是空的」

## 什么时候**不**用

- 单维度任务

## 第 1 步：给每维配关键词

不是「维度名」，而是能代表该能力的**关键词**（方法名、字段名、行为词），去全部 `verify-*.mjs` 里找。

## 第 2 步：找「有断言覆盖它」的脚本

- 找到 → 记为「有功能实证」，列出脚本名
- 找不到 → 该维自评「有」是**空口无凭**

## 第 3 步：逐维出「实证清单」

每维输出：维度 id / 自评 / 命中的验收脚本 / 是否空口。

## 反例（写下来防复发）

- ✗ 只用「路径存在」当证据 → 存在≠能用
- ✗ 维度名当关键词 → 关键词太泛，命中一堆无关
- ✗ 找不到覆盖就不报 → 空口维度被放过
- ✗ 把「有文件」当「有功能」 → 假实证

## 自检清单

- [ ] 每维配具体关键词（非维度名）
- [ ] 扫全部 verify-*.mjs 找断言
- [ ] 逐维出实证清单
- [ ] 空口维度必须报出

## 参考实现指路

本仓库 `tools/evolve/audit-dim-evidence.mjs`（给每维配关键词，在全部 verify-*.mjs 里找「有断言覆盖」的脚本，输出维度→实证清单，空口维度单独列出）；配套 `audit-self-claims.mjs`（只验路径存在，**存在≠能用**）。
