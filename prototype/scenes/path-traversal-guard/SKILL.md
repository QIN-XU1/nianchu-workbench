# 路径穿越防护 技能

> 一个「按路径读文件」的接口，如果直接拼接用户输入，`../../etc/passwd` 就能读到系统文件。
> 判据：**`../`、绝对路径、编码变体，都被挡住了吗？**

## 什么时候用

- 静态文件服务、插件目录直出
- 任何「用户给路径、服务读文件」的接口
- 安全评审

## 什么时候**不**用

- 纯内存数据（不碰文件系统）

## 第 1 步：规范化后再判断

- 用 `path.resolve(root, userPath)` 规范化
- 断言结果**仍在 root 之下**（`resolved.startsWith(root + sep)`）
- 不在 → 拒绝（400/403/404 均可，只要非 200）

## 第 2 步：挡多种变体

| 变体 | 例子 |
|---|---|
| 相对穿越 | `../../etc/passwd` |
| URL 编码 | `%2e%2e%2f` |
| 双写 | `....//` |
| 绝对路径 | `/etc/passwd`、`C:\Windows\...` |

**先解码再规范化**，否则编码变体绕过。

## 第 3 步：写反例测试

必须有一条反例：发 `../` 请求，**断言被拒绝**（403/404），不是「返回了某个文件」。

## 反例（写下来防复发）

- ✗ 直接 `join(root, userPath)` 不判断 → 穿越成功
- ✗ 只挡 `../` 不挡 `%2e%2e%2f` → 编码绕过
- ✗ 只挡相对不挡绝对路径 → `C:\Windows\win.ini` 读到
- ✗ 没有反例测试 → 不知道到底挡没挡

## 自检清单

- [ ] resolve 后断言在 root 之下
- [ ] 解码后再判断（防编码变体）
- [ ] 挡相对穿越 + 绝对路径
- [ ] 有反例：`../` 必须被拒
