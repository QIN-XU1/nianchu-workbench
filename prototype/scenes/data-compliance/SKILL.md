# 数据合规 技能

> 合规不是「加个隐私政策弹窗」就完事：**收集是否有依据、是否最小必要、用户能否删除、跨境是否合规**。
> 判据：**用户要求删数据，你能不能真的删干净并证明？**

## 什么时候用

- 涉及个人信息的产品
- 上线前合规审查
- 跨境数据
- 用户投诉/监管问询

## 什么时候**不**用

- 完全不涉及个人数据

## 第 1 步：合法性基础（收集的依据）

| 依据 | 说明 |
|---|---|
| **同意** | 明确、自愿、可撤回 |
| 合同必需 | 提供服务所必需 |
| 法定义务 | |
| 合法利益 | 需评估（且不能凌驾用户权利） |

⛔ 「默认勾选同意」= 无效同意。

## 第 2 步：最小必要（只收要用的）

| 检查 | 判据 |
|---|---|
| 每个字段都有用途 | 不能「以后可能有用」 |
| 不超范围 | 要手机号就别顺便要通讯录 |
| 敏感信息单独同意 | 生物/健康/金融 |

## 第 3 步：用户权利（能兑现吗）

| 权利 | 要求 |
|---|---|
| **知情** | 隐私政策清楚 |
| **访问** | 能导出自己的数据 |
| **删除（被遗忘权）** | 能删干净（见 `data-retention`） |
| **撤回同意** | 能关 |
| **可携带** | 能导出格式 |

★ 「承诺能删」但删不干净（备份/副本/日志里还有）= 不兑现。

## 第 4 步：跨境与共享

| 项 | 要求 |
|---|---|
| 跨境传输 | 评估/标准合同/本地化 |
| 第三方共享 | 告知 + 协议 |
| 委托处理 | 数据处理协议 |

## 第 5 步：安全与留存

| 项 | 要求 |
|---|---|
| 加密 | 传输+存储 |
| 留存期限 | 限期（见 `data-retention`） |
| 泄露通报 | 有预案 |
| 审计 | 访问日志（见 `audit-log`） |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 合法性基础 + 最小必要 + 权利可兑现 + 跨境合规
- WARN = 有隐私政策但删除不彻底
- FAIL = 默认勾选 / 超范围收集 / 删不干净 / 跨境无评估
- UNKNOWN = 拿不到数据处理清单

**1. 合法性基础**
| 数据 | 依据 |
|---|---|

**2. 最小必要**
| 字段 | 用途 |
|---|---|

**3. 用户权利**
| 权利 | 能兑现 |
|---|---|

**4. 判不了的部分**
- <拿不到的数据流>

## 假阳性清单（这些不算「合规」）

- 有隐私政策但默认勾选
- 能删主库但备份还有
- 超范围收集

## 假阴性清单（最常漏的 8 类）

1. **默认勾选同意**（无效）
2. **超范围收集**
3. **删不干净**（备份/日志有）
4. **敏感信息无单独同意**
5. **跨境无评估**
6. **第三方共享未告知**
7. **无留存期限**
8. **泄露无预案**


## 与其他技能的关系

- `data-retention`：删除与留存
- `secrets-management`：加密
- `audit-log`：访问审计
- `multi-tenancy`：数据隔离

## 边界（如实说清）

- 合规因国家/行业差异大，需法务确认
- 本技能不构成法律意见，只做工程检查
- 本技能不实现，只审查
