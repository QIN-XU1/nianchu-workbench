# 无障碍审计 技能

> 无障碍最容易被当成「加个 alt 就行」。但真正的阻断级问题往往在：
> **键盘操作不了、焦点跑不出来、屏幕阅读器读不出语义**。
> 判据：**一个只用键盘 + 屏幕阅读器的人，能不能完成核心任务？**
> 不能的，就是阻断级，不是「体验不好」。

## 什么时候用

- 上线前的无障碍检查
- 有合规要求（WCAG 2.1 AA 常见）
- 用户反馈「键盘用不了」
- 表单/弹窗/菜单这类交互组件

## 什么时候**不**用

- 纯后端/CLI（无界面）
- 只看视觉设计 → `design-review`

## 第 1 步：两档分级（先分轻重）

| 档 | 定义 | 例子 |
|---|---|---|
| **阻断级 P0** | 核心任务无法完成 | 键盘无法触达按钮、焦点陷入弹窗出不来、图片按钮无名称 |
| **体验级 P1** | 能用但难受 | 对比度不足、焦点框不可见、无 skip link |

⛔ 把 P1 当 P0 报会淹没真问题；把 P0 当 P1 会出合规事故。

## 第 2 步：四类检查（每类都有可复现步骤）

### 2.1 键盘可达（阻断级最多）

| 检查 | 复现步骤 | 通过判据 |
|---|---|---|
| 所有交互元素可 Tab 到 | 只用 Tab 键走一遍 | 按钮/链接/输入都能聚焦 |
| 焦点顺序合理 | Tab 时看焦点走向 | 与视觉顺序一致 |
| 焦点可见 | 聚焦时看有无轮廓 | 有清晰焦点环（不是 `outline:none`） |
| 无键盘陷阱 | 在弹窗/富文本里 Tab | 能 Tab 出去，不是死循环 |

⛔ `outline: none` 且无替代焦点样式 = 阻断级。

### 2.2 语义化（屏幕阅读器依赖它）

| 检查 | 判据 |
|---|---|
| 图片有 alt（或 alt="" 表装饰） | 内容图必须有描述 |
| 表单控件有关联 label | `<label for>` 或 aria-label |
| 按钮是 `<button>` 不是 div 加 click | 语义元素自带键盘行为 |
| 标题层级 h1→h2 不跳级 | 屏幕阅读器靠它导航 |
| 动态内容有 aria-live | 否则读屏器不知道更新了 |

### 2.3 对比度（可量化）

| 文本类型 | WCAG AA 最低 |
|---|---|
| 普通文本 | 4.5:1 |
| 大字（≥18pt 或 14pt 粗） | 3:1 |
| UI 组件边界/图标 | 3:1 |

⛔ 用工具量，不靠眼睛。灰色 #999 在白底只有 2.8:1，不达标。

### 2.4 动效与可读

| 检查 | 判据 |
|---|---|
| 尊重 prefers-reduced-motion | 减弱动效 |
| 不用颜色单独传达信息 | 「红=错误」要配图标/文字 |
| 200% 缩放不破版 | 文字放大后仍可用 |

## 第 3 步：三种验证手段（缺一不可）

| 手段 | 能发现什么 | 不能发现 |
|---|---|---|
| **自动扫描**（axe 等） | 对比度/缺 alt/缺 label | 焦点顺序/键盘陷阱 |
| **键盘实测** | 可达性/焦点 | 语义正确性 |
| **屏幕阅读器实测** | 语义/朗读顺序 | 视觉对比度 |

⛔ 只跑自动扫描 = 漏掉最多的一类（键盘与语义）。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 无阻断级 + 体验级可接受
- WARN = 只有体验级问题
- FAIL = 存在阻断级（键盘/语义/焦点）
- UNKNOWN = 无法实测（缺真机/读屏器）

## 假阳性清单（这些不算「无障碍」）

- 只加了 alt
- 跑了自动扫描 0 问题
- 鼠标能用（键盘不一定）
- 颜色能区分（对比度不一定够）

## 假阴性清单（最常漏的 8 类）

1. **`outline:none`** 无替代焦点
2. **div+onclick** 冒充按钮（键盘不可用）
3. **弹窗焦点陷阱**（Tab 出不去）
4. **表单无 label**（只有 placeholder）
5. **对比度不足**（浅灰字）
6. **动态内容无 aria-live**
7. **用颜色单独传达**（红绿不分者看不到）
8. **只跑自动扫描** 就下结论

node tools/quality/commit-gate.mjs   # 提交前（含界面层验收）

## 与其他技能的关系

- `design-review`：视觉设计（本技能是可访问性）
- `i18n-review`：多语言（常与 a11y 一起查）
- `release-gate`：发布前把 a11y 作为一道闸
- `threat-model`：无障碍也有安全面（如读屏泄露）

## 边界（如实说清）

- 自动工具只能覆盖约 30-40% 的问题
- 读屏器行为因浏览器/系统而异，需实测
- WCAG 有主观条款（如「合理」），需产品判断
- 本技能不修代码，只出问题清单与复现步骤
