# 指标定义 技能

> 「DAU 到底多少」这种问题，十个团队有十一种算法。
> 指标对不上的根因几乎从不是算错，而是**口径不同**：算不算游客、去重按天还是按人、
> 时间窗用 UTC 还是本地时区。
> 判据：**两个人按同一份定义算，能不能得到同一个数？** 不能的，定义就没写完。

## 什么时候用

- 定一个新指标
- 两个报表数不一致
- 跨团队对齐口径
- 指标变更要留档

## 什么时候**不**用

- 只查一次性的数据分析（不必固化成指标）
- 要设计实验 → `experiment-design`

## 第 1 步：五要素（缺一不可）

| 要素 | 问题 | 例子 |
|---|---|---|
| **业务含义** | 这个指标回答什么问题 | 「有多少人在用」 |
| **分子** | 怎么算「发生了」 | 有 ≥1 次有效行为的去重用户数 |
| **分母** | 算比率时的基数 | 当日活跃用户 |
| **去重口径** | 按什么去重 | 按 user_id，同一人多次算 1 |
| **时间窗口** | 什么时间段、什么时区 | 自然日 00:00-24:00，UTC+8 |

## 第 2 步：三个最容易含糊的点

### 2.1 「有效」怎么定义

| 指标 | 「有效」的陷阱 |
|---|---|
| 活跃 | 打开 app 算不算？后台唤起算不算？ |
| 留存 | 第 2 天回来算，还是 7 天内回来算？ |
| 转化 | 点了按钮算，还是完成了算？ |

⛔ 不定义「有效」，指标就是浮动的。

### 2.2 去重的边界

| 情况 | 要说清 |
|---|---|
| 同一人多设备 | 按人还是按设备 |
| 游客/未登录 | 算不算 |
| 内部测试账号 | 排不排除 |
| 机器人/爬虫 | 过不过滤 |

### 2.3 时间窗与时区

| 陷阱 | 后果 |
|---|---|
| UTC vs 本地时区 | 「当日」差 8 小时 |
| 滚动 7 天 vs 自然周 | 数字不同 |
| 事件时间 vs 入库时间 | 乱序/延迟导致差异 |
| 边界含不含（闭/开区间） | 差一个 |

## 第 3 步：对不上数时怎么排查

### 3.1 五个排查点（按概率排序）

| # | 查什么 |
|---|---|
| 1 | 时间窗（时区/边界） |
| 2 | 去重口径（人/设备/游客） |
| 3 | 「有效」定义（阈值/事件） |
| 4 | 数据延迟（是否含未入库） |
| 5 | 过滤条件（内部账号/机器人） |

⛔ 90% 的「数对不上」是前 2 项，不是算法错。

## 第 4 步：口径变更要留档

指标定义会随业务演化。每次变更必须记：

| 记录项 | 内容 |
|---|---|
| 变更时间 | |
| 旧口径 → 新口径 | |
| 为什么变 | |
| 对历史数据的影响 | 是否需要重算/加注释 |

⛔ 不改档就改口径 = 历史报表出现「无法解释的跳变」。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 五要素齐 + 边界清楚 + 有变更记录
- WARN = 有要素含糊（如「有效」没定阈值）
- FAIL = 两报表口径不同却在比较 / 无变更记录
- UNKNOWN = 拿不到数据源定义

## 假阳性清单（这些不算「定义清楚」）

- 只说「DAU 就是日活」
- 有分子没分母（比率类）
- 没提去重
- 没提时区

## 假阴性清单（最常漏的 8 类）

1. **「有效」没定义阈值**
2. **游客算不算没说**
3. **时区没说**（UTC vs 本地）
4. **边界开闭没说**
5. **事件时间 vs 入库时间混淆**
6. **内部账号没排除**
7. **口径变更不留档**
8. **两报表口径不同直接比**

## 本仓库可用的命令


## 与其他技能的关系

- `experiment-design`：实验主指标的定义
- `data-reconcile`：数据对账（本技能定义口径）
- `inventory-ledger`：数据资产清单
- `doc-consistency`：文档中的数字要一致

## 边界（如实说清）

- 指标定义是业务决策，不是纯技术问题
- 不同业务阶段可能需要不同口径（要显式区分）
- 本技能不计算指标，只定义「怎么算才算对」
