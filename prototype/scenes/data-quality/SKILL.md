# 数据质量 技能

> 「数据不准」是最难查的问题，因为它不报错，只是**悄悄错**。
> 判据不是「数据看起来对」，而是：**这份数据的每个质量维度，有没有被持续监控？**

## 什么时候用

- 数据用于决策/报表
- 数据源多、要合并
- 数据驱动的功能
- 怀疑数据有问题

## 什么时候**不**用

- 一次性分析（不必建监控）
- 数据一致性核对的具体步骤 → `data-reconcile`

## 第 1 步：五个质量维度

| 维度 | 问题 | 检查 |
|---|---|---|
| **完整性** | 有没有缺失 | 空值率、必填项 |
| **准确性** | 对不对 | 与权威源比对、范围校验 |
| **一致性** | 各处一致吗 | 跨表/跨系统比对 |
| **时效性** | 够新吗 | 延迟、是否含最新 |
| **唯一性** | 有没有重复 | 主键/业务键去重 |

## 第 2 步：常见脏数据模式

| 模式 | 例子 |
|---|---|
| 空值伪装 | `"NULL"`/`""`/`0` 当缺失 |
| 格式不一 | 日期 `2024-1-1` vs `2024-01-01` |
| 重复 | 同一实体多条 |
| 孤儿 | 外键指向不存在的记录 |
| 越界 | 年龄 -5、金额负数 |
| 编码混乱 | 中英文、全角半角 |
| 时区错 | 同一字段混 UTC 和本地 |

## 第 3 步：数据契约（源头治）

| 手段 | 说明 |
|---|---|
| Schema 约束 | 类型/非空/范围在入库时拦 |
| 上游校验 | 生产方保证格式 |
| 数据契约 | 上下游约定字段语义与约束 |
| 拒绝而非静默 | 坏数据进隔离区，不是硬塞 |

⛔ 「先收下后面再清洗」= 脏数据扩散，越洗越乱。

## 第 4 步：监控（持续）

| 指标 | 告警 |
|---|---|
| 空值率突增 | 是 |
| 行数骤降/骤增 | 是 |
| 唯一性破坏 | 是 |
| 时效延迟 | 是 |
| 分布漂移 | 是 |

★ 数据质量要像服务监控一样**持续监控**，不是一次性清洗。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 五维检查 + 数据契约 + 持续监控
- WARN = 检查了但无监控
- FAIL = 脏数据无处理 / 无约束 / 一次性清洗
- UNKNOWN = 拿不到数据样本

**1. 五维评估**
| 维度 | 现状 | 问题 |
|---|---|---|

**2. 脏数据模式**
| 模式 | 本数据有吗 |
|---|---|

**3. 数据契约**
| 手段 | 有吗 |
|---|---|

**4. 监控**
| 指标 | 有吗 |
|---|---|

**5. 判不了的部分**
- <拿不到的权威源>

## 假阳性清单（这些不算「数据质量好」）

- 抽样看着对
- 清洗过一次
- 没报错

## 假阴性清单（最常漏的 8 类）

1. **空值伪装**（""/0/"NULL"）
2. **日期格式不一**
3. **重复记录**
4. **孤儿外键**
5. **越界值**
6. **时区混用**
7. **无数据契约**（源头不管）
8. **只有一次性清洗无监控**

## 本仓库可用的命令

```bash
node tools/memory/query.mjs          # 数据查询
node tools/quality/commit-gate.mjs
```

## 与其他技能的关系

- `data-reconcile`：一致性核对
- `metric-definition`：指标口径
- `schema-design`：入库约束
- `data-migration`：迁移的数据完整性

## 边界（如实说清）

- 「准确」需要权威源，有时没有
- 数据质量是持续工作，不是项目
- 本技能不改数据，只评估与设计监控
