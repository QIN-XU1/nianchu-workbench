# ETL/数据管道设计 技能

> 数据管道最核心的要求不是「能跑」，而是**能重跑而不出错**（幂等）。
> 判据：**这个管道跑了两次，结果和跑一次一样吗？** 不一样就是定时炸弹。

## 什么时候用

- 数据仓库/报表数据
- 多源数据汇聚
- 增量同步

## 什么时候**不**用

- 简单的单表查询

## 第 1 步：抽取（Extract）

| 方式 | 说明 |
|---|---|
| 全量 | 简单但慢/贵 |
| **增量**（按时间戳/ID） | 只取变化 |
| **CDC**（变更数据捕获） | 从 binlog 抓变更（最实时准确） |

⛔ 增量按「更新时间」有坑：更新时间可能回填、时区不一、删除了抓不到（软删/CDC）。

## 第 2 步：转换（Transform）

| 要点 | 说明 |
|---|---|
| 清洗 | 空值/格式/去重 |
| 幂等 | 同样的输入产生同样的输出 |
| 可测试 | 转换逻辑单测 |

## 第 3 步：加载（Load）—— 幂等是关键

| 方式 | 幂等 | 说明 |
|---|---|---|
| **覆盖分区**（先删后插） | ✅ | 重跑安全（推荐） |
| 追加 | ❌ | 重跑重复 |
| Upsert（按主键） | ✅ | 幂等 |

★ **必须能安全重跑**：管道失败重跑不能产生重复。用「覆盖分区」或「upsert」而非「append」。

## 第 4 步：调度与依赖

| 项 | 要求 |
|---|---|
| 依赖 | DAG（有依赖的按序） |
| 重试 | 失败重试 |
| 回填 | 历史数据重跑 |
| 监控 | 延迟/失败告警 |

## 第 5 步：数据质量校验（管道内）

| 检查 | 例 |
|---|---|
| 行数合理 | 不骤降骤增 |
| 主键唯一 | 无重复 |
| 空值率 | 不突增 |
| 引用完整 | 无孤儿 |

⛔ 管道跑成功但数据错 = 更危险（无人知）。要在管道里做质量校验。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 增量可靠 + 加载幂等（覆盖/upsert）+ 质量校验
- WARN = 有管道但加载非幂等
- FAIL = append 重跑重复 / 无质量校验 / 增量漏删除
- UNKNOWN = 拿不到数据源

## 假阳性清单（这些不算「管道可靠」）

- 能跑但重跑重复
- 无质量校验
- 增量漏删除

## 假阴性清单（最常漏的 8 类）

1. **append 重跑重复**
2. **增量漏删除**（删除抓不到）
3. **更新时间回填漏数据**
4. **无质量校验**
5. **无回填机制**
6. **时区不一致**
7. **依赖乱序**
8. **无延迟监控**

- 大数据量管道性能是独立问题
- CDC 依赖数据库能力
- 本技能不实现，只设计
