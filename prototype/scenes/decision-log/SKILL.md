# 决策记录 技能

> 决策记录的价值不在「留个档」，而在**半年后有人问「当初为什么不选另一个」时，能给出答案**。
> 以及更重要的一条：**写下「什么条件下该重新考虑」**——否则一个当时的正确决定，
> 会在条件变化后变成没人敢碰的教条。
> 判据：**新来的人读这份记录，能不能理解为什么、并知道何时该翻案？**

## 什么时候用

- 做了影响后续一段时间的技术/产品决策
- 在几个方案里选了其一
- 决定了「不做什么」（负决定同样要记）
- 交接班前

## 什么时候**不**用

- 日常小事（今天吃什么）
- 已经写成正式 ADR 的（那是更重的一层）
- 纯执行无需决策的

## 第 1 步：四段结构（缺一不可）

### 1.1 背景（为什么现在要决策）

　　现状是什么、遇到什么问题、不决策的代价是什么。

⛔ 不写背景的记录，半年后看不懂「当初为什么纠结」。

### 1.2 备选方案（至少两个，含「不做」）

| 方案 | 优点 | 缺点 |
|---|---|---|
| A | | |
| B | | |
| 不做 | | |

⛔ 只记「我们选了什么」不记其他选项 = 无法评估「当时是不是最优」。

### 1.3 决定 + 理由

　　决定：选 A。
　　理由：<关键权衡点>。
　　谁决定的、谁参与了。

### 1.4 重新考虑的条件（最重要，最常漏）

　　如果出现以下情况，应重新评估：
　　· <条件 1，如「日活超过 10 万」>
　　· <条件 2，如「供应商涨价超过 50%」>
　　· <时间：如「6 个月后强制复盘」>

⛔ 不写翻案条件 = 决定变教条。**这一条是决策记录区别于「会议纪要」的关键。**

## 第 2 步：写清「没选的那个」为什么没选

| 常漏项 | 为什么要写 |
|---|---|
| 被否方案的致命缺点 | 防止半年后重新讨论一遍 |
| 当时的约束（预算/时间/人力） | 约束变了结论可能变 |
| 明知的风险与接受的代价 | 证明是「知情决定」不是「没想到」 |

⛔ 「我们知道 X 有风险但接受，因为 Y」比「我们觉得没问题」可信得多。

## 第 3 步：负决定也要记

「决定不做 X」和「决定做 Y」一样重要：

| 负决定 | 为什么记 |
|---|---|
| 不做某功能 | 防止反复有人提 |
| 不引入某依赖 | 防止后来偷偷引入 |
| 不支持的平台 | 明确边界 |

## 第 4 步：可追溯性

| 要素 | 要求 |
|---|---|
| 编号/日期 | 可引用 |
| 决策者 | 谁拍的板 |
| 关联 | 关联的 issue/PR/文档 |
| 状态 | 有效 / 被取代（被哪个取代） |

⛔ 决策被推翻时，**不要把旧记录删掉**——改成「被 #N 取代」，保留历史。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 四段齐（含翻案条件）+ 备选齐 + 负决定有记
- WARN = 缺翻案条件 或 缺备选
- FAIL = 只有决定没理由 / 删掉被推翻的旧记录
- UNKNOWN = 拿不到决策背景

**决策记录模板**
　　## 决策 #<编号>：<标题>
　　- 日期：<>
　　- 决策者：<>
　　- 状态：有效

　　### 背景
　　<现状、问题、不决策的代价>

　　### 备选
　　| 方案 | 优点 | 缺点 |
　　|---|---|---|
　　| A | | |
　　| B | | |
　　| 不做 | | |

　　### 决定与理由
　　决定：<>
　　理由：<关键权衡>
　　接受的风险：<>

　　### 重新考虑的条件
　　- <>
　　- <>

　　### 关联
　　- issue/PR：<>

**判不了的部分**
- <哪些背景信息缺失>

## 假阳性清单（这些不算「决策记录」）

- 只有「我们决定用 A」
- 没有备选方案
- 没有翻案条件
- 没有决策者
- 推翻后删了旧记录

## 假阴性清单（最常漏的 8 类）

1. **没写翻案条件**（决定变教条）
2. **没写备选方案**（无法评估是否最优）
3. **没写「没选的那个为什么」**
4. **没写当时约束**（约束变结论应变）
5. **没记负决定**（反复被重提）
6. **没写接受的风险**（像没想到）
7. **推翻时删旧记录**（断历史）
8. **没写决策者**（无人负责）

## 本仓库可用的命令

```bash
node tools/evolve/evolve.mjs verify      # 台账完整性（决策也要可追溯）
```

## 与其他技能的关系

- `adr`：更正式的技术决策记录（本技能是轻量版，更强调翻案条件）
- `postmortem`：事故复盘（也是一种决策记录）
- `handoff`：交接时传递未结决策
- `tech-selection`：选型决定（本技能记录其结果）

## 边界（如实说清）

- 不是每个决定都值得记；只记「影响一段时间」的
- 翻案条件难以预测，宁可写得宽泛些
- 决策记录不保证决策正确，只保证可追溯
- 本技能不替你做决定，只记录「怎么定的」
