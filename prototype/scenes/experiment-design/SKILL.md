# 实验设计 技能

> 实验最容易出的错不是「算错显著性」，而是**先看结果再定假设**、
> **样本不够就下结论**、**中途偷看就停**。这些都会让「显著」变成噪音。
> 判据：**这个实验的结论，在实验开始前就能预测它会被什么推翻吗？**
> 不能的，不是实验，是找证据支持已有想法。

## 什么时候用

- 要验证一个改动是否真的有效
- 要比较两个方案
- 要给「提升 X%」找证据

## 什么时候**不**用

- 改动明确是 bug 修复（不需要实验）
- 无法随机分组（→ 准实验/前后对比，且要说清局限）
- 样本本来就极小（→ 定性研究更合适）

## 第 1 步：可证伪的假设（先写，再跑）

### 1.1 假设的三要素

```
改动：<做什么>
指标：<看哪个可量化指标>
方向与幅度：<预计提升多少，或至少不降>
```

### 1.2 必须同时写「什么会推翻它」

| 项 | 例子 |
|---|---|
| 主指标 | 注册转化率 |
| 预期 | 提升 ≥ 2%（相对） |
| **推翻条件** | 提升 < 1% 或 主指标不降但次指标（留存）降 |

⛔ 写完假设再跑，且跑之前不能改假设——否则是事后编故事。

## 第 2 步：样本量（不是「跑一周看看」）

### 2.1 三个输入决定样本量

| 输入 | 说明 |
|---|---|
| **基线转化率** | 现在是多少 |
| **最小可检测效应（MDE）** | 多小的提升值得检测（业务上） |
| **显著性水平 α 与功效 1−β** | 常规 α=0.05、功效=0.8 |

### 2.2 常见陷阱

| 陷阱 | 后果 |
|---|---|
| 样本不够就停 | 假阴性（真有效却说无效） |
| 样本太大 | 微小无意义差异也「显著」 |
| MDE 定太小 | 需要天文数字样本 |

⛔ 「跑一周」不是样本量依据；**先算需要多少，再看要跑多久**。

## 第 3 步：停止规则（防止偷看偏差）

### 3.1 绝对不做的事

| 反模式 | 为什么错 |
|---|---|
| 每天看 p 值，显著了就停 | 多次检验 → 假阳性率暴涨 |
| 中途觉得「没戏」就提前停 | 截断偏差 |
| 结果不好就换指标 | p-hacking |

### 3.2 正确做法

- **固定时长或固定样本量**，跑满再分析
- 若必须提前停，用**序贯检验**（如 alpha spending）
- 分析时**先看主指标**，次指标只作辅助

## 第 4 步：混杂与不可做实验

### 4.1 常见混杂

| 混杂 | 处理 |
|---|---|
| 新奇效应（用户对新 UI 好奇） | 跑够长让新鲜感消退 |
| 季节性（大促/节假日） | 覆盖完整周期 |
| 分流不均（样本比例失衡） | 检查 SRM（样本比例失配） |
| 污染（对照组看到实验组） | 按用户/设备隔离 |

### 4.2 不能做随机实验时

| 情形 | 替代 | 要承认的局限 |
|---|---|---|
| 全量功能无法分组 | 前后对比 | 无法排除时间因素 |
| 伦理/合规限制 | 准实验 | 有选择偏差 |
| 极小样本 | 定性访谈 | 不能推广 |

## 输出格式

- PASS = 假设可证伪 + 样本量算过 + 有停止规则 + 混杂已处理

## 假阳性清单（这些不算「实验」）

- 只有「跑一周看看」
- 假设写在结果之后
- 没算样本量
- 中途偷看就停

## 假阴性清单（最常漏的 8 类）

1. **先看结果再定假设**
2. **样本量没算**
3. **偷看 p 值就停**
4. **换指标（p-hacking）**
5. **忽略新奇效应**
6. **忽略季节性**
7. **没查分流不均（SRM）**
8. **把准实验当随机实验**

## 本仓库可用的命令

```bash
node tools/cost/meter.mjs        # 实验成本核算（若涉及付费调用）
node tools/quality/commit-gate.mjs   # 提交实验代码前
```

## 与其他技能的关系

- `metric-definition`：指标口径（实验主指标的来源）
- `capability-benchmark`：不是实验，是对标打分
- `data-reconcile`：实验数据核对
- `postmortem`：实验结论错后的复盘

## 边界（如实说清）

- 统计显著 ≠ 业务重要；要看效应大小与成本
- 长期效应短期实验测不出（需 holdback 组）
- 网络效应强的产品无法干净随机
- 本技能不跑实验，只设计「怎么跑才可信」
