# 分布式定时调度 技能

> 单机 cron 简单；分布式定时调度的三个难点：**多实例只跑一个、任务分片、错过补偿**。
> 判据：**部署了 5 个实例，一个定时任务会被执行 5 次吗？宕机期间错过的会补跑吗？**

## 什么时候用

- 定时任务在多实例上跑
- 要防重复执行
- 大任务要分片
- 要错过补偿

## 什么时候**不**用

- 单实例简单 cron

## 第 1 步：防重复执行（多实例）

| 方案 | 说明 |
|---|---|
| **选主** | 只有主执行（见 `leader-election`） |
| **分布式锁** | 抢到锁的执行（见 `distributed-lock`） |
| **调度中心** | 统一调度分发给 worker |
| 数据库标记 | 抢一行 |

⛔ 多个实例各自 cron = 同一任务跑 N 次 = 数据重复。

## 第 2 步：任务分片（大任务并行）

| 方案 | 说明 |
|---|---|
| 按分片键分 | 每个 worker 处理一片 |
| 调度中心分片 | 中心分配 |
| 注意 | 分片要能独立、可重试 |

## 第 3 步：错过补偿（宕机期间）

| 情况 | 处理 |
|---|---|
| 宕机错过了时间点 | 启动后检查上次执行时间，补跑 |
| 补偿幂等 | 补跑不重复副作用 |
| 补偿策略 | 补一次 / 跳过 / 补全 |

⛔ 错过了不补 = 数据缺口。

## 第 4 步：幂等与重试

| 项 | 要求 |
|---|---|
| 任务幂等 | 重跑/补跑不重复 |
| 失败重试 | 有限次+退避 |
| 超时 | 长任务要超时/心跳 |

## 第 5 步：可观测

| 项 | 要求 |
|---|---|
| 执行记录 | 何时跑、结果、耗时 |
| 错过告警 | 该跑没跑 |
| 失败告警 | |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 防重复 + 分片 + 补偿 + 幂等 + 可观测
- WARN = 防重复但无补偿
- FAIL = 多实例重复跑 / 无补偿 / 非幂等
- UNKNOWN = 拿不到调度实现

| 方案 | 说明 |
|---|---|

**2. 分片**

**3. 补偿**
| 项 | 策略 |
|---|---|

## 假阳性清单（这些不算「调度对」）

- 多实例各自 cron
- 错过不补
- 任务非幂等

## 假阴性清单（最常漏的 8 类）

1. **多实例重复跑**
2. **错过不补**（数据缺口）
3. **任务非幂等**（补跑重复）
4. **无超时**（卡死）
5. **无执行记录**
6. **分片不均**
7. **时区错**（见 `timezone-handling`）
8. **无错过告警**
