# UI 插件热更新 技能

> 改一行文案要跑 30 秒构建？插件化 + 免构建直出能让「改文件 → 刷新即变」。
> 判据：**改了文件不跑构建、刷新就变吗？会不会命中缓存导致「改了没变」？坏插件会不会拖垮整个面板？**

## 什么时候用

- 做可扩展的 UI（插件面板）
- 要评审「免构建热更新」这类声明
- 出现「改了文件但界面没变」

## 什么时候**不**用

- 单体无插件的静态页

## 第 1 步：插件目录直出（绕过构建）

`/ui-plugins/**` 由服务直接读文件返回，**不经过打包器**。改文件 → 刷新即变。

## 第 2 步：必须 no-store，不能命中缓存

响应头 `Cache-Control: no-store`。否则浏览器缓存旧文件，「改了没变」是假象。

## 第 3 步：坏插件不拖垮面板

单个插件语法错误/加载失败时，只报数（哪个坏了），其它插件照常加载。**不能一个坏的全白屏。**

## 第 4 步：挡路径穿越

`/ui-plugins/../../etc/passwd` 必须被拒绝（403/404），不能真读到系统文件。

## 反例（写下来防复发）

- ✗ 插件走打包器 → 改一行要重新构建
- ✗ 有缓存 → 改了看不到
- ✗ 一个坏插件导致整个面板白屏
- ✗ 不挡 `../` → 任意文件读取漏洞

## 自检清单

- [ ] `/ui-plugins/**` 直出、不构建
- [ ] `Cache-Control: no-store`
- [ ] 坏插件只报数不拖垮
- [ ] 路径穿越被挡

## 参考实现指路

本仓库 `tools/workbench/verify-hot-update.mjs`（14 项：改文件刷新即变、no-store、坏插件不拖垮、路径穿越被挡，含 ②③④ 三条反例）。

## 实测数据（本仓库，可复算）

```
node tools/workbench/verify-hot-update.mjs
```

实测 **14 通过 / 0 失败**（脚本自起服务 + headless Edge）：

1. `/ui-plugins/index.json` 列出插件并带 `mtime`（供前端 cache-bust）
2. `/ui-plugins/<id>/<file>` **直读磁盘**，响应 `Cache-Control: no-store`
3. **改一行文案 → 不跑构建 → 刷新即变**（这是「免构建」的核心证据）
4. 反例②：坏插件只报数，其它插件照常加载（不拖垮面板）
5. 反例③：`/ui-plugins/../../etc/passwd` 必须被拒
6. 边界如实说：只有 `/ui-plugins/**` 免构建；**应用外壳（React 组件/路由/样式基座）仍要构建**
   —— 这一点写进了实现注释，不夸大。

**教训**：**「热更新」的范围要写清楚**。说「整个前端免构建」是吹牛；说「插件目录免构建、外壳仍要构建」才是真的。
