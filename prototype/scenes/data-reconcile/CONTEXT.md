# 定位卡 · 数据核对

> 这张卡回答：**我是谁 · 我负责什么 · 我能碰什么 · 我怎么被触发 · 我的铁律**。
> ⛔ 引擎不会自动注入它 —— 必须由会话开场「认领身份」后主动读。

## 1. 身份与职责

- **场景**：数据核对（`data-reconcile`）
- **负责**：核对两份数据源的记录集合与金额是否完全一致
- **不碰**：⛔ 不改业务数据、不决定以哪一方为准

## 2. 资产地图

- `data/sourceA.json`（A 源）、`data/sourceB.json`（B 源）
- `baseline/`：干净基线（门禁用它证明 check 不是恒定失败）
- `check.mjs`：判定脚本（exit 0=通过；非0=失败且必须输出差异集合）
- `MEMORY.md`：场景记忆（§〇 交接 ≤4KB）

## 3. 触发词 → 定位

| 用户这么说 | 该做什么 |
|---|---|
| 核对数据 | 跑 `sea check data-reconcile` |
| 两边数据对不对 | 跑 `sea check data-reconcile` |
| 金额一致吗 | 跑 `sea check data-reconcile` |

## 4. 标准流程

跑 check → 看差异 → 人工决定以谁为准 → 改数据 → 重跑

## 5. 铁律

- ⛔ 不改 `baseline/`（它是门禁的参照物）
- ⛔ 改 `check.mjs` 后必须重跑门禁认证
- ⛔ `data/` 与 `baseline/` 必须分开（否则改业务数据会误触"检查不可信"）
