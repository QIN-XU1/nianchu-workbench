# API 文档 技能

> API 文档的验收标准不是「写全了字段」，而是**调用者不看源码、不问人，能不能一次调对**。
> 判据：**拿这份文档，一个新人能不能在 10 分钟内发出第一个成功请求？**
> 不能的，文档就是「字段清单」不是「文档」。

## 什么时候用

- 对外/对内 API 交付
- 接口变更后更新文档
- OpenAPI/Swagger 编写

## 什么时候**不**用

- 纯内部函数文档（这不是 API）
- 只写 README 概览 → `readme-bootstrap`

## 第 1 步：每个接口必须有的六件事

| # | 内容 | 为什么必需 |
|---|---|---|
| 1 | **一句话说清做什么** | 调用者先判断要不要用 |
| 2 | **完整请求样例**（可复制） | 照着发就能通 |
| 3 | **参数表**（类型/必填/范围/默认） | 避免猜 |
| 4 | **成功响应样例** | 知道拿什么 |
| 5 | **错误码表**（含触发条件） | 出错能自救 |
| 6 | **什么时候不该用** | 防止误用 |

⛔ 只列字段不给可复制样例 = 调用者还要试错。

## 第 2 步：参数表要写全

| 列 | 要求 |
|---|---|
| 名称 | 与代码一致 |
| 类型 | 精确（string/int/array<object>） |
| 必填 | 明确 |
| 范围/枚举 | 所有合法值 |
| 默认值 | 不填时是什么 |
| 说明 | 一句话 |

⛔ 「必填」不标、枚举不全、默认值不写——是文档被问最多的三件事。

## 第 3 步：错误码（最常被敷衍）

每个错误码要写：
- **码/状态**
- **什么情况触发**
- **怎么处理**

| 反例 | 正例 |
|---|---|
| 「400 参数错误」 | 「40001：`email` 格式非法，请按 RFC5322 校验后重试」 |
| 「500 服务器错误」 | 「50002：下游超时，可重试（幂等接口），建议退避 1s」 |

⛔ 只说「出错了」的文档，让调用者只能来问人。

## 第 4 步：说清边界与约束

| 要说的 | 例子 |
|---|---|
| 限流 | 每秒 10 次 |
| 幂等 | 带 Idempotency-Key 时重复请求返回同一结果 |
| 分页 | 游标分页，`next_cursor` |
| 版本 | v1 到某日期弃用 |
| 认证 | Bearer token |

## 第 5 步：可验证（样例要真能跑）

| 检查 | 判据 |
|---|---|
| 样例可复制 | curl 直接能发（填上占位符） |
| 响应是真实的 | 不是手编的字段 |
| 有最小样例 | 只有必填参数也能通 |

⛔ 编造的响应样例会误导调用者。最好从真实调用截取。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 六件事齐 + 错误码可处理 + 样例可跑
- WARN = 缺例子或错误码不全
- FAIL = 无请求样例 / 错误码只有状态码 / 参数缺必填标注
- UNKNOWN = 拿不到接口实现

**接口文档模板**
```markdown
## <METHOD> <path>
<一句话做什么>

### 请求样例
<可复制的 curl>

### 参数
| 名称 | 类型 | 必填 | 范围/默认 | 说明 |

### 成功响应
<真实样例 + 字段说明>

### 错误码
| 码 | 触发条件 | 处理建议 |

### 约束
- 限流 / 幂等 / 分页 / 版本

### 什么时候不该用
- <>
```

**判不了的部分**
- <哪些接口行为不确定>

## 假阳性清单（这些不算「有 API 文档」）

- 只有字段清单没有样例
- 错误码只有 400/500
- 参数没标必填
- 样例是编的

## 假阴性清单（最常漏的 8 类）

1. **无可复制请求样例**
2. **错误码不可处理**（只说「出错」）
3. **必填未标注**
4. **枚举/默认值不全**
5. **没写限流/幂等**
6. **分页没说清**
7. **没说「什么时候不该用」**
8. **样例响应是编造的**

## 本仓库可用的命令

```bash
node tools/quality/verify-docs.mjs   # 文档与仓库一致
node tools/quality/commit-gate.mjs   # 提交前门禁
```

## 与其他技能的关系

- `api-contract`：接口契约设计（本技能写文档）
- `readme-bootstrap`：README 概览
- `i18n-review`：文档多语言
- `doc-consistency`：文档数字一致

## 边界（如实说清）

- 文档会过期；理想是 OpenAPI 从代码生成并校验
- 不同读者要不同深度（快速上手 vs 完整参考）
- 本技能不生成 SDK，只写文档
