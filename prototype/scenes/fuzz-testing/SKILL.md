# 模糊测试 技能

> 手动测试覆盖不了「意料之外的输入」。模糊测试自动生成畸形输入，找崩溃/越界/死循环。
> 判据：**这个解析器/协议实现，喂垃圾输入会不会崩？**

## 什么时候用

- 解析器/编解码器/协议
- 文件格式处理
- 安全关键代码
- 有内存不安全语言（C/C++/Rust unsafe）

## 什么时候**不**用

- 纯业务 CRUD（收益低）

## 第 1 步：种子与变异

| 项 | 说明 |
|---|---|
| **种子语料** | 有效输入作为起点（覆盖格式） |
| **变异** | 随机改字节/插入/删截 |
| **覆盖引导** | 用覆盖率反馈指导（libFuzzer/AFL） |

## 第 2 步：断言什么算失败

| 失败 | 例 |
|---|---|
| 崩溃 | segfault |
| 内存错 | 越界/泄漏/UB（Sanitizer） |
| 死循环/超时 | |
| 断言违反 | 不变量破坏 |

⛔ 只找崩溃不找「逻辑错」= 漏一半。

## 第 3 步：工具

| 工具 | 语言 |
|---|---|
| libFuzzer/AFL++ | C/C++ |
| cargo-fuzz | Rust |
| go-fuzz/原生 | Go |
| Atheris | Python |
| Jazzer | Java |

配 Sanitizer（ASan/UBSan）抓内存错。

## 第 4 步：持续与回归

| 项 | 要求 |
|---|---|
| CI 常跑 | 持续 fuzz |
| 语料积累 | 覆盖越多越好 |
| 崩了转回归测试 | 每个崩溃用例固定 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 种子+变异+覆盖引导+Sanitizer+回归
- WARN = 有 fuzz 但无覆盖引导
- FAIL = 无 fuzz（安全关键）/ 只找崩溃 / 无 Sanitizer
- UNKNOWN = 拿不到目标

## 假阳性清单（这些不算「fuzz 有效」）

- 纯随机无种子
- 无覆盖引导（覆盖低）
- 无 Sanitizer（漏内存错）

## 假阴性清单（最常漏的 8 类）

1. **无种子语料**
2. **无覆盖引导**
3. **无 Sanitizer**
4. **只找崩溃不找逻辑错**
5. **无超时（死循环）**
6. **崩了不转回归**
7. **不在 CI 跑**
8. **只测 happy 格式**

## 边界（如实说清）

- Fuzz 找的是崩溃类，不保证无漏洞
- 需要语料和算力
- 本技能不实现，只设计
