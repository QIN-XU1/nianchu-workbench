# 记忆预算 技能

> 记忆库只进不出，很快就撑爆上下文窗口。要按作用域设预算，超了就只注入一部分——但**不删信息**。
> 判据：**超预算时只注入一部分吗？裁剪是「不注入」还是「删掉」？被裁的能追溯吗？**

## 什么时候用

- agent 有分层记忆（核心/场景/项目/杂项）且会增长
- 上下文窗口吃紧
- 要评审「记忆预算」这类声明

## 什么时候**不**用

- 无持久记忆的短会话

## 第 1 步：按作用域分类，各有预算

把记忆分四类，每类单独设预算：

| 作用域 | 典型内容 |
|---|---|
| core | 全局必须遵守的（身份/铁律） |
| scene | 当前场景的 |
| project | 项目级的 |
| misc | 其它 |

前缀映射：`core.*` → core、`scene.*` → scene、`project.*` → project、其它 → misc。

## 第 2 步：超预算只注入一部分，不删条目

- 预算超了 → **只注入一部分**，记录 `skipped > 0`
- 注入量**不超预算**
- **裁剪 ≠ 删除**：被裁的条目信息还在，只是这轮不注入

## 第 3 步：被裁的要打标记，可追溯

被裁条目打 `outOfBudget` 标记。这样能解释「为什么这条这轮没注入」，而不是「消失了」。

## 第 4 步：交接闸门

`core` 超预算时**闸门不放行**（不许用「换一批」绕过）；交接必须齐全（`scene.handoff` + 写明「下一步」），否则拒绝。

## 反例（写下来防复发）

- ✗ 超预算直接删条目 → 信息永久丢失
- ✗ 裁剪不打标记 → 无法解释为什么没注入
- ✗ 注入量超预算 → 窗口还是爆
- ✗ core 超预算就「换一批」 → 绕过预算
- ✗ 交接缺「下一步」也放行 → 下一个人接不上

## 自检清单

- [ ] 四作用域各有预算
- [ ] 超预算只注入一部分（skipped>0）
- [ ] 裁剪不删除、打 outOfBudget
- [ ] core 超预算闸门不放行
- [ ] 交接缺 handoff/下一步 → 拒绝
