# 一键复算 技能

> 验收脚本散在几十个文件里，没人会逐个跑。没有总入口，「全绿」就只能靠嘴说。
> 判据：**一条命令能跑完所有验收，并说清 通过/失败/UNKNOWN/WARN 各几个吗？**

## 什么时候用

- 验收脚本超过 5 个
- 要对外证明「可复算」
- 要 CI 一键跑

## 什么时候**不**用

- 只有一两个检查

## 第 1 步：自动发现，不手写清单

遍历目录找 `verify-*.mjs`（或统一前缀），**排除自身**（否则递归跑自己）。

## 第 2 步：逐个真跑，捕获 exit + 输出

- 用同步/异步子进程逐个跑（顺序跑，避免端口/资源冲突）
- 捕获 `exit code` 与 stdout
- 从输出抽「通过 N / 失败 M」与「四态」

## 第 3 步：按退出码归类（关键）

**不要「没有四态就默认 UNKNOWN」**——那会把 exit 1 的真失败也标成 UNKNOWN（掩盖）。

正确：有「四态」行用四态；没有就按 0/1/2/3 → PASS/FAIL/UNKNOWN/WARN。

## 第 4 步：汇总要区分四类

输出：脚本总数 / 有失败 / UNKNOWN / WARN / 无通过行。**「0 失败」必须和「UNKNOWN 几个」一起看**，否则会把「没验」当「验过」。

## 反例（写下来防复发）

- ✗ 不排除自身 → 无限递归
- ✗ 没有四态就默认 UNKNOWN → 掩盖 exit 1 的真失败（我踩过）
- ✗ 并行跑所有脚本 → 端口/临时目录互相踩
- ✗ 只报「0 失败」不报 UNKNOWN 数 → 假绿

## 自检清单

- [ ] 自动发现 + 排除自身
- [ ] 逐个真跑，捕获 exit + 输出
- [ ] 无四态时按退出码归类（不默认 UNKNOWN）
- [ ] 汇总区分 通过/失败/UNKNOWN/WARN

## 参考实现指路

本仓库 `tools/verify-all.mjs`（遍历 tools 下 verify-*.mjs、排除自身、execSync 捕获、按 0/1/2/3 归类、汇总四类）。实测 63 脚本 · 有失败 0 · UNKNOWN 3 · WARN 1。

## 实战记录（本仓库真实事件，2026-11-22）

**事件一（口径 bug）**：我写这个工具时，第一版「没有四态行 → 默认 UNKNOWN」，
结果掩盖了 3 个 `exit 1` 的真失败。改成按退出码归类后才暴露。

**事件二（正则交替 bug）**：另一个同源的审计脚本用正则
`\.(?:mjs|ts|tsx|js|json)` 提取路径，因为 **`js` 排在 `json` 前面**，
把 `evidence/evolve/project-verdict.json` 截成 `project-verdict.js`，
误报「1 处引用不存在」。改成 `json|mjs|tsx|ts|js`（长后缀在前）后归零。

同一个坑在本仓库出现过两次（另一次是 `ts|tsx` 把 `.tsx` 截成 `.ts`）。

**修法**：把「后缀短的写在前」固化成回归用例——`tools/skills/verify-references.mjs`
里有一条反例专门断言 `.json 不被截成 .js`。

**复算**：`node tools/skills/verify-references.mjs`（4/4，含该反例）。

**教训**：**汇总工具本身也会骗人**。凡是用「解析文字」做归类的地方，都要有一层「按机器可读信号（退出码）兜底」。
