# Web 性能优化 技能

> Web 性能别凭感觉优化，先量 Core Web Vitals。用户感受的是「首屏多久出来」，不是「JS 多少 KB」。
> 判据：**LCP / INP / CLS 达标吗？在真机弱网下也达标吗？**

## 什么时候用

- 页面/首屏慢
- Core Web Vitals 不达标
- 要改善体验/SEO

## 什么时候**不**用

- 后端 API 慢（那是 `perf-profile`）

## 第 1 步：先量 Core Web Vitals

| 指标 | 含义 | 好 |
|---|---|---|
| **LCP** | 最大内容渲染 | < 2.5s |
| **INP** | 交互响应 | < 200ms |
| **CLS** | 布局偏移 | < 0.1 |

⛔ 不看真机/弱网数据 = 你在快网络上测的没用。

## 第 2 步：关键渲染路径

| 优化 | 说明 |
|---|---|
| 减少阻塞渲染的 CSS/JS | 内联关键 CSS、异步 JS |
| 首屏资源优先 | preload 关键资源 |
| 延迟非关键 | defer/懒加载 |

## 第 3 步：资源优化

| 项 | 手段 |
|---|---|
| JS/CSS | 压缩、tree-shaking、代码分割 |
| 图片 | 现代格式（WebP/AVIF）、响应式、懒加载、尺寸合适 |
| 字体 | 子集化、font-display |
| 缓存 | 内容哈希+长缓存（见 `http-caching`） |

## 第 4 步：LCP / CLS 专项

| 指标 | 常见原因 | 修法 |
|---|---|---|
| LCP 高 | 大图/慢服务器/阻塞渲染 | 优化首屏图、预加载 |
| CLS 高 | 图片无尺寸、动态插入 | 预留空间 |
| INP 高 | 长任务阻塞主线程 | 拆分任务、web worker |

⛔ 图片不写宽高 = 加载后跳动 = CLS 差。

## 第 5 步：验证

| 项 | 要求 |
|---|---|
| 实验室数据 | Lighthouse |
| 真实用户数据（RUM） | 真机分布 |
| 弱网 | 3G/慢速 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = CWV 达标 + 关键路径优化 + 真机验证
- WARN = 有优化但无 RUM
- FAIL = 不量就优化 / CLS 差 / 阻塞渲染严重
- UNKNOWN = 拿不到性能数据

**1. CWV**
| 指标 | 值 |
|---|---|

**2. 关键路径**
| 项 | 优化 |
|---|---|

**3. 判不了的部分**
- <拿不到的真实数据>

## 假阳性清单（这些不算「性能好」）

- 只在快网络测
- 压缩了但 LCP 差
- 图片无尺寸

## 假阴性清单（最常漏的 8 类）

1. **不量就优化**
2. **只快网络测**（真机差）
3. **图片无宽高**（CLS）
4. **阻塞渲染资源**
5. **图片未优化**
6. **无代码分割**
7. **字体阻塞**
8. **无 RUM**

- 实验室与真实有差异
- 性能预算要团队共识
- 本技能不实现，只设计
