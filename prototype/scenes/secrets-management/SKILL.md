# 密钥管理 技能

> 密钥泄露是最贵的事故：一次泄露就可能要全量轮转、通知用户、赔钱。
> 三类最常见的泄露：**硬编码进代码、进了日志、进了 git 历史**。
> 判据：**如果一个开发者离职/一台机器被攻破，能不能拿走所有密钥？**

## 什么时候用

- 审查配置/代码里的凭证
- 设计密钥存储
- 出了泄露事件
- 合规审计

## 什么时候**不**用

- 无任何凭证的纯静态站点

## 第 1 步：先找「硬编码与泄露」（最高危）

| 藏身处 | 检查 |
|---|---|
| **源码硬编码** | `sk-`/`AKIA`/`password=`/`secret=` 正则扫 |
| **git 历史** | 曾提交过的密钥（即使现在删了，历史里还在） |
| **配置文件** | `.env` 有没有进仓库 |
| **日志** | 打印了完整 request/headers |
| **异常/错误** | 堆栈里带出连接串 |
| **前端 bundle** | 打包进了浏览器代码 |
| **CI 输出** | 构建日志暴露 |
| **镜像层** | Docker 层里残留 |

⛔ 「现在代码里删了」不等于「泄露解除」——**git 历史还在**，必须轮转密钥。

## 第 2 步：存储位置分级

| 方式 | 安全性 | 适用 |
|---|---|---|
| **密钥管理服务**（Vault/KMS/Secrets Manager） | 最高 | 生产 |
| 环境变量（从密钥服务注入） | 中 | 常见 |
| 加密配置文件 | 中 | 有限场景 |
| 明文配置文件 | ❌ | 不该出现 |
| 代码硬编码 | ❌❌ | 绝不 |

## 第 3 步：最小权限与隔离

| 检查 | 判据 |
|---|---|
| 每个服务用独立凭证 | 不是共享一个万能 key |
| 权限最小 | 只读的就别给写 |
| 按环境隔离 | dev key 不能操作 prod |
| 有效期 | 短期凭证（STS/token）优于长期 AK |

⛔ 所有服务共用一个「超级 key」= 一处泄露全线沦陷。

## 第 4 步：轮转

| 项 | 要求 |
|---|---|
| 周期 | 定期（如 90 天） |
| 泄露时 | 立即轮转（不是「计划轮转」） |
| 轮转不中断 | 支持双 key 并存过渡 |
| 自动 | 手动轮转迟早忘 |

## 第 5 步：检测（事后）

| 手段 | 查什么 |
|---|---|
| 密钥扫描（CI 钩子） | 提交时拦硬编码 |
| 泄露监控（如 GitHub secret scanning） | 公开仓库泄露 |
| 使用异常告警 | 异地/异常时段使用 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 无硬编码 + 密钥服务存 + 最小权限 + 有轮转
- WARN = 环境变量存但无轮转
- FAIL = 代码/日志/前端有密钥 / git 历史有密钥未轮转 / 共享超级 key
- UNKNOWN = 拿不到配置

## 假阳性清单（这些不算「管理好」）

- 用了环境变量但没有轮转
- 删了代码里的 key 但没轮转（git 历史还在）
- 有 Vault 但所有服务共用 root token

## 假阴性清单（最常漏的 8 类）

1. **git 历史里的密钥**（删了也没用，要轮转）
2. **日志打印完整 headers/request**
3. **前端 bundle 打包进密钥**
4. **共享超级 key**
5. **dev key 能操作 prod**
6. **无轮转**
7. **Docker 层残留**
8. **异常堆栈暴露连接串**

## 本仓库可用的命令

node tools/quality/commit-gate.mjs   # 提交前门禁

## 与其他技能的关系

- `security-review`：代码安全（本技能专密钥）
- `input-validation`：防泄露到错误信息
- `observability-design`：日志脱敏
- `ci-pipeline`：密钥扫描进 CI

## 边界（如实说清）

- 密钥管理服务的「信任根」本身要保护
- 轮转需要下游配合，可能中断
- 本技能不实现 Vault，只审查与设计
