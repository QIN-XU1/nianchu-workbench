# 文件上传审查 技能

> 文件上传是 webshell 和 RCE 的重灾区：**只校验扩展名 = 直接上传 .php/.jsp 拿服务器**。
> 判据：**用户上传一个改名成 .jpg 的脚本，会发生什么？**

## 什么时候用

- 有文件上传功能
- 头像/附件/图片
- 用户上传后服务端处理

## 什么时候**不**用

- 无上传功能

## 第 1 步：类型校验（最核心）

| 校验方式 | 安全性 |
|---|---|
| 只查扩展名 | ❌ 可改 |
| 查 Content-Type | ❌ 客户端可伪造 |
| **查文件头（magic bytes）** | ✅ 看真实内容 |
| **白名单允许的类型** | ✅ 默认拒绝 |

⛔ 「检查 `.jpg` 后缀」= 把 `shell.php` 改名 `shell.jpg` 就绕过。必须查文件头 + 白名单。

## 第 2 步：存储隔离（防执行）

| 风险 | 防法 |
|---|---|
| 上传目录可执行脚本 | 上传目录**禁止执行**（Nginx/Apache 配置） |
| 路径穿越（`../../etc`） | 文件名规范化 + 不用原始文件名 |
| 覆盖已有文件 | 用随机名/ID |
| 目录遍历 | 存储路径白名单 |

★ 最经典的失败：上传目录在 web 根下且允许 PHP 执行 → 传 `.jpg` 里藏 PHP → 访问即执行。

## 第 3 步：大小与数量

| 检查 | 目的 |
|---|---|
| 单文件大小上限 | 防磁盘/内存耗尽 |
| 总数/频率 | 防滥用 |
| 解压炸弹 | 压缩包解压后爆内存（zip bomb） |

## 第 4 步：图片/文档处理的风险

| 风险 | 说明 |
|---|---|
| **图片解析库漏洞**（ImageMagick/旧库） | 恶意图片触发 RCE |
| **zip bomb** | 解压爆内存 |
| **XXE**（XML/Office） | 外部实体注入 |
| **SSRF**（图片 URL 导入） | 导入远程图片时打内网 |
| **SVG** 含脚本 | SVG 可嵌入 JS，当图片显示时执行 |

## 第 5 步：访问控制

| 检查 | 判据 |
|---|---|
| 私有文件鉴权 | 别人的文件不能直接访问 |
| 直链不可猜测 | 随机路径，不要可枚举 |
| CDN 签名 | 私有内容用签名 URL |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 内容校验 + 白名单 + 存储禁执行 + 大小限制 + 鉴权
- WARN = 校验了但存储未隔离执行
- FAIL = 只查扩展名 / 上传目录可执行 / 路径穿越
- UNKNOWN = 拿不到上传实现

## 假阳性清单（这些不算「上传安全」）

- 只查扩展名
- 有大小限制但无类型校验
- 上传目录可执行

## 假阴性清单（最常漏的 8 类）

1. **只查扩展名**（改后缀绕过）
2. **上传目录可执行**（webshell）
3. **路径穿越**
4. **用原始文件名**（覆盖/穿越）
5. **无大小限制**（磁盘爆）
6. **zip bomb**
7. **图片库漏洞**（RCE）
8. **SVG 含脚本**

## 边界（如实说清）

- 文件类型识别没有 100%（但白名单能大幅降低）
- 转码（重新编码图片）能消除部分风险但有成本
- 本技能不实现，只审查
