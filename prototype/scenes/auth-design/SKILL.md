# 认证授权设计 技能

> 认证（你是谁）和授权（你能做什么）是两件事，常被混为一谈。
> 最常见的漏洞不是「没登录」，而是**登录了但能看别人的数据（越权）**。
> 判据：**把 URL 里的 id 改成别人的，你能看到别人的数据吗？** 能 = IDOR 越权。

## 什么时候用

- 设计登录/权限
- 审查越权风险
- 多租户隔离
- 第三方登录

## 什么时候**不**用

- 无用户体系的纯公开服务

## 第 1 步：认证方式

| 方式 | 特点 | 陷阱 |
|---|---|---|
| **Session + Cookie** | 服务端状态 | CSRF、会话固定 |
| **JWT** | 无状态 | 无法主动失效、密钥泄露 |
| **OAuth/OIDC** | 第三方登录 | state/redirect 校验 |
| **API Key** | 服务间 | 泄露、无过期 |

## 第 2 步：授权模型

| 模型 | 说明 | 适用 |
|---|---|---|
| **RBAC**（角色） | 按角色授权 | 最常见 |
| **ABAC**（属性） | 按属性/上下文 | 细粒度 |
| **ReBAC**（关系） | 按关系（如文档协作者） | 协作场景 |

## 第 3 步：越权（最高频漏洞）

| 类型 | 说明 | 例子 |
|---|---|---|
| **水平越权（IDOR）** | 访问同级别他人资源 | 改 URL id 看别人订单 |
| **垂直越权** | 低权限做高权限操作 | 普通用户调管理接口 |

★ 防御的核心：**每个请求都要校验「这个用户能不能操作这个具体资源」**，不能只校验「登录了没」。

⛔ 只在前端隐藏按钮 = 后端没校验 = 直接调 API 越权。

## 第 4 步：认证常见漏洞

| 漏洞 | 说明 |
|---|---|
| **会话固定** | 登录后不换 session id |
| **JWT 算法混淆** | `alg:none` 或 RS256→HS256 |
| **JWT 不过期/不校验签名** | |
| **密码存储弱** | 明文/MD5（应 bcrypt/argon2） |
| **暴力破解** | 无登录限流 |
| **CSRF** | Cookie 认证无 CSRF token |
| **重置密码可枚举** | 泄露账号是否存在 |
| **OAuth state 不校验** | CSRF/开放重定向 |

## 第 5 步：多租户隔离

| 检查 | 判据 |
|---|---|
| 每个查询带 tenant 条件 | 不是靠应用层记得加 |
| 数据库行级隔离 | RLS 或强制 where |
| 缓存 key 含租户 | 防串数据 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 认证合理 + 每请求授权校验 + 无越权 + 密码强哈希
- WARN = 有认证但资源级授权不足
- FAIL = 只前端校验 / IDOR / 明文密码 / JWT alg:none
- UNKNOWN = 拿不到权限实现

## 假阳性清单（这些不算「有授权」）

- 登录了但没资源级校验
- 前端隐藏按钮
- 只校验角色不校验资源归属

## 假阴性清单（最常漏的 8 类）

1. **IDOR 水平越权**（改 id 看别人）
2. **只前端隐藏按钮**
3. **JWT alg:none / 不校验签名**
4. **密码明文/MD5 存储**
5. **会话固定**（登录不换 id）
6. **登录无限流**（暴力破解）
7. **CSRF**（Cookie 认证无 token）
8. **多租户查询漏 tenant**（串数据）
