# 成本优化 技能

> 成本优化最常见的错：**砍错地方**。花三天优化了一个占比 2% 的成本，忽略了 60% 的大头。
> 判据：**你的优化，动的是成本占比最大的那部分吗？** 不是就是白忙。

## 什么时候用

- 账单太贵
- agent token 成本高
- 要降本

## 什么时候**不**用

- 成本已经很低
- 只查一次账单 → 直接看

## 第 1 步：先量化成本构成（最重要）

| 维度 | 拆解 |
|---|---|
| 按服务 | 哪个服务最贵 |
| 按资源 | 计算/存储/带宽/DB |
| 按调用 | agent 里 token/工具/模型 |
| 固定 vs 变动 | 预留资源 vs 按量 |

⛔ 不量化就优化 = 拍脑袋。先画成本占比图。

## 第 2 步：常见大头与手段

| 大头 | 手段 |
|---|---|
| 计算 | 降配、弹性伸缩、spot |
| 存储 | 冷热分层、清理、压缩 |
| 带宽/CDN | 缓存、压缩 |
| 数据库 | 索引优化、读写分离、归档 |
| **LLM token** | 小模型、缓存、压缩上下文、批处理 |

## 第 3 步：LLM/agent 成本（我们领域）

| 手段 | 说明 |
|---|---|
| **模型分级** | 简单任务用小模型 |
| **prompt 缓存** | 相同前缀复用（provider 支持时） |
| **上下文压缩** | 见 `context-management` |
| **批处理** | 非实时批量更便宜 |
| **减少工具往返** | 少而准的工具调用 |

⛔ 用最贵的模型做所有事 = 最贵的方式。

## 第 4 步：优化的风险（别为了省钱降质量）

| 优化 | 风险 |
|---|---|
| 降配 | 稳定性下降 |
| 缓存 | 一致性 |
| 小模型 | 效果下降 |
| 归档 | 查询变慢 |

★ 每个优化都要问：**牺牲了什么？可接受吗？**

## 第 5 步：持续监控

| 项 | 说明 |
|---|---|
| 成本告警 | 异常上涨 |
| 按维度归因 | 谁花的 |
| 单位成本 | 每请求/每用户成本 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 量化构成 + 优化大头 + 评估质量影响 + 监控
- WARN = 优化了但无量化
- FAIL = 砍小头留大头 / 降质量不评估 / 无监控
- UNKNOWN = 拿不到账单明细

| 项 | 占比 |
|---|---|

| 大头 | 手段 | 牺牲 |
|---|---|---|

**3. LLM 成本**
| 手段 | 用了 |
|---|---|

## 假阳性清单（这些不算「降本有效」）

- 优化了小占比
- 降配降质量
- 无成本归因

## 假阴性清单（最常漏的 8 类）

1. **不量化砍小头**
2. **用最贵模型做所有事**
3. **无 prompt 缓存**
4. **上下文不压缩**
5. **存储不分冷热**
6. **无成本告警**
7. **降质不评估**
8. **无单位成本视角**

## 本仓库可用的命令

```bash
node tools/cost/ledger.mjs       # 记账
```

## 与其他技能的关系

- `context-management`：省 token
- `caching-strategy`：省计算
- `tech-selection`：模型选择
- `capacity-planning`：容量与成本

## 边界（如实说清）

- 成本优化不能牺牲核心质量
- 预留 vs 按量是预测问题
- 本技能不实现，只分析
