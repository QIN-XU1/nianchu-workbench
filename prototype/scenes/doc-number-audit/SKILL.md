# 文档数字核对 技能

> 文档里写「91 个方法」「186 个技能」「899 格证据」——这些数字会随代码变而**悄悄过期**（上面三个就是写这一行时的真值，明天可能就不是）。
> 判据：**文档里的每个数字，都能和代码实测对上吗？对不上的是哪几个？**

## 什么时候用

- 文档/README 里写了具体数字
- 代码改了之后，担心文档没跟上
- 评审「文档准确」这类声明

## 什么时候**不**用

- 文档里没有具体数字

## 第 1 步：抽取文档里的数字 + 上下文

把「数字 + 它修饰的名词」抽出来（如「91 个方法」「186 个技能」），并记录它在哪一行。

## 第 2 步：对每类数字找真值来源

- 方法数 → 读服务端 `/api/host-status` 的 implemented 数组长度
- 技能数 → 数 `prototype/scenes/` 下每个子目录里的 SKILL.md
- 证据格数 → 跑 provenance 脚本

**真值必须来自可执行来源，不是另一份文档。**

## 第 3 步：比对并分类

- 一致 → 通过
- 不一致 → 报偏差（文档值 vs 真值）
- 找不到真值来源 → 标 UNKNOWN（不猜）

## 反例（写下来防复发）

- ✗ 用「另一份文档的数字」当真值 → 两份一起错
- ✗ 数字一致就放过，不看它修饰的名词对不对 → 数字对但语义错
- ✗ 找不到真值就跳过不报 → 掩盖过期

## 自检清单

- [ ] 抽出了文档数字 + 名词 + 行号
- [ ] 每个数字有可执行的取值来源
- [ ] 不一致的报了偏差
- [ ] 无来源的标 UNKNOWN

## 参考实现指路

本仓库 `tools/quality/audit-doc-numbers.mjs`：抽取文档数字，跑命令取真值（技能数/方法数/证据格），比对并报告；未覆盖项以 WARN 报出（exit 3），不阻断但可见。
