# 数据血缘 技能

> 数据血缘解决两个问题：**「这个数从哪来的？」**（溯源）和 **「改这个会影响谁？」**（影响分析）。
> 没有血缘的数据系统，改一个上游字段不知道会崩多少下游报表。
> 判据：**一个数字错了，能不能顺藤摸瓜找到根因？**

## 什么时候用

- 数据仓库/多表依赖
- 数据出错溯源
- 要评估改动影响

## 什么时候**不**用

- 单一独立表

## 第 1 步：血缘的粒度

| 粒度 | 说明 |
|---|---|
| 表级 | A 表→B 表（粗） |
| **字段级** | A.x→B.y（细，最有用） |
| 任务级 | 哪个 ETL 任务 |

★ 字段级血缘最有价值（改字段才知影响），但最难建。

## 第 2 步：怎么采集

| 方式 | 说明 |
|---|---|
| **解析 SQL** | 从 ETL SQL 解析表/字段依赖 |
| 埋点上报 | 任务运行时上报 |
| 手工登记 | 易过时 |

## 第 3 步：两个方向

| 方向 | 用途 |
|---|---|
| **上游（溯源）** | 这个数从哪来 → 排错 |
| **下游（影响）** | 改这个影响谁 → 变更评估 |

⛔ 只有上游没有下游 = 能排错但改之前不知会崩谁。

## 第 4 步：与质量/变更联动

| 联动 | 说明 |
|---|---|
| 数据质量告警 → 查上游 | 定位根因 |
| 改 schema → 查下游 | 影响分析（见 `schema-evolution`） |
| 删除数据 → 查依赖 | 防误删 |

## 第 5 步：常见坑

| 坑 | 后果 |
|---|---|
| 血缘过时 | 误导 |
| 只表级无字段级 | 影响分析太粗 |
| 不覆盖所有任务 | 有盲区 |
| 无人维护 | 建了不用 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 字段级 + 双方向 + 自动采集 + 联动质量/变更
- WARN = 只有表级或只一个方向
- FAIL = 无血缘 / 手工易过时 / 只溯源无影响分析
- UNKNOWN = 拿不到数据管道

## 假阳性清单（这些不算「有血缘」）

- 只有表级
- 手工登记已过时
- 只溯源无影响分析

## 假阴性清单（最常漏的 8 类）

1. **只表级无字段级**
2. **只上游无下游**
3. **手工血缘过时**
4. **不覆盖所有任务**（盲区）
5. **不与质量告警联动**
6. **不与变更联动**
7. **建了不维护**
8. **删除前不查依赖**

## 本仓库可用的命令

```bash
node tools/memory/query.mjs          # 查询

```

## 与其他技能的关系

- `etl-design`：管道（血缘来源）
- `data-quality`：质量告警溯源
- `schema-evolution`：变更影响
- `data-retention`：删除前查依赖

## 边界（如实说清）

- 字段级血缘解析复杂（动态 SQL 难）
- 血缘维护是持续成本
- 本技能不实现，只设计
