# 代码生成 技能

> 代码生成适合**大量同构的重复代码**（CRUD、DTO、协议桩）；不适合**多变、需人判断**的逻辑。
> 判据：**生成的代码，是「每次都一样的样板」，还是「需要人调的业务」？** 后者不该生成。

## 什么时候用

- 大量同构代码（CRUD/接口桩/DTO）
- 从单一源（schema/proto）派生
- 要保证一致性

## 什么时候**不**用

- 逻辑多变需判断
- 生成后又大量手改（那不如手写）

## 第 1 步：单一源驱动

| 源 | 生成 |
|---|---|
| OpenAPI | 客户端/服务端桩 |
| proto | gRPC 代码 |
| DB schema | ORM 模型 |
| 配置 | 常量/枚举 |

★ 从**单一权威源**生成，保证一致性（见 capability A10 单一源思想）。

## 第 2 步：模板设计

| 原则 | 说明 |
|---|---|
| 模板与逻辑分离 | 模板只管结构 |
| 可扩展点 | 留 hook 让人定制 |
| 幂等生成 | 重复生成结果一致 |

## 第 3 步：生成物维护

| 策略 | 说明 |
|---|---|
| **不入库**（构建时生成） | 避免手改与生成冲突 |
| 入库 + 标记 | 需标注「勿手改」 |
| 校验 | CI 检查生成物与源一致（防漂移） |

⛔ 生成物入库还手改 = 下次生成覆盖手改 = 冲突。

## 第 4 步：与手写边界

- 生成「骨架/样板」，手写「业务」
- 生成的文件不要手改（改源或模板）
- 定制点用 hook/子类而非直接改生成物

## 第 5 步：验证

| 项 | 要求 |
|---|---|
| 生成物能编译/跑 | CI |
| 与源一致 | 漂移检测 |
| 可读 | 生成的代码也要能看懂 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 单一源 + 幂等 + 漂移检测 + 边界清晰
- WARN = 生成物入库无漂移检测
- FAIL = 生成后又大量手改 / 无单一源 / 生成物不可维护
- UNKNOWN = 拿不到生成设置

## 假阳性清单（这些不算「代码生成好」）

- 生成后手改
- 无单一源
- 生成物与源漂移

## 假阴性清单（最常漏的 8 类）

1. **生成后大量手改**
2. **无单一源**
3. **生成物漂移无检测**
4. **模板含业务逻辑**
5. **生成不可复现**
6. **无扩展点**
7. **生成物不可读**
8. **改源不改模板**

## 边界（如实说清）

- 代码生成增加工具链复杂度
- 过度生成会让调试变难
- 本技能不实现生成器，只设计
