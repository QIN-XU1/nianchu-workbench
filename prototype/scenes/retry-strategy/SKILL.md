# 重试策略 技能

> 重试最大的反直觉：**盲目重试会把小故障放大成大故障**。
> 下游抖了一下，所有客户端同时重试 3 次 = 瞬间 4 倍流量 = 彻底打垮。
> 判据：**重试会不会让本来能恢复的下游彻底挂掉？** 会的就是设计错了。

## 什么时候用

- 调用外部服务/网络
- 有瞬时抖动
- 要提升成功率

## 什么时候**不**用

- 错误是永久的（4xx 参数错、鉴权失败、404）
- 操作不幂等（重试会重复副作用）
- 调用方已经是重试上游（重试套重试）

## 第 1 步：分错误类型（决定性一步）

| 错误类 | 例子 | 该重试吗 |
|---|---|---|
| **瞬时** | 超时、连接重置、503 | ✅ 重试 |
| **限流** | 429 | ✅ 但按 Retry-After |
| **永久** | 400/401/403/404/422 | ❌ 绝不 |
| **未知** | 500（可能是 bug） | ⚠ 谨慎，有限次 |

⛔ 对 4xx 重试是纯浪费，还会放大错误日志。

## 第 2 步：退避（必须指数 + 抖动）

| 方案 | 问题 |
|---|---|
| 固定间隔 | 同时重试 → 风暴 |
| 线性递增 | 仍会同步 |
| **指数退避** | 1s/2s/4s/8s |
| **指数 + 抖动** | 1±随机 → 打散同步 |

- 「抖动」= 在退避时间上加随机量（full jitter: `sleep = random(0, base*2^n)`）
- 这是防「重试风暴」的关键

## 第 3 步：次数与总时限

| 项 | 建议 |
|---|---|
| 最大次数 | 3-5 次（不要无限） |
| **总时限** | 必须有（如 10s 内没成就不重试了） |
| 熔断 | 连续失败到阈值 → 停止重试一段时间（配合降级） |

⛔ 只限次数不限总时长 = 多次长超时叠加，用户等 1 分钟。

## 第 4 步：幂等前提（否则不能重试）

重试的前提是**操作幂等**（见 `idempotency-design`）。
不幂等的写操作重试 = 重复扣款/重复下单。

## 第 5 步：重试放大检查（多层调用）

| 层级 | 每层重试 3 次 |
|---|---|
| A 调 B 调 C | C 挂一次 → A 侧实际发了 3×3×3 = 27 次 |

⛔ 多层重试叠加 = 指数放大。**只在最外层重试，或全局预算限制**。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 只重试瞬时错 + 指数抖动 + 有总时限 + 幂等
- WARN = 无抖动 或 无总时限
- FAIL = 重试 4xx / 无限重试 / 多层叠加无预算 / 非幂等重试
- UNKNOWN = 拿不到错误分类

## 假阳性清单（这些不算「有重试」）

- 对所有错误都重试
- 固定间隔
- 无限重试
- 没考虑幂等

## 假阴性清单（最常漏的 8 类）

1. **重试 4xx**（永久错）
2. **无抖动**（同步风暴）
3. **无总时限**
4. **无限重试**
5. **多层重试叠加**（27 倍放大）
6. **非幂等重试**（重复副作用）
7. **无熔断**（持续打挂下游）
8. **重试不记录**（看不到重试率）

## 与其他技能的关系

- `idempotency-design`：重试的前提

## 边界（如实说清）

- 重试不能修复永久错误，会掩盖 bug
- 重试增加延迟；实时性高的场景要权衡
- 本技能不实现，只设计规则
