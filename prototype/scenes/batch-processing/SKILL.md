# 批处理设计 技能

> 批处理的三大要求：**能分批（不爆内存）、能断点续跑（挂了不用从头）、能重跑不重复（幂等）**。
> 判据：**跑到 90% 挂了，能不能从 90% 继续而不是从头？重跑会不会重复？**

## 什么时候用

- 大批量数据处理
- 定时任务
- 数据迁移/清洗

## 什么时候**不**用

- 数据量小一次性

## 第 1 步：分批（防爆内存/超时）

| 策略 | 说明 |
|---|---|
| 按 ID/时间游标分页 | 每批处理 N 条 |
| 批大小 | 按内存/时间调 |
| 流式处理 | 边读边处理不全部加载 |

⛔ 一次性 `SELECT *` 全表加载 = 内存爆。

## 第 2 步：断点续跑（挂了能继续）

| 做法 | 说明 |
|---|---|
| **记录进度**（游标/offset） | 处理到哪了 |
| **检查点**（checkpoint） | 每批完成后存进度 |
| 幂等 | 续跑重处理一批不重复 |

★ 没检查点 = 跑 90% 挂了，只能从头（浪费）。

## 第 3 步：幂等（重跑不重复）

| 方式 | 说明 |
|---|---|
| Upsert | 按主键覆盖 |
| 覆盖分区 | 先删后插 |
| 去重键 | 处理前查是否已处理 |

⛔ append + 重跑 = 重复数据。

## 第 4 步：失败处理

| 情况 | 处理 |
|---|---|
| 单条失败 | 记录并继续（隔离坏数据） |
| 整批失败 | 重试整批 |
| 毒数据 | 隔离到死信，不阻塞 |

## 第 5 步：资源与调度

| 项 | 要求 |
|---|---|
| 并发 | 不要太高（压垮 DB） |
| 错峰 | 避开高峰 |
| 超时 | 长任务要心跳/续期 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 分批 + 检查点 + 幂等 + 坏数据隔离
- WARN = 分批但无检查点
- FAIL = 全量加载 / 无幂等 / 无坏数据隔离
- UNKNOWN = 拿不到数据量

## 假阳性清单（这些不算「批处理好」）

- 能跑但挂从头
- append 重跑重复
- 全量加载

## 假阴性清单（最常漏的 8 类）

1. **全量加载**（内存爆）
2. **无检查点**（挂从头）
3. **非幂等**（重跑重复）
4. **坏数据阻塞整批**
5. **并发太高**（压垮 DB）
6. **无超时**（卡死）
7. **不避峰**
8. **无进度可观测**

## 边界（如实说清）

- 极大数据要分布式处理（Spark 等）
- 批处理延迟高（要实时用流处理）
- 本技能不实现，只设计
