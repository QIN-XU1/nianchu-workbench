# 输入校验 技能

> 输入校验的核心不是「拦掉坏输入」，而是**信任边界**：哪些输入永不可信。
> 所有来自外部的数据（请求体/URL/头/文件/第三方回调）都不可信。
> 判据：**这个输入能到达的地方，每一处都假设它是恶意的吗？**

## 什么时候用

- 设计 API 入参
- 处理表单/文件上传
- 有 SQL/命令/模板拼接
- 防注入/XSS

## 什么时候**不**用

- 纯内部可信调用（但仍应校验类型）

## 第 1 步：信任边界（决定校验在哪）

| 层 | 校验什么 | 能替代其他层吗 |
|---|---|---|
| **前端** | 用户体验（即时提示） | ❌ 可被绕过 |
| **API 网关** | 认证/限流/大体量 | ❌ 不校验业务 |
| **服务端业务** | 类型/范围/业务规则 | ✅ 权威 |
| **数据库** | 约束（非空/唯一/外键） | 兜底 |

⛔ 只在前端校验 = 直接 curl 就绕过。

## 第 2 步：白名单 vs 黑名单

| 方式 | 安全 | 说明 |
|---|---|---|
| **白名单**（只允许已知好） | ✅ 强 | 默认拒绝 |
| **黑名单**（禁止已知坏） | ❌ 弱 | 总有没想到的坏 |

⛔ 防注入/XSS 用黑名单 = 一定会漏。用白名单 + 编码。

## 第 3 步：校验什么（维度清单）

| 维度 | 检查 |
|---|---|
| **类型** | 是字符串还是对象？数字范围？ |
| **长度** | 最大/最小（防超长 DoS） |
| **范围/枚举** | 值在允许集合内 |
| **格式** | 邮箱/电话/日期按格式 |
| **编码** | 防注入：SQL 参数化、HTML 转义、命令参数分离 |
| **文件** | 类型（看内容不看扩展名）、大小、文件名 |

## 第 4 步：输出编码（防注入的关键）

| 场景 | 防法 |
|---|---|
| SQL | **参数化查询**（不是拼接 + 转义） |
| HTML | 上下文相关转义（不手写） |
| 命令 | 参数数组分离（不拼 shell 字符串） |
| URL/路径 | 路径规范化 + 白名单 |
| 日志 | 防日志注入（控制字符） |

⛔ 「转义特殊字符」不如「参数化/分离参数」根本。

## 第 5 步：错误信息

| 反例 | 正例 |
|---|---|
| 「参数错误」 | 「email 格式非法」 |
| 回显完整 SQL/堆栈 | 只回显安全信息 |
| 泄露存在性（用户不存在 vs 密码错） | 统一「账号或密码错误」 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 服务端权威校验 + 白名单 + 参数化/转义 + 错误信息安全
- WARN = 校验在但用黑名单
- FAIL = 只前端校验 / SQL 拼接 / 错误泄露内部
- UNKNOWN = 拿不到入参处理

## 假阳性清单（这些不算「有校验」）

- 只前端校验
- 黑名单防注入
- 「手写转义」当参数化

## 假阴性清单（最常漏的 8 类）

1. **只前端校验**（curl 绕过）
2. **SQL 拼接**（注入）
3. **黑名单防 XSS/注入**（必漏）
4. **回显堆栈/SQL**
5. **文件只看扩展名**
6. **无长度上限**（DoS）
7. **错误泄露账号是否存在**
8. **日志注入**（控制字符）

## 与其他技能的关系

- `security-review`：整体安全（本技能是入口）
- `sql-review`：参数化与注入
- `api-doc`：参数约束文档
- `threat-model`：威胁面识别

## 边界（如实说清）

- 校验完备性无法证明，只能覆盖已知维度
- 有些注入（如二次注入）需存储后再校验
- 本技能不写代码，只列校验点
