# 国际化审查 技能

> 国际化最常见的错不是「翻译不准」，而是**结构上不支持多语言**：
> 字符串拼接（`"Hello " + name`）、写死日期格式（`2024-01-01`）、
> 用英文语序假设（`"1 item"` / `"2 items"`）、没有 RTL。
> 判据：**换一种语言，代码要不要改？** 要改的，就是国际化没做到。

## 什么时候用

- 要做多语言版本
- 已有 i18n 但要查质量
- 接入阿拉伯语/希伯来语（RTL）
- 文案在不同语言下溢出

## 什么时候**不**用

- 明确只支持一种语言（且不会变）
- 只查文案翻译质量 → 那是翻译问题不是国际化问题

## 第 1 步：硬编码文案（最基础）

| 检查 | 判据 |
|---|---|
| UI 里有没有中/英文直接写在代码里 | 有 = 未国际化 |
| 有没有绕过 i18n 层的字符串 | `"保存"` 直接出现 |
| 错误信息是否也走 i18n | 常被漏（后端返回英文错误直接展示） |

⛔ 分批做时，硬编码文案是「漏得最多」的一类——新功能往往忘了走 i18n。

## 第 2 步：字符串拼接（结构性问题）

| 反例 | 为什么错 | 正例 |
|---|---|---|
| `"Hello " + name` | 不同语言语序不同 | 占位符 `t('hello', {name})` |
| `count + " items"` | 复数规则不同 | 用 ICU 复数 |
| `"Delete " + type` | 宾格/性数变化 | 整句做 key |

⛔ 拼接 = 翻译者看不到完整句子 = 翻不对。

## 第 3 步：复数与国际规则

| 规则 | 说明 |
|---|---|
| **复数** | 英语 2 形、阿拉伯语 6 形、中文 1 形 —— 不能用 `count === 1 ? a : b` |
| **性/格** | 俄语/德语名词有格变化 |
| **数字格式** | 千分位、小数点是 `.` 还是 `,`（德语 1.000,5） |
| **日期** | `YYYY-MM-DD` vs `DD/MM/YYYY` vs `MM/DD/YYYY` |
| **货币** | 符号位置、小数位 |
| **姓名顺序** | 中「姓+名」vs 英「名+姓」 |

## 第 4 步：RTL（从右到左）

接阿拉伯语/希伯来语必须支持：

| 检查 | 判据 |
|---|---|
| 布局镜像 | 用 `dir="rtl"` 而非写死 `margin-left` |
| 用逻辑属性 | `margin-inline-start` 而非 `margin-left` |
| 图标方向 | 箭头/返回要镜像 |
| 混排数字/英文 | 双向文本（bidi）正确 |

⛔ 写死 `left/right` 的 CSS 在 RTL 下全错位。

## 第 5 步：文案膨胀与溢出

| 现象 | 原因 |
|---|---|
| 德语翻译比英语长 30%+ 撑破按钮 | 没预留空间 |
| 中文两字在日文变四字溢出 | 同类问题 |

判据：**按钮/标签要能容纳最长语言的文案**（一般按英文 +40% 预留）。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 无硬编码 + 无拼接 + 复数/格式走库 + RTL 支持
- WARN = 有硬编码但核心流程已 i18n
- FAIL = 有字符串拼接 / 无复数规则 / 写死日期
- UNKNOWN = 无法确认目标语言集

**1. 硬编码**
| 位置 | 文案 | 是否走 i18n |
|---|---|---|

**2. 结构问题**
| 位置 | 问题类型（拼接/复数/格式/RTL） | 影响 |
|---|---|---|

**3. RTL 支持**
| 检查 | 现状 |
|---|---|
| 逻辑属性 | |
| 图标镜像 | |

**4. 溢出风险**
| 组件 | 最长语言预估 | 会溢出？ |
|---|---|---|

**5. 判不了的部分**
- <哪些语言/端未覆盖>

## 假阳性清单（这些不算「已国际化」）

- 有 i18n 库但文案还是硬编码
- 只有英文和中文（不代表支持 RTL/复数复杂语言）
- 用拼接但「看起来对」

## 假阴性清单（最常漏的 8 类）

1. **字符串拼接**
2. **`count === 1 ? a : b`** 假复数
3. **写死日期格式**
4. **写死数字/货币格式**
5. **CSS 写死 left/right**（RTL 全错）
6. **没预留文案膨胀空间**
7. **后端错误信息不过 i18n**
8. **用颜色/图标表达语言相关含义**

## 本仓库可用的命令

```bash
node tools/quality/commit-gate.mjs   # 提交前门禁
```

## 与其他技能的关系

- `accessibility-audit`：多语言常伴随 a11y 问题
- `design-review`：视觉设计
- `doc-write`：文档的多语言
- `release-gate`：发布前检查目标语言覆盖

## 边界（如实说清）

- 翻译质量需要母语者审，本技能只查结构
- 语言集决定工作量；只支持 LTR 语言时 RTL 可暂缓
- 本技能不产出翻译，只查「结构支不支持」
