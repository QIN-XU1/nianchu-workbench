# 12-Factor 应用 技能

> 12-factor 是云原生应用的基线：配置外置、无状态、日志当事件流、优雅退出。
> 判据：**这个应用能不能「打包一次，在任何环境跑」？**

## 什么时候用

- 容器化/上云前
- 应用难部署/难移植
- 多环境配置混乱

## 什么时候**不**用

- 桌面/嵌入式应用

## 核心因子（重点几条）

| 因子 | 要求 |
|---|---|
| **配置** | 放环境变量，不进代码 |
| **无状态** | 进程不存会话/本地状态（状态放外部） |
| **并发** | 靠进程模型水平扩 |
| **易处理** | 可随时启停（优雅停机） |
| **日志** | 输出到 stdout 事件流（不自己管文件） |
| **端口绑定** | 自包含服务，绑端口 |
| **dev/prod 一致** | 环境尽量一致 |
| **依赖显式** | 声明依赖 |

## 常见违反

| 违反 | 后果 |
|---|---|
| 配置写死代码 | 换环境要改代码重编 |
| 本地存 session | 不能水平扩 |
| 日志写本地文件 | 容器里丢/难收集 |
| 启动要人工步骤 | 不能自动化 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 配置外置 + 无状态 + 日志 stdout + 优雅启停
- WARN = 有部分违反但不阻断
- FAIL = 配置写死 / 有状态 / 日志写文件
- UNKNOWN = 拿不到部署方式

## 假阳性清单（这些不算「云原生」）

- 能跑容器但有状态
- 配置写死

## 假阴性清单（最常漏的 8 类）

1. **配置写死**
2. **本地存状态**
3. **日志写文件**
4. **启动要人工步骤**
5. **依赖不声明**
6. **dev/prod 差异大**
7. **无优雅停机**
8. **进程模型不可扩**
