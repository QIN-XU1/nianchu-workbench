# 单文件体量红线 技能

> 一个文件 23KB、50KB、100KB 地长下去，就没人能审、没人敢改。
> 判据：**有体量红线吗？超了会失败还是只提示？豁免有没有写理由和复核日？**

## 什么时候用

- 代码库开始变大
- 要评审「可维护性」这类声明
- 出现「这个文件太大了不敢动」

## 什么时候**不**用

- 单文件脚本（无长期维护）

## 第 1 步：三档判据（不是拍脑袋）

参考可维护性经验值，设三档：

| 档 | 阈值 | 处理 |
|---|---|---|
| 红线 | 32KB | 必须拆 |
| 提示 | 中档（如 24KB） | 提示拆分 |
| 关注 | 低档（如 16KB） | 记录 |

## 第 2 步：红线是失败，不是提示

超过 32KB → **退出 1**，必须拆或**显式豁免**。提示档只提示。

## 第 3 步：豁免必须写理由 + 复核日

例外要有：为什么不能拆、谁批的、什么时候复核。**没有复核日的豁免等于永久漏洞。**

## 第 4 步：把「体量纪律」与「验收纪律」分开

「我们用断言管矩阵证据」是验收纪律，不是**产品代码的体量纪律**。两者不能混为一谈。

## 反例（写下来防复发）

- ✗ 只提示不失败 → 没人管，继续长
- ✗ 阈值拍脑袋（1KB 或 1MB） → 太严或太松
- ✗ 豁免无理由无复核日 → 永久豁免
- ✗ 用验收纪律冒充体量纪律 → 自欺

## 自检清单

- [ ] 三档阈值有依据
- [ ] 红线超了退出 1
- [ ] 豁免带理由 + 复核日
- [ ] 体量纪律与验收纪律区分
