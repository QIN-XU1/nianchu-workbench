# 评估设计 技能

> 评估最容易自欺：**用训练/开发时见过的样本测，分数虚高；或只测 happy path，真实场景全崩**。
> 判据：**这个评测，能测出「不好」吗？** 一个永远通过的评测等于没有。

## 什么时候用

- 评估 agent/模型/系统效果
- 要对比两个方案
- 上线前的质量把关

## 什么时候**不**用

- 单元测试（那是代码正确性）
- 只做一次人工抽查

## 第 1 步：定指标（可量化、分层）

| 层 | 指标 |
|---|---|
| **最终效果** | 任务成功率、用户满意度 |
| **中间步骤** | 检索召回、工具调用正确率 |
| **成本** | token/延迟/金钱 |
| **安全** | 越权/泄露/有害输出 |

⛔ 只看「成功率」不分层 = 失败时不知道哪一步坏了。

## 第 2 步：建评测集（决定评测可信度）

| 要求 | 说明 |
|---|---|
| **代表性** | 覆盖真实分布（不是理想样本） |
| **含边界** | 罕见但重要的 case |
| **含负例** | 该拒绝/该说不知道的 |
| **独立** | 与开发样本不重叠（防过拟合） |
| **有标注** | 标准答案/判定标准 |

★ 评测集要**独立于开发时的样本**，否则是「用练习册考题考试」。

## 第 3 步：判定方式

| 方式 | 适用 | 风险 |
|---|---|---|
| 精确匹配 | 有唯一答案 | 太严（近义判错） |
| 规则/正则 | 结构化的 | 脆 |
| **LLM 评判** | 开放式 | 评判者偏差（要用强模型+校准） |
| 人工 | 金标准 | 贵、慢 |

⛔ 用被评估的同款模型自评 = 自己判自己。

## 第 4 步：防自欺（评估的元问题）

| 陷阱 | 防法 |
|---|---|
| 只测 happy path | 加负例/边界 |
| 评测集泄露 | 独立集 |
| 只报平均 | 看分布/最差类 |
| 无基线 | 与基线对比 |
| 单次运行 | 多次取稳定 |

## 第 5 步：持续评估（不是一次）

| 做法 | 说明 |
|---|---|
| 回归集 | 每次改动重跑 |
| 线上监控 | A/B、用户反馈 |
| 失败归因 | 每个失败标注原因 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 分层指标 + 独立代表性评测集 + 合理判定 + 有基线
- WARN = 有评测集但无负例/无基线
- FAIL = 评测集与开发重叠 / 只 happy path / 自评
- UNKNOWN = 拿不到评测数据

## 假阳性清单（这些不算「评估有效」）

- 测的是训练样本
- 只 happy path
- 模型自评

## 假阴性清单（最常漏的 8 类）

1. **评测集与开发重叠**（虚高）
2. **只 happy path**
3. **无负例**（该拒的没测）
4. **只报平均**（掩盖差类）
5. **无基线**
6. **模型自评**
7. **单次运行**
8. **失败不归因**

## 边界（如实说清）

- 开放式任务难有客观标准
- 评测集会过时（分布漂移）
- 本技能不跑评测，只设计
