# 会话持久化 技能

> 用户关掉页面再回来，希望对话还在、能接着聊。这要求「会话不只是内存里的一段数组」。
> 判据：**会话索引在吗？每条消息都落盘了吗？失败了也留痕吗？**

## 什么时候用

- agent 要支持「关掉再打开继续」
- 多会话切换、会话列表
- 评审「跨会话记忆/会话持久化」这类声明

## 什么时候**不**用

- 一次性无状态调用

## 第 1 步：会话索引 + 逐条消息落盘

- 一个**索引**记录所有会话（id、名字、创建时间、最近一条摘要）
- 每个会话一个文件，**每条消息追加落盘**（不是只在结束时写一次）
- 落盘目录用**平台用户目录**（APPDATA / Application Support / XDG），不写进仓库

## 第 2 步：失败也留痕

模型失败、工具报错、被中断——这些也要作为一条消息记下来（如 `type: turn-failed`），带上 state 和 reason。

判据：**「用户说了但没记录」是不允许的**。哪怕失败，也要有痕迹。

## 第 3 步：按 id 恢复与续聊

- 给定 sessionId，能读出完整消息列表
- 新消息追加到同一会话
- 会话索引能列出最近 N 个会话

## 反例（写下来防复发）

- ✗ 消息只在内存，进程一停全丢
- ✗ 失败不记录 → 用户以为「没发出去」，实际模型报错了
- ✗ 会话数据写进仓库目录 → 跨机器/跨用户就乱
- ✗ 只在会话结束时一次性写 → 中途崩了整段丢

## 自检清单

- [ ] 会话索引存在且能列最近会话
- [ ] 每条消息追加落盘（含失败）
- [ ] 数据在平台用户目录
- [ ] 按 sessionId 能恢复并续聊
- [ ] 失败带 state/reason 留痕

## 参考实现指路

本仓库 `tools/agent/runtime.mjs`：会话索引（listSessions）、逐条消息 appendMessage、失败落 `turn-failed`、数据在 `USER_DATA_DIR`（APPDATA/Application Support/XDG）。宿主经 `/api/*` 暴露会话能力。
