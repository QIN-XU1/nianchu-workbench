# 混沌工程 技能

> 混沌工程不是「随便搞破坏」，是**有假设、可控地注入故障，验证系统在故障下的行为**。
> 判据：**你注入的故障，有没有一个「系统应该怎样」的假设？** 没有就是瞎搞。

## 什么时候用

- 验证高可用/容灾
- 上线前验证韧性
- 建立对系统的信心

## 什么时候**不**用

- 系统还不稳定（先修，再混沌）
- 无监控（注入故障也不知道发生什么）
- 生产无爆炸半径控制

## 第 1 步：先写假设（科学方法）

```
假设：杀掉一个 DB 从库，读请求自动切到主库，P99 延迟上升 < 100ms，无报错。
```

⛔ 没有假设的「注入故障看会发生什么」= 不是实验，是赌博。

## 第 2 步：控制爆炸半径（最重要）

| 手段 | 说明 |
|---|---|
| **先非生产** | 测试环境先验证 |
| **小比例** | 只影响 1% 流量/实例 |
| **可随时停止** | 一键终止 |
| **避开高峰** | 不在大促做 |
| **黑白名单** | 排除关键客户 |

⛔ 一上来在生产全量注入 = 自己制造事故。

## 第 3 步：注入什么（故障类型）

| 类型 | 例 |
|---|---|
| 实例故障 | 杀进程/容器 |
| 网络 | 延迟/丢包/分区 |
| 资源 | CPU/内存/磁盘满 |
| 依赖 | 下游超时/错误 |
| 时钟 | 时钟偏移 |

## 第 4 步：观察与恢复

| 项 | 要求 |
|---|---|
| 监控 | 注入时实时看指标 |
| 自动恢复 | 故障停止后系统恢复 |
| 记录 | 假设是否成立 |
| 改进 | 不成立则修 |

## 第 5 步：成熟度

| 阶段 | 做法 |
|---|---|
| 1 | 手动，测试环境 |
| 2 | 自动，非生产定期 |
| 3 | 生产小比例，有护栏 |
| 4 | 持续混沌（Chaos Monkey 式） |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 有假设 + 爆炸半径控制 + 可停止 + 观察
- WARN = 有注入但无假设
- FAIL = 生产全量注入 / 无停止 / 无监控
- UNKNOWN = 拿不到系统拓扑

## 假阳性清单（这些不算「混沌工程」）

- 随机搞破坏无假设
- 生产全量注入
- 无监控

## 假阴性清单（最常漏的 8 类）

1. **无假设**（瞎搞）
2. **无爆炸半径控制**
3. **生产全量**（自造事故）
4. **不可随时停**
5. **无监控**（不知道发生什么）
6. **高峰做**（放大风险）
7. **不排除关键客户**
8. **假设不成立不修**

## 边界（如实说清）

- 生产混沌风险真实，需成熟团队
- 混沌不能替代其他测试
- 本技能不实现工具，只设计实验
