# 灾备设计 技能

> 灾备最常见的自欺：**「我们有备份」但从没验证过能恢复**。
> 备份是坏的、或备份里没有关键数据、或恢复要 48 小时——这些只有演练才知道。
> 判据：**真出事的时候，多长时间能恢复，丢多少数据，你答得出来且敢担保吗？**

## 什么时候用

- 设计高可用/灾备
- 要定备份策略
- 合规要求业务连续性
- 出过数据丢失事故

## 什么时候**不**用

- 可随时重建的无状态服务（但仍要备份配置）

## 第 1 步：先定 RTO/RPO（两个最重要数字）

| 指标 | 含义 | 例子 |
|---|---|---|
| **RTO**（恢复时间目标） | 出事到恢复要多久 | 1 小时 |
| **RPO**（恢复点目标） | 能容忍丢多少数据 | 15 分钟 |

| RTO/RPO | 架构代价 |
|---|---|
| 小时级 / 小时级 | 定时备份 + 冷备 |
| 分钟级 / 分钟级 | 热备 + 持续复制 |
| 秒级 / 近零 | 多活 + 同步复制（最贵） |

⛔ 不写 RTO/RPO 的灾备 = 没有目标，不知道做够没有。

## 第 2 步：备份策略

| 项 | 要求 |
|---|---|
| **类型** | 全量 + 增量组合 |
| **频率** | 决定 RPO |
| **异地** | 备份不能和主库同机房（同归于尽） |
| **保留** | 按合规/业务 |
| **加密** | 备份也是数据，要加密 |
| **不可变** | 防勒索软件加密备份 |

★ **最重要**：备份必须**验证过能恢复**（定期做恢复演练，不是只看「备份成功」）。

## 第 3 步：多活/容灾架构

| 架构 | RTO | 复杂度 |
|---|---|---|
| 单机房 | 高 | 低 |
| 同城双活 | 低 | 中 |
| 异地多活 | 很低 | 很高（数据冲突） |
| 冷备切换 | 中高 | 低 |

⛔ 异地多活最难的是**数据一致性**（多写冲突），不是部署。

## 第 4 步：演练（决定灾备真假）

| 演练 | 目的 |
|---|---|
| **备份恢复演练** | 证明备份可用 |
| **切换演练** | 证明能切到备 |
| **故障注入**（chaos） | 主动制造故障看反应 |
| **桌面推演** | 流程是否清晰 |

⛔ 从不演练的灾备 = 假设，不是方案。

## 第 5 步：切换与回切

| 项 | 要点 |
|---|---|
| 切换决策 | 谁有权决定切 |
| 数据同步 | 切换时数据一致吗 |
| 回切 | 主恢复后怎么切回（常被忘） |
| DNS/流量 | 切换的传播延迟 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = RTO/RPO 明确 + 备份异地且验证过恢复 + 演练过 + 有回切
- WARN = 有备份但没验证恢复
- FAIL = 备份与主同机房 / 从不演练 / 无 RTO/RPO
- UNKNOWN = 拿不到架构与数据流

**1. RTO/RPO**
| 系统 | RTO | RPO | 依据 |
|---|---|---|---|

**2. 备份**
| 项 | 值 |
|---|---|
| 类型/频率 | |
| 异地 | |
| 不可变 | |
| 验证恢复 | |

**3. 架构**
| 架构 | RTO达成 | 数据一致 |
|---|---|---|

**4. 演练**
| 演练 | 做过 |
|---|---|

**5. 判不了的部分**
- <依赖的灾备能力不明>

## 假阳性清单（这些不算「有灾备」）

- 有备份但从没恢复过
- 备份和主库同机房
- 有文档没演练

## 假阴性清单（最常漏的 8 类）

1. **备份没验证过能恢复**
2. **备份与主同机房**
3. **无 RTO/RPO**
4. **从不演练**
5. **无回切方案**
6. **备份未加密/可变**（勒索）
7. **切换无决策授权**
8. **只备数据库不备配置/密钥**

## 本仓库可用的命令

```bash
node tools/memory/verify-bulk-corrupt.mjs   # 备份可读性检查示例
node tools/quality/commit-gate.mjs          # 提交前门禁
```

## 与其他技能的关系

- `rollback-plan`：单次变更的回滚（本技能是整体灾备）
- `runbook`：恢复的具体步骤
- `data-migration`：备份验证
- `incident-comms`：灾难时对外沟通
- `postmortem`：演练/事故复盘

## 边界（如实说清）

- 灾备成本随 RTO/RPO 收紧指数上升
- 异地多活的数据冲突几乎无法完全消除
- 本技能不实现，只设计与验证方案
