# 数据网格 技能

> 数据网格的核心：把数据所有权交给**领域团队**，数据当**产品**，有自助平台和联邦治理。
> 但它不是银弹——组织没准备好就上，只会更乱。
> 判据：**谁对「这份数据质量」负责，说得清吗？**

## 什么时候考虑

- 集中式数据团队成瓶颈
- 领域多、数据来源分散
- 数据质量责任不清

## 什么时候**不**用

- 组织小、数据少（集中式更简单）

## 四个原则

| 原则 | 说明 |
|---|---|
| **领域所有权** | 谁产生数据谁负责 |
| **数据即产品** | 有 SLA、可发现、可用 |
| **自助平台** | 平台团队提供工具，领域自建管道 |
| **联邦治理** | 全局标准 + 本地自治 |

## 现实约束

| 约束 | 说明 |
|---|---|
| 组织成熟度 | 领域团队要有数据能力 |
| 平台先行 | 没有自助平台，网格变各自为战 |
| 治理不能丢 | 无标准=数据沼泽 |

⛔ 组织不成熟、平台没建就上网格 = 数据更乱。

## 与集中式对比

| 维度 | 集中式 | 数据网格 |
|---|---|---|
| 所有权 | 数据团队 | 领域团队 |
| 扩展性 | 团队成瓶颈 | 领域自治 |
| 一致性 | 易统一 | 靠联邦治理 |
| 门槛 | 低 | 高（组织和平台） |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 领域所有权清 + 平台支撑 + 联邦治理
- WARN = 有意向但平台/治理不足
- FAIL = 无平台就上网格 / 责任不清
- UNKNOWN = 拿不到组织结构

## 假阳性清单（这些不算「数据网格」）

- 只改了组织名
- 无平台
- 无治理

## 假阴性清单（最常漏的 8 类）

1. **无平台就上网格**
2. **责任不清**
3. **无联邦治理**（数据沼泽）
4. **领域团队无数据能力**
5. **数据产品无 SLA**
6. **只改组织不改机制**
7. **无数据目录**
8. **过度去中心化**

## 边界（如实说清）

- 数据网格是组织+技术双变革，门槛高
- 多数中小组织用集中式更划算
- 本技能只评估，不实现
