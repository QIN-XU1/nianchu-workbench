# 接口错误语义 技能

> 拼错一个接口名，如果服务返回 200 + 首页 HTML，调用方会以为成功了。错误被彻底掩盖。
> 判据：**每个错误请求，拿到的都是 4xx + JSON 吗？信息具体吗？不泄漏内部细节吗？**

## 什么时候用

- 设计/审查 HTTP 接口
- 排查「明明调错了却显示成功」
- 要评审「错误处理」这类声明

## 什么时候**不**用

- 纯内部函数（不是接口边界）

## 第 1 步：错误必须 4xx + application/json

对每个真实端点发错误请求，断言：

| 断言 | 要求 | 反例 |
|---|---|---|
| 状态码 | 4xx（不能 200） | 200 意味着错误被当成功 |
| content-type | `application/json` | `text/html` 说明掉进 SPA 兜底 |
| body | 可 JSON.parse，且有 `ok:false` 或 `error` | 空 body 或 HTML |

## 第 2 步：未知路由也必须是 404 JSON

拼错的 `/api/xxx`、路径相近的错误，都要 404 JSON——不能掉进「返回 index.html」的兜底。

## 第 3 步：错误信息质量

- 非空、不过长
- **不含绝对路径**（泄漏目录结构）
- **不含堆栈**（泄漏实现）
- **不含内部占位符**（如 `{{...}}`）

## 反例（写下来防复发）

- ✗ 错误请求返回 200 → 静默成功
- ✗ 返回 HTML 首页 → 调用方解析失败却不知道是路由问题
- ✗ 错误信息带 `C:\Users\...` → 泄漏路径
- ✗ 错误信息是 `{{err}}` 未替换 → 无意义

## 自检清单

- [ ] 错误请求 4xx + JSON
- [ ] 未知路由 404 JSON
- [ ] 信息非空、不泄漏路径/堆栈/占位符
- [ ] 有反例自测（造 200+HTML 必须判不合格）

## 参考实现指路

本仓库 `tools/workbench/verify-api-error-contract.mjs`（对每个端点发错误请求，断言 4xx+JSON+信息质量；内置反例自测：200+HTML 必须判不合格）。

## 实测数据（本仓库，可复算）

```
node tools/workbench/verify-api-error-contract.mjs
```

实测 **29 通过 / 0 失败 / 跳过 2**（跳过的是需要合法输入的端点）。

- 对每个真实端点发**错误请求**，断言：状态码 4xx、`content-type: application/json`、
  body 可 `JSON.parse` 且有 `ok:false` 或 `error`
- 未知路由 / 拼写相近路径 → **404 JSON**（不能掉进 SPA 兜底返回 index.html）
- 错误信息质量：非空、不过长、**不含绝对路径 / 堆栈 / 内部占位符**
- 内置**反例自测**：造一个「200 + HTML」的假响应，检查逻辑必须判它不合格

**为什么这个反例必须内置**：如果没有它，一个「永远通过」的错误检查会给你虚假安全感
——它可能只是没真正检查 content-type。

**教训**：**校验器本身要能被证伪**。给校验器喂一个「应该不合格」的输入，是它可信的最低门槛。
