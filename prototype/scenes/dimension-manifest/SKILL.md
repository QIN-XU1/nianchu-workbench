# 维度验收登记 技能

> 说「31 个维度都做到了」，但如果某个维度根本没有验收脚本，那这句话就没有依据。
> 判据：**每个维度都能指向一个真跑的验收脚本吗？没有的有没有被显式标出来？**

## 什么时候用

- 多维度的能力矩阵/评分表
- 要评审「每维都有证据」这类声明
- 发现「某维度只有文字描述，没有脚本」

## 什么时候**不**用

- 单一维度的任务

## 第 1 步：显式登记 dim → 脚本

写一张登记表：每个维度 id 对应一个验收脚本路径。**不要靠命名约定猜**（`verify-a1.mjs` 之类），要显式写。

## 第 2 步：真跑每个脚本，记录 exit + 计数

- 跑脚本，记 `exit code` 与「通过 N / 失败 M」
- 判定：exit 0 且 fail 0 → PASS；exit 2 → UNKNOWN；否则 FAIL

## 第 3 步：三类特殊维度要显式标

| 类 | 处理 |
|---|---|
| **无专属验收** | 单独计数（不是静默跳过） |
| **排除项**（用户未选） | 标「排除」，不参与「必须有验收」 |
| **UNKNOWN**（环境不可验） | 单独计数，不算失败 |

## 反例（写下来防复发）

- ✗ 没有登记的维度被静默跳过 → 看起来全绿，其实没验
- ✗ 把排除项当失败 → 冤枉
- ✗ 把 UNKNOWN 当 FAIL → 甩锅环境
- ✗ 只统计「通过几个」不统计「没验几个」 → 掩盖空洞

## 自检清单

- [ ] dim → 脚本 显式登记
- [ ] 每个脚本真跑，记录 exit + 计数
- [ ] 无专属验收/排除/UNKNOWN 分别计数
- [ ] 有反例（无验收的维度必须被报出来）

## 参考实现指路

本仓库 `tools/evolve/verify-dim-manifest.mjs`（DIM_VERIFIERS 显式登记 dim→脚本；EXCLUDED={A10,A15}；exit 2 归 UNKNOWN；输出 通过/失败/UNKNOWN/无专属验收/跳过/排除 六类计数）。

## 实测数据（本仓库，可复算）

```
node tools/evolve/verify-dim-manifest.mjs
```

当前结果：

```
通过 29 维 · 失败 0 · UNKNOWN 0 · 无专属验收 0 · 跳过 0 · 排除 2
四态: PASS
```

**排除的 2 维**：A10（IM/消息通道）、A15（审批闸/越界拦截）——用户明确不要，故不参与「必须有验收」。

**一个真实的过程教训**：D2（信息密度）一度长期 UNKNOWN——因为它的浏览器渲染依赖服务，
而脚本不自起服务。给 `verify-d2-density.mjs` 接上 `_serve.mjs` 自起后，
它从「只验源码 5 条」升级为「真 headless 渲染 17 条」，D2 变 PASS，dim-manifest 才凑齐 29/29。

**教训**：**「每维都有验收」这个结论，要先看有几个是 UNKNOWN**。29 维全 PASS 才是真的全绿；
若有 3 个 UNKNOWN，实际是 26 维有证据 + 3 维没验。
