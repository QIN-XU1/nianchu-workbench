# Webhook 设计 技能

> Webhook 是「反过来推」的 API：你主动调别人的 URL。它的失败模式比主动调用多：
> **对方没收到、收到重复、伪造的、或被利用打内网**。
> 判据：**对面收到重复或伪造的 webhook，会不会做错事？**

## 什么时候用

- 对外提供事件回调
- 接收第三方回调
- 事件驱动集成

## 什么时候**不**用

- 内部同步调用够用
- 对方不提供 webhook

## 第 1 步：发送方要做的

| 项 | 要求 |
|---|---|
| **验签** | 带签名（HMAC），接收方校验来源 |
| **重试** | 失败重试（指数退避，有限次） |
| **超时** | 接收方慢不能拖死自己 |
| **幂等** | 接收方可能收到重复（至少一次） |
| **事件 ID** | 每条带唯一 ID（供接收方去重） |
| **异步** | 发送不阻塞主流程 |

## 第 2 步：接收方要做的

| 项 | 要求 |
|---|---|
| **验签** | 校验 HMAC + 时间戳（防重放） |
| **去重** | 按 event ID 去重（至少一次投递） |
| **快速响应** | 先返回 200 再异步处理（别阻塞） |
| **幂等处理** | 同一事件重复处理结果一致 |
| **防重放** | 时间戳窗口 + 不重复的 nonce |

## 第 3 步：安全（最易漏）

| 风险 | 防法 |
|---|---|
| **伪造回调** | HMAC 签名校验（密钥保密） |
| **重放** | 时间戳 + 事件 ID 去重 |
| **SSRF**（发送方） | 校验目标 URL 不是内网/元数据地址 |
| **签名比较** | 用常量时间比较（防时序攻击） |
| **密钥轮换** | 支持新旧密钥并存 |

★ SSRF：如果 webhook URL 由用户填写，用户填 `http://169.254.169.254/`（云元数据）或内网地址，你就成了攻击内网的跳板。**必须校验目标地址，拒绝内网/保留地址。**

## 第 4 步：可靠性

| 项 | 要求 |
|---|---|
| 至少一次 | 保证不丢（代价是可能重复） |
| 死信 | 多次失败后进死信，人工处理 |
| 事件日志 | 记录发了什么、结果 |
| 顺序 | 一般不保证顺序，接收方要能处理乱序 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 验签 + 去重 + 时间戳防重放 + SSRF 校验 + 死信
- WARN = 有验签无防重放
- FAIL = 无验签 / 无去重 / SSRF 不校验 / 同步阻塞
- UNKNOWN = 拿不到 webhook 实现

## 假阳性清单（这些不算「有 webhook」）

- 发请求了但无签名
- 无去重（重复处理）
- 用户随便填 URL 无 SSRF 校验

## 假阴性清单（最常漏的 8 类）

1. **无验签**（可伪造）
2. **无去重**（重复处理）
3. **无时间戳**（可重放）
4. **SSRF 不校验**（打内网/元数据）
5. **同步阻塞发送**
6. **签名用 == 比较**（时序攻击）
7. **无死信**
8. **依赖顺序**（实际乱序）

## 边界（如实说清）

- webhook 天然是至少一次，去重是接收方责任
- 对端不配合则可靠性受限于对端
- 本技能不实现，只设计
