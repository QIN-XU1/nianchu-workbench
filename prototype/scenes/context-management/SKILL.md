# 上下文管理 技能

> agent 的上下文是最稀缺资源。塞太多 → 贵、慢、且模型注意力被稀释（lost in the middle）；
> 塞太少 → 缺信息做错。
> 判据：**上下文里每一段，都是「这个任务此刻需要的」吗？** 不是的就不该在。

## 什么时候用

- 上下文接近上限
- 多轮对话越聊越乱
- 要决定放什么进 prompt
- RAG/工具结果注入

## 什么时候**不**用

- 单轮短任务（上下文充裕）

## 第 1 步：先建立预算意识

| 区域 | 典型占比 |
|---|---|
| system prompt（规则/工具/技能目录） | 固定开销 |
| 历史对话 | 累积增长（要压缩） |
| 检索/工具结果 | 按需、可截断 |
| 当前任务 | 必须保 |

⛔ 没有预算概念 = 历史无限增长，最后挤掉 system prompt 或直接爆。

## 第 2 步：压缩策略（历史越长越需要）

| 策略 | 说明 | 风险 |
|---|---|---|
| **滑动窗口** | 只留最近 N 轮 | 丢早期关键信息 |
| **摘要** | 把旧对话摘要成一段 | 摘要可能丢细节 |
| **结构化记忆** | 提取事实存外部，用时检索 | 要设计存储 |
| **分层保留** | 近期全量 + 早期摘要 | 折中，推荐 |

★ 最好的不是「压缩得多狠」，是**把值得长期记的抽到外部记忆**，需要时再取。

## 第 3 步：按需注入（progressive disclosure）

| 做法 | 好处 |
|---|---|
| 工具/技能只放「目录」（名字+一句描述） | 省 token |
| 用到哪个再加载全文 | 按需 |
| 检索结果只给相关片段 | 不是整文档 |

⛔ 一次性把所有工具描述/文档全文塞进去 = 上下文被无关内容占满。

## 第 4 步：「lost in the middle」与位置

- 模型对**开头和结尾**的注意力高于中间
- 关键指令放 system（开头）或重述在结尾
- 重要信息不要埋在长上下文中间

## 第 5 步：上下文腐烂（长会话的隐形问题）

| 症状 | 原因 |
|---|---|
| 前面说过的后面忘了 | 被挤掉/被稀释 |
| 自相矛盾 | 早期约束没保住 |
| 越聊越偏 | 无关信息累积 |

对策：**定期重述关键状态**（当前目标、已确认约束），别指望它一直记得。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 有预算 + 压缩/外部记忆 + 按需注入 + 关键状态重述
- WARN = 有窗口但无摘要/外部记忆
- FAIL = 历史无限增长 / 全量塞入 / 关键技术信息埋在中间
- UNKNOWN = 拿不到上下文构成

**1. 预算**
| 区域 | 占比 |
|---|---|

**2. 压缩**
| 策略 | 说明 |
|---|---|

**3. 按需注入**
| 内容 | 是否只放目录 |
|---|---|

**4. 判不了的部分**
- <拿不到的上下文用量>

## 假阳性清单（这些不算「上下文管理好」）

- 只是把窗口调大
- 压缩了但丢了关键约束
- 全量塞工具描述

## 假阴性清单（最常漏的 8 类）

1. **历史无限增长**（挤爆）
2. **压缩丢关键约束**（自相矛盾）
3. **全量塞工具/文档**
4. **关键信息埋在中间**（lost in middle）
5. **无外部记忆**（全靠窗口）
6. **长会话不重述状态**
7. **检索结果给整篇**
8. **无预算意识**

## 与其他技能的关系

- `agent-tool-design`：工具按需注入
- `prompt-engineering`：提示词结构
- `multi-agent-orchestration`：子 agent 上下文隔离
- `tech-selection`：模型选择

## 边界（如实说清）

- 压缩必然有损，关键信息要靠外部记忆
- 不同模型的有效上下文≠标称上下文
- 本技能不实现压缩，只设计策略
