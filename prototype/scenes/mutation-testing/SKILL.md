# 变异测试 技能

> 一个永远 PASS 的测试，和一个没有测试，是一回事。
> 判据：**往代码里注入真 bug，测试抓得到吗？抓不到的比例是多少？**

## 什么时候用

- 验证测试/检查脚本本身有效
- 担心「测试全绿但其实没测到东西」
- 评审「测试覆盖」这类声明

## 什么时候**不**用

- 一次性脚本、无回归价值

## 第 1 步：定义变异算子（往哪注入 bug）

常见几类：

- 边界翻转（`>` → `>=`）
- 返回值篡改（`return x` → `return null`）
- 条件删除（`if (x) y` → `y`）
- 常量偏移（`0` → `1`）

## 第 2 步：注入 → 跑测试 → 看是否被抓

- **被杀**（killed）：测试变红 → 说明测试有效
- **存活**（survived）：测试仍绿 → 说明这段没被测到

## 第 3 步：算杀灭率 + 定位「载荷点」

- 杀灭率 = 被杀 / 总变异
- 存活的变异要逐个解释：是等价变异（不改变行为）还是**真漏洞**
- 只保留「承重」的变异（真能抓 bug 的），其余剔除

## 反例（写下来防复发）

- ✗ 只注入不改变行为的等价变异 → 杀灭率虚高
- ✗ 存活变异不解释 → 掩盖真漏洞
- ✗ 变异注入后不还原 → 代码被改坏
- ✗ 不统计杀灭率 → 无法判断测试质量

## 自检清单

- [ ] 有明确的变异算子
- [ ] 注入后跑测试，区分被杀/存活
- [ ] 存活变异逐个解释
- [ ] 统计杀灭率并落盘
- [ ] 变异后还原
