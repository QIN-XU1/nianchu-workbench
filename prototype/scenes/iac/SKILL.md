# 基础设施即代码（IaC）技能

> IaC 的核心价值：**基础设施可复现、可审查、可回滚**。手点控制台 = 不可复现、无人知道改了什么。
> 判据：**能不能从零重建一套一模一样的环境？** 不能就是没做到 IaC。

## 什么时候用

- 管理云资源/服务器/网络
- 多环境（dev/staging/prod）
- 要可复现/可审查

## 什么时候**不**用

- 极小固定环境

## 第 1 步：声明式 vs 命令式

| 范式 | 例 | 特点 |
|---|---|---|
| **声明式** | Terraform/K8s YAML | 描述「要什么状态」，工具算差异 |
| 命令式 | 脚本逐条执行 | 描述「怎么做」，难幂等 |

★ 声明式是主流（幂等、可 diff）。

## 第 2 步：状态管理（Terraform 的核心）

| 项 | 要求 |
|---|---|
| **远程状态** | 存共享后端（不能本地，多人协作冲突） |
| **状态锁定** | 防并发修改 |
| **敏感状态** | 加密（状态里有密码） |
| 备份 | 状态丢了很麻烦 |

⛔ 本地 state + 多人 = 状态冲突/覆盖，灾难。

## 第 3 步：幂等与规划

| 步骤 | 说明 |
|---|---|
| plan | 看「将要改什么」（dry-run） |
| apply | 执行 |
| **plan 要审查** | 防意外删除/重建 |

⛔ 不看 plan 直接 apply = 可能删库重建。

## 第 4 步：漂移检测（手动改了的后果）

| 问题 | 说明 |
|---|---|
| 有人手点了控制台 | 实际 ≠ 代码 |
| 漂移后果 | 下次 apply 覆盖/冲突 |
| 检测 | 定期 plan 看差异 |

## 第 5 步：模块化与环境隔离

| 项 | 要求 |
|---|---|
| 模块复用 | 通用组件参数化 |
| 环境隔离 | dev/prod 状态分离 |
| 变量 | 不硬编码（环境差异） |
| 密钥 | 不进代码（见 `secrets-management`） |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 声明式 + 远程状态+锁 + 审查 plan + 漂移检测
- WARN = 有 IaC 但本地状态
- FAIL = 手点控制台 / 本地 state / 不看 plan / 密钥进代码
- UNKNOWN = 拿不到基础设施

## 假阳性清单（这些不算「有 IaC」）

- 有脚本但非声明式
- 本地 state
- 手点控制台补

## 假阴性清单（最常漏的 8 类）

1. **本地 state**（多人冲突）
2. **不看 plan 直接 apply**
3. **无漂移检测**
4. **密钥进代码/state**
5. **无状态锁定**
6. **环境不隔离**
7. **硬编码变量**
8. **无模块复用**（复制粘贴）
