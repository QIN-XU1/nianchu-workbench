# 团队派单与回执 技能

> 多个 agent 协作，最容易出的事是「单子派出去没了下文」「互相等对方」。
> 判据：**每张单子在哪一态？能跳级吗？没回执能报出来吗？**

## 什么时候用

- 多 agent 分工、派单、回收执
- 要评审「多 agent 协作协议」这类声明
- 出现「任务卡住、不知道谁在等谁」

## 什么时候**不**用

- 单 agent 独立任务

## 第 1 步：五态流转，禁止跳级

一张单子的生命周期：

| 态 | 含义 |
|---|---|
| issued | 已派单 |
| acked | 已接单 |
| working | 处理中 |
| receipted | 已回执 |
| closed | 已关闭 |

**必须逐级流转**，禁止 issued 直接跳 closed。跳级 = 状态机被绕过。

## 第 2 步：回执必须带结论 + 证据

回执不能只说「做完了」。要带：

- 结论（做成了 / 失败 + 原因）
- 证据（产出物路径、命令输出、校验结果）

**缺证据的回执要拒收**——否则「说完成了」就成真。

## 第 3 步：主动报「黑洞」与「互等」

- **黑洞**：超时未接单（派了没人理）
- **互等**：A 等 B 回执、B 等 A 动作，死锁

`audit` 要能主动把这两类报出来，而不是等用户发现。

## 反例（写下来防复发）

- ✗ issued 直接 closed → 状态机形同虚设
- ✗ 回执只写「完成」无证据 → 无法验证
- ✗ 黑洞不报 → 单子丢了没人知道
- ✗ 互等不检测 → 两个 agent 一起卡死

## 自检清单

- [ ] 五态齐全且逐级流转（禁止跳级）
- [ ] 回执带结论 + 证据，缺证据拒收
- [ ] 超时未接单报黑洞
- [ ] 互相等待报互等
- [ ] audit 主动报出异常单

## 参考实现指路

本仓库 `tools/agent/handoff.mjs`：五态 issued→acked→working→receipted→closed、禁止跳级、回执必须带结论+证据、超时未接=黑洞/未回执=互等、audit 主动报出。`verify-handoff.mjs` 27/27 是它的可复算反例。

## 实测数据（本仓库，可复算）

```
node tools/agent/verify-handoff.mjs
```

实测 **27 通过 / 0 失败**，覆盖：

- 五态流转 issued → acked → working → receipted → closed
- **禁止跳级**（issued 直接 closed 必须被拒）
- 回执必须带结论 + 证据，**缺证据拒收**
- 超时未接单 → 报「黑洞」；未回执 → 报「互等」
- `audit` 主动把这些异常单列出来（不是等人发现）

**为什么「互等」要单独检测**：两个 agent 各自在等对方动作时，界面上看是「都在处理中」，
不报出来就会一起卡死。这是多 agent 协作最常见的死锁形态。

**教训**：**状态机不是文档，是可执行断言**。「禁止跳级」「缺证据拒收」都要有对应反例，否则只是口号。
