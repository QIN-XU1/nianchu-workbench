# 信息密度可调 技能

> 有人喜欢紧凑（一屏看更多），有人喜欢宽松（不费眼）。可调密度是尊重差异。
> 判据：**三档真的生效且单调吗？调密度时信息丢没丢？可点击区域缩到 24px 以下了吗？**

## 什么时候用

- 信息密集的界面（表格/面板/工作台）
- 要评审「可调密度」这类声明

## 什么时候**不**用

- 单屏极简界面（无可调空间）

## 第 1 步：三档，系数严格单调

`compact < cozy < comfy`，通过根元素属性（如 `data-density`）与 CSS 变量（如 `--nb-dens`）同步：

- compact：0.78
- cozy：1
- comfy：1.18

**必须严格递增**，不能两档一样。

## 第 2 步：内容不能丢

调密度调的是**间距**，不是信息。断言：三档下**可见文本字符数必须一致**。

## 第 3 步：命中区不随密度缩

可点击区域下限 `--nb-tap-min: 24px`（WCAG 2.5.8），**三档都要守住**。密度再紧也不能让按钮小于 24px。

## 第 4 步：非法档位回落

URL 里传 `?density=bogus` 时，回落到 cozy（默认），**不能当成 compact 蒙混**。

## 反例（写下来防复发）

- ✗ 三档系数不单调 → 用户感觉「调了没用」
- ✗ 调密度导致文本被截断/隐藏 → 丢信息
- ✗ 密度调紧后按钮小于 24px → 违反可访问性
- ✗ 非法档位当成某档 → 用户困惑

## 自检清单

- [ ] 三档系数严格单调
- [ ] 三档可见文本字符数一致
- [ ] 三档 `--nb-tap-min` ≥ 24px
- [ ] 非法档位回落默认
- [ ] 真渲染验证（不是只查源码）

## 参考实现指路

本仓库 `tools/agent/verify-d2-density.mjs`（真 headless 渲染三档 0.78/1/1.18、单调递增、字符数一致、24px 守门、非法回落；含反例）。

## 实测数据（本仓库，可复算）

```
node tools/agent/verify-d2-density.mjs
```

实测 **17 通过 / 0 失败**（真 headless 渲染，非只读源码）：

| 档位 | `--nb-dens` | 根属性 `data-nb-density` |
|---|---|---|
| compact | **0.78** | compact |
| cozy | **1** | cozy |
| comfy | **1.18** | comfy |

- 三档严格单调递增（实测 0.78 < 1 < 1.18）
- 三档 **可见文本字符数一致**（密度只调间距，不丢信息）
- 三档 `--nb-tap-min = 24px`（WCAG 2.5.8 命中区下限，不随密度缩）
- 反例：`?density=bogus` → 根属性回落到 cozy（不是 compact）

**一个真实坑**：每档必须用**独立浏览器 profile**（`--user-data-dir` 加序号）。否则上一次写进
localStorage 的档位会影响下一次——实测过「三档都读成 compact」。

**教训**：**测无状态行为时，先确保被测环境真的无状态**（localStorage/缓存/profile 都是状态）。
