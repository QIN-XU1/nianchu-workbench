# 数据仓库建模 技能

> 数仓建模的核心是**让分析查询又快又对**，不是把业务表照搬。
> 判据：**业务方问「上个月各品类销售额」，能不能一次查出来而不是拼半天？**

## 什么时候用

- 建设数据仓库/分析平台
- 报表数据组织
- 数据分析慢

## 什么时候**不**用

- 简单业务库（OLTP）

## 第 1 步：分层（ODS→DWD→DWS→ADS）

| 层 | 作用 |
|---|---|
| **ODS** | 原始数据（贴源） |
| **DWD** | 明细（清洗/规范化） |
| **DWS** | 汇总（按主题宽表） |
| **ADS** | 应用层（面向报表） |

⛔ 不分层 = 报表直接查原始表 = 慢且乱。

## 第 2 步：维度建模（星型）

| 概念 | 说明 |
|---|---|
| **事实表** | 度量（销售额/数量）+ 外键 |
| **维度表** | 描述（时间/商品/地区） |
| 星型 | 事实表连多个维度（推荐） |
| 雪花 | 维度再规范化（少用，join 多） |

★ 星型模型是数仓主流：简单、查询快、易理解。

## 第 3 步：缓慢变化维（SCD）

维度属性会变（如商品归属品类变了）：

| 类型 | 处理 |
|---|---|
| Type 1 | 直接覆盖（丢历史） |
| **Type 2** | 加版本行（保留历史，最常用） |
| Type 3 | 加列（有限历史） |

⛔ 用 Type 1 覆盖 = 历史报表对不上（当时品类变了）。

## 第 4 步：事实表类型

| 类型 | 说明 |
|---|---|
| 事务事实 | 每笔事件一行 |
| 周期快照 | 每天/月状态 |
| 累积快照 | 流程状态变化 |

## 第 5 步：常见坑

| 坑 | 后果 |
|---|---|
| 不分层 | 乱、慢 |
| SCD 用 Type1 | 历史失真 |
| 维度不一致 | 同指标不同数 |
| 无数据字典 | 不知字段含义 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 分层 + 星型 + SCD Type2 + 字典
- WARN = 有建模但无分层
- FAIL = 照搬业务表 / SCD 覆盖 / 无字典
- UNKNOWN = 拿不到数据模型

## 假阳性清单（这些不算「数仓建好」）

- 不分层直接查原始表
- SCD 覆盖
- 无数据字典

## 假阴性清单（最常漏的 8 类）

1. **不分层**
2. **SCD 用 Type1**（历史失真）
3. **维度不一致**
4. **无数据字典**
5. **雪花滥用**（join 多）
6. **事实表混维度**
7. **无汇总层**（每次现算）
8. **命名混乱**
