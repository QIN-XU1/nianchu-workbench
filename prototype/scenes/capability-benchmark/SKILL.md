# 能力对标 技能

> 对标最容易出的两个错：
> ① **用总分掩盖单项落后** —— 「净胜 10 分」听起来赢了，但那一项落后就是对方能说你不如他的地方。
> ② **把「没查到」当「没有」** —— 缺席也是要举证的。
> 所以本技能的两条硬规矩：**判定用「零落后」不用总分**，**每个判定都要标证据强度**。

## 什么时候用

- 要在多个产品/项目/方案之间做能力对比
- 要回答「我们和它差在哪一维」
- 要判断「能不能说在这个维度超过了」
- 要给一份对标报告做质量把关

## 什么时候**不**用

- 只拆一个对象 → `source-dive`
- 要在多个技术方案里选一个 → `tech-selection`（那是决策，不是对标）
- 要审自己的证据是否可复算 → `evidence-audit`

## 第 1 步：定维度（先定判据，再去看东西）

### 1.1 维度的三条要求

| 要求 | 反例 |
|---|---|
| **可判定**（能给出有/部分/无） | 「体验好不好」 |
| **对象无关**（对每个对象都成立） | 「是否用 React」（那是实现细节） |
| **不重叠**（两维不测同一件事） | 「有缓存」与「有性能优化」 |

### 1.2 判定档位（四档，必须写死）

| 档位 | 定义 | 关键 |
|---|---|---|
| **有** | 完整实现且默认生效 | 「完整」+「默认」两个条件都要满足 |
| **部分** | 有实现但残缺 / 默认关 / 只在某端生效 | 必须写清**哪部分有、哪部分没有** |
| **无** | 没有这个能力 | 必须举证「查过」（见第 3 步） |
| **判不了** | 证据不足以下结论 | **绝不并入「有」**，也绝不并入「无」 |

⛔ 「部分」是最常被滥用的档 —— 它不该是「我不确定」的垃圾桶，
而应是「明确知道有一半」。写不出「哪部分有」就不该判部分。

### 1.3 明确「非目标」

有些维度**我们主动不做**（产品形态决定）。必须：

1. 在维度表里标出来
2. 写明理由（谁决定的、为什么）
3. **不计入输赢**，但公开可见

⛔ 不标非目标，会出现两种坏结果：
- 被迫去补一个不该做的东西
- 或者偷偷把它算成「平」，掩盖真实差异

## 第 2 步：逐格取证（每格都要能复算）

### 2.1 证据的三种强度

| 强度 | 定义 | 可复算吗 |
|---|---|---|
| **REAL** | 指向对方仓库里的真实文件（路径可 join） | ✅ |
| **MIXED** | 有真实路径，但也引了我方分析文档 | ⚠ 半硬 |
| **ABSENT** | 缺席核验（判无 + 扫描 0 命中） | ✅（证据在过程里） |
| **OWN** | 只引我方分析文档 | ❌ 循环论证 |
| **NONE** | 无证据 | ❌ |

⛔ **OWN 是最危险的一类**：它看起来有证据（引了一份文档），
但那文档是我们自己写的 —— 等于「我说它有」变成「我引用我说它有」。

### 2.2 「无」也必须举证

判「无」不是「我没找到」，而是「我查了这些地方，都没有」：

```
【缺席核验】扫描 D:/refs/xxx.git；关键词 cron|schedul|timer|periodic
**0 命中**。
```

必须写：**查了哪个仓库 + 用了什么关键词 + 命中数**。

⛔ 不写这些，「无」就是不可复算的断言 —— 和「有」但没有路径一样糟。

### 2.3 多包仓库的陷阱

单包结论不能推广到多包仓库。本仓库踩过：
`pi` 的 `zlib` 被误判为「无压缩能力」—— 因为只查了单文件，而那是多 package 仓库。

判据：**判「无」之前，确认查的是整个仓库（含所有 packages/），不是某个子目录。**

## 第 3 步：判定用「零落后」，不用总分

### 3.1 为什么不用加权总分

| 方案 | 结果 | 问题 |
|---|---|---|
| 加权总分 | 「我们 8.5 分，它 7.2 分，我们赢」 | 掩盖了「有一维我们 0 分它满分」 |
| **零落后** | 「有 1 维落后，不能说全面超越」 | 直接指出短板 |

**理由**：对标的语义是「我比它强」，只要有一维不如，这个说法就不成立。
加权是「平均更好」，不是「更强」。

### 3.2 四类结论

| 结论 | 条件 |
|---|---|
| **实质超越** | 可比维 ≥ N 且 落后维 = 0 且 净胜 ≥ M 且 覆盖 ≥ X% |
| **基本超越** | 可比维 ≥ N 且 落后维 = 0 且 净胜 ≥ 0 |
| **不及** | 存在任何落后维（哪怕净胜很大） |
| **可比不足** | 可比维 < N（样本太小，结论无统计意义） |

⛔ 「可比不足」不能写成「超越」，也不能写成「不及」—— 那是没比。

### 3.3 口径必须声明（两套数字都报）

| 口径 | 含义 | 用途 |
|---|---|---|
| **宽松**（有+部分家数） | 把「部分」算作不落后 | 说明不是完全空白 |
| **严格**（证据可复算家数） | 只算证据硬的 | 说明领先是真的 |

⛔ 混用会说错话。正确写法：

> 净胜 14 家（宽松口径）；其中证据可复算的 11 家，另 3 家依赖半硬证据，**未核实**。

## 第 4 步：不可比的对象要单独归类（不能混进输赢）

### 4.1 三类不可比

| 类型 | 特征 | 处理 |
|---|---|---|
| **无源码** | 纯 SaaS / 闭源产品 | 标 UNKNOWN，**不参与输赢** |
| **非实现** | 资料集 / 提示词集 / 教程 | 不参与实现比较 |
| **证据未复算** | 有源码但证据还没核 | 列入待办，不进结论 |

### 4.2 为什么要单独归类

如果把它们混进「平」或「输」，结论就是假的：

- 混进「平」→ 假装比过了
- 混进「输」→ 因为拿不到证据就认输

⛔ 「没法比」不是「打平」，也不是「输」。它是第三种状态，必须单独说。

## 第 5 步：报告必须包含「这个结论在什么条件下会翻」

### 5.1 三个翻转条件

| 条件 | 说明 |
|---|---|
| **证据补齐后** | 现在是 OWN 的格补成 REAL 后，判定可能变 |
| **对方迭代后** | 对手也在进步，今天的领先明天可能没了 |
| **我们的非目标变化** | 如果我们决定做那个维度，对比结果会变 |

### 5.2 写法

> 当前判「不及」（A12 落后一维）。
> **如果**把技能数从 35 补到 150+，这一维会翻转。
> **但如果**对方同期也在扩，可能仍然落后。

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 维度可判定 + 逐格有证据 + 零落后判定 + 口径声明 + 翻转条件
- WARN = 有证据是 MIXED/OWN（列出）
- FAIL = 用总分掩盖落后 / 「无」未举证 / 不可比混进输赢
- UNKNOWN = 维度定义不清 / 拿不到对象源码

## 假阳性清单（这些不构成「完整对标」）

- 维度少于 10 个（样本太小）
- 所有格都判「部分」（等于没判）
- 没有「判不了」的格（说明没遇到证据不足，可能是没认真查）
- 总分领先但没有逐维明细
- 只比了我们强的维度

## 假阴性清单（最常漏的 8 类）

1. **用加权总分掩盖单项落后**
2. **「没查到」当成「没有」**（未举证）
3. **单包结论推广到多包仓库**
4. **OWN 证据当成 REAL**（循环论证）
5. **口径混用**（宽松当严格）
6. **不可比对象混进输赢**
7. **没标非目标**（被迫补不该做的 / 偷偷算成平）
8. **没有翻转条件**（结论变教条）

## 本仓库可用的命令

```bash
node tools/evolve/audit-evidence-provenance.mjs    # REAL/MIXED/ABSENT/OWN 分布
node tools/evolve/audit-evidence-content.mjs       # 内容抽检（低价值证据）
node tools/evolve/fair-compare.mjs                 # 零落后判定
node tools/benchmark/absence-check.mjs             # 缺席核验（证明真的没有）
node tools/benchmark/check-matrix-integrity.mjs    # 矩阵完整性
```

## 与其他技能的关系

- `source-dive`：单对象拆解（本技能是多对象汇总）
- `evidence-audit`：证据可复算性审计
- `tech-selection`：多方案选一个（决策，非对标）
- `project-verdict`：逐项目结项判定
- `postmortem`：对标结论出错后的复盘

## 边界（如实说清）

- 对标**不能证明「产品更好」**，只证明「在这个维度集上更强」
- 维度集本身是主观选择；换一套维度结论可能不同
- 拿不到源码的对象永远只能 UNKNOWN，无法纳入输赢
- 「零落后」要求证据完整；证据不全时只能报「可比不足」
- 本技能不产出代码，只产出「谁更强、差在哪」的判断
