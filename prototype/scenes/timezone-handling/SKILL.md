# 时区处理 技能

> 时区 bug 的共同特征：**本地测试全过，跨时区/跨夏令时全错**。
> 三条铁律：**存 UTC、算用 UTC、显示才转本地**。
> 判据：**跨夏令时切换的那一天，你的逻辑还对吗？**

## 什么时候用

- 存储/比较时间
- 跨时区用户
- 有「当日/本月」这类时间窗

## 什么时候**不**用

- 纯本地单时区工具（也要注意夏令时）

## 第 1 步：三条铁律

| 铁律 | 说明 |
|---|---|
| **存 UTC** | 数据库存 UTC 时间戳（或带时区的 timestamptz） |
| **算用 UTC** | 比较、排序、计算间隔都用 UTC |
| **显示转本地** | 只在展示给用户时转成用户时区 |

⛔ 存本地时间且不带时区 = 永远不知道它属于哪个时区。

## 第 2 步：夏令时（DST）的坑

| 坑 | 说明 |
|---|---|
| **时间不存在** | 春季拨快，2:30 不存在（跳到 3:30） |
| **时间出现两次** | 秋季拨慢，1:30 出现两次 |
| **一天不是 24 小时** | 切换日 23 或 25 小时 |
| **固定偏移错误** | 用 UTC+8 硬编码（中国无 DST 但别国用 UTC+8 且变） |

⛔ 用固定偏移（如 `+08:00`）在夏令时国家必然错。要用**时区名**（`Asia/Shanghai`）。

## 第 3 步：「当日/本月」怎么算

| 需求 | 正确做法 |
|---|---|
| 「今天」 | 按**用户时区**的今天，不是服务器时区 |
| 「本月」 | 按用户时区的月初边界 |
| 「24 小时内」 | 用 UTC 时间差，不涉及日历 |

⛔ 「今天」用服务器时区算 = 跨时区用户看到错误的一天。

## 第 4 步：常见误用清单

| 误用 | 后果 |
|---|---|
| `new Date()` 当本地时间用 | 它本身无时区概念 |
| 字符串 `2024-01-01` 直接比较 | 无时区，跨区错 |
| `date + 86400` 加一天 | 夏令时日不是 86400 秒 |
| 数据库 `datetime` 无时区 | 不知道哪区 |
| 前端本地格式化 | 只适合展示 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 存 UTC + 用时区名 + 显示转本地 + DST 处理
- WARN = 存 UTC 但硬编码偏移
- FAIL = 存本地无时区 / 用固定偏移 / 「今天」用服务器时区
- UNKNOWN = 拿不到存储方式

## 假阳性清单（这些不算「处理了时区」）

- 存了 UTC 但展示不转本地
- 用固定偏移当支持时区
- 本地测试过了

## 假阴性清单（最常漏的 8 类）

1. **存本地无时区**
2. **固定偏移**当支持夏令时
3. **「今天」用服务器时区**
4. **date + 86400** 加一天
5. **`new Date()` 当本地**
6. **字符串无时区直接比**
7. **DST 切换日没测**
8. **DB 用无时区类型**

## 边界（如实说清）

- 有些历史数据无时区信息，迁移时有歧义
- 用户时区可能由客户端提供，不可完全信（要校验）
- 本技能不写代码，只定规则
