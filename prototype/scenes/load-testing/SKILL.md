# 负载测试 技能

> 压测不是为了「跑个高 QPS 截图」，而是找**系统的拐点与瓶颈**。
> 判据：**压测结果能回答「瓶颈在哪、能扛多少、先崩哪层」吗？**

## 什么时候用

- 大促/上线前容量验证
- 找性能瓶颈
- 验证扩容效果

## 什么时候**不**用

- 单机微服务（直接 profile）

## 第 1 步：定目标

| 问题 | 要回答 |
|---|---|
| 压什么场景 | 核心链路 |
| 多大量 | 业务峰值×冗余 |
| 什么指标 | QPS/延迟/错误率 |

## 第 2 步：造真实流量

| 要点 | 说明 |
|---|---|
| 真实比例 | 读写比、接口分布 |
| 真实数据 | 数据量级要对（小表压不出问题） |
| 思考时间 | 模拟真实节奏 |
| 独立压测环境 | 不污染生产 |

⛔ 只压一个接口 ≠ 真实场景；数据量太小 ≠ 真实。

## 第 3 步：找拐点与瓶颈

| 现象 | 含义 |
|---|---|
| QPS 上去但延迟暴涨 | 到拐点 |
| 错误率突增 | 容量耗尽 |
| 某层先满 | 瓶颈在那（DB/连接池/CPU） |

## 第 4 步：压测类型

| 类型 | 目的 |
|---|---|
| 负载测试 | 正常到峰值 |
| 压力测试 | 超载看崩溃点 |
| 浸泡测试 | 长时间看内存泄漏 |
| 尖峰测试 | 突增流量 |

## 第 5 步：观察与结论

- 全链路监控（不只压测机）
- 定位瓶颈层
- 结论要可行动（加哪层）

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 真实流量 + 找拐点 + 定位瓶颈
- WARN = 压了但数据量不真实
- FAIL = 只压单接口 / 无监控 / 结论不可行动
- UNKNOWN = 拿不到容量数据

## 假阳性清单（这些不算「压测好」）

- 只压单接口
- 小数据量
- 没看下游

## 假阴性清单（最常漏的 8 类）

1. **只压单接口**
2. **数据量不真实**
3. **不看下游瓶颈**
4. **无浸泡测试**（泄漏）
5. **压测机自身是瓶颈**
6. **污染生产**
7. **不模拟思考时间**
8. **结论不可行动**

- 压测环境难完全等同生产
- 本技能不实现，只设计
