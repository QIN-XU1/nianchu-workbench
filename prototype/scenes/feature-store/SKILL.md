# 特征存储 技能

> 特征存储解决的核心问题：**训练用一套特征计算、线上用另一套 → 训练/服务偏差（train-serving skew）→ 线上效果崩**。
> 判据：**同一个特征，训练时和线上服务时是同一段代码算出来的吗？** 不是就有偏差风险。

## 什么时候用

- ML 特征的统一管理
- 多模型复用特征
- 训练/服务特征不一致

## 什么时候**不**用

- 简单模型、特征少且固定

## 第 1 步：训练/服务偏差（头号问题）

| 问题 | 后果 |
|---|---|
| 训练用离线 SQL 算特征 | 线上用实时代码算 → 不一致 |
| 时间点不对 | 特征穿越（用了未来数据） |

★ **同一特征定义、同一计算逻辑**用在训练和服务。特征存储就是为此。

## 第 2 步：离线/在线双存储

| 存储 | 用途 |
|---|---|
| **离线**（批） | 训练、批量打分 |
| **在线**（低延迟） | 实时推理取特征 |
| 一致性 | 两者值要一致 |

## 第 3 步：特征时间点（point-in-time）

| 概念 | 说明 |
|---|---|
| 特征穿越 | 训练时用了「未来才知道」的特征 → 离线效果好、线上崩 |
| point-in-time join | 按事件时间取当时该有的特征 |

⛔ 特征穿越是最隐蔽的 ML bug：离线 AUC 很高，上线就废。

## 第 4 步：复用与治理

| 项 | 要求 |
|---|---|
| 特征目录 | 可发现、有定义 |
| 复用 | 多模型共享 |
| 版本 | 特征定义变更可追溯 |

## 第 5 步：监控

| 项 | 说明 |
|---|---|
| 特征分布 | 训练 vs 服务分布对比 |
| 缺失率 | 突增 |
| 延迟 | 在线特征取用延迟 |

## 输出格式

**结论**：`四态: PASS | WARN | FAIL | UNKNOWN`
- PASS = 训练/服务同逻辑 + 双存储一致 + point-in-time + 监控
- WARN = 有特征管理但无 point-in-time
- FAIL = 训练/服务两套代码 / 特征穿越 / 无监控
- UNKNOWN = 拿不到特征定义

## 假阳性清单（这些不算「有特征存储」）

- 只有离线特征表
- 训练/服务两套代码
- 无 point-in-time

## 假阴性清单（最常漏的 8 类）

1. **训练/服务两套代码**
2. **特征穿越**（离线虚高）
3. **离线在线不一致**
4. **无 point-in-time**
5. **无特征目录**
6. **无版本**
7. **无分布监控**
8. **在线特征延迟高**

## 与其他技能的关系

- `ml-serving`：训练/服务一致
- `data-lineage`：特征血缘
- `data-quality`：特征质量
- `data-warehouse`：离线特征

## 边界（如实说清）

- 特征存储是重基建，小团队可能过度
- point-in-time join 有性能成本
- 本技能不实现，只设计
