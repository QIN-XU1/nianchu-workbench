## verdict

**refuted**

拆开看，主张是一个「观测 + 处方」的复合体，两者的验证结论**相反**：

- **观测部分：全部成立，逐条精确复现。** 28076、18533、P4=930、hermes 重复计数、`isSourceFile` 收到文件名——我一个数字都没能推翻，全部对上了。
- **处方/结论部分：不成立。** 「9543 = 我们的真实代码量」这条结论有**三条硬伤**，其中两条决定性：
  1. **9543 已经过期**：HEAD 上同一套规则算得 **9550**。`7b8ac00c` 把 `hermes-patches` 加回来了（7 个源码文件），但台账 `after: 9543`、`delta: -18533` 都没更新，commit message 里「仍是 9543」「`hermes-patches` 只有 1 个源码文件」**两句都是错的**（实际 7 个，实际 9550）。
  2. **重复计数没有消除，只是搬了家**：`us` 9550 个文件里 **4746 个与某个参照系统 byte-identical**。hermes 的重复（17455）确实修掉了，但 openbitfun 的重复（**4683**）原样保留——因为 `apps/vouch-web` 是 OpenBitFun 的 fork，而 fork 当然被 `git ls-files` 跟踪，于是新判据放它过去了。性质与 hermes 完全相同，量级 27%。
  3. **修复引入新 bug，且这个 bug 吃掉了 P3 的对照基准**：`isSourceFile` 改收完整路径后，它内部的 `SKIP_DIR.test(p)` 开始看得见路径里的 `node_modules`，把 `keepInNodeModules` 白名单整个打死。**`dsh` 主体从 3995 个文件变成 0 个文件**（我实测两版复现，JSON 里 `dsh.files=0` 佐证）。dsh 的 P3 率 **4.76 高于 hermes 的 4.24**——它本是 P3 的最强基准，现在被静默退役，于是「P3 最强」从 4.76 掉到 4.24。主张说「P3 领先扩大」，**这个"扩大"有一部分是删掉最强对照换来的**。

一句话：**观测是对的，处方对了一半，结论是错的。** 9543 既不是「真实代码量」（约一半内容 byte-identical 于别人），也不是当前的数（9550）。

## 硬伤（如果有）

### 硬伤 1（决定性）：`isSourceFile` 的修复打死了 `keepInNodeModules` 白名单，`dsh` 主体被清零

- 现象：`evidence/evolve/executable-compare.json` 中 `dsh.files = 0`。
- 根因链：`tools/benchmark/executable-compare.mjs:283` 传完整路径 → `:220-228` `isSourceFile` 对完整路径做 `SKIP_DIR.test(p)` → 路径含 `node_modules` → 白名单放行的文件也判 `false`；而 `:260-275` `collect()` 在 `insideNm===false` 时**故意绕过** `SKIP_DIR`（`:241` 注释「不再被 SKIP_DIR 拦」）。**文件层把目录层刚放行的一次又收回去了。**
- 实测（同一份 `collect`，只换 `isSourceFile` 入参）：

  ```
  dsh subject, isSourceFile(e.name)   [OLD code] files = 3995
  dsh subject, isSourceFile(fullPath) [NEW code] files = 0
  => regression: dsh lost 3995 files
  ```
- **为什么这是硬伤而不只是小 bug**：`dsh` 的 P3 率 = **4.76**（19/3995），**高于 hermes 的 4.24**。它被清零后，P3 的「最强参照」从 4.76 掉到 4.24。主张说「P3 从 6.20 → 8.59（领先扩大）」——**这个"领先扩大"里有一部分是把最强的对照基准删掉换来的**。这是「更诚实」的反面。
- **讽刺之处**：主张的 obs 正是「路径传参不对导致过滤不生效」。修好路径传参后，**过滤现在生效到把白名单也过滤掉了**。原来的 bug 是「过滤太松」，新的是「过滤太紧」，**同一行代码的两个方向都踩了**。且 `:354-355` 是特意给 dsh 开的口子（`:237` 注释「不开口子就是 0 文件」），现在这个口子被同一 commit 堵死。
