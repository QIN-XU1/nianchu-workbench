# H-0121 独立验证

**验证对象**：`research/改进台账.json` → `H-0121`
**主张**：对 8 个核心验收器各写一条突变规格（把被测核心函数改成永远失效），若每条都让该文件 `--selftest` 变红，则证明这些断言真的承重。
**度量**：突变后自检变红的规格数；基线 0 → 改后 8；样本量 8；verdict=keep
**验证方**：v-h0121（独立）— 全程只读，未跑 `verify-mutation.mjs` 主流程、未跑 `measure-*`

---

## verdict

**refuted**

理由（一句话）：**"8/8 变红" 这个数字本身是真的，但它推不出主张要的结论。**
主张的因果是「变红 ⇒ 这些断言承重」。我把 8 条突变放进内存（`data:` URL 导入，零落盘）逐个跑，得到三个独立的反证：

1. **2/8 条（25%）是靠「崩溃」变红的，不是靠断言。** 断言层根本没跑到判定点就 `TypeError` 抛出。
2. **68 条被触及的断言里 21 条（31%）在突变下依然是绿的** —— 它们对「核心函数永远失效」这个失效完全无感，正是主张所说要排除的「摆设断言」。
3. **基线 `0` 与既有台账矛盾。** 同一批函数早在 H-0077/0078/0079/0081/0076 就被同一种突变做过检验，其中 3 个文件（`evidence-grade` / `scope-map` / `build-neuron` / `backoff` / `freshness`）的突变结论已经逐字写进既有条目。H-0121 不是从 0 到 8，而是「把已经点名过的 8 条重跑一遍并计一次新分」。

## 硬伤

1. **`build-neuron` 与 `freshness` 两条"承重"是崩溃造成的（2/8 = 25%）。**
   `buildGraph → {nodes:[],edges:[]}` 后在 `tools/ui/build-neuron.mjs:146` 读 `.deg` 抛 `TypeError`；`staleEntries → {total:0,items:[]}` 后在 `tools/memory/freshness.mjs:145` 读 `rS.items[0].severity` 抛 `TypeError`。两者 exit≠0 来自未捕获异常，断言层只跑到 2/8 和 7/8 就中断。**这证明文件会坏、不证明那 8 条断言承重。**

2. **31% 被触及的断言在此突变下仍是绿的（68 条中 21 条）。**
   明细：`backoff` 4/8 绿、`readability` 5/10 绿、`audit-coverage` 4/8 绿、`freshness` 4/7 绿、`scope-map` 2/6 绿。这些断言对「核心函数永远失效」无感，按主张自己的定义就是「摆设」。`8/8 PASS` 掩盖了它们。

3. **`baseline: 0` / `delta: 8` 与既有台账直接冲突。**
   `selftest-reality.json`（11-15）已对 14 个文件做过同类突变检验；台账 `H-0076/0077/0078/0079/0081` 分别逐字记录了 `staleEntries`/`evidence-grade`+`scope-map`/`computeBackoff`/`buildGraph`/`reconcile` 的突变变红结论。8 个目标中 **≥6 个不是新证据**。真实新增量最多 2 个（`backoff` 已见于 H-0078、`commit-readability` 是唯一无任何既有突变记录的）。

4. **提交版 `verify-mutation.mjs` 还原不安全（无 try/finally、无信号处理）。**
   `git show HEAD:tools/evolve/verify-mutation.mjs` 第 188-193 行为顺序执行：写突变 → 跑自检 → 写回。此版本**就是产出 `mutation-load-bearing.json` 的版本**（提交 `2fc6d3a8` 只含该版本）。期间被 Ctrl-C 会留下突变体污染真实仓库。当前工作区已被他人补上 try/finally + 三个信号 + uncaughtException，反证该缺陷真实存在。

5. **超时 = 变红 = 承重。**
   `verify-mutation.mjs:114-122` `runSelftest` 用 `timeout:600000`，`catch` 里 `e.status` 为 `null`（超时/被信号杀）时回落为 `1`。**自检hang住会被判成"抓住了失效"。**

6. **"8/8" 可被刷分，缺区分度。**
   8 条全是「返回空/0/null」，最易触发崩溃最易变红。它无法区分「断言写得好」与「文件崩得快」。作为承重证据，这个数字的判别力接近 0。

7. **结果证据未入库，且字段不足以支撑结论。**
   `evidence/evolve/mutation-load-bearing.json` 被 `.gitignore:260` 排除，未随 `2fc6d3a8` 提交；其 schema 只有 `mutatedExit`/`restoredExit` 两个整数，**无法区分断言判否 / 崩溃 / 超时**。
