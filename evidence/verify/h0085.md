### 硬伤 1（致命·主张核心可证伪）：`after=40` 是跨脚本拼接出来的假数字

主张的度量是 `evolve.mjs 自检条数`，`baseline=24 → after=40`，`delta=16`，`samples=40`。

```
38a3e991（搬走断言）  evolve.mjs --selftest => 24/24   ← 回到基线

```

### 硬伤 3（严重·修复引入的新问题）：C2 闸门把 31 条 unknown 条目永久锁死

沙箱实跑（隔离台账，不动真台账）：

```
record() on status=unknown => {"ok":false,"reasons":["H-0001 已记录（status=unknown），只追加，不许改历史"]}
attest() on same           => false  "C2：verdict 是 unknown ⇒ …"
```

- `evolve.mjs:113`：`record()` 只接受 `status==='open'`，**unknown 条目无法重测**。
- `evolve.mjs:252-258`：`attest()` **一律**拒绝 `verdict=unknown`。
- CLI 只有 `register/record/attest/dispute/list/verify`（`:568-686`），**无 reopen/retest**。

→ **两条路全封死，31 条 `status=unknown` 条目永久无法结案**，即使后来补够样本也无处可写。

这**部分违背**项目自己的 C2 原则。C2 的原话（`evolve.mjs:125-127`）是「判不了就说判不了，不是判不了就什么都不说」—— 前半句（保持 unknown）做到了，但「后来判得了了怎么办」这条出口被堵死，变成「判不了就永远判不了」。**正确做法应是**：`attest()` 拒绝的是「拿旧的小样本结论去洗 closed」，而不是「禁止任何 unknown 条目日后补证升级」；应留一条 `retest`/`reopen` 路径。

### 硬伤 4（中）：闸门不完整 —— 只看 `verdict` 不看 `status`，且不做行为级验证

- **绕过口**：`status=unknown` 但 `verdict=null` 的条目 → `attest()` **返回 ok:true**（沙箱实测）。当前台账 31/31 都是 `verdict='unknown'`，**经 `record()` 不可达**；但 `attest()` 的设计动机原文是「直接改 JSON = 伪造留痕」（`:204`），**手改 JSON 删掉 `verdict` 正是它要防的攻击**，闸门恰好防不住。
- **验证降级**：`c3cac601` 原本在 `evolve.mjs` 里加了两条**行为级**反例（`样本量 5 < 8 ⇒ attest 必须拒绝`、`verdict 为 unknown 时 attest 必须报 C2 拒绝`），`38a3e991` 为压 32KB 红线把它们**删除**，换成 `evolve.attest-c2.test.mjs` 里的**源码正则检查**（`checkGates()` 只读文件文本做 `regex`，不调用 `attest()`）。
- **且该文件不承重**：全仓 grep `attest-c2` 只有 2 个命中（自身 + 一个 evidence json），**没有任何 gate 执行它**；裸跑 `node tools/evolve/evolve.attest-c2.test.mjs` **exit 0 且零输出**（`:110` 要求显式 `--selftest`）—— 在 `audit-verifiers.mjs` 那类「扫到 `--selftest` 就跳过/或按 exit code 判绿」的审计里，这是一个**假绿**。

→ 机制本身有效（B2/B3/B4 已行为验证），但**回归保护被降级为不承重的源码正则**，且 `evolve.mjs` 的 27 条自检里**零条**覆盖 C2 闸门。H-0085 声称的「新增 2 条反例钉住」在 HEAD 上**已不存在于承重自检中**。
