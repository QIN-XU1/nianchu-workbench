# 42 · 记忆神经元修复：从"空图"到"路径全在"

> 用户指出："记忆神经元根本没做过实际写入"。
> **这个判断是对的。查下来不是"没写入"，是"读不到"。**

---

## 一、根因链条（四层，逐层扒开）

### 第 1 层：`memRoot` 是空字符串

`preload.js` 的算法：
```js
const __wbHome = (process.env.DSH_CUSTOMER_HOME || '');
memRoot: __wbHome ? (__wbHome + '\\场景记忆') : '',
```

**而 `DSH_CUSTOMER_HOME` 从未被设置。**

实测（CDP 直接读运行时）：
```
paths: { "memRoot": "", "reviewDir": "...", "dataDir": "..." }
```

**`memRoot = ""` ⇒ 神经元拿到空路径 ⇒ 读不到任何文件 ⇒ 空图。**

### 第 2 层：记忆地图只登记了 4 个场景

`记忆地图.json` 里 `areas` 只有 4 条（命令 / B站 / 自我复盘 / 本地电脑）。

**我新建的 7 个场景全没登记**：调研 / 竞品拆解 / 逆向分析 / 架构梳理 / 实施计划 / 管线 / 关系军师。

⇒ 即使 memRoot 修好了，神经元也只显示 4 个。

### 第 3 层：`areas/*.md` 文件不存在

`索引.json` 里每个 area 都指向 `areas/<id>.md`，但新场景的这 7 个文件根本没建 ⇒ 路径失效。

### 第 4 层：`META_DIR` 与真实文件位置不一致

原项目代码：
```js
const ROOT = MEM_ROOT + '\\_共享记忆';
const META_DIR = MEM_ROOT;              // ← 注意
nodes.push({ id: 'doc-todo', path: META_DIR + '\\_待办.md' });   // ← 找 MEM\_待办.md
```

**但真实文件在 `MEM\_共享记忆\_待办.md`。**

⇒ 这是**原项目自带的路径不一致缺陷**，`_待办` / `_跨场景通知` / `冲突` 三个节点永远失效。

## 二、逐层修复

### 修 1：设 DSH_CUSTOMER_HOME（两层保险）

**main.js**（启动时显式设置）：
```js
if (!process.env.DSH_CUSTOMER_HOME) {
  const guess = path.join(__dirname, '..', '引擎数据', '.dsh');
  if (fs.existsSync(guess)) {
    process.env.DSH_CUSTOMER_HOME = guess;
  }
}
```

**preload.js**（加兜底推导）：
```js
const __wbHome = (function () {
  if (process.env.DSH_CUSTOMER_HOME) return process.env.DSH_CUSTOMER_HOME;
  const guess = path.join(__dirname, '..', '引擎数据', '.dsh');
  if (fs.existsSync(guess)) return guess;
  return '';
})();
```

**验证**：启动日志出现 `[mem] DSH_CUSTOMER_HOME = ...\引擎数据\.dsh`，
运行时 `memRoot` 非空。

### 修 2：新建 `工具/mem-map.mjs` 重建记忆地图

它不是手改 json，而是**从场景 json 自动派生**：

```
读 11 个场景 → 为每个找记忆目录 → 找 AI 面板 id → 生成 areas
→ 校验每个 privateMemory 路径真实存在 → 同步 索引.json 与 索引.md
```

**关键设计：它会校验，不是盲写。**
有 3 种模式：
- `--check` 只校验现有地图
- `--dry` 预览不写
- 默认 重建并同步

重跑结果：**登记 4 → 11 个场景，全部路径有效。**

### 修 3：补齐 7 个 `areas/*.md`

按原项目格式生成：场景 id / 场景名 / 记忆目录 / 面板文件 / 职责 / 记忆指针。

### 修 4：路径不一致 —— 用"指针文件"而不是复制

原项目的 `META_DIR = MEM_ROOT`，而真实文件在 `_共享记忆\` 下。

**两种解法：**

| 方案 | 风险 |
|---|---|
复制一份到 `MEM_ROOT\` | **同一事实存两处** —— 原项目文档明确警告过这个坑（"两份数字打架"） |
**建指针文件** | 无风险，且说明了原因 |

我选了**指针**：

```markdown
# _待办

> **这是指针文件，不是真身。**
> 真身：`_共享记忆\_待办.md`
> 原因：记忆神经元的 META_DIR = MEM_ROOT（场景记忆根），
>       而共享层的板实际放在 _共享记忆\ 下 —— 两者路径不一致。
> 这里放指针而不是复制，避免同一事实存两处。
```

### 修 5：数据源节点格式错

**我第一版写成了数组**：
```json
"dataSources": [{"key":"skills","path":"..."}]
```

**但代码要的是对象**：
```js
Object.keys(memMap.dataSources).forEach(function (key) { ... })
var ds = memMap.dataSources[key] || {};
```

而且它有 `SKIP = { scenes, skills, projects, tasks }` —— **`skills` 会被跳过**。

改成对象 + 用可识别的 key：
```json
"dataSources": {
  "tools":  { "path": "绝对路径\\工具", "count": 9 },
  "docs":   { "path": "绝对路径\\方案", "count": 49 },
  "health": { "path": "绝对路径\\体检结果.json" },
  "backups":{ "path": "绝对路径\\场景记忆", "count": 1 }
}
```

**并且路径必须是绝对路径**（`statOk` 直接传给 `app.file.stat`）。

### 修 6：登记当前项目

`项目.json` 从 `{"projects": []}` 变成：
```json
{"projects": [{
  "id": "dsh-workbench", "name": "DeepSeek 工作台",
  "owner": "命令", "status": "active",
  "paths": ["D:\\file\\AI Temp\\DeepSeek\\Agent自研\\workbench"],
  "aliases": ["工作台", "workbench"]
}]}
```

## 五、这轮学到的（四条硬教训）

### 教训 1：空字符串是最隐蔽的失败

`memRoot = ""` 不报错、不抛异常，只是让所有读取静默返回空。
**表现是"界面正常但内容空白"** —— 最难查的一类问题。

**解法**：边界值必须显式校验（我后来加了"memRoot 已非空"这条断言）。

### 教训 2：登记表会腐烂

`记忆地图.json` 是手写的、场景增加了却不登记 ⇒ 4 个 vs 11 个。
**这是"两处存同一事实"的典型症状。**

**解法**：要么从单一源头派生（我做的 `mem-map.mjs`），要么设校验闸。

### 教训 3：原项目代码也有缺陷

`META_DIR = MEM_ROOT` 与真实文件位置不一致，导致 3 个节点永远失效。
**不能假设"原项目是对的"** —— 但也不能贸然改它的代码（我用指针文件绕开）。

### 教训 4：数据结构要对上，不是"看起来像"

我把 `dataSources` 写成数组，代码要的是对象。
**JSON 合法 ≠ 结构正确**。直到真的 stat 才发现。
