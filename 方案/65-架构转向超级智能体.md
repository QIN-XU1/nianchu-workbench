# 65 · 架构转向：从「工作台」到「超级智能体」

> 用户原话：
> 「我既然想的是打造一个超级智能体或是agent就必然会产出**不可估量的场景以及子agent**，
> 而这些都**全权交给AI在执行任务时自行选择要调度哪些场景、场景之间如何联系**等等，
> 所以**只留一个负责交互的对话框**即可」

---

## 一、这次转向的本质

### 1.1 之前的设计（错的）

```
用户 → 看 11 个场景标签 → 手动点某个场景 → 在那个场景里对话
```

**问题**：场景数量被 UI 标签栏锁死。用户想加第 12 个场景，就得改 JSON、改 UI。

### 1.2 现在的设计（对的）

```
用户 → 唯一个对话框 → 说需求
                        ↓
              AI 自己判断：
              · 这事需要哪些场景？
              · 场景存不存在？
              · 不存在就创建
              · 怎么调度它们
              · 结果怎么汇总
```

**场景是 AI 的工作产物，不是 UI 的固定标签。**

---

## 二、三层记忆（luanyujia 的核心遗产，必须真正用起来）

**现有文件结构已经完整**，但新前端完全没读它——这是最大的浪费。

```
引擎数据/.dsh/场景记忆/
├── _共享记忆/                    ← 共享层（所有场景可读）
│   ├── 索引.json                  ← ★ 场景注册表（动态，不是硬编码）
│   ├── 项目.json                  ← 项目清单
│   ├── 记忆地图.json               ← 数据源地图
│   ├── 体检结果.json               ← 健康检查
│   ├── areas/*.md                ← 区域明细
│   ├── _待办.md                    ← 通知与待办
│   └── 冲突.md                     ← 冲突记录
│
├── 命令/                         ← 场景私有（每个场景一个文件夹）
│   ├── 身份卡.md                   ← 这个场景是谁
│   ├── 场景私有记忆.md              ← §〇交接(≤4KB) + 职责 + 坑
│   ├── _文件索引.md                 ← 文件在哪
│   └── 归档/                       ← 旧轮次
│
└── <其他 10 个场景>/               ← 同样的结构
```

### 2.1 三层判据（luanyujia 原文）

| 层 | 放什么 | 读取频率 | 体量上限 |
|---|---|---|---|
**注入层** | 只放"不读就会白干"的铁律 | 每轮都付 | 越短越好 |
**私有层** | §〇交接 + 身份卡 + 项目记忆 | 每场开场读一次 | §〇 ≤4KB，主文件 ≤25KB |
**共享层** | 发生了什么/该做什么/东西在哪/健康吗 | 按需查 | 无限 |

**核心判据**：「这东西**谁会读**？**多久读一次**？」
- 每轮读 → 注入层（必须极短）
- 每场开场读 → 私有层
- 需要时才查 → 共享层

### 2.2 §〇 交接只有四个回答

```
### 1) 上次交接      <做了什么 / 结果 / 证据>
### 2) 当前项目      <表格：项目|记忆文件|状态|下一步>
### 3) 私有记忆变更  <YYYY-MM-DD：改了什么 + 为什么>
### 4) 下一步 / 卡点 <谁先动，按什么顺序 / 等谁>
### 5) 全貌         <工具生成，别手改>
```

**原文警告**：不要把 §〇 写成周报。新会话读完必须能回答"下一步该干什么"。

## 三、新架构

### 3.1 只有两个东西

```
┌──────────────────────────────────────────────────────────────┐
│  中枢（Hub）—— 唯一交互入口                                    │
│                                                               │
│  ┌───────────────────────┬────────────────────────────────┐  │
│  │  记忆神经元 3D          │  中枢对话（唯一对话框）          │  │
│  │                       │                                │  │
│  │  · 场景地图（动态）      │  · 你在这里交办需求              │  │
│  │  · 场景亮起 = 正在调度   │  · AI 自主决定调度什么           │  │
│  │  · 可旋转/缩放/点击      │  · 结果显示在这里               │  │
│  │                       │                                │  │
│  └───────────────────────┴────────────────────────────────┘  │
│                                                               │
│  去掉了：场景标签栏（场景不是标签，是 AI 的产物）                 │
│  去掉了：第二/第三个对话框（只有一个）                           │
└──────────────────────────────────────────────────────────────┘
                            │
                            ▼ AI 调度
┌──────────────────────────────────────────────────────────────┐
│  场景（动态，数量无上限）                                       │
│                                                               │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐        │
│  │ 架构梳理  │ │ 实施计划  │ │ 竞品拆解  │ │ ???      │  ...  │
│  │ 身份卡    │ │ 身份卡    │ │ 身份卡    │ │ 身份卡    │        │
│  │ 私有记忆  │ │ 私有记忆  │ │ 私有记忆  │ │ 私有记忆  │        │
│  │ 独立会话  │ │ 独立会话  │ │ 独立会话  │ │ 独立会话  │        │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘        │
│                                                               │
│  场景被调度时 → 神经元对应节点亮起                                │
└──────────────────────────────────────────────────────────────┘
                            │
                            ▼ 读写
┌──────────────────────────────────────────────────────────────┐
│  共享层（所有场景可读写的公共部分）                              │
│  宿主画像 · 区域表 · 项目清单 · 通知待办 · 索引台账              │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 场景的生命周期（这才是自我进化）

```
① AI 接到需求
      ↓
② 查 索引.json："已有场景里谁合适？"
      ↓
   ┌──── 有合适的 ────┐         ┌──── 没有合适的 ────┐
   ▼                  ▼         ▼                    ▼
③ 调度它           ④ 创建新场景：
   派任务给它           · 生成 身份卡.md
   节点亮起             · 生成 场景私有记忆.md（含 §〇）
                        · 创建独立会话
                        · 更新 索引.json
                        · 神经元新增节点
      ↓
⑤ 汇总结果 → 回到中枢对话
      ↓
⑥ 写回记忆：更新各场景 §〇交接 + 共享层台账
```

**这就是"自我进化"**：场景会随着任务长出来，不是人预先枚举的。

### 3.3 每个场景的独立 AI

| 要求 | 实现方式 |
|---|---|
**独立会话** | 每个场景有自己的 `sessionId`（11 个已经是独立的，实测确认） |
**独立记忆注入** | 场景会话启动时注入：身份卡 + §〇交接 + 本项目记忆 |
**互不干扰** | 场景 A 不知道场景 B 的私有记忆（只能读共享层） |
**独立技能** | 每个场景文件夹可带 `技能/` 子目录 |

**当前缺陷**：新前端的 harness 面板只挂 webview，**完全没有做记忆注入**。
所以场景 AI 实际上是个"裸的通用 agent"，这正是用户说的
「失去了 luanyujia 要实现的场景私有化以及相关记忆的逻辑」。

## 六、为什么这样才是"超级智能体"

### 6.1 三个判定标准

| 标准 | 之前 | 现在 |
|---|---|---|
**场景可无限增长** | ❌ 锁死在 UI 标签 | ✅ AI 按需创建 |
**AI 自主决策** | ❌ 人点标签 | ✅ AI 看需求自己判断 |
**记忆真正隔离** | ❌ 没读私有记忆 | ✅ 每场景注入自己的 |

### 6.2 与 luanyujia 的关系

| 项 | luanyujia 的做法 | 我们保留 | 我们超越 |
|---|---|---|---|
三层记忆 | ✅ 注入/私有/共享 | ✅ 完整保留 | ✅ 加上动态场景注册 |
场景私有化 | ✅ 每场景一个文件夹 | ✅ 保留 | ✅ AI 可创建新场景 |
§〇 交接 | ✅ ≤4KB 四问题 | ✅ 保留 | ✅ 自动注入 |
UI | 固定场景标签 | — | ✅ 改成神经元地图 |
调度 | 人手动切 | — | ✅ AI 自主调度 |

## 七、一句话

> **之前我做的是「工作台」—— 11 个固定场景，人点标签切换。
> 你要的是「超级智能体」—— 场景不可预估，AI 自己长出来、自己调度。**
>
> **关键不在 UI，在机制：**
> **① 场景从 索引.json 动态读（不是硬编码）**
> **② 场景能被 AI 创建（写记忆文件夹 + 注册）**
> **③ 每个场景的 AI 只加载自己的私有记忆（这是 luanyujia 的核心遗产）**
> **④ UI 只有中枢一个入口**
>
> **先做 P0 五项，把地基换过来。**
