## 二、每个机制的核心设计

### 2.1 记忆哨兵

**5 个不变量：**
```
INV-1  注入层 AGENTS.md ≤ 2048 字节
INV-2  每个场景 §〇 交接 ≤ 4096 字节
INV-3  每个场景私有记忆 ≤ 25600 字节
INV-4  §〇 只能有 1 份"上次交接"（多份 = 没覆盖写）
INV-5  §〇 四问齐全（上次交接/当前项目/下一步/全貌）
```

**为什么这些是硬指标（原项目真实数据）：**
```
§〇 涨到 40 KB → 没人读 → 交接形同虚设
注入层 60 KB   → 每轮多付 20k token → 一天几十轮 = 灾难
```

**变异测试亮点：边界测试**
```
INV-1 灌到 3000 字节 → FAIL ✓
INV-1 刚好 2048 字节 → PASS ✓  ← 证明判据不"随便报"
```

### 2.2 身份哨兵

**7 个不变量，核心是 INV-7：**
```
INV-1  有 AI 面板的场景必须在索引里
INV-2  索引里的场景必须存在
INV-3  sessionId 格式必须合法
INV-4  sessionId 不能是占位符
INV-5  定位卡必须真实存在
INV-6  场景 json 的 id = 文件名
INV-7  ★ sessionId 必须在引擎会话库里真实存在
```

**INV-7 为什么重要（原项目警告）：**
> "抄示例里的 session-0000… 只会'看起来配好了'，实际不钉会话"

**实测结果：**
```
引擎会话库：167 个真实会话
场景配置：  11 个
身份索引：  11 行
结果：10 个场景的 sessionId 全部真实存在 ✓
```

### 2.3 派单哨兵

**8 个不变量：**
```
INV-1  dispatch 必须有四件套（现象/照哪做/怎么验）
INV-2  announce 不该有回执
INV-3  acked 必须带证据（≥ 20 字符）
INV-4  ★ dispatch 超 deadline 未回执 → 报告
INV-5  acked 但没投递 → 不可能
INV-6  id 格式 d-YYYYMMDD-NNN
INV-7  状态必须是五态之一
INV-8  closed 必须有 ackedAt
```

**INV-4 是整个机制的核心：**
> 原项目："没有'未回执'这个状态，派单就等于扔进黑洞。"
> 实测：36 条通知只有 8 条真投递 = 22% 执行率

**五态状态机：**
```
① created      刚登记
     ↓ 真唤醒
② delivered    已投递
     ↓ 对方回执
③ acked        已回执（带证据）
     ↓
⑤ closed       销账

② ──超时无回执──→ ④ unacked（进"我发出没回"清单）
```

**证据长度校验：**
```
--ack --evidence "好了"           → 拒绝（太短，"只说好了等于没说"）
--ack --evidence "跑通了 8/8..."  → 接受
```

### 2.4 越界哨兵

**4 个不变量：**
```
INV-1  所有核心资产路径必须在场地地图里有归属
INV-3  A 档（宪法）在窗口内被修改 → 报告
E 档   当前场景写了别人的地盘 → 报告
INV-4  窗口内多个场景地盘同时被改 → 提示（不违规）
```

**场地地图五档（72 条规则）：**
```
A  共享·宪法      1 条   AGENTS.md
C  共享·工具      8 条   工具/技能/MCP/插件/主进程/前端
B  共享·台账     12 条   索引/派单/通知/待办/基线
D  自己的专属     51 条   各场景的配置/定位卡/记忆/契约
E  别人的专属     （由 D 档归属推导）
```

**诚实声明（写在代码注释里）：**
```
事后审计而非事前拦截：
  事前拦截需要所有写文件的地方都知道"我是谁"
  但 bash/脚本/编辑器都没有这个上下文，改造成本极高

  事后审计可行：按文件 mtime + 场地地图归属推断
  局限：无法 100% 确定是谁写的，只能提示"可疑"
```

**实测发现：**
```
第一次跑：22 个路径未定义归属
  → 补齐场地地图规则
第二次跑：5 个
  → 继续补
第三次跑：0 个 ✓
```

**这个过程本身证明了 INV-1 的价值：没有归属表，就无法判断谁能改。**

## 三、本轮抓到的 3 个真 bug

### bug 1：派单哨兵时间不可控

```
现象：测试期望 "30.0 小时"，实际输出 "28.8 小时"
根因：变异测试用固定 NOW_MS 构造 createdAt
     哨兵用 Date.now() 判断超时
     → 两者时间基准不同 → 不可复现
修复：支持 SEA_NOW 环境变量注入"当前时间"
```

**这是"时间依赖"的经典问题：测试必须能控制时间。**

### bug 2：越界哨兵的 ROOT 写死（最隐蔽）

```
现象：6 个用例全部失败，输出都是"路径未定义归属"
根因：ROOT = path.resolve(WB, '../..')  ← 模块加载时算死
     测试注入 SEA_WB_ROOT=<临时目录>
     → path.relative(ROOT, wbRoot) 算出绝对路径
     → 与场地地图的 "workbench/工具/**" 模式完全匹配不上
修复：ROOT 从 wbRoot 动态推导
```

**这个 bug 特别危险：它让哨兵"看起来在跑"，但所有路径都匹配失败，
所以 INV-1 疯狂误报，而 INV-3/E 档永远不触发。**

### bug 3：越界哨兵扫描范围漏了 .dsh 根目录

```
现象：INV-3（A 档被改）永远不触发
根因：scanDirs 里有 .dsh/场景记忆、.dsh/skills
     但没有 .dsh 根目录
     → AGENTS.md 根本不在扫描范围
修复：加入 .dsh 根目录
```

**漏扫 = 检查形同虚设。这是"覆盖范围"问题，不是逻辑问题。**
