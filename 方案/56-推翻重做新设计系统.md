## 三、记忆神经元：完全重写

### 3.1 为什么必须重写

旧的 `renderers.neuron` 是 600 行 3D 渲染器：
- 多层同心环（R1=430 / R2=700 / R0=150）
- 3D 正弦起伏（`sin(t*2)`、`cos(t*1.7)`）
- 星点 / 流光 / 呼吸 / 自动旋转

**三个环的节点在 45°/135°/225°/315° 方向投影后必然重叠** —— 改参数解决不了。

### 3.2 新做法

**不动 `renderers.js` 一行，直接覆盖 `APP_RENDERERS.neuron`。**

新布局：平面放射
```
        技能(上半圈)
           │
   场景(内环) ─ 核心 ─ 场景(内环)
           │
   项目/数据源(外环)
```

### 3.3 改进前后

| 项 | 之前 | 现在 |
|---|---|---|
统计信息 | 竖排成一列，**压在画布上** | **横排胶囊**，独立 HUD 条 |
节点布局 | 3D 三环，全部挤中心 | **平面放射**，核心居中、场景内环、技能/项目外环 |
颜色 | 12 种（绿/蓝/红/青/金…） | **单一克莱因蓝 + 灰阶** |
标签 | `?`（数据读错） | **正确名称**（架构梳理/自我复盘/B站…） |
标签重叠 | 严重 | 沿「中心→节点」方向外推避让 |
背景 | 纯黑 | 径向渐变 + 极淡网格 |

### 3.4 数据读取的坑

我第一版写反了优先级：

```javascript
// 错：优先读 记忆地图.json
const areas = (map && map.areas) || (idx && idx.areas) || [];

// 对：优先读 索引.json（字段名才有 id/name）
const areas = (idx && idx.areas) || (map && map.areas) || [];
```

**索引.json 的 area**：`{id, name, owner, memory, file, panel}`
**记忆地图.json 的 area**：字段名不同

读错了就全部变成 `area-undefined` / `?`。

### 4.3 数据都是真的

| 区块 | 数据来源 |
|---|---|

主控会话 | 真实的 `harness` webview（连 3080 引擎） |
派发 | **`session/prompt` RPC**（不是假的注入） |

### 4.4 派单实现的关键修正

我第一版用错了 API：

```javascript
// 错：injectHarnessPanel(webContentsId, pinTarget)
//     这是"钉住会话"用的，参数是 webContentsId，不能派单
window.app.injectHarnessPanel({ sessionId, text })

// 对：走引擎的 session/prompt RPC
fetch(base + '/api/session/prompt', {
  body: JSON.stringify({
    type: 'client-request',
    method: 'session/prompt',
    payload: { args: { request: { sessionId, content: [{type:'text', text}] } } }
  })
})
```

### 4.5 布局对齐

实测数据：
```
主 Agent 面板     x=1256  宽 280
场景区右边界       1256px   ← 正好相等，不重叠
```

**试过两套失败方案：**
- ✗ `margin-right` → 压缩内部布局，导致文字竖排
- ✗ `padding-right` → 子元素 `width:100%` 时无效，面板盖住内容
- ✅ `width: calc(100% - 280px)` → 精确让位

## 五、踩到的坑（都记进代码注释了）

### 5.1 不要靠猜 DOM 结构写 CSS

我犯的错：看到「架构梳理」竖排，就以为是行容器方向错了，
直接把 `sf-board` 的 div 改成 `flex-direction:column`，
结果把原本 5 个节点的横向列表搞成 2 个卡片。

**正确做法**：读 `sf-board-panel.js` 第 109-125 行，看清 `row` 本来就是 `display:flex` 横向，
只需要保证内部 span 不被压窄。

### 5.2 竖排的真正原因永远是「被压窄」

实测：`SPAN 22x88 "架构梳理：汇总裁判"`
宽度只有 22px，中文每字换行 → 看起来像竖排。

**不是 `writing-mode` 问题，是 flex 里没有 `min-width` 被挤扁了。**
