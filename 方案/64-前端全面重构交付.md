## 三、核心功能：主 Agent + 3D 神经元联动

### 3.1 用户的原始需求（逐字）

> 「我在与你对话的过程中，其实你是作为一个项目经理或是管理层的身份，
> 我与你交付完我的需求之后，你需要连接上对应的场景也就是记忆神经元，
> 然而这些记忆神经元也会随之亮起，**所以这也就是为什么要做成 3D 形式的了**」

### 3.2 3D 实现方案

```
                     ┌──────────┐
                     │  场景层   │  球半径 1.0，11 个节点
                     │  (外球)   │  Fibonacci 球面均匀分布
                     └────┬─────┘
                          │
                    ┌─────┴─────┐
                    │  记忆层    │  球半径 0.42，11 个节点
                    │  (内球)    │
                    └─────┬─────┘
                          │
                      ┌───┴───┐
                      │ 核心   │  shell=0，圆心
                      │ DSH   │  半径 18
                      └───────┘
```

**3D 的技术要点：**

1. **欧拉角旋转**（偏航 yaw + 俯仰 pitch）
   ```javascript
   rotate3d(x, y, z, yaw, pitch) {
     x1 = x*cos(yaw) + z*sin(yaw)
     z1 = -x*sin(yaw) + z*cos(yaw)
     y1 = y*cos(pitch) - z1*sin(pitch)
     z2 = y*sin(pitch) + z1*cos(pitch)
   }
   ```

2. **透视投影**（近大远小）
   ```javascript
   project(p, cx, cy, camDist, fov) {
     denom = fov / (fov + camDist - p.z)
     sx = cx + p.x * denom
     sy = cy + p.y * denom
     scale = denom          // z 越大 → denom 越大 → 节点越大
     depth = p.z
   }
   ```

3. **深度影响透明度**：`alpha = 0.38 + 0.62 * depth01`

4. **按 depth 排序绘制**：远的先画，近的后画（正确的遮挡关系）

5. **点亮动画**：`glow = 8 + 14 * pulse`，脉冲 `sin(t * 3.2)`

### 3.3 联动链路（实测通过）

```
主 Agent 点击「派发」
   ↓
lightNeuron(sceneId, true)          ← 立刻点亮，不等结果
   ↓
window.__NEURON3D[0].lightScene()   ← 场景节点 + 记忆节点一起亮
   ↓
api.util.dispatch(sessionId, text)  ← 走 engine.prompt
   ↓
主进程 → 拿 cookie → POST session/prompt
   ↓
引擎执行（asOfSeq 增加）
   ↓
轮询 session/list 检测完成
   ↓
lightNeuron(sceneId, false)         ← 熄灭
```

## 五、dsh-TUI 嵌入

### 5.1 三个根因（全部实测定位）

**① Electron-as-Node 的 stdin 没有 setRawMode**

```
系统 node + PTY:      stdin.isTTY=true   setRawMode=function   ✓
Electron-as-node:     stdin.isTTY=undefined  setRawMode=undefined  ✗
→ Ink 报 "Raw mode is not supported"
```

**② cli.js 在 app.asar 里，普通 node 读不了**

```
require('...app.asar/.../cli.js') → MODULE_NOT_FOUND
→ 用 @electron/asar 解包到 外壳/_asar/
```

**③ session-mounts.json 里有死进程残留**

```json
{"owners": [{"pid": 4688, ...}]}   ← 4688 已死但记录还在
→ "already owned by an active write handle"
```

### 5.2 最终链路

```
xterm.js（渲染 ANSI）
  ↓ IPC
node-pty（真实 PTY，conpty 后端）
  ↓
真 node.exe（不是 Electron）
  ↓
_asar 解包后的 cli.js
  ↓
dsh-tui profile
  ↓
像素鲸鱼界面 ✓
```

## 七、本轮修复的真实 bug（全部有实测证据）

| # | bug | 根因 | 证据 |
|---|---|---|---|
1 | 面板显示"未知面板类型" | 渲染器注册晚于场景渲染 | 手动 render 成功但 DOM 是降级卡 |

7 | 3D 位置抖动 | 每次迭代 `Math.random()` | 改为确定性 Fibonacci 球 |

### 9.4 写入冲突

- tokens.css 用 `--color-*`
- layout.css/components.css 用 `--s0/--t1`

**教训**：并行开发必须先约定文件边界，且**一个目录只能有一个写者**。
