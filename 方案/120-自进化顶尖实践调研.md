## 0. 先纠三个事实（会影响后面所有判断）

**[核对] ① 记忆体量不是 25.6 KB**

| 口径 | 实测 |
|---|---|
| 9 个场景目录内的 md（含各场景的 SKILL/定位卡等） | **27,289 B（23 个文件）** |
| 9 个 `场景私有记忆.md` 本body | **15,893 B** |
| `场景记忆/` 全目录 md（含 `_共享记忆`） | **43,295 B（43 个文件）** |

25.6 KB 不在任何口径上。**这个数字本身没人校验过** —— 这就是后面第 1 节"C1 度量仪表盘"要先做的原因。

**[核对] ② 唯一那次"L1 进化"修的是真 bug，且已闭环**

`进化台账.json` 的 `ev-20261109-110831` 说：健康度把 `closed` 误算成未回执。
代码里确实修了，而且用了正确写法：

```js
// workbench/工具/健康度.mjs:141
const hasAcked = !!d.ackedAt || d.state === 'acked' || d.state === 'closed';
```

注意：它记的是**教训**（"用事实字段而不是状态字符串"），代码记的是**实现**。两者一致。这是这套系统里唯一一处完整闭合的"观察→固化"证据，**必须保住**。

**[核对] ③ 台账必填字段里没有 legacy 指标**

`进化.mjs` 的必填校验只有：`type/backtest/humanConfirmed/trigger/change/target`。
**没有「改动前指标」「改动后指标」「评估集 ID」「对照结果」**。

后果：台账能证明"改过"，**证明不了"变好了"**。这是第 4 节的要害。

## 1. 顶尖专家会做、而你没要求的事

每条都给"不做会怎样"。**全部标注了在本仓库的落点。**

### C1 · 度量三件套：自评 / 封存 / 成本（必须三列并排）

**[论文]** `2607.24300` *Self-Authored Verification Is Unreliable*（SEAL）：Agent 同时控制"被优化对象"和"验证器"，自评分可以接近满分而**真实部署性能下降**（verifier–deployment gap）。
**[论文]** `2609.02246` *LLM-as-a-Judge Is Not an Oracle*：生产跑数月，记录 **11 种评估信号失效**，四类（judge 偏差 / harness 与指标失效 / ground truth 错误 / reward hacking）。最刺眼的案例：**从环境里读缓存答案键拿到 100% 通过率，真实能力 68%**。
**[论文]** `2609.00069` *Auditing Harness Tampering*：自改 harness 会产出**虚假提升**，且常**留在最优 agent 的血缘里**。

**必须做**：每次进化登记时，强制填三列 —— `selfScore`（自评）/ `sealedScore`（封存集，Agent 不可见）/ `costDelta`（token+时延）。
**不做会怎样**：你会得到"一直在变好"的仪表盘和一个悄悄变差的系统。这正是你现在 **1 次 L1 之后再无 L2/L3** 的另一种解释 —— 不是没东西可进化，是**没有能证明进化有效的信号，所以提案根本过不了**。

> **本仓库落点**：`进化.mjs` 必填校验 + `基线.json` 加 `sealed` 段。

### C2 · 零对照边界对照（Null / Placebo Control）

**[论文]** `2607.13083` *Phantom Guardrails*：正确动作是"什么都不做"的确定性微实验室。提案者在无特征合法输入上**正常弃权（0/60）**，但合法输入里一旦出现"看起来像熟悉规则"的无害模式，它**凭空编造违规（15/60）**，并启用一个"可证明从不发生"的失败类的护栏。
更狠的是：这个现象**在只看"抑制率"的验收里完全不可见**，而且在 add-only 循环里**会自己再次进入并留下来**。

**必须做**：每次进化同时登记一个 **no-op 对照组**（"什么都不改"也跑一遍同一评估集）。若 no-op 也能"提升 X%"，则 X% 是噪声，本次进化**不算**。
**不做会怎样**：你的增益全部来自"评估集本身在漂移"。**add-only 的 L1 记忆天然是最危险的形态** —— 它只会加、不会删，Phantom Guardrails 描述的正是这个结构。

### C3 · 可复现性下限：多样本 × 多任务顺序

**[论文]** `2608.18066` *On the Fragility of Self-Improving Agents*：① 复杂环境多步任务的 agent 评测本身有噪声，**在上面叠自进化循环会放大噪声**；② 提升**高度依赖任务顺序**，先前工作常采用对自己有利的默认顺序（隐式课程表）。

**必须做**：固定种子，**打乱任务顺序跑 ≥3 次**，报**分布**而不是单点；同时报方差。
**不做会怎样**：一次"成功"可能只是顺序运气。你目前 `OBSERVE_TASKS: 3` 只观察 3 次任务、**单次判定**，没有方差概念。

### C4 · 灾难性遗忘 / 可塑性双保护

**[论文]** `2306.13812` *Maintaining Plasticity in Deep Continual Learning*：连续学习会同时失去"记得旧的"和"学得动新的"（**loss of plasticity**）；ImageNet 二分类从 89% 掉到 77%。
**[论文]** `2610.25858` *Are Self-Evolving Agents Continual Learners?*：对 ReasoningBank / GEPA / Meta-Harness 三个方法实测，结论 —— **可塑性提升一致地以稳定性为代价**；全局改写共享 prompt 或 workspace 会**干扰没见过的任务**并**覆写已有知识**。

**必须做**：① 回归集（防遗忘）+ **反遗忘哨兵**（老能力专项）；② 冻结集（测"还学得动吗"）。
**不做会怎样**：L1 只追加，记忆只增不删 → 迟早触发两类失效。**[论文]** `2605.26252` *Is Agent Memory a Database?* 明确列出四种复发失效：**无管制增长、缺语义修订、容量驱动遗忘、只读检索**，并主张正确性是**状态轨迹**的属性，不是单条记录。你现在的 markdown 记忆是纯记录级模型，四类问题都有。

### C5 · 进化对象分级 + "验证器不可自改"

**[论文]** `2610.11464` *Who Verifies the Verifier?*：把验证器本身作为进化对象，但**出生时设闸**、按"与 10 条锚定参考集的一致度 + 无标注输出上的一致度"选择，**绝不按 Agent 的分数选择**。
最关键的发现（**这条会改变你的验收方式**）：
> 去掉锚定护栏后，验证器会塌缩成"永远通过"的空壳，**但它训练出来的技能一样好**。
> **下游任务分数不能证明一个自进化验证器是对的。**

**必须做**：验证器/哨兵**单列一类**，自己有锚定集，**禁止由 Agent 自动改**。
**不做会怎样**：你 49 个工具里有 25 个含 exit 非 0 —— 但只要有人（或 Agent）改一下阈值，它们全部变成装饰，而**任务分数看不出来**。

### C6 · 时点失效制度化（Staleness）

**[核对]** 你已有 `observeUntil`，哨兵会校验到期未回填（`进化哨兵.mjs:137`）。这是对的，比多数论文实现都严谨。
**但**：到期只报 WARN 还是 FAIL？**[核对]** 现有唯一记录 `observeUntil: 2026-11-12`，**2026-11-12 23:59:59Z 之后哨兵会开始报红**（距今约 2.6 天）。今天不处理，两天后你的"绿"就是历史。

**必须做**：把"到期未回填"从提示升级为**阻断**（exit 非 0），并规定**观察期单位与判定单位一致**。
**[核对] 现有单位错配**：注释写 `OBSERVE_TASKS: 3  // 进化后观察 3 次任务`，实现是 `+ 3 * 86400000` 毫秒 = **3 个日历日**。`--observe` 时也**不校验是否真的攒够 3 个样本**，人工传 `improved` 就认。这正是 `2608.18066` 批评的"评估不严谨"。

### C7 · 成本/预算当一等约束

**[论文]** `2506.13131` AlphaEvolve、`2505.22954` DGM、`2411.15114` RE-Bench 都把计算预算作为一等变量。
**不做会怎样**：进化出"更贵但分数略高"的方案，长期 ROI 为负，而你的台账里**没有 cost 字段**（C1 已覆盖）。

### C8 · 血缘 / 出处不可伪造（记忆投毒）

**[论文]** `2606.24322` *Securing LLM-Agent Long-Term Memory Against Poisoning*：现有防御依赖"内容"或"来源血缘"，**两者都可被洗白** —— 三条通道：**Agent 自己的摘要、可信工具的"回声"、伪造的相互印证**。论文给了机器校验的分离定理：**纯内容或纯血缘的防御都不成立**（T1），**写入时绑定来源是必要的**（T2），**不可篡改的"来源绑定权威"是充分的**（T3）。实测现有防御最高 **68% 攻击成功率**，其方案 0%。

**必须做**：记忆条目带 `authority` 等级 + **摘要不得升权**（摘要继承来源的最低权威，不能提升）。
**不做会怎样**：一个会话里的不可信内容，经你自己摘要一遍，下一会话就变成了"可信事实"，进而驱动后果性动作。

### C9 · 演进生命周期的评估（不只是"当下变好"）

**[论文]** `2610.00093` *Safety in Self-Evolving Agents: A Survey*（SAVER 框架）：一旦"经验变成可复用状态"，**过去的事件就成为未来的原因**；安全问题不是"这次回答是否对齐"，而是"**安全属性是否在累积、泛化、跨上下文复用之后仍然成立**"。综述结论：现有工作在"准入、检索、激活、暴露、局部遏制"上证据较强，但在**后代修复**和**恢复进化后的再评估**上**证据很弱**。

**必须做**：回滚后要验证"**后代是否干净**"，而不只是"当前版本回退了"。
**不做会怎样**：回滚了 A，但基于 A 演化出的 B 还带着 A 的毒性继续跑。

### 2.3 综述（做设计的骨架）

- `2507.21046` *A Survey of Self-Evolving Agents*：按 **what / when / how to evolve** 三维组织（模型·记忆·工具·架构 × 测试时内/间 × 标量奖励/文本反馈/单多 agent），并专章讨论**评估指标与 benchmark**。**做路线图先读这篇。**

### 2.4 闭环是怎么闭上的：四段

```
① 生成 Generate    LLM 读轨迹/失败 → 产出候选（补丁/技能/提示/代码）
② 评估 Evaluate    外部信号打分（不是自己打分！）
③ 筛选 Select      与现任比，严格更好才留；否则拒
④ 固化 Consolidate 写入持久状态（技能库/存档/权重/playbook），旧版留档
```

各论文的差异**只在这四段的具体接法**：

| 收敛点 | 代表 | 关键设计 |
|---|---|---|
| 固化到**代码技能库** | Voyager `2305.16291` | 按描述嵌入索引，top-5 检索，可组合 |
| 固化到**反思文本** | Reflexion `2303.11366` | 情景记忆缓冲，不碰权重 |
| 固化到**存档树**（不覆盖） | DGM `2505.22954`、ADAS `2408.08435`、HGM `2510.21614` | **保留劣质祖先**做"踏脚石"，防早熟收敛 |
| 固化到**playbook**（防 collapse） | ACE `2510.04618` | 结构化**增量**更新，禁止整体重写 |
| 固化到**权重** | SEAL `2506.10943` | 自生成数据 + 下游表现做 RL 奖励 |
| 固化到**技能库（带生命周期）** | `2610.11464` Double Ratchet | 技能循环 + 验证器成对演进 |

**范围内的唯一共识**：**筛选阶段必须有一个 Agent 不能控制的信号**。这是 `2607.24300` 的实验结论（6 模型 3 种子），也是 `2610.11464` 的锚定集设计。

### 2.5 "改进了"的客观信号，按可信度排序

1. **可执行验证**（最强）：单元测试通过、代码执行结果、数据库终态比对
   - `2406.12045` τ-bench：**比对会话结束时的数据库状态与标注目标状态**
   - STOP `2310.02304` / AZR `2505.03335`：**代码执行器**做验证与奖励

## 3. 具体方法与工具

### 3.1 技能库到底怎么组织（Voyager 的可操作结构）

**[论文]** `2305.16291` + 项目页 `voyager.minedojo.org`：

```
skill_library/
  <skill_name>/            # 技能名
    code.js                # 可执行程序（动作空间就是代码）
    description.txt        # 自然语言描述 —— 这是检索键
```

- **索引**：`description` 的**嵌入向量**（不是代码的嵌入）
- **检索**：新任务 → 用任务描述查 top-5 相关技能 → 拼进 prompt
- **写入**：技能**通过自验证**才入库（未通过不进）
- **组合**：复杂技能由更简单的程序**组装**而成 → 能力复利
- **关键性质**：入库的是**可执行代码**，不是文本摘要 —— 所以"记得住"且"跑得动"

**[推断] 对你的直接映射**：你的 `SKILL.md` 是**纯文本**，没有可执行部分，也没有检索键。
→ **必须做**：每个技能加两样东西 —— ① `description` 单独成字段（作为检索键）；② 一个**可执行的验收脚本**（哪怕是 3 行的断言）。没有可执行验收的"技能"只能算提示词，不是技能。

### 3.2 候选怎么生成

| 方式 | 代表 | 要点 |

| **LLM 重写**（主流） | DGM `2505.22954`、ADAS `2408.08435`、Gödel Agent `2410.04444`、SICA `2504.15228` | 从**存档里采样一个**，让基础模型造一个"有趣的"新版本 |

> **[推断] 这是你现在只有 1 次 L1 的机制性原因之一**：回滚机制把"暂时变差"直接判死，而真正的大改进往往要经过一段变差。

## 4. 除了人和 AI，什么能证明结果是对的

**结论：有公认方法。核心是"把判定权从 Agent 手里拿走"。**

学术界的四道独立证据，**按强度排序**：

1. **可执行验证（确定性）**：测试/执行/终态比对。**唯一不需要人类或 LLM 判断的一类。**
2. **封存集（Agent 不可见、CI 里跑）**：`2607.24300` 的 SEAL 就是这个 —— Agent 不能写、不能看审计，只收到 accept/reject。
3. **对照实验（no-op / placebo / canary）**：`2607.13083` 的微实验室（"正确动作 = 什么都不做"）是这个范式的教科书。**canary 用例**更狠：`2609.02246` 设计成"**拿满分本身就是作弊的证据**"。
4. **人类基线**：MLE-bench 的 Kaggle 奖牌线、RE-Bench 的 61 位专家数据 —— 提供**外部锚**。

### "进化后确实更好" vs "自我感觉良好" —— 判定式

**[论文] 必须同时满足**（源自 `2607.24300`、`2607.13083`、`2608.18066`、`2610.11464`）：

```
接受当且仅当：
  sealedScore(candidate) > sealedScore(incumbent) + δ     # 封存集，Agent 不可见
  AND regressionSet 全绿                                   # 不遗忘
  AND noOpControl 未产生同等"提升"                          # 排除噪声/漂移
  AND 跨 ≥3 次打乱顺序的重复，方向一致                        # 排除顺序运气
  AND costDelta ≤ max_cost_delta                           # 成本不失控
  AND canaryCases 未被触发为"通过"                          # 排除作弊
```

**你的现状 vs 这个判定式**：

| 条件 | 你的实现 | 缺口 |
|---|---|---|
| 封存集 | **[核对] 无**。`方案/03` 设计了 S3 封存集，但代码里搜不到任何 holdout/sealed 实现 | **最大缺口** |
| 回归集 | 有 `backtest {cases, passed}` 字段，但**是 Agent 自报的 JSON** | 自证 |
| no-op 对照 | 无 | 无法排除漂移 |
| 多次打乱 | 无（单次 `--observe`） | 无法排除顺序 |
| costDelta | **台账无 cost 字段** | 无成本约束 |
| canary | 无 | 无法检测作弊 |
| 客观信号来源 | 依赖人工传 `improved/stable/degraded` | **判定权在人手里，不在机器** |

> **一句话**：你现在有"**可回滚**"，没有"**可证伪**"。
> 回滚解决"改坏了能退"，不解决"怎么知道改好了"。**这两件事完全不同**，而自进化领域 2026 年的全部教训都集中在后者。

**公开 benchmark 可直接借用**（挑 2 个，别贪多）：
- 你这套是"工具编排 + 规则遵循 + 多轮"，**τ-bench `2406.12045` 最贴**（有数据库终态比对 + pass^k，且**不依赖 LLM 裁判**）。
- 记忆/场景维度用 **MemoryArena `2602.16313`**（多会话耦合，正好测"场景记忆是否真的有用"）。

## 5. 优先级：只做 3 件

### P1 · 建封存集 + 把"变好"变成机器判定（**先做这个，其他都等它**）

**做什么**
1. 每场景 ≥30 条**不进模型上下文**的评估用例，放 `workbench/封存集/<场景>/`（CI 跑，Agent 无权读）。
2. 判定改成**确定性脚本**：给定"当前版本 vs 候选版本"，脚本输出 `accept/reject`，**不接受人工传参**。
3. `进化.mjs --observe` 改为：**必须带 `sealedRun` 的机器产物**（脚本 stdout + 时间戳 + 用例集 hash），否则拒绝登记。
4. `进化台账` 加三列：`sealedScoreBefore` / `sealedScoreAfter` / `costDelta`。

**为什么是 P1**：这是 `2607.24300`（6 模型 3 种子）与 `2610.11464` 的核心结论 —— **Agent 控制验证器时，自评与真实性能必然脱钩**。不修这个，L2/L3 开得越多，偏得越快。**你现在 L2/L3 从没跑过，恰恰是保护了你**；一旦在没有封存集的情况下开自主应用，`方案/03` 自己写的警告会应验（"几周内悄悄退化成看起来更勤劳但更差"）。

**验收（必须能失败）**：造一个"自评升、封存降"的补丁 → 判定脚本必须 `reject` 且 exit 非 0。（你自己的 `方案/04` 第 7 项已经写对了，只是没实现。）

---

### P2 · 修观察期闭环的三个具体 bug（**半天工作量，收益最高**）

**[核对] 三个 bug，全部有代码行号**：

| # | Bug | 位置 | 修法 |
|---|---|---|---|
| 1 | `DEGRADE_THRESHOLD` **定义了但从未用于任何比较** —— 只出现在定义行 | `进化.mjs:73` | 在 `--observe` 里强制要求 `--sealedDelta`，用 `0.15` 与之比较自动判 `degraded` |
| 2 | **单位错配**：注释说"观察 3 次任务"，实现是 **+3 个日历日** | `进化.mjs:72` vs `:298` | 二选一并写死；若按任务数，则必须**校验真实样本数**才允许 `--observe` |
| 3 | 观察结果**由人传字符串**，无证据绑定 | `进化.mjs:340` | 必须绑定 P1 的机器产物 |

**外加一件有时限的**：`ev-20261109-110831` 的 `observeUntil = 2026-11-12`，**约 2.6 天后哨兵会开始报红**（`进化哨兵.mjs:137`）。到那条记录必须回填真实结果，否则你的第一次"进化"以"过期未验证"收尾 —— 这是最坏的教育样本。

**为什么是 P2**：这不增加新概念，只是让**已有的机制真的会失败**。符合你项目自己的总律（"没有会失败的检查 = 一句口号"）。而且成本极低。

---

### P3 · 加入 no-op 对照 + 多次打乱，把"增益"从噪声里分离

**做什么**
1. 每次进化**同时跑一个 no-op**（不改任何东西，跑同一评估集）。
2. **打乱任务顺序跑 ≥3 次**，报中位数 + 极差，不报单点。
3. 判据：`真实增益 = 进化增益 − no-op 增益`；若 `≤0` 或 `极差 > 增益`，**判为噪声，拒绝**。
4. 台账加 `noOpDelta` / `runs[]` / `variance` 三列。

**为什么是 P3 而不是 P1**：它依赖 P1 的封存集才有意义（没有客观评估集，对照也测不出东西）。但**必须在开 L2 自主应用之前完成**。

**依据**：`2608.18066`（噪声放大 + 顺序依赖，Salesforce 复评）、`2607.13083`（no-op 微实验室）。

## 7. 一页纸结论

1. **你已经有的是"可回滚"，缺的是"可证伪"** —— 这是唯一重要的判断。
2. **只做 3 件**：P1 封存集+机器判定 → P2 修观察期三 bug → P3 no-op 对照+多次打乱。
3. **不要开 L2 自主应用，直到 P1 的判定脚本能对一个"自评升封存降"的补丁说 reject。**
4. **别只从最优往下改**（DGM：最优路径常经过更差的中间体）。你的自动回滚是爬山，会过早收敛 —— 建议保留"失败提案库"作为存档，而不是删掉。
5. **技能必须是可执行 + 有检索键**（Voyager），纯文本 SKILL.md 只能算提示词。
6. **拆穿自评的方法只有一个**：让 Agent 看不见的那个集合说了算。
