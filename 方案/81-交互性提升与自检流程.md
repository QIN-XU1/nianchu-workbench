## 二、按三点要求做的实现

### 2.1 星点随机出现并闪亮（要求①）

参考 particles.js 的 `move.out_mode: "out"` + `opacity.anim`：

```js
function makeStar(W, H) {
  return {
    x, y,                                        // 归一化坐标
    vx, vy,                                      // 速度（会移动）
    baseA,                                       // 基础亮度
    r0,                                          // 基准半径（不变）
    twSpeed, twPhase,                            // 闪烁频率/相位
    life: Math.random(),                         // 生命周期
    lifeSpeed: 0.0014~0.0046,                    // 周期 3~12 秒
  };
}

function updateStars() {
  // 移动
  s.x += s.vx * dt * 60;

  // 移出边界 → 从另一侧进入
  if (s.x > 1.02) s.x = -0.02;

  // 生命周期结束 → **随机新位置重生**
  if (s.life > 1) { s.life = 0; s.x = Math.random(); s.y = Math.random(); }

  // 亮度 = 基础 × 闪烁 × 生命周期曲线
  s.a = s.baseA * tw * (0.55 + 0.45 * lifeCurve);
}
```

**关键：不是"固定位置闪烁"，而是真的在移动 + 随机重生。**

### 2.2 节点团与背景互动（要求②）

三层互动：

```
① 鼠标附近：星点被吸引 + 变亮 + 连线（grab 模式）
② 节点周围：引力场（星点被捕获，绕节点聚集）
③ 节点点亮：冲击波（推开星点）
```

代码：
```js
// 层 2：节点引力场
for (const np of S.nodeScreenPos) {
  const GR = np.r + 0.032;                    // 引力半径
  if (d2 < GR * GR) {
    const k = 1 - Math.sqrt(d2) / GR;
    const strength = np.lit ? 1.5 : 0.65;     // 点亮节点引力更强
    a = Math.min(1, a + k * 0.45 * strength);
    s.x -= dx * k * 0.0014 * strength;        // 向节点靠拢
  }
}

// 层 3：点亮节点的冲击波
const WR = 0.14 + ln.wave * 0.20;             // 波半径随时间扩大
if (d2 < WR * WR) {
  s.x += (dx/d) * k * 0.0018;                 // 推开
}
```

**这实现了"背景不再是背景"。**

## 三、自检流程（用户明确要求）

### 3.1 我建立了三类自检

**类型 A：代码逻辑自检（运行时前）**
```python
# 检查持久累加的 bug
re.findall(r's\.r\s*=\s*Math\.max', t)          # 应为 0

# 检查重复定义
seg.count("r0:")                                 # 应为 1

# 检查花括号平衡
t.count("{") == t.count("}")

# 检查调用次数
t.count('S.labelRects.push')                     # 应为 1
```

**类型 B：数学自检（模拟计算）**
```python
# 模拟 1000 颗星的最终亮度
baseA = random() * 0.30 + 0.16
final = baseA * (0.55 + 0.45*random.uniform(-1,1)) * (0.55 + 0.45*random.uniform(0,1))
# 结果：均值 0.134，0/1000 低于阈值
```

**类型 C：运行时自检（CDP 查询真实状态）**
```javascript
starCount, visibleStars, avgA, avgR, maxR
// r0=0 时: avgR=0 → 星点不可见 → 立刻发现
```

### 3.2 自检抓出的 4 个真实 bug

| # | Bug | 自检方式 | 后果 |
|---|---|---|---|
1 | `s.r = Math.max(s.r, s.r*1.85)` | 代码扫描 | **指数增长，60帧后半径 10^15 → 全屏白** |
2 | `r0` 重复定义（后者为 0） | 运行时查询 `avgR` | **r=0 → 星点全不可见** |
3 | 旧标签代码残留 | 运行时截图 + 代码扫描 | 标签画两遍 → **严重重叠** |
4 | 删除时漏掉 `if {}` 闭合括号 | `node --check` + 花括号计数 | **neuron 模块加载失败 → "未知面板类型"** |

**这 4 个 bug 全部是通过自检发现的，不是我"凭感觉"发现的。**

## 五、诚实的反思

实际情况：
- 改参数 → 重启 → 截图 → 发现问题 → 再改 → 再重启

**根本原因：我没有把"逻辑正确性"和"视觉正确性"分开验证。**

```
① 改代码
② 代码逻辑自检（静态扫描：重复定义/持久累加/括号平衡/调用次数）

⑦ 截图验证（视觉）
```

**这次严格按这个流程，立刻抓出了 4 个 bug，其中 2 个是"看不出原因"的（r0=0、括号缺失）。**
