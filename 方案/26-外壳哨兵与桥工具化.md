## 1. L0 外壳哨兵

### 1.1 照 luanyujia 的两条硬规矩

> ① **根目录白名单制**：`<工作区>` 根不许丢文件；顶层新夹子先问机主
> ② **临时文件只放两处**：大体积/一次性 → `_临时/`；⛔ `%TEMP%` / C 盘不再接受

**为什么需要"哨兵"而不是"写进文档"**：
> 规矩写在文档里，AI 会忘；落成检查器，违规就 exit 1 —— **这才叫自动**。

### 1.2 实现

| 能力 | 判据 |
|---|---|
根目录目录白名单 | 只允许 `prototype/plugins/research/verification/challenges/方案/boards/collab/would-do/_临时` |
根目录文件白名单 | 只允许 `README.md/.gitignore/package.json` + 配置类 |
守卫 `guard(path)` | 写前判断：C 盘拒 / %TEMP% 拒 / 根目录散文件拒 / 临时文件位置错拒 |

### 1.3 自检 8/8

```
✓ 根目录放文件被拒         ⛔ 根目录不许丢文件「random.txt」
✓ 白名单文件允许           白名单文件
✓ 临时区允许临时文件        允许
✓ 非临时区临时文件被拒       ⛔ 临时文件应放 _临时/
✓ C 盘被拒               ⛔ C 盘不接受
✓ %TEMP% 被拒            ⛔ C 盘不接受
✓ 正常子目录允许           允许
✓ 真实根目录合规           6 项全在白名单
```

**注意最后一条**：它检查的是**真实项目根目录**，当前 6 项全在白名单内。

## 2. 桥工具化（三重门控）

### 2.1 之前的缺口

桥能跑（4.8 秒、答案干净），但**场景不会调它** —— 它只是个独立脚本。

现在变成统一入口：`askViaBridge()`。

### 2.2 三重门控（顺序很重要）

```
① 开关检查（默认关）
     ↓
② 机密闸（密码/token/身份证/银行卡/手机号 → 拒发）
     ↓
③ 授权模式（off / observe / auto）
     ↓
④ 真发（仅 auto 模式）
```

**为什么顺序是 ①②③④**：
- 开关在最前：不花钱
- 机密闸在发送之前：**一旦发出去收不回来**
- 授权模式在真发之前：这是 superagent 的"权限由宿主强制"

### 2.3 自检 5/5

```
✓ 桥关闭时拒绝              code=CAPABILITY_OFF
✓ 机密内容被拒              code=SECRET_BLOCKED hit=true
✓ observe 只记录不真发        code=OBSERVED recorded=true
✓ off 模式拒绝外部调用        code=MODE_OFF
✓ auto + dryRun 不真发       code=DRY_RUN
```

**`observe` 的实际表现**：
```
observe 模式：已记录"它会问什么"，但**没有真的发出去**
  它会问：用一句话说明什么是测试
  改模式：node prototype/auth.mjs set auto
```

## 3. 自检卫生（本轮最有价值的部分）

### 3.1 问题：测试互相污染

回归时发现一个**严重的工程问题**：

| 现象 | 根因 |
|---|---|
首屏从 2 行变 4 行（U4 失败） | collab/boards/ask 自检留下测试数据 |
新能力从 15/15 掉到 14/15 | auth 自检留下 `global: auto` |
幂等性失败（第 1 次 15/15，第 2 次 14/15） | 同上 |

### 3.2 为什么这比功能 bug 更严重

> **测试不可信 = 所有验证都不可信。**
> 一个"有时通过有时失败"的测试，比没有测试更坏 —— 它会让人怀疑真实结果。

### 3.3 四层修复

| 层次 | 修法 |
|---|---|
① **模块自清理** | `hygiene.mjs` 提供 `snapshotDir/snapshotDirs`，自检前后包裹 |
② **单文件显式备份** | `capabilities.json` / `auth-mode.json` 是单文件，`snapshotDir` 不处理 ⇒ 显式读写 |
③ **自检自建干净现场** | auth 自检**开始时就重置**为 observe，不假设现场干净 |
④ **无条件恢复默认** | auth 自检结束时**无条件**写回 `observe`，不"恢复原值"（原值可能已污染） |

### 3.4 幂等性检查器

新增 `idempotent-test.mjs`：连跑两轮，逐项比较结果 + 检查残留状态。

```
=== 幂等性检查 ===
第 1 轮：boards=5/5 collab=5/5 auth=6/6 inject=8/8 induct=8/8 shell=8/8 ask=5/5
第 2 轮：boards=5/5 collab=5/5 auth=6/6 inject=8/8 induct=8/8 shell=8/8 ask=5/5

✓ boards     第1轮=5/5 第2轮=5/5
✓ collab     第1轮=5/5 第2轮=5/5
✓ auth       第1轮=6/6 第2轮=6/6
...

=== 跑完后残留状态 ===
  capabilities: 正常
  auth: observe
  boards: (无)
  collab: (无)
  would-do: (无)

===== 幂等性：通过 =====
```

### 3.5 诊断过程（值得记录）

用二分法定位污染源：

```
起点 auth: observe
跑完 boards   → auth=observe   ✓
跑完 collab   → auth=observe   ✓
跑完 auth     → auth=observe   ✓
跑完 inject   → auth=observe   ✓
跑完 induct   → auth=observe   ✓
跑完 shell    → auth=observe   ✓
跑完 ask      → auth=auto      ✗  ← 找到污染源
```

**这种"逐套件追踪状态"的诊断方式，比读代码猜快得多。**
