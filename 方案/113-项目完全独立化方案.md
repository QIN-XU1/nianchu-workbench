## 四、技术方案

### 4.1 引擎启动方式（已验证可行）

```js
// 外壳/main.js
const nodeExe = path.join(ENGINE_DIR, 'node.exe');        // 自带 Node
const cliJs   = path.join(ENGINE_DIR, 'node_modules',
                          '@deepseek-ai', 'dsh-desktop-host', 'lib', 'cli.js');

spawn(nodeExe, [cliJs, 'web', '--no-open', '--port', PORT], {
  cwd: ENGINE_DIR,
  env: {
    ...process.env,
    DSH_HOME: path.join(DATA_DIR, '.dsh'),   // 数据目录
  },
});
// 从 stdout 抓 token：
// dsh web: http://127.0.0.1:31582/?token=xxx
```

**这个流程之前已经验证通过**（在 `_standalone` 实验里跑通过，后来删了）。

### 4.2 关键约束（都踩过坑）

| 约束 | 原因 |
|---|---|
**必须用真 node.exe，不能用 Electron 当 Node** | 引擎有运行时指纹检查，检测到 Electron 会拒绝启动 |
**必须设 DSH_HOME 指向数据目录** | 否则数据落在引擎目录里，升级会丢 |
**ELECTRON_RUN_AS_NODE 必须清空** | 否则 electron 以纯 Node 运行，起不了窗口 |
**路径含空格必须加引号** | `D:\file\AI Temp\...` 有空格 |

### 4.3 数据迁移

```
workbench/引擎数据/.dsh/       → 数据/.dsh/
workbench/引擎数据/.dsh-tui/   → 数据/.dsh-tui/   （可选，202 MB 会话记录）
workbench/外壳/scenarios/      → 外壳/scenarios/  （9 个场景配置）
```


## 七、与 DSH 的关系

### 独立后

```
DSH Harness（可选，用来开发）
      ↓ 插件入口（可选）
   工作台（独立运行）
```

### 三种模式并存

| 模式 | 场景 |
|---|---|
**独立运行** | 双击启动，自带引擎，完全脱离 DSH |
**从 DSH 跳转** | 保留 `workbench-launcher` 插件，共享当前 DSH 引擎 |
**开发调试** | 在 DSH 里改插件（memory-neuron）看数据视图 |

**两者不冲突**：独立版用自己的引擎，跳转版借 DSH 的引擎。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
引擎指纹检查拒绝 Electron | 必须带真 node.exe（88 MB） |
数据迁移丢失 | 先备份，迁移后校验文件数 |
升级引擎覆盖数据 | 引擎/ 与 数据/ 分离 |
端口冲突 | 自动探测可用端口 |
首启动慢 | 保留现有的加载页 + 重试 |

---

## 九、我的建议

**先做第一步（清理垃圾）** —— 零风险，立省 817 MB。

**再做第二、三步（结构 + main.js）** —— 中等风险，需要改代码。

**最后才打包** —— 因为打包后调试困难。
