## 四、L3 记忆层

### 4.1 职责

会话会被换掉，记忆必须留在文件里。**这一层解决"换会话不失忆"。**

### 4.2 三层结构

```
┌─ ① 注入层（AGENTS.md）─────────────────┐
│  每轮自动注入 ⇒ 必须极短（≤2KB）         │
│  只放"不读就会白干"的铁律                 │
└────────────────────────────────────────┘
┌─ ② 私有层（场景记忆/<名>/）────────────┐
│  场景私有记忆.md（§〇 ≤4KB · 主 25KB）   │
│  开场读一次 ⇒ 换会话时它是唯一入口         │
└────────────────────────────────────────┘
┌─ ③ 共享层（_共享记忆/ 四块板）──────────┐
│  通知/待办/索引/体检                    │
│  谁需要谁读                              │
└────────────────────────────────────────┘
```

### 4.3 §〇 五小节（固定格式）

```markdown
## §〇 当前交接
### 1) 上次交接     <做了什么 + 时间>
### 2) 当前项目     <项目表：项目|记忆文件|状态|下一步>
### 3) 私有记忆变更  <YYYY-MM-DD：改了什么>
### 4) 下一步/卡点   <下一步：谁先动；卡点：无或等谁>
### 5) 全貌         <工具生成>
```

**§〇 只回答四个问题：我是谁 / 干到哪 / 下一步 / 卡在哪。**

### 4.4 体量红线

| 对象 | 红线 |
|---|---|
注入层 `AGENTS.md` | **2 KB** |
`§〇 交接` | **4 KB** |
场景记忆主文件 | **25 KB** |
项目记忆 | 8 KB |

### 4.5 关键机制：注入文本生成

```powershell
node 工具\memory.mjs --inject --scene 命令
```

输出 = 全局铁律 + 定位卡 + §〇 交接 + 待办摘要，**总预算 ≤2KB**。

### 4.6 验收

```powershell
node 工具\memory.mjs --check
```

**标准**：三层齐 + 全部红线内。

### 4.7 当前状态

✅ 完整。注入层 1.67 KB / 私有层 11/11 通过 / 共享层 4/4。

## 五、L4 协作层

### 5.1 职责

多个 AI 当同事：谁说了算、谁改哪里、怎么交活、怎么算交付。

### 5.2 四块板（各回答一个问题）

| 板 | 回答 | 更新频率 |
|---|---|---|
**通知看板** `_跨场景通知.md` | 发生了什么 | 高频（每次协作） |
**待办板** `_待办.md` | 该做什么 | 中频 |
**总索引** `索引.md` | 东西在哪 | 低频 |
**体检结果** `体检结果.json` | 机器健康吗 | 每周 |

**为什么必须分开**：更新频率差一个量级 + 读者不是同一批人。

### 5.3 防无限对话（这是血的教训）

luanyujia 的真实事故：
> 5 条帮手互发技术小论文，轮数**一夜涨到 262/224/101 轮**，
> 结局是 `Insufficient Balance (402)` —— **余额被来回对话烧光**。

**七条硬约束**：
```
1. 一次派单 = 一条回执 = 结束（≤200 字 / ≤10 行）
2. 要问就开工前一次问清，不许连环问
3. 调度方不回「收到」—— 回执单向，收到即结案
4. 帮手之间禁止互发消息
5. 见 402 立即停所有派单
6. 回执标记：【需要回执】/【不需要回执·知悉】+ 末行【结束】
7. 回执必须用工具投递，只在自己窗口打字不算回
```

### 5.4 工具

```powershell
node 工具\collab.mjs board                       # 看四块板
node 工具\collab.mjs send --to 调研 --msg "..."    # 派单（自动补标记）
node 工具\collab.mjs inbox --scene 调研            # 看收件箱
node 工具\collab.mjs check                       # 校验四块板
```

**`send` 会自动补标记并检查 200 字上限。**

### 5.5 验收

```powershell
node 工具\collab.mjs check
```

### 5.6 当前状态

✅ 完整。四块板齐备。

## 六、L5 管线层

### 6.1 职责

**场景之间传数据。** 不是留言板，是结构化产物流转。

### 6.2 三个概念

```
场景契约（sceneboard/scenes/<id>.json）
  inputs:  [需要什么产物]
  outputs: [{ id, name, to: [接收方] }]

产物（产物/<名>-<日期>-<id>.md + index.json + events.jsonl）

管线（sceneboard/pipelines/<id>.json）
  nodes: [场景清单]
  edges: [{ from, to, artifact }]   ← DAG
```

### 6.3 「造一个软件」管线

```
        ┌─→ 竞品拆解 ─→ 功能矩阵 ┐
调研 ───┤                          ├─→ 架构梳理 ─→ 实施计划
        └─→ 逆向分析 ─→ 实现细节 ─┘
             └────→ 可复用模式 ────┘
```

**调研分两路，两路都汇入架构梳理。**

### 6.4 三条设计原则

1. **产物不可变** —— 要改就发新版
2. **事件流是唯一真相** —— `index.json` 可从 `events.jsonl` 重放重建
3. **校验能发现坏数据** —— 缺文件 / 有环 / 未知场景

### 6.5 工具

```powershell
node 工具\sceneflow.mjs verify              # 校验
node 工具\sceneflow.mjs board               # 看板
node 工具\sceneflow.mjs pipe --id build-software  # 管线进度
node 工具\artifact.mjs --check              # 产物完整性
node 工具\artifact.mjs --versions           # 版本检查
node 工具\artifact.mjs --clean --go         # 清测试残留
```

### 6.6 当前状态

✅ 完整。2 个产物 · 5 条事件 · 2 条管线 · 11 个契约。

### 7.3 验证可信度的三条判据

来自 luanyujia 的血泪教训：

1. **自证必须排除被核对象** —— 否则"必然合格"
2. **必须带一个应当失败的反例** —— 否则永远通过的测试没价值
3. **结论要能说出差异集合** —— 不是只给一个 0

**我们的实现**：
- `scene-validate.mjs` 当场上抓到 2 个真 bug（CRLF 失配、缺契约）
- `artifact.mjs` 发现了 `no-such-scene` 脏数据
- `sceneflow.mjs verify` 发现了"索引与事件不一致"

## 九、唯一缺口：L2 会话绑定

### 9.1 现状

```
11 个场景的 AI 面板 sessionId 全部为空
→ 点开面板显示「引擎还没就绪」
→ 记忆文件没被 AI 读过（还是 1.1-1.6KB 骨架）
```

### 9.2 根因

建会话需要：
1. DSH 引擎在线（当前在 44401，HTTP 401）
2. **token**（只能从 GUI 启动日志里拿）
3. 调 `session/create` RPC

### 9.3 两条可行路径

**路径 A：在工作台里建（推荐）**
```
1. 启动工作台（它会 probe 引擎）
2. 在 GUI 里手动建 11 个会话（名字照 _场景身份索引.md 的会话名列）
3. 把 sessionId 抄回 scenarios/*.json
4. 跑 node 工具\scene-audit.mjs --bind 确认
```

**路径 B：用脚本建（需要 token）**
```
1. 从 server.log 拿到 token
2. node 外壳\scripts\建会话.mjs --title "<会话名>" --base http://127.0.0.1:<端口>
3. 输出最后一行就是 sessionId
```

### 9.4 已记录

`_待办.md` 已写入：
> 为 11 个场景建 AI 会话并写回 sessionId（需要 DSH 引擎在线 + token）
