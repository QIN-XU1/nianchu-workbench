## 二、发现的真正根因：`HARNESS_DIR` 指向了不存在的目录

这是本轮**最有价值的发现**。

### 2.1 现象

点了按钮有弹窗，但内容是空的或报错：

| 按钮 | 删除优化前 | 实测结果 |
|---|---|---|
`btn-skills` | "暂无技能" | 但实际有 4 个技能 |
`btn-mcp` | ⚠ 读不到配置 ENOENT | 实际上有 9 个 MCP |
`btn-tools` | "0 个工具 / 读取失败" | 实际上有 95 个工具 |

### 2.2 根因

`main.js` 第 88 行：

```js
const HARNESS_DIR = (function () {
  const sibling = path.join(path.dirname(__dirname), '引擎');   // ← 写死"引擎"
  ...
})();
```

但这个项目二次开发后，实际目录叫 **`引擎数据`**：

```
workbench/引擎          ← 缺失（原版命名）
workbench/引擎数据/.dsh  ← 存在（实际使用）
```

**后果链**：
```
HARNESS_DIR 错 → DSH_DATA_DIR 错 → SKILLS_DIR 错 → MCP 路径错
                                  → 工具清单路径错
```

### 2.3 修法

```js
const HARNESS_DIR = (function () {
  const base = path.dirname(__dirname);
  const CANDIDATES = ['引擎数据', '引擎'];   // 按优先级探测

  for (const name of CANDIDATES) {
    const dir = path.join(base, name);
    if (fs.existsSync(path.join(dir, '.dsh'))) return dir;   // 判据：有 .dsh 子目录
  }
  for (const name of CANDIDATES) {
    const dir = path.join(base, name);
    if (fs.existsSync(dir)) return dir;
  }
  return path.join(base, '引擎数据');
})();
```

### 2.4 修复效果

| 按钮 | 修复前 | 修复后 |
|---|---|---|
`btn-skills` | "暂无技能" | ✅ **4 个技能** |
`btn-mcp` | ENOENT 报错 | ✅ **9 个 MCP，可开关** |
`btn-tools` | "0 个工具" | ✅ **95 个工具** |

## 三、三个次要根因

### 3.1 `工具清单.json` 格式不匹配

原版读 `外壳/data/工具清单.json`（不存在）。
我改读 `工具/tools.json`（存在），但第一次字段名写错：

```js
// 错：{ name, tools }
groups: [{ name, tools }]

// 对（渲染器期望）：
groups: [{ title, sections: [{ title, items }] }]
```

**字段名错就显示"0 个工具"** —— 这是典型的"不看渲染器就瞎猜格式"。

### 3.2 MCP 面板路径里有未替换的占位符

```js
var FILE = '<工作台>\\引擎\\.dsh\\profiles\\web\\cordis.patch.yml';
```

`<工作台>` **从来没被替换成真实路径** ⇒ `fs.readFile` 直接 ENOENT。

修法：加 `resolveMcpFile()`，从 `location.href` 推导项目根。

### 3.3 `sf-board` 渲染器注册被覆盖

```
index.html 原顺序：
  116: renderers.js          ← 最后执行 window.APP_RENDERERS = renderers
  123: sf-board-panel.js     ← 先注册，随后被上面覆盖
```

**`renderers.js` 里一句整体赋值把外部注册冲掉了。**

修法两处：
1. 把 `sf-board-panel.js` 移到 `renderers.js` **之后**
2. 给 `renderers.js` 加保护：
```js
if (window.APP_RENDERERS) {
  for (const k in window.APP_RENDERERS) {
    if (!(k in renderers)) renderers[k] = window.APP_RENDERERS[k];
  }
}
window.APP_RENDERERS = renderers;
```

**效果**：渲染器 36 → **37**，`sf-board` 注册成功，"未知面板类型"消失。

## 四、重要方法论：区分"真问题"和"观测误差"

### 4.1 竖排问题的反复

整屏截图里 AI 面板一直显示竖排文字，我修了三次布局都无效。

**最后单独裁剪 webview 区域截图**，发现：
```
webview 内部：完全正常（水平文字，"已读"，模型名）
整屏截图：  竖排（假象）
```

**结论：整屏截图工具在 webview 区域有渲染失真，实际界面是好的。**

### 4.2 教训

> **测量方式本身可能产生假象。**
> 当"实测数据说正常"但"截图说异常"时，应该交叉验证（单独截 webview / 读 DOM 元素宽度），
> 而不是继续改代码。
