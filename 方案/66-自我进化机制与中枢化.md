# 66 · 自我进化机制 + 中枢化改造

> 用户核心要求（原话）：
> 「**当我提出了一份任务，但是没有相应场景，则必须先构建场景**」
>
> 「我既然想的是打造一个超级智能体或是agent就必然会产出**不可估量的场景以及子agent**，
> 而这些都**全权交给AI在执行任务时自行选择要调度哪些场景、场景之间如何联系**等等，
> 所以**只留一个负责交互的对话框即可**」
>
> 「每个场景都有自己的**定位卡、私有记忆、身份卡、技能**，
> 但部分场景或是全场景都会有一份**共享层**，包含宿主画像、区域表、项目清单、通知与待办、索引与台账」

## 二、核心成果：场景孵化器（自我进化的执行器）

### 2.1 一个场景 = 五件套（缺一不可）

```
① 场景契约  sceneboard/scenes/<id>.json
   role / inputs / outputs / capabilities / notDo
   → AI 判断"要不要用这个场景"的依据

② 场景定义  外壳/scenarios/<id>.json
   panels / layout
   → UI 渲染的依据

③ 身份卡    场景记忆/<中文名>/身份卡.md
   这个场景是谁 / 面板清单 / 我能做什么 / 我不做什么
   → 场景 AI 启动时读的自我认知

④ 私有记忆  场景记忆/<中文名>/场景私有记忆.md
   §〇交接（≤4KB）+ 核心职责 + 职责边界 + 坑
   → luanyujia 三层记忆的核心，场景 AI 只读自己的

⑤ 注册表    _共享记忆/索引.json 增加一条
   id / name / owner / memory / file / panel
   → 中枢查询"有哪些场景"的唯一真源
```

### 2.2 新工具

| 工具 | 作用 |
|---|---|
`工具/scene-hatch.mjs` | **场景孵化器**：从 spec 创建五件套 |
`工具/scene-bind.mjs` | **会话绑定器**：为场景建独立会话并写回 |
`工具/migrate-to-hub.mjs` | 命令 → 中枢 迁移（已完成） |

### 2.3 用法（AI 调度时用）

```powershell
# 1. 查现有场景（AI 调度前必做）
node 工具\scene-hatch.mjs --list

# 2. 没有合适的场景 → 先孵化
node 工具\scene-hatch.mjs --create --spec spec.json

# 3. 为新场景建独立会话
node 工具\scene-bind.mjs --scene <id>

# 4. 校验
node 工具\scene-hatch.mjs --check <id>
```

### 2.4 spec 文件格式

```json
{
  "id": "probe-hatch",
  "name": "探针孵化",
  "role": "验证场景孵化器能否从零创建完整五件套",
  "description": "...",
  "inputs": ["用户需求描述"],
  "outputs": [
    { "id": "hatch-report", "name": "孵化报告", "type": "report",
      "to": ["hub"], "format": "markdown", "schema": ["五件套清单", "校验结果"] }
  ],
  "capabilities": ["..."],
  "notDo": ["..."],
  "reason": "任务需要但场景不存在",
  "hatchedBy": "hub"
}
```

## 四、中枢化改造

### 4.1 命令 → 中枢（Hub）

| 项 | 之前 | 现在 |
|---|---|---|
场景 id | `command` | `hub` |
场景名 | 命令 | **中枢** |
记忆目录 | 场景记忆/命令 | **场景记忆/中枢** |
契约标记 | 无 | **`isHub: true`** |
排序 | 按 id | **中枢置顶** |

### 4.2 中枢的专属能力（写进契约和记忆）

```
capabilities:
  · 需求分解：把用户一句话拆成可调度的子任务
  · 场景发现：查 _共享记忆/索引.json 找到匹配的场景
  · 场景孵化：没有合适场景时，用 scene-hatch.mjs 先造场景
  · 任务派发：把子任务给对应场景的独立会话
  · 状态汇总：收集各场景结果，合成一个回答
  · 记忆写回：更新各场景 §〇 交接 + 共享层台账

notDo:
  · 不亲自做具体业务（那是场景的事）
  · 不越过场景直接改场景私有记忆
```

### 4.3 场景列表改为「注册表驱动」

**这是最关键架构改动。**

```javascript
// 之前：硬编码扫描 scenarios/*.json
//       场景数量被文件系统锁死
function listScenarios() {
  for (const f of fs.readdirSync(SCENARIOS_DIR)) { ... }
}

// 现在：优先读注册表（AI 的产物）
function listScenarios() {
  const areas = readSceneRegistry();   // 索引.json
  if (areas && areas.length) {
    return areas.sort(中枢置顶);       // 动态、无上限
  }
  // 回落目录扫描（向后兼容）
}
```

**实测：`allFromRegistry: true`，11 个场景全部来自注册表。**

## 五、三层记忆：真正用起来

### 5.1 现有结构（已完整）

```
引擎数据/.dsh/场景记忆/
├── _共享记忆/                    ← 共享层
│   ├── 索引.json                  ← ★ 场景注册表（AI 的动态真源）
│   ├── 项目.json                  ← 项目清单（宿主画像的一部分）
│   ├── 记忆地图.json               ← 数据源地图
│   ├── 体检结果.json               ← 健康检查
│   ├── areas/*.md                ← 区域明细（11 个）
│   ├── _待办.md                    ← 通知与待办
│   ├── _跨场景通知.md
│   └── 冲突.md                     ← 冲突记录
│
├── 中枢/                         ← 场景私有
│   ├── 身份卡.md                   ← 我是谁
│   ├── 场景私有记忆.md              ← §〇交接 + 中枢专属能力
│   ├── _文件索引.md                 ← 东西在哪
│   └── 归档/
│
└── <其他 10 个场景>/               ← 同样结构
```

### 5.2 三层判据（luanyujia 原文）

| 层 | 放什么 | 读取频率 | 体量上限 |
|---|---|---|---|
**注入层** | 只放"不读就会白干"的铁律 | 每轮都付 | 越短越好 |
**私有层** | §〇交接 + 身份卡 + 项目记忆 | 每场开场读一次 | §〇 ≤4KB，主文件 ≤25KB |
**共享层** | 发生了什么/该做什么/东西在哪/健康吗 | 按需查 | 无限 |

**核心判据**：「这东西**谁会读**？**多久读一次**？」

### 5.3 §〇 交接只有四个回答

```
### 1) 上次交接      <做了什么 / 结果 / 证据>
### 2) 当前项目      <表格：项目|记忆文件|状态|下一步>
### 3) 私有记忆变更  <YYYY-MM-DD：改了什么 + 为什么>
### 4) 下一步 / 卡点 <谁先动，按什么顺序 / 等谁>
### 5) 全貌         <工具生成，别手改>
```

**孵化器会自动生成这个骨架**，实测 1.52KB < 4KB 红线。

## 八、我的判断

### 8.1 这一轮真正解决了什么

**机制层面（这是关键）：**
- 场景从「硬编码的固定集合」变成「AI 可创建的动态产物」
- 创建流程从「手工改 4 个文件」变成「一条命令」
- 校验从「人肉检查」变成「工具报告」

**UI 层面：**
- 从「11 个场景标签 + 2 个对话框」变成「1 个神经元地图 + 1 个对话框」

### 8.2 还差什么才是"超级智能体"

**现在有的：**
- ✅ 场景可创建、可注册、可校验
- ✅ 每个场景有独立会话
- ✅ 每个场景有私有记忆骨架

**还缺的（这才是灵魂）：**
- ❌ **中枢 AI 真的会用这些工具**（现在还需要人工跑命令）
- ❌ **记忆真的被注入到场景会话**（现在只是文件躺在那）
- ❌ **场景之间的产物真的流转**（契约里写了 inputs/outputs，但没打通）

**下一轮要做的核心：把这三条打通。**
