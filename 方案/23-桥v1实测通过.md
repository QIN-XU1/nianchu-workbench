## 2. 我用什么做的（零依赖）

本机没有 puppeteer / playwright，但发现两个现成条件：
- **Node 24 内置 `WebSocket`**
- **Chrome 156 支持 CDP**（Chrome DevTools Protocol）

所以桥是**零依赖**的：只用 `fetch` + 内置 `WebSocket`。

```
prototype/bridge/
├── sites.json      站点薄壳（照抄 luanyujia 的字段形状）
├── cdp.mjs         极简 CDP 客户端（连接 / 求值 / 安全关闭）
├── bridge.mjs      一步问答：机密闸 → 探测 → 找页 → 输入 → 发送 → 两步等待 → 提取
└── bridge-test.mjs 7 项实测
```

**链路**：脚本 → CDP → 已登录的 Chrome 标签页 → DeepSeek 网页版 → 取回答案文本。

## 3. 六个真实 bug（全部由实测暴露，我是边跑边修）

这一轮最值钱的部分不是"做出来了"，而是**跑的过程里挖出的坑**。前五个都让桥"看起来能跑，实际不能用"。

### 坑 ①：DeepSeek 页面有 3 个 textarea

```
[0] TEXTAREA 679x34 @(305,418) val="用一句话说明什么是栈"
[1] TEXTAREA 679x34 @(305,590) val="把上一条概念翻译成英文"
[2] TEXTAREA 701x60 @(294,621) ph="给 DeepSeek 发送消息" val=""
```

`[0]` 和 `[1]` 是**历史消息的回显**（也是 textarea），只有 `[2]` 是真输入框。

**我原来的错**：取"最后一个可见 textarea"。这在某些滚动状态下会选错。

**修法**：按"像不像聊天输入框"打分：
```
有 placeholder        +10
位于页面下半部         +6
宽度 ≥400            +3
高度 30~220          +2
有内容（历史回显）      -4
```

### 坑 ②：DeepSeek 用虚拟滚动（`ds-virtual-list`）

页面 `document.body.innerText` **只有 207 字符**——旧消息被卸载了。
真实内容在 `.ds-virtual-list-visible-items` 的子元素里。

**后果**：我原来靠"页面涨 N 字"判断有没有在回答 → **永远涨不动** → 一路等到 120 秒硬超时。

**修法**：不再看整页字数，改为**按结构读消息**：
- 用户消息 class 含 `_9663006`
- AI 回答 class 含 `_4f9bf79`
- `取消 | 发送` 是生成中的按钮行，要跳过

### 坑 ③：发送按钮是文本按钮，不是几何位置

诊断显示页面上有 `<button>发送</button>` @(916,631)，"取消" 在它左边。
我原来按几何位置（输入框右下角）找，找不到。

**修法**：先按文本精确匹配"发送"，再退化到"包含发送且不含取消"，最后才用几何位置。

### 坑 ④：超短答案导致"永远判不出说完了"

DeepSeek 常回极短答案。问"把上一条翻译成英文"，它答 **"Stack"（5 个字符）**。

我原来要求 `lastAssistLen >= 8` 才算"有回答" → 5 < 8 → **永远判定不成立** → 又白等 120 秒。

**修法**：门槛降到 `>= 1`，并增加第三条规则：
```
① 不忙 + 有回答 + 静默 ≥3s
② 不忙 + 有完事标记 + 有回答 + 静默 ≥2.5s
③ 消息条数稳定 ≥3 轮 + 有回答 + 不忙   ← 应对超短答案
```

### 坑 ⑤：正则被转义吃掉

用 Python 写 JS 时，`\\n` 在正则里变成了真实换行，导致：
```
SyntaxError: Invalid regular expression: missing /
```
**修法**：不用带换行的正则，改成先 `replace(/\s/g,'')` 再 `includes`。

### 坑 ⑥：CDP 关闭太快导致 Node 崩溃

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)
```
**修法**：`close()` 改成 async，等 socket 真正 `close` 事件；CLI 退出前 drain 300ms。

## 4. 三条自检（luanyujia 明确要求的）

```
桥自检
  ✓ 未就绪时明确报错（不返回空串）  code=NOT_LOGGED_IN
    msg=DeepSeek 网页版 页面没有输入框 —— 多半是没登录。请在那个窗口手动登录一次。
  ✓ 机密闸拦截密码  拦截类型=密码/口令
  ✓ 普通文本不被误拦  放行
```

**注意第一条**：未登录时它**明确报错**，而不是返回空字符串。这是 luanyujia 反复强调的：
> "空字符串会被上层当成'AI 说没有'，然后你排查半天。"

## 5. 怎么启动（供你复现）

```powershell
cd "D:\file\AI Temp\DeepSeek\Agent自研"

# ① 启动带调试端口的 Chrome（独立 profile，不碰日常浏览器）
& "$env:LOCALAPPDATA\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 `
  --user-data-dir="$PWD\prototype\bridge\.profiles\deepseek"

# ② 在那个窗口手动登录 chat.deepseek.com（桥故意不做自动登录）

# ③ 探测
node prototype\bridge\bridge.mjs probe

# ④ 问一句
node prototype\bridge\bridge.mjs ask deepseek "用一句话解释什么是闭包"

# ⑤ 跑完整实测
node prototype\bridge\bridge-test.mjs deepseek
```

> ⚠ 注意工作目录：要在项目目录下跑，不是 `C:\Users\15282`。

## 6. 桥的真实边界（必须说清）

| 能做的 | 不能做的 |
|---|---|
一次问答、要一段文字 | ❌ 跑一百次批量（慢、易掉登录、易触发风控） |
代码推理、文字总结 | ❌ 必须准时的任务（一次 5~60 秒） |
省 API token | ❌ 并发同站（必然串话） |
| | ❌ 掉登录/风控后全挂 |

> 这几条不是我猜的，是 luanyujia 原文自己承认的代价：
> **"它适合'问一次、要一段文字'；不适合'跑一百次'或'必须准时'。"**
