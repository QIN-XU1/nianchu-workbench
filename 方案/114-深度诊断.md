# 114 · 深度诊断：为什么这个项目「更大」而不是「更深」

> 用户：「我想要的是一直都是一个更深入的版本，而不是一个更大的版本」

---

## 一、先承认：用户的判断是对的

我用数据证明这一点。

### 证据 1：文档比使用多得多

```
方案文档:     117 份
实际会话:     0 个
场景记忆总计: 25.6 KB（9 个场景，平均 2.8 KB）
```

**写了 117 份方案，但一次真实会话都没跑过。**

### 证据 2：记忆内容是空的

抽查 `架构梳理/场景私有记忆.md`（1220 字符）：

```markdown
## §〇 当前交接

### 1) 上次交接
- （新场景，还没有交接记录）  ·  2026-11-07

### 2) 当前项目
| 项目 | 记忆文件 | 状态 | 下一步 |
|---|---|---|---|
| 无 | — | — | — |
```

**这就是「骨架建好了，但没住人」。**

### 证据 3：派单是测试性质的

```
d-20261109-001  hub→arch-review       closed
d-20261109-002  hub→incident-analysis closed
d-20261109-003  hub→build-plan        closed
d-20261109-004  hub→incident-analysis closed
```

4 条全部是我在测试机制时人工造的，不是真实任务。

## 二、找到三个致命断层

### 断层 1：场景定位卡从未注入给 AI 🔴🔴🔴

**证据**：`main.js` 里只有两个 system prompt 构造器：

```js
buildSiteSystem(c)   // 个人站
buildOaSystem(c)     // OA 项目（已废弃场景）
```

**没有任何一个跟 9 个场景有关**。

搜索关键词结果：
```
提到「场景私有记忆」: 0 次
提到「身份卡」:       0 次
提到「AGENTS.md」:    0 次
```

而场景目录下明明有：
```
arch-review-context.md          1496 B   ← 定位卡
build-plan-context.md           1378 B
competitor-analyze-context.md   1402 B
...
```

**这些文件只是躺在那里，AI 永远读不到。**

**后果**：AI 在每个场景里表现完全一样——它不知道自己是"架构梳理"还是"调研"，
不知道自己不该碰什么，也不知道这个场景的历史坑。**整个"场景"概念空转。**

### 断层 2：场景会话不存在 🔴🔴

```json
// arch-review.json
{
  "type": "harness",
  "sessionTitle": "架构梳理",
  "sessionId": "session-a0656d6f-0f32-48e0-9ce6-aebf0019f86c"
}
```

但实际：
```
数据/.dsh/sessions/   →  0 个会话
```

**那个 sessionId 是占位符，真实会话从未创建。**

### 断层 3：场景记忆没有写入路径 🔴

`harness.js`（221 行）里：
```
提到「context」: 0 次
提到「scene」:   0 次
提到「prompt」:  0 次
提到「memory」:  0 次
```

它只是嵌了一个 webview 把 Harness 界面放进去。
**AI 回答完，没有任何机制把结论写回场景记忆。**

所以「记忆」永远是空的。

## 四、真正的「深」应该是什么

### 判据：一条链路能端到端跑通，才算深

```
用户提需求
    ↓
① 场景判定（该用哪个场景？）
    ↓
② 场景会话带着「定位卡 + 身份卡 + 私有记忆 + 技能」启动 ← ★ 现在断了
    ↓
③ AI 在这个场景的约束下工作（知道不碰什么、知道历史坑）
    ↓
④ 任务完成
    ↓
⑤ 结论写回场景记忆（§〇 交接 + §五 坑与决策）← ★ 现在断了
    ↓
⑥ 下次同场景，AI 能读到上次的交接 ← ★ 现在断了
```

**这条链路一次都没跑通。**

而 117 份方案、49 个工具、127 项测试，全都建立在「这条链路是通的」这个假设之上。

**假设不成立，上面所有东西都是空转。**

---

## 五、修复方向（等调研补充业界做法）

### 必修 1：场景上下文注入

需要让 AI 在场景会话里能读到：
- 场景定位卡（是什么/不碰什么）
- 身份卡（扮演什么角色）
- 私有记忆（§〇 交接 + §五 坑与决策）
- 该场景的专属技能
- 共享层（AGENTS.md 铁律）

### 必修 2：会话真实绑定

每个场景要有真实的会话，不是占位 sessionId。

### 必修 3：记忆写回

任务完成后，结论要能自动/半自动写回场景记忆。

### 必修 4：能证明它工作了

不是"127 项测试通过"（那是测试测试自己），
而是：**跑一个真实任务 → 记忆有变化 → 下次能读到 → 输出质量提升**。

## 七、一句话

> **这个项目的问题不是"不够多"，是"没通"。**
>
> **最重要的不是再加 10 个工具，而是让一条链路真正跑通：**
> **场景会话带着记忆启动 → AI 在约束下工作 → 结论写回记忆 → 下次能读到。**
