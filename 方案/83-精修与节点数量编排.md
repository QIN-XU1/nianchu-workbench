## 一、① 删除点击后的光圈

### 自检发现

```js
// drawStarlight 内部：isFocus 时 power = 0.88（自动更亮）
if (isFocus) power = 0.88;

// 但选中态又额外画了一层 5.2 倍半径的呼吸光晕
if (isSel) {
  const haloR = starR * (5.2 + breathe * 0.9);   // ← 多余
  c2d.fillStyle = sg; c2d.fill();
}
```

**`focusId` 同时覆盖 hover 和 sel，所以选中时星光已经自动更亮了。**
再叠一层光圈 = 双重 → 丑。

### 修法

**删除整个选中态额外绘制块。** 选中只靠 `drawStarlight` 的 `isFocus` 强度差异表达。

```js
// 现在：留空（注释说明设计意图）
// drawStarlight 已经根据 isFocus 提升强度
// → 选中时星光自动更亮，无需额外光圈
```

**与悬停完全一致 —— 正如用户所说"鼠标移动到节点上的效果就足够了"。**

## 二、② 连线"断断续续"的真因

### 自检

```js
// 之前：5 段渐变
grad.addColorStop(0.00, 'rgba(198,224,248, aEnd)');      // 0.78
grad.addColorStop(0.18, 'rgba(214,234,252, aEnd*1.12)'); // 0.87
grad.addColorStop(0.50, 'rgba(228,242,255, aMid)');      // 1.00
grad.addColorStop(0.82, 'rgba(214,234,252, aEnd*1.12)'); // 0.87
grad.addColorStop(1.00, 'rgba(198,224,248, aEnd)');      // 0.78
```

**问题：**
- 两端较暗（0.78）在 Bloom 下与背景融合 → 视觉"断"
- 中间亮两头暗 → 违反物理直觉（光沿导线应该均匀）

### 修法

**改为纯色，整条线亮度一致。**

```js
if (isHot || isNeighborLink || lit) {
  c2d.strokeStyle = 'rgba(214,234,252,' + alpha + ')';
} else {
  c2d.strokeStyle = 'rgba(110,155,200,' + alpha + ')';
}
```

**Bloom 会自然让端点在节点处衰减（物理正确，无需手动渐变）。**

## 三、③ 节点数量编排（本轮最大成果）

### 3.1 自检发现的两个致命问题

**问题 A：`baseDir` 算了从未使用**

```js
const baseDir = domainDir[n.domain] || 0;   // ← 算了
// 之后：立方体内纯随机采样（完全不用 baseDir）
```

**结果：1000 个节点 = 均匀一片星云，完全无结构。**

**问题 B：没有档位概念**

固定半径 + 固定采样算法，节点越多越挤。

### 3.2 四档编排策略

```js
const TIER_S_MAX = 24;      // S 档上限
const TIER_M_MAX = 120;     // M 档上限
const TIER_L_MAX = 600;     // L 档上限

function getTier(n) {
  if (n <= 24) return 'S';
  if (n <= 120) return 'M';
  if (n <= 600) return 'L';
  return 'XL';
}
```

| 档位 | 节点数 | 布局 | 星光 | 标签 | 光晕 |
|---|---|---|---|---|---|
**S** | ≤24 | 体积均匀（不聚类） | 全（含芒） | 全部 | 100% |
**M** | 25~120 | **领域聚类** | 全（含芒） | 仅交互时 | 82% |
**L** | 121~600 | **领域聚类** | 无芒 | 稀疏(1/3) | 65% |
**XL** | >600 | **领域聚类** | 无芒 | 不显示 | 50% |

### 3.3 密度自适应

```js
// 节点越多 → 空间范围越大（把节点撑开）
const densityFactor = Math.max(1.0,
  Math.min(1.85, 1 + Math.log10(Math.max(1, nodeN) / 10) * 0.62));

// 上限受画布约束（留 6% 边距）
const RX = Math.min(W * 0.475, baseRX * densityFactor);
```

数学验证：
```
n=10   tier=S   密度因子=1.00
n=50   tier=M   密度因子=1.43
n=200  tier=L   密度因子=1.81
n=1000 tier=XL  密度因子=1.85（封顶）
```

### 3.4 领域聚类算法

```js
// 团心在球面均匀分布（纬度均匀 + 经度黄金角）
const lat = (dc <= 1) ? 0 : (-0.85 + (1.7 * (di + 0.5)) / dc);
const lon = (di * 2.39996) % TAU;   // 黄金角

// 团心半径：节点多的团稍靠外
const rrBase = 0.34 + 0.44 * Math.min(1, cnt / avgPerDomain);

// 团半径：∝ sqrt(节点数)，上限 0.26（防团间重叠）
const rad = Math.min(0.26, 0.085 * Math.sqrt(cnt));

// 节点位置 = 团心 + 团内偏移
px = (cc.x + nx * cc.rad * inBall) * RX;
```

### 3.5 实测效果对比

| 节点数 | 改前 | 改后 |
|---|---|---|
**1000** | 均匀一片星云，无任何结构 | **清晰聚成 4 个星团** |
最小间距 | 0.5px | 1.2px |
渲染耗时 | 41ms | 41ms |

**关键：1000 个节点时，截图能清楚看出「工程团」「内容团」「工具团」「关系团」四个独立星团。**

## 四、自检抓出的 bug

```

但别处仍用裸变量 scaleMode → ReferenceError → render 全挂
```

```
替换采样逻辑时，用了 clusterCenters 但没定义 → 分层失效
```

**修：补上定义块。**

### bug：锚点缩进不匹配（3 次）

```
用字符串替换时，多次因缩进差异匹配失败
```

**教训：改用「行号定位 + 边界标记」替换，比字符串匹配可靠。**
