## 二、怎么做到的（三段关键突破）

### 2.1 第一段：发现"引擎地址错了"

**症状**：AI 面板一直显示"引擎还没就绪"。

**诊断**：
```
引擎 URL : http://127.0.0.1:31238/chat   ← 指向自己！
引擎 webview: "等待引擎…"
```

**根因**（main.js L980）：
```js
if (engineIsForeign) return 'http://127.0.0.1:' + SITE_PORT + '/chat';
```

复用外部引擎时，工作台强制走**自己的**保活入口 `/chat`，形成自引用循环。

**修法**：复用外部引擎时直连 `BASE`（真正的外部端口）。

### 2.2 第二段：发现"/chat 需要 token"

`/chat` 的实现：
```js
const t = harnessToken;
if (t) { 302 → BASE + '/?token=' + t }
```

**但复用外部引擎时拿不到 token** ⇒ 落到"自动重试"分支 ⇒ 永远等。

**修法**：加退路 —— 有 token 就带 token，没 token 给"直连引擎"的可点链接。

### 2.3 第三段：自己起一个 web 引擎拿 token

**关键发现**：桌面版 DSH 的 token 只在内存里，不落盘。

**解法**：用官方 CLI 起一个独立的 web 引擎：

```powershell
$env:DSH_HOME = "$env:USERPROFILE\.dsh"
& "...\runtime\cli\bin\dsh.cmd" --profile web --port 3080 --no-open
```

**输出**：
```
dsh web: http://127.0.0.1:3080/?token=3yeNHhvSWx9Ej_Xc4pHDGeLdhCz6mAEpyH6k7EPRw4s
```

**这个 token 就是建会话的钥匙。**

## 三、建会话的技术细节

### 3.1 RPC 的真实 payload 格式（从源码里挖出来的）

```json
{
  "type": "client-request",
  "rpcId": "r1",
  "method": "session/create",
  "payload": { "args": { "request": { "workspaceId": "..." } } }
}
```

**光看 API 会以为是普通 REST**，但必须带 `type:client-request` 这层包装。

### 3.2 三步流程

```
① token → cookie   fetch(BASE + '/?token=' + token, { redirect: 'manual' })
                   拿 set-cookie
② session/create   → sessionId
③ session/rename   → 标题
④ 写回 scenarios/<id>.json 的 panels[].sessionId
```
