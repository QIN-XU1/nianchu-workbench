## 三、真正的机制移植（核心成果）

### 3.1 紫微斗数：固定槽位 + 可变填充 —— 解决规模化

#### 我之前的错误方案：二十八宿环形

```
环形布局的本质问题：无限扩展是伪命题

10 个场景  → 间隔 36°，OK
100 个场景 → 间隔 3.6°，挤
1000 个    → 糊成一圈

即使加了 LOD 降级、面积正比扇区，
本质仍是"把 N 个东西塞进圆环" —— 永远会挤。
```

#### 紫微的答案：十二宫是固定容器

```
紫微斗数机制（我确定的部分）：

十二宫是固定槽位：
  命宫 兄弟 夫妻 子女 财帛 疾厄
  迁移 交友 官禄 田宅 福德 父母

每宫内容由「安星决」填充：
  · 星曜按固定规则分配到宫位
  · 同一颗星在不同宫位，性质不同
  · 主星/辅星/煞星 有层级

核心思想：容器固定，内容可无限填充。
```

#### 移植结果

```
十二宫 → 场景的十二个固定容器

宫位        本义          对应场景类别
────────────────────────────────────────────
命宫        核心/本性      中枢自身
兄弟宫      同辈协作      并行执行的场景
夫妻宫      紧密搭档      强依赖场景
子女宫      产出/衍生      产出型（文档/方案/报告）
财帛宫      资源/价值      资源型（性能/存储/成本）
疾厄宫      健康/隐患      故障诊断/健康检查
迁移宫      对外/移动      对外接口/集成
交友宫      人脉/外部      外部服务/第三方
官禄宫      事业/职责      执行型（计划/实施/运维）
田宅宫      基业/存储      数据/记忆存储
福德宫      精神/沉淀      复盘/总结/沉淀
父母宫      根源/约束      规则/配置/约束
```

#### 压力测试验证

```
场景数    宫数  空宫  最多宫场景数  耗时     结论
    100    12     2       50      1.5ms   ○ 需宫内列表
    500    12     2      250      4.1ms   ◉ 需宫内分页
   1000    12     2      500      9.1ms   ◉ 需宫内分页
   5000    12     2     2500     23.6ms   ◉ 需宫内分页
  20000    12     2    10000     89.4ms   ◉ 需宫内分页
 100000    12     2    50000    435.9ms   ◉ 需宫内分页

★ 宫数恒定 12，永不增长
★ 无论 100 还是 100000 个场景，容器都是 12 格
★ 宫格满了用宫内列表/分页，容器本身永不膨胀
```

**这就是正解。** 不再有"场景越多越挤"的伪命题。

#### 压力测试又抓出一个算法缺陷

**初版结果：官禄宫 50 个，兄弟宫 0 个（严重失衡）**

根因：关键词匹配太弱
- 单字命中就算
- 没分词
- 兜底全给官禄宫

**修正：多级加权评分**
```
① 名称完全相等    权重 ×80
② 名称包含关键词  权重 ×40
③ id 包含         权重 ×20
④ role 包含       权重 ×12
⑤ description 包含 权重 ×5
⑥ 关键词越长越精确，整体乘精度系数
⑦ 无匹配 → 按 id 哈希均匀分摊到通用四宫（不都塞官禄）
```

**修正后：官禄宫 18 个，田宅宫 23 个，兄弟宫 12 个，福德宫 12 个…分布均匀。**

### 3.2 易经：6 位状态编码 —— 解决状态散乱

#### 机制本质（易经最核心的贡献之一）

```
太极 → 两仪（阴阳）
两仪 → 四象
四象 → 八卦
八卦 → 六十四卦（8×8）

编码：每卦 = 6 个爻（阳=1，阴=0）
     六十四卦 = 6 位二进制 = 0~63
     卦序有严格排列
     卦爻辞 = 每种状态的处置规则
```

**这不是占卜，是「完备状态编码」的典范。**

#### 移植结果

```
场景状态 = 6 位 = 64 种

bit0  有场景定义        (DEFINED)
bit1  有 AI 会话         (SESSION)
bit2  正在执行           (RUNNING)
bit3  有产物             (ARTIFACT)
bit4  记忆完整           (MEMORY)
bit5  有错误             (ERROR)

例：63 = 全备（可调度）
    31 = 半备（记忆缺失）
    3  = 裸会（有定义+会话）
    1  = 空壳（仅定义）
    0  = 空
```

**好处：**
- 一次性判断状态（不用散落 if-else）
- 状态转移有明确表（就像卦变）
- 界面按状态码显示不同视觉
- 监控可聚合统计

### 3.3 奇门遁甲：三层叠加（待实现）

#### 机制本质

```
九宫格固定空间（洛书）
叠加三才盘：
  地盘 = 固定九宫
  天盘 = 随时间转动
  人盘 = 八门
再叠九星八神 → 一局
阴遁阳遁随节气切换
```

#### 移植方案（P1）

```
每个场景节点 3 层状态：
  静态层（配置）   ← sceneboard/scenes/*.json
  动态层（运行态） ← session.list 的 running/asOfSeq
  操作层（权限）   ← 当前可做什么
渲染时三层叠加
```

### 3.4 六爻：用神体系 —— 解决"1000 个里怎么找相关的"

#### 机制本质

```
一卦六爻，各有：
  地支 / 五行 / 阴阳 / 世应 / 六亲

关键机制「用神」：
  测不同事取不同爻为用神
  测财取妻财爻，测官取官鬼爻
  → 同一个卦，问不同事，看不同的爻
```

#### 移植方案（P1）

```
中枢接到需求 → 先判断"用神"
  · 性能类 → 焦点 = 性能标签场景
  · 架构类 → 焦点 = 架构标签场景
  → 只高亮那类场景，其余淡化
```

**这解决了「1000 个场景里，我怎么找到相关的」。**
