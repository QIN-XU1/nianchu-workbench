## 二、① 旋转太快：我快了 2.9 倍

### 2.1 Three.js OrbitControls 的标准公式

```js
// OrbitControls 内部实现
const rotateAngle = 2 * Math.PI * deltaX / element.clientHeight;
rotateLeft(rotateAngle * this.rotateSpeed);   // rotateSpeed 默认 1
```

**含义：**
```
拖过 1 倍画布高度  →  转 180°（半圈）
拖过 2 倍画布高度  →  转 360°（一圈）
```

### 2.2 我的实现对比

```js
// 之前（错）
S.yaw += dx * 0.0115;
// 画布高 786px → 转一圈需 547px

// OrbitControls 标准 → 转一圈需 1572px
```

**我快了 2.9 倍。这就是"稍微转一下不知道转到哪"的原因。**

### 2.3 修正

```js
const ROTATE_SPEED = 1.0;                                    // 与 OrbitControls 一致
const yawDelta = (Math.PI * dx / H0) * ROTATE_SPEED;          // π × dx / H
const pitchDelta = (Math.PI * dy / H0) * ROTATE_SPEED;
```

**关键：按画布高度自适应，不是固定系数。**
这样不同尺寸的画布手感一致。

### 2.4 实测验证

```
拖 100px → 22.9°
推算一圈需 1572px   ✓ 与 OrbitControls 完全一致
```

### 2.5 顺带：极角限制

```js
const PITCH_MIN = -1.35;
const PITCH_MAX = 1.35;
// 软钳制：越界后只按 6% 位移（比之前的 12% 更硬，接近 OrbitControls）
```

OrbitControls 用 `minPolarAngle / maxPolarAngle`，默认 `[0, π]`（可翻越极点）。
我们限制到 ±77°，避免用户转到"看不见任何东西"的角度。

## 三、② 高亮语义错误

### 3.1 我之前的设计（错）

```js
// 悬停命中节点 → 立即记录 stickyFocus（保留 90 秒）
if (n) {
  S.stickyFocus = n.id;
  S.stickyAt = Date.now();
}
// 未命中 → 不清除
```

**问题：拖拽背景时鼠标必然划过若干节点，每个都被记录成 `stickyFocus`。**
**松手后这些节点仍高亮 —— 用户看到的正是这个 bug。**

### 3.2 正确的语义分层

| 状态 | 触发 | 生命周期 | 含义 |
|---|---|---|---|
**hover** | 鼠标悬停 | 瞬时（鼠标离开即消失） | "我现在在看这个" |
**sel** | 点击 | 持久（再点一次取消） | "我选中了这个" |
**dragSnapshot** | pointerdown 快照 | 仅拖拽期间 | "拖拽前的高亮，别熄灭" |

**关键区别：**
- `hover` 是临时的 —— 拖拽时鼠标划过节点，**不应该高亮**
- `sel` 是持久的 —— 只有用户明确点击才有
- `dragSnapshot` 是快照 —— 只在拖拽开始时记录**已有**的焦点

### 3.3 实现

```js
// ① pointerdown 时快照
S.dragSnapshot = (S.sel && S.sel.id) || (S.hover && S.hover.id) || null;

// ② 拖拽期间完全不检测悬停
if (S.rotating || S.draggingNode) return;

// ③ focusId 优先级
let focusId = (S.hover && S.hover.id) || (S.sel && S.sel.id) || null;
if (!focusId && (S.rotating || S.draggingNode) && S.dragSnapshot) {
  focusId = S.dragSnapshot;
}

// ④ 松手时清除快照
function endDrag() {
  S.dragSnapshot = null;
}
```

### 3.4 实测验证

```
测试 2：拖拽路径经过节点
  拖拽中: hover=null, snapshot=null, rotating=true     ✓
  松手后: hover=null, sel=null, snapshot=null         ✓
  → 划过节点完全没有高亮

测试 3：先选中，再拖拽
  点击选中: sel="架构梳理"
  拖拽后:   sel="架构梳理"                            ✓（保持）
```

## 四、自检抓出的第三个 bug

### 4.1 click 与 drag 混淆

**测试 3 第一次跑失败：**
```
点击选中"架构梳理" → 拖拽背景 → sel = null（丢了）
```

**根因：**
```js
// click handler（第 2100 行）
S.sel = (n && S.sel && S.sel.id === n.id) ? null : n;
```

拖拽背景后松手，如果鼠标恰好落在节点上，**浏览器仍会派发 click** → `sel` 被切成 null。

### 4.2 修法：5px 拖拽阈值

```js
// pointerdown 记录起点
S.downX = ev.offsetX;
S.downY = ev.offsetY;
S.movedDist = 0;

// pointermove 累计距离
S.movedDist = Math.sqrt(ddx*ddx + ddy*ddy);

// click 里判定
if (S.movedDist > 5) {
  S.movedDist = 0;
  return;    // 拖拽结束，不处理 click
}
```

**这是所有专业画布应用的标配**（Figma / Sketch / Photoshop / Google Maps 都有）。
