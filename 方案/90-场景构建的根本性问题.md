| 项目 | Stars 量级 | 核心设计 |
|---|---|---|

### 1.1 ComfyUI 的关键设计（最值得借鉴）

```
① 单一画布（node graph）
   所有工作流都在同一张画布上，不是"11 个独立页面"

② 节点 + 连线
   数据流**可见**，一目了然

③ 可折叠节点（Ctrl+C）
   复杂图中把不需要看的节点折叠，减少噪音

④ 子图（Reusable subgraphs）
   把一组节点打包成子图，可以嵌套复用

⑤ App Mode
   同一份工作流，暴露成"只有几个输入框"的简单 UI
   → 复杂能力 + 简单入口 的分离
```

### 1.2 这解释了为什么"场景"这个设计有问题

**我的场景 = 独立页面**：
```
点击场景 → 切换整个界面 → 里面平铺 N 个面板
```

**ComfyUI/ComfyUI 的做法 = 统一画布**：
```
所有节点在同一张画布
↓
想看细节：展开节点
↓
想看全貌：折叠节点
↓
想执行：App Mode（只留输入输出）
```

## 二、我的设计错在哪（逐条）

### 错误 1：场景是"页面"，不是"画布区域"

**我的做法：**
```
scenarios/arch-review.json  → 一个完整页面（4 个面板平铺）
scenarios/bilibili.json     → 另一个完整页面（2 个面板平铺）
→ 11 个场景 = 11 个页面，互相割裂
```

**问题：**
- 看不到场景之间的关系
- 切场景 = 界面全变，用户失去位置感
- 面板平铺，没有主次

**正确做法（按 ComfyUI）：**
```
一张画布
  ├─ 场景 A（一组节点的容器）
  ├─ 场景 B（另一个容器）
  └─ 连线表示数据流
点击场景 A → 展开它（不是切换页面）
```

### 错误 2：面板是"固定配置"，不是"可组合节点"

**我的做法：**
```json
"panels": [
  { "type": "sf-board", "col": 1, "row": 1, "w": 1, "h": 2 },
  { "type": "harness",  "col": 2, "row": 1, "w": 3, "h": 2 }
]
```

**问题：**
- 面板布局写死在 json 里
- 用户不能拖拽重组
- 新增面板要改 json

**正确做法（按 ComfyUI）：**
```
面板 = 节点
节点可以：拖拽位置 / 调整大小 / 折叠 / 删除 / 添加
布局保存在用户侧，不是硬编码在场景定义里
```

### 错误 3：大部分面板是**占位实现**

**审计证据（_generic.js）：**
```js
// 磁盘面板
export const createPcDrives = makePcPanel('磁盘', '▤', '待接入 pc:drives API');
// 大文件
export const createPcTopLarge = makePcPanel('大文件', '▥', '待接入 pc:toplarge API');
// 垃圾
export const createPcJunk = makePcPanel('垃圾文件', '▧', '待接入 pc:junk API');
// 台账
export const createPcLedger = makePcPanel('台账', '▦', '待接入 pc:ledger API');
// 审查文件
export async function createReviewFiles(...) {
  emptyState(body, '▥', '审查文件列表', '待接入 review API');   // ← 空状态
}
```

**10 种面板里，真正能用的只有 3 种：**
| 面板类型 | 状态 |
|---|---|
`neuron` | ✅ 完整（2758 行） |
`harness` | ✅ 可用（webview 嵌 dsh） |
`embed` | ✅ 可用（webview） |
`main-agent` | ✅ 可用（dsh-TUI） |
`sf-board` | ○ 半成品（只显示管线数） |
`review-doc` | ✗ 占位（只显示目录路径） |
`review-files` | ✗ 占位（永远空状态） |
`pc-drives` | ✗ 占位 |
`pc-toplarge` | ✗ 占位 |
`pc-junk` | ✗ 占位 |
`pc-ledger` | ✗ 占位 |

**7/11 面板是占位或半成品。这就是"没什么参考性"的原因。**

### 错误 4：场景的业务逻辑是"想当然"的

以 `pc-cleanup`（本地电脑）为例，它配置了 4 个面板：
```
pc-drives    磁盘
pc-toplarge  大文件
pc-junk      垃圾
pc-ai        AI 对话
```

**但后端**：`kun:sys:disks` 通道存在，`pc:toplarge` / `pc:junk` / `pc:ledger` **根本不存在**。

**我编造了后端没有的能力。**

## 四、我建议的新方向（需要你确认）

### 4.1 核心转变：从"11 个页面"到"一张画布"

```
现在：
  11 个独立场景页面，互相割裂

建议：
  一张画布，场景是可折叠的"区域"
  区域内是真实可用的面板
  区域之间有数据流连线
```

### 4.2 具体方案 A：ComfyUI 式节点画布

```
┌─────────────────────────────────────────────────┐
│  ┌──────┐    ┌──────┐    ┌──────┐              │
│  │调研  │───→│架构  │───→│实施  │              │
│  │(折叠)│    │(展开)│    │(折叠)│              │
│  └──────┘    └──────┘    └──────┘              │
│                                 │               │
│               ┌──────┐          ↓               │
│               │中枢  │←─────────┘               │
│               │(AI)  │                          │
│               └──────┘                          │
└─────────────────────────────────────────────────┘
```

**优点：** 关系可见、可拖拽、可折叠
**缺点：** 需要重写布局引擎（大工程）

### 4.3 具体方案 B：Tab + 可拖拽面板（VSCode 式）

```
┌─────────────────────────────────────────────────┐
│ [中枢] [调研] [架构] [实施] ...  ← 场景标签      │
├──────────────────────┬──────────────────────────┤
│                      │                          │
│   主面板区           │   侧面板区               │
│   （可拖拽分割）      │   （可拖拽分割）          │
│                      │                          │
└──────────────────────┴──────────────────────────┘
```

**优点：** 实现成本低、每个场景独立
**缺点：** 场景间关系仍不可见

### 4.4 具体方案 C：中枢 + 按需展开面板

```
中枢永远在
  ↓
用户提需求 → AI 判断需要哪些场景
  ↓
AI 动态创建面板（不是预设的）
  ↓
面板进"工作台"（可拖拽、可关闭）
```

**最符合用户之前说的"不可预估的场景，全权交给 AI 调度"。**

## 五、必须先解决的底层问题

### 5.1 面板能力是空的

**无论选哪个方案，都必须先解决：**
```
11 种面板里只有 4 种真能用
7 种是占位
```

**要做的：**
1. 每个面板类型必须**真实接入后端**
2. 不存在的能力**不能假装存在**

### 5.2 后端能力没被用起来

```
review:files / review:read / review:root  → 真实存在但没用
engine:prompt / engine:rpc                → 真实存在但没用
kun:sys:disks / kun:file:*                → 真实存在但没用
```

**"面板做得没参考性"，根源是没接真实数据。**

## 六、我需要你决策的三件事

### 决策 1：布局范式

| 方案 | 特点 | 成本 |
|---|---|---|
**A** ComfyUI 式节点画布 | 关系可见、可拖拽折叠 | 高（重写布局） |
**B** VSCode 式 Tab + 拖拽分割 | 实现快、每场景独立 | 中 |
**C** 中枢 + AI 动态创建面板 | 最符合"AI 自主调度" | 中高 |

### 决策 2：场景数量

| 选项 | 说明 |
|---|---|
**固定 11 个** | 沿用现有，只修面板 |
**精简到 3~5 个** | 只保留真正有后端支撑的 |
**动态生成** | 场景由 AI 按需创建，无预设 |

### 决策 3：面板优先级

**哪 3 个面板最重要？** 我建议：
1. **harness**（AI 对话）—— 核心
2. **review-files**（审查文件）—— 有后端支撑
3. **engine-panel**（新建）—— 直连 DSH 引擎
