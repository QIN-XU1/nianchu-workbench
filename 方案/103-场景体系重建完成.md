### 2.2 边界设计（最关键）


**明确列出不做的 5 件事：**
- 改代码
- 重启 GUI
- 删除崩溃日志
- 确定性地断言硬件问题
- 修改其他场景的记忆

## 四、技能边做边补的实证

### 4.1 初版技能写错了

我在写 `skills/incident-analysis/SKILL.md` 时假设：
```
"40 条崩溃全在 /chat"
```

**真实数据推翻：**
```
56 条根本没有 url 字段（uncaughtException + child-process-gone）
render-crash 的 40 条 URL 分散在多个站点
只有 8 条在 /chat
```

### 4.2 已修正

技能里改成了：
```markdown
> ⚠ 本节是分析后回填的，不是提前编的。
> 我在初版技能里假设"40 条崩溃全在 /chat"，
> 真实数据推翻了这个假设 —— 这正是"技能必须边做边写"的证明。
```

**并追加了「真实分析的关键发现」一节。**

**这就是"技能边做边补"的实际含义：**
```
先做 → 拿到真实数据 → 修正技能 → 下次做得更好
```

不是"提前写一份看起来很专业的技能"。

## 五、修复一个重大 bug：flow 边全部丢失

### 5.1 现象

修复前神经元里：
```
edges: 12
edgeKinds: { domain: 4, similar: 8 }   ← 全是兜底连线
一条 flow 边都没有
```

**但契约文件里有 13 条 `outputs.to` 关系。**

### 5.2 根因

**两个不同文件被混用了：**

```
外壳/scenarios/<id>.json      = 场景配置（面板布局）
sceneboard/scenes/<id>.json   = 场景契约（inputs/outputs）
```

调用链：
```js
// neuron.js
const r = await api.util.scene(s.id);   // 期望拿到契约

// main.js
function getScenario(id) {
  const f = path.join(SCENARIOS_DIR, sid + '.json');   // ← 读的是场景配置
  return JSON.parse(...);                              // ← 没有 outputs
}

// neuron.js
contracts[s.id] = r.scene;
if (!Array.isArray(c.outputs)) continue;   // ← 永远成立，flow 边全跳过
```

### 5.3 修复

**① main.js：** `getScenario` 现在把契约挂在 `scene.contract` 上
```js
const cf = path.join(__dirname, '..', 'sceneboard', 'scenes', sid + '.json');
if (fs.existsSync(cf)) {
  scene.contract = JSON.parse(...);
}
```

**② neuron.js：** 优先用 `scene.contract`
```js
contracts[s.id] = sceneObj.contract || sceneObj;
```

### 5.4 验证

| | 修复前 | 修复后 |
|---|---|---|
边数 | 12 | **19** |
flow | 0 | **12** |
indirect | 0 | 5 |
domain | 4 | 0 |
similar | 8 | 2 |

**故障分析的三条边：**
```
✓ 故障分析 -- 实施计划   [flow]      ← 真实契约关系
✓ 架构梳理 -- 故障分析   [indirect]  ← 共同邻居
✓ 故障分析 -- 逆向分析   [indirect]  ← 共同邻居
```

### 5.5 这个 bug 的影响

```
导致：
· 所有场景的真实依赖关系从未显示过
· 用户看到的连线全是"猜的"（同领域/关键词相似）
· 契约里辛苦写的 inputs/outputs 白写了
```

## 七、经验沉淀

### 7.1 判据的价值

```
没有判据：11 个场景（其中 3 个是假的）
有判据：  9 个场景（全是真的）
```

**判据不是"增加流程"，是"减少浪费"。**

### 7.2 技能必须边做边写

```
❌ 先写技能再干活 → 技能里全是臆想的"最佳实践"
✅ 先干活再写技能 → 技能里全是真实的坑
```

**本轮的实证：** 初版技能假设被真实数据推翻，已修正。

### 7.3 "无法判断"是最重要的输出

崩溃分析报告里最有价值的一节不是"发现 4 个模式"，
而是"6 个数据缺口" —— 它告诉下一步该补什么。

### 7.4 真实数据才能发现真 bug

本轮修的这个 flow 边 bug：
```
变异测试发现不了（它测的是工具的判据，不是集成问题）
单元测试发现不了
只有打开界面、看实际渲染结果，才能发现
```
