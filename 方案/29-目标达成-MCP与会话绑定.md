## 1. MCP 真实接入

### 1.1 零依赖的 MCP 客户端

MCP = JSON-RPC over stdio。本质是"写一行 JSON 到 stdin，读一行从 stdout"，不需要任何 npm 包。

```
spawn 子进程 → initialize → notifications/initialized → tools/list → tools/call → 关闭
```

### 1.2 协议自检 5/5

用 Node 自己造了一个假 MCP 服务器验证协议实现：

```
✓ initialize + tools/list      2 个工具
✓ 工具名正确                    echo, add
✓ tools/call 返回正确            add(3,4)=7
✓ 未知服务器明确报错              未知的 MCP 服务器
✓ 协议容错（非 JSON 行忽略）
```

### 1.3 真实可用的最小 MCP 服务器

写了 `mcp-fs-server.mjs`（只读文件系统），三个工具：
- `list_dir` 列目录
- `read_file` 读文件（≤64KB）
- `file_stat` 文件信息

**安全**：路径必须在项目根内（防穿越），只读不写。

### 1.4 端到端 7/7（开关 → 真实调用）

```
✓ MCP 默认关闭              isOn=false
✓ 动态发现 MCP 服务器         label=文件系统（本地只读）
✓ 开启后 isOn              isOn=true
✓ list_dir 真实返回          47 项
✓ read_file 真实返回         8771 字符
✓ 路径越界被拒               tools/call 失败（越界）
✓ 关闭后 isOn=false        isOn=false
```

**关键设计：动态发现 + 默认关闭**
- `capabilities.mjs` 会自动从 `mcp-servers.json` 读取服务器
- **新增的一律默认关**（不会因为配置了文件就自动开始烧 token）

## 2. 场景绑定真实会话

### 2.1 需求原文

> "会话开场的第一件事是先认领身份，拿自己的会话ID去对场景表对号入座。"

之前 `identity.mjs` 四步认领已实现，但**没有任何会话 id 被绑定**（全是 null）。

### 2.2 真实 DSH 会话结构（踩了两次坑才摸清）

我最初以为是 `sessions/<id>.json`，实际是**两层目录**：

```
sessions/
└── --D-file-AI~0020Temp-DeepSeek-Agent~81EA~7814--/     ← 工作区名（URI 编码）
    └── 178bac74-1a84-4607-ac92-db8218f4b832/            ← session uuid
        └── session.v4.jsonl.zstd                        ← zstd 压缩的 jsonl
```

修正后才正确发现 **11 个真实会话**（含大小、工作区、时间、压缩格式）。

### 2.3 绑定与防串台

| 能力 | 实测 |
|---|---|
列出真实会话 | ✅ 11 个，含 4837KB 的大会话 |
绑定 | ✅ `data-reconcile → selftest-session-xyz` |
**防串台** | ✅ `会话 X 已绑定到 data-reconcile —— 一个会话只能属于一个场景` |
解绑复原 | ✅ |

**防串台是这条的关键**：一个会话被两个场景绑定 ⇒ 两个场景的 AI 会互相"知道"对方的活（luanyujia 记录过的真实事故）。
