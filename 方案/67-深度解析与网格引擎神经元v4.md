## 二、原项目的场景机制（逐条摘录）

### 2.1 核心原则

> **「一个场景 = 一份 JSON。」**
> 「放进 `scenarios/` 目录即被自动发现：**不需要注册、不需要改主进程代码**。」
> 「**加场景 = 丢一份 json**：目录每次都重扫，不缓存列表。」

### 2.2 网格规则（这是"可自定义"的核心）

> **「列数是可配的，行是等分的。」**
>
> ```
> 默认 4 列，列宽等分；行高也等分（grid-auto-rows: minmax(0, 1fr)）
> 面板之间固定间隙，面板内容自己滚动，整页不滚
> 每个面板 = 网格项：grid-column: <col> / span <w>、grid-row: <row> / span <h>
> ```
>
> | 字段 | 含义 | 默认 |
> |---|---|---|
> | `col` | 起始列，从 1 开始 | 自动 |
> | `row` | 起始行，从 1 开始 | 自动 |
> | `w` | 跨几列 | 2 |
> | `h` | 跨几行 | 2 |
>
> **三条规则：**
> 1. 只写 w/h 不写 col/row → 进自动流
> 2. 整份 json 一个坐标都不写 → 全自动排版，补洞拉伸填满
> 3. 写了起点 → 落在该格，向右跨 w、向下跨 h
>
> ⚠ 坐标是「**起点 + 跨度**」，不是终点。
> `col:4 w:1` 才是最后一列；`col:4 w:2` 会伸到第 5 列（越界）

### 2.3 cols 的用途（这是"任意比例"的关键）

> 「列数是**比例的最小单位**。4 列能表达 1:3、2:2、3:1，**表达不了 2:3**。
> 要"五分之三 / 五分之二"这种比例，就把 cols 调大：」

```json
{
  "cols": 20,
  "panels": [
    { "id": "a", "title": "主区", "type": "view", "col": 1,  "row": 1, "w": 12, "h": 2 },
    { "id": "b", "title": "侧栏", "type": "file", "col": 13, "row": 1, "w": 8,  "h": 2 }
  ]
}
```
（12/20 = 3/5，8/20 = 2/5）

### 2.4 常见版式（可直接抄）

| 版式 | 坐标 |
|---|---|
**上 3 下 1** | A `col1 row1 w3 h2` ｜ B `col4 row1 w1 h2` |
**左 1 右 3** | A `col1 row1 w1 h2` ｜ B `col2 row1 w3 h2` |
**左右各半** | A `col1 row1 w2 h2` ｜ B `col3 row1 w2 h2` |
**2 × 2** | A `col1 row1 w2 h1`、B `col3 row1 w2 h1`、C `col1 row2 w2 h1`、D `col3 row2 w2 h1` |
**上下通栏** | A `col1 row1 w4 h1` ｜ B `col1 row2 w4 h1` |
**主区+侧栏+底部** | 主区 `col1 row1 w3 h2`｜侧栏 `col4 row1 w1 h2`｜工具条 `col1 row3 w4 h1` |

### 2.5 面板通用能力（宿主自动装配）

```
┌───────────────────────────────────────────────────────┐
│ [01] 标题  小字              [自定义按钮…]  [▲]      │
│ ───────────────────────────────────────────────────── │
│                                                       │
│  面板正文（渲染器自己画）                               │
│                                                       │
└───────────────────────────────────────────────────────┘
```

| 部件 | 从哪来 | 说明 |
|---|---|---|
序号徽标 `01` | 宿主 | 面板在 json 里的顺序（补零两位），方便口头指认 |
标题 | 面板 `title` | |
小字 | 面板 `sub` | 状态/路径，渲染器可随时更新 |
**▲ 展开到最高** | AI 面板默认；其它写 `"expand": true` | 临时占满网格高度，ESC 也能收 |
自定义按钮 | 渲染器 | `head.appendChild(...)` 追加到末尾 |

### 2.6 数据分区（关键）

> 「宿主组装面板时会往 `meta` 里注入 `scenario` 字段，面板用它给存储键加前缀：」
> ```js
> const key = 'my-panel:' + meta.scenario + ':' + meta.id;
> ```
> **why**：同一个面板类型会被多个场景复用，不带前缀就会互相覆盖。

### 2.7 四条硬规矩

1. **文件名 = `id`**：读取逻辑就是 `scenarios/<id>.json`
2. **`type` 必须已注册**：没注册时显示灰字，**不报错不崩**
3. **面板 `id` 是身份，不是标签**：改 id = 换了一个面板（绑定与状态全丢）
4. **场景之间互不影响**：加一个场景不该动到已有场景

### 2.8 加新面板六步

```
① 起名：小写连字符（pc-drives / site-preview），一个词表达"它显示什么"
② 渲染器：注册一个函数（约定：返回 DOM，不碰全局）
③ 配置：场景 json 的 panels 里写 { id, type, title, col, row, w, h }
④ 数据：想清楚数据从哪来（主进程 IPC / 读文件 / 系统调用）
⑤ 空态与错误态：没数据时显示什么（90% 的人会漏）
⑥ 自检：切场景、⟳ 重载、拔掉数据源，三种情况各看一次
```

**判据**：「一个新面板如果"没数据时一片白、不报错"，它就不合格。
白屏是最难排查的故障，必须显式给空态。」

## 三、补上的 5 项基础能力

### 3.1 新增 `ui/panels/grid.js`（网格布局引擎）

```js
computeLayout(scene)   // 读 cols、按 col/row/w/h 摆放、越界检测、自动补洞
applyGrid(gridEl, layout)  // 应用 grid-template-columns
applyCell(el, cell)        // 应用 grid-column / grid-row
```

**实现要点：**
- `cols` 默认 4，可任意配
- 坐标是「起点 + 跨度」
- 越界 → 告警 + 按实际需要列数渲染（不画歪）
- 坐标只写一半 → 告警 + 按自动流处理
- 抢占 → 找空位
- 无坐标 → 行优先扫描补洞
- 实在放不下 → 追加到最底部

### 3.2 新增 `ui/panels/frame.js`（面板容器）

**宿主自动装配的部分：**
```
[01] 标题 小字 [自定义按钮] [▲]
```

- **序号徽标**：`String(index+1).padStart(2, '0')`
- **▲ 展开到最高**：AI 面板默认开启（`panel.type === 'harness'`），其它写 `expand: true`
  - 实现：原格插一个占位格钉住版面 + 面板改覆盖层
  - ESC 也能收
- **scenario 注入**：`meta.scenario = sceneId`，面板用它给存储键加前缀
- `setSub(text)` 更新小字
- `addAction(node)` 往标题栏加按钮
- `storageKey(name)` = `name:sceneId:panelId`

### 3.3 改 `ui/index.js`：renderScene 用新引擎

```js
const layout = grid.computeLayout(scene);
grid.applyGrid(shell.gridEl, layout);
for (const cell of layout.cells) {
  const frame = frameMod.createPanelFrame(p, sceneId, i);
  grid.applyCell(frame.el, cell);
  await registry.renderInto(frame, p, ctx);
  shell.gridEl.appendChild(frame.el);
}
```

### 3.4 改 `ui/panels/registry.js`：新增 `renderInto`

渲染到已有的 frame（frame 已建好标题/序号/▲），而不是自己建容器。

## 四、神经元 v4：彻底重做

### 4.1 v2/v3 的问题（用户："你整个神经元做得并不好"）

| # | 问题 | 具体 |
|---|---|---|
① | 大片空白 | 半径用 `Math.min(W,H)`，面板 1170×842 时水平浪费 40% |
② | 节点太小 | 场景节点半径 5~10px |
③ | 标签稀疏 | 只有 depth>0.30 才显示，大部分节点没名字 |
④ | 结构不明 | 看不出「中枢→场景→私有记忆」的层次 |
⑤ | 无纵深 | 背景纯黑，没有空间感 |
⑥ | **节点重复** | 中枢画了两次（core + scene-hub） |

### 4.2 v4 的设计

**核心理念：神经元不是装饰，是导航。**
每个节点都要能回答：这是什么、现在什么状态、点它去哪。

#### 布局：三环同心椭圆

```
      ┌──────────── 外环：场景层 ────────────┐
      │  ● 调研      ● 架构梳理   ● 实施计划  │
      │                                       │
      │      ┌──── 内环：记忆层 ────┐          │
      │      │  ○       ○        │          │
      │      │      ◉ 中枢        │          │
      │      │  ○       ○        │          │
      │      └────────────────────┘          │
      └───────────────────────────────────────┘

      rx = W × 0.42   ry = H × 0.38
      内环半径 = 外环 × 0.52
```

**为什么用椭圆不是圆**：面板是宽扁的，用 `Math.min(W,H)` 做圆会水平浪费 40%。
椭圆自适应宽高比，空间利用率接近 100%。

#### 视觉改进

| 项 | v3 | v4 |
|---|---|---|
记忆节点标签 | 单字（"调""关"）无信息量 | **不画标签**（纯结构标记，空心小圈） |
内环距离 | 0.62 太近 | **0.52，拉开层次** |
中枢节点 | 静态 | **始终呼吸动画**（sin 1.6Hz） |
场景节点 | 无状态区分 | 待命（实心）/ 活跃（光晕脉冲） |
悬停 | 只高亮自己 | **高亮整条链路**（中枢→场景→记忆） |
背景 | 纯黑 | 径向渐变 + **同心椭圆 + 24 向刻度** |
节点 | 平涂 | **内高光（立体感）** |

#### 6 项修复

1. **跳过 isHub 场景**（消除中枢重复）
2. **椭圆布局**（消除大片空白）
3. **记忆节点不画标签**（消除无意义单字）
4. **内环绕距 0.52**（拉开层次）
5. **中枢呼吸 + 点亮脉冲**（体现"活的"）
6. **悬停高亮链路**（可追踪）
