## 三、关键发现：我缺两个核心技术

### 3.1 3d-force-graph 的默认视觉参数（经过大量实战验证）

```
backgroundColor     #000011        ← 深蓝黑，不是纯黑！
nodeRelSize         4
nodeOpacity         0.75           ← 不是 1.0
linkOpacity         0.2            ← 连线 20%（我之前 5.5% 太淡，18% 接近了）
linkCurvature                       ← 曲线，不是直线
linkDirectionalParticles            ← 沿边流动的粒子
```

### 3.2 ★ Bloom 泛光后处理（我之前完全没有）

**这是我最大的缺失。**

真实的高科技感画面（星域、赛博朋克、科幻 UI）都有 **Bloom**：
- 亮的东西会向周围"溢出"光
- 让画面有"发光感"而不是"平涂感"
- 这是「科技感」的核心技术

**3d-force-graph 有专门的 Bloom 示例：**
`https://vasturiano.github.io/3d-force-graph/example/bloom-effect/`

**我们现在的实现完全没有 Bloom。** 节点只是画一个圆 + 一层径向渐变，没有真正的发光溢出。

### 3.3 ★ Link Particles（沿边流动的粒子）

**这个我之前做了，但只用在高亮态。**

3d-force-graph 的做法：
```js
// 每条边都可以有 N 个粒子沿线流动
linkDirectionalParticles(N)
linkDirectionalParticleSpeed(speed)
linkDirectionalParticleWidth(width)
linkDirectionalParticleColor(color)
```

**效果**：数据在流动的感觉。不是静态的连线，而是"有东西在传"。

> 「我并不能理解你的审美了，**这还不如之前的**」

### 4.1 我做错了什么

| 我做的 | 为什么不好 |
|---|---|
星尘 520 颗 | **太密了**，像噪点，不是星空 |
星云 4 团 | **太亮太明显**，像脏污渍，不是星云 |
背景 #1B2836 | **太亮**，失去了"深空"感 |
节点光晕 | 无 Bloom，只是渐变圆，不发光 |

**用户说"不如之前的"** —— 之前的版本虽然黑，但至少有"深空"的感觉。
我为了提升"可见像素"（0.5% → 76%），把画面做"满"了，反而失去了质感。

### 4.2 正确的方向

```
之前（错）：为了可见而填满 → 像噪点
现在（对）：少量高亮 + 大量暗部 + Bloom 发光 → 像真实星域
```

**关键：不是"更多可见像素"，而是"正确的明暗对比"。**

真实星空的亮度分布：
```
95% 纯黑 + 5% 星点
星点有强光晕（Bloom）
整体观感：深邃、稀疏、明亮的光点
```

我之前把 76% 做成"可见"，那是错的**方向**。

## 五、正确的设计原则（基于参考）

### 5.1 明暗结构

```
层级            亮度        占比
────────────────────────────────────
深空底          #000011      85%
                                 （保留深邃感，不要提亮）
星尘            微弱          10%
                                 （稀疏，不是噪点）
星云            中等          4%
                                 （柔，不是亮斑）
节点            明亮          1%
                                 （Bloom 发光）
高亮态          耀眼          <0.5%
                                 （强 Bloom）
```

**核心：大量深色 + 少量高亮 + Bloom 发光。**

### 5.2 Bloom 实现方案（Canvas 2D，无 ThreeJS）

不需要引入 ThreeJS。Canvas 2D 可以用"多次模糊叠加"模拟 Bloom：

```js
// 1. 画所有发光物体
// 2. 用 globalCompositeOperation='lighter' + shadowBlur 叠加
// 3. 或者：画完之后，把画布缩小 1/4，再放大回去叠加（廉价模糊）
```

**最简方案：**
```js
// 主画布画基础内容
// 创建离屏画布（1/4 尺寸），把亮的部分画上去
// 用 CSS filter: blur 或多次缩放模糊
// 用 'lighter' 混合模式叠加回主画布
```

### 5.3 连线

```
linkOpacity 0.2        （不是 5.5%，不是 18%）
linkCurvature          （曲线）
linkDirectionalParticles 2~3  （沿线流动粒子）
```

### 5.4 节点

```
nodeOpacity 0.75
光晕 → 靠 Bloom 实现，不靠手动径向渐变
```

## 六、我要做的重设计

### 6.1 撤回错误

- 星尘 520 → 回到 200 左右（稀疏才像星空）
- 星云透明度 0.34~0.52 → 降到 0.12~0.20（柔，不是亮斑）
- 背景 #1B2836 → 回到 #000011 附近（深空）

### 6.2 新增 Bloom

```
实现：离屏画布 + 缩放模糊 + lighter 混合
效果：所有发光物（节点/高亮边/粒子）都有真实光晕溢出
```

### 6.3 新增 Link Particles

```
每条边在"关联活跃"时，有 2~3 个粒子沿曲线流动
符合用户要求："每个场景在受到主agent命令被执行后亮起，并互相亮线关联"
```

## 八、一句话

> **我错在把"更多可见像素"当成目标，把画面填满了，失去了深空感。**
>
> **参考 3d-force-graph（GitHub 上万星项目）后，正确方向是：**
> **· 85% 深空底（保留深邃）**
> **· 少量高亮 + Bloom 泛光（真实发光感）**
> **· 连线 20% 透明度 + 沿线流动粒子**
>
> **我之前完全没有 Bloom —— 这是「科技感」的核心技术缺失。**
