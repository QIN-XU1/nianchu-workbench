## 一、③ 点击后不相连节点也高亮 —— 索引错位 bug

### 1.1 根因

```js
// 建边时（第 484-485 行）
na.links.push(ei);
nb.links.push(ei);           // ← ei 是 S.edges 的索引

// 渲染时（第 940 行）
const sortedE = S.edges.slice().sort(...);   // ← 排序后顺序变了

// 循环（第 948-949 行）
for (let ei = 0; ei < sortedE.length; ei++) {
  const e = sortedE[ei];                    // ← ei 变成 sortedE 的索引

// 查询（第 969 行）
highlightLinks.has(ei)                      // ← 用 sortedE 索引查 S.edges 集合
```

**索引错位 → 高亮的边完全随机 → 出现"不相连的节点也被连线"。**

### 1.2 修法：用对象引用

```js
// 建边
na.links.push(edges[ei]);    // 存对象引用（不受排序影响）

// 高亮集合
for (const linkObj of focusNode.links) highlightLinks.add(linkObj);

// 查询
const isNeighborLink = highlightLinks.has(e);   // 用对象引用
```

### 1.3 实测

```
选中「管线」，真实邻居 3 个，高亮 4 个（含自己）
错误高亮：无   ✓
```

## 二、① 滚轮改为画布级 2D 缩放

### 2.1 自检：之前用 fov（3D 透视缩放）

```js
const fov = (S.radiusX || R) * 2.6 / S.zoom;   // ← 改 fov
```

**这是 3D 透视缩放：近处物体放大很多、远处几乎不变 → 视觉变形。**

### 2.2 画布工具的正确做法（Photoshop / ComfyUI）

```
① 缩放 = 2D 仿射变换（viewScale）
   整个画面按比例缩放，所有物体等比变大
② 缩放以光标为锚点（光标下的内容保持不动）
③ 平移 = 画布偏移（panX / panY）
```

### 2.3 实现

```js
// 状态
viewScale: 1.0,    // 2D 缩放倍数
panX: 0,           // 平移
panY: 0,

// render 里（背景画完后）
const vs = S.viewScale || 1;
const panXv = S.panX || 0;
const panYv = S.panY || 0;
c2d.setTransform(DPR * vs, 0, 0, DPR * vs, DPR * panXv, DPR * panYv);
```

**这样所有绘制（星点/节点/边/标签）自动缩放，无需改绘制代码。**

### 2.4 锚点公式（这里犯了个错）

**第一版（错）：**
```js
S.panX = mx - worldX * newScale - W / 2;   // ← 多减了 W/2
```

**实测偏差正好 610px = W/2。**

**正确推导：**
```
屏幕 = proj × vs + pan  →  proj = (screen - pan) / vs
锚点：mx = projP × vs1 + pan1
→ pan1 = mx - (mx - pan0)/vs0 × vs1
```

**修正：**
```js
S.panX = mx - (mx - oldPanX) / oldScale * newScale;
S.panY = my - (my - oldPanY) / oldScale * newScale;
```

**实测：节点位移从 651px → 0px。**

### 2.5 坐标补偿（引入变换后必须同步）

| 位置 | 补偿方式 |
|---|---|
`hitTest` | `screenSx = pr.sx * vs + panX`，命中半径 × vs |
拖节点 | 目标位置 `(ev.offsetX - panX) / vs` |
grab 偏移 | 同上 |

## 三、② 连线"断断续续"的第三个原因

### 3.1 之前只想到两个原因

| 试过的 | 结果 |
|---|---|
① 渐变两端太淡 | 改为纯色 → 仍断 |
② 星形半透明导致穿透 | 改为不透明 → 仍断 |

### 3.2 真正原因：**亚像素渲染**

```
普通边线宽 0.38px
DPR = 1.25（实际渲染 0.475 物理像素）
→ 某些像素渲染不下 → 出现"点状断线"
```

**这不是颜色问题，是**物理像素不足**。**

### 3.3 修法

```js
// ① 线宽下限 0.5px（保证至少半个物理像素）
lineW = Math.max(0.5, lineW);

// ② 圆头端点（避免方块状断点）
c2d.lineCap = 'round';
c2d.lineJoin = 'round';
```

**用户说得对："并不一定要做渐变处理"——问题根本不在渐变。**

## 四、"具体怎么连" — 四级强度模型

用户说「隐隐连线形式很好，但具体怎么连你得深究」。

### 4.1 四级连接强度

| 级别 | kind | 依据 | 含义 | 视觉 |
|---|---|---|---|---|
**L1** | `flow` | 契约 `outputs.to` | A 的产物直接给 B 用 | 0.42 / 0.9px |
**L2** | `indirect` | **共同邻居**（图论） | 通过 C 有工作流关联 | 0.20 / 0.65px |
**L3** | `domain` | domain 字段相同 | 同类工作 | 0.11 / 0.52px |
**L4** | `similar` | role 关键词重叠 | 职责相似 | 0.06 / 0.48px |

### 4.2 为什么 L2 用"共同邻居"

```
A ──→ C ──→ B
若 A、B 都连到 C，说明它们在**同一个工作流**里
这是图论里最可靠的"间接关联"依据
```

**比"同领域"更有说服力**：同领域只说明类型相似，共同邻居说明真的在协作。

### 4.3 防止爆炸

| 级别 | 限制 |
|---|---|
L2 indirect | 只保留最强 30 条（按共同邻居数排序） |
L3 domain | 同领域节点 > 8 个时不加 |
L4 similar | 仅在节点数 ≤ 40 时启用，且关键词交集 ≥ 2 |

**实测当前 10 个节点：domain 10 条 + similar 11 条。**

### 4.4 视觉分级（"隐隐的"）

```
L1 flow      0.42 / 0.9px   ← 明确
L2 indirect  0.20 / 0.65px  ← 中等
L3 domain    0.11 / 0.52px  ← 隐隐
L4 similar   0.06 / 0.48px  ← 极淡
```

**每级差距约 2 倍，视觉上能分辨层次但不会突兀。**
