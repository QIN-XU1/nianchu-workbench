# 15 · 真实数据可用 + 基线分离（第五轮实测）

> 本轮的关键词：**sea 第一次在真实项目数据上工作，并驱动了一次真实修复。**

---

## 1. 这轮发现的架构冲突（重要）

### 1.1 冲突本身

| 需求 | 矛盾 |
|---|---|
门禁要 **G1 基线必须通过** | 否则无法证明 check 不是"恒定失败" |
真实场景的价值 | **恰恰是它的数据可能有问题**（否则没什么可查） |

我最初让 `docs-index` 场景直接用真实数据（README 索引确实漏了文档），结果：

```
门禁 validate → REJECT
  G1 基线通过 : false     ← 基线就报错
```

**这不是门禁的错，是架构缺了一层。**

### 1.2 解法：基线与真实数据分离

```
scenes/docs-index/
├── scene.json    { ..., baselineDir: "baseline" }
├── check.mjs
├── data/         ← 真实数据（可以有问题）
└── baseline/     ← 干净基线（门禁用它证明 check 不是恒定失败）
```

- **门禁 G1 + 变异** 全部跑在 `baseline/` 上
- **首屏 + sea check** 跑在 `data/` 上

**效果**：

| 用途 | 结果 |
|---|---|
门禁认证 | ✅ **ACCEPT**（G1 true / G2 2/2 / G3 true / G0.5 true） |
首屏 | ✅ **报出真实问题**：`未登记文档 2(13-…, 14-…)` |

> **这是本轮最重要的设计**：一个场景同时做到"既能被机器认证，又能报出真实问题"。

## 5. 这轮暴露的新问题

| # | 问题 | 影响 | 计划 |
|---|---|---|---|
**E1** | `docs-index` 的 `data/` 是**手工快照**，不会自动跟随 README 变化 | 真实场景会"过期"，报旧问题 | 需要 `tools/refresh-docs-index.mjs` 自动从 README 生成数据 |
**E2** | 没有 `baselineDir` 的真实场景**无法被认证** | 会挡住真实场景 | 需给出"如何获得干净基线"的指引 |
**E3** | 我手工造数据时**误报过 4 篇** | 说明"数据不实时"会直接导致误报 | E1 的修复是必须的 |

**E1 最关键**：一个"手工快照 + 不自动更新"的检查，就是会过期的检查。
这正好是 `docs-index` 场景要检查的东西的**反面**——有点讽刺，也很真实。
