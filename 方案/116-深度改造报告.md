## 问题 1 · 顶尖专家会做哪些我没要求的事情

### 我原来的做法 vs 顶尖做法

| 我在做的 | 本质 | 是不是「更深」 |
|---|---|---|
49 个哨兵工具 | 加机制 | ❌ 更大 |
117 份方案文档 | 加文档 | ❌ 更大 |
9 个场景 × 6 件套 | 加覆盖度 | ❌ 更大 |
127 项插件测试 | 加测试 | ❌ 更大 |

### 两份独立调研指出的、我没要求但必须做的事

**记忆系统方向**（36 KB 报告，26 个 arXiv 编号核验）：

1. **失效机制（invalidation）而非只追加** ← 硬伤级
   - arXiv `2610.36308`：把一条无关证据换成一条**过期的竞争事实**，
     准确率从 **100% 掉到 44.6%**
   - 我的 AGENTS.md 里写「§五 只追加」，**在结构性制造过期事实**

2. **写入是 ADD/UPDATE/DELETE/NOOP 四选一**，不是追加
   - 依据：Mem0 论文 `2504.19413` §2.1 原文

3. **记忆安全**
   - arXiv `2611.01700` MemHarmBench：恶意指令存入记忆后，
     即使原始攻击内容删除，仍然生效且 "behaviorally stealthy"
   - 我的 `发消息.mjs` → `_跨场景通知.md` 就是一条**无校验的写入通道**，
     现有 9 个哨兵没有一个能发现

4. 其余：三因子排序（recency×importance×relevance，`Generative Agents`）、
   provenance、后台巩固、分层摘要、上下文硬预算、净价值核算

**自进化方向**（29.8 KB 报告，论文编号逐条核验）：

1. **你有「可回滚」，缺「可证伪」** ← 核心判断
   - 回滚解决「改坏了能退」，不解决「怎么知道改好了」

2. **Agent 控制验证器时，自评必然脱钩**
   - arXiv `2607.24300`（6 模型 3 种子）
   - 我的 L2/L3 从没跑过 —— **这恰好保护了我**

3. **别只从最优往下改**
   - DGM 项目页：最优 agent 的路径上**常常经过比父代更差的中间体**
   - 我的自动回滚是爬山逻辑，会过早收敛

4. **技能必须是可执行 + 有检索键**（Voyager `2305.16291`）
   - 我的 `SKILL.md` 是纯文本、无可执行部分、无检索键
   - 严格说只能算提示词，不算技能

## 问题 3 · 他们会用什么具体方法和工具

### 检索
```
语义 + BM25 + RRF（Reciprocal Rank Fusion）+ 图距离重排
```
Graphiti 官方文档原文写明 "reranked using Reciprocal Rank Fusion"。

**但调研也指出**：我的记忆只有 15,893 B ≈ 8–10k token，
**远没到需要检索的规模，全量注入是对的。现在上向量库是过早优化。**

### 评估（这一点最重要）

指标口径从 LongMemEval 源码核出来：
```
recall_all@5 / ndcg_any@5 / recall_all@10
评检索时恒定跳过 30 个 abstention 实例
```

业界证明「A 比 B 好」要四件事同时成立：
1. 同基准同预算
2. **检索分与答对分分开报**
3. **收益必须配成本**（Mem0 的结论句式是 "26% judge 提升 + 91% p95 延迟降低 + 90% token 节省"）
4. **必须有 Raw-RAG 基线**

**我现在四条一条都不满足。**

### 开源工具（star 数经 GitHub API 核验）
```

topoteretes/cognee     33.2k
```

## 本轮实际执行的改造

### 1. 修掉进化观察期三个 bug（依据调研 P2）

| # | bug | 修法 |
|---|---|---|
1 | `DEGRADE_THRESHOLD` 定义了但从不使用 | `--observe` 用它自动判定 |
2 | 注释「3 次任务」，实现 +3 日历日 | 拆成 `OBSERVE_DAYS` / `OBSERVE_MIN_SAMPLES` |
3 | 观察结果由人传字符串，无证据绑定 | 改为 `--sealed-delta` + `--samples` |

**带反例验证**：
```
不带 --sealed-delta   → exit 2，拒绝
--samples 1（<3）    → exit 2，拒绝
```

### 2. 新增第 10 个哨兵：记忆召回哨兵

`workbench/工具/记忆召回哨兵.mjs`

现有 9 个哨兵全在验「字节数」= 只验了「编译通过」。
这个验的是**记忆里到底有没有该知道的事**：
```
recall_all@k / recall_any@k / 注入成本
阈值: RECALL_MIN=0.70, INJECT_TOKENS_MAX=8000
```
自测 9/9，含 2 条反例。**自测抓出我自己一个 bug**（切块逻辑导致 recall 永远算 0）。

### 3. 修复两个致命断层（这是本轮最重要的成果）

#### 断层 1：场景定位卡从未注入给 AI

**证据**：`main.js` 里只有 `buildSiteSystem` / `buildOaSystem` 两个构造器，
搜「场景私有记忆」= 0 次、「身份卡」= 0 次、「AGENTS.md」= 0 次。

而 9 份定位卡躺在 `scenarios/*-context.md`，AI 永远读不到。

**修法**（从引擎源码找到通道）：
```
dsh-agent-instructions 的 DEFAULT_LOCAL_INSTRUCTION_FILE_CANDIDATES
  = ["AGENTS.local.md", "CLAUDE.local.md"]
```
→ 新建 `workbench/工具/场景注入.mjs`，为每个场景生成 `AGENTS.local.md`，
内容 = 定位卡 + 铁律 + 身份卡 + §〇交接 + §五坑 + 写回指令，**预算 2048 B**

实测 9 个场景全部 ≤2048 B。

#### 断层 2：场景会话不存在

7 个场景的 sessionId 是占位符（引擎里不存在）。身份哨兵一直在报警。

**修法**：从 `dsh-client-connection/lib/client.node.js` 源码摸清 RPC 协议：
```
POST /api/session/create
{ type:"client-request", rpcId, method:"session/create", payload:{ args:{ request:{ cwd } } } }
```
踩了 4 次坑才全对（method 要完整路径、payload 要包 args、request 是字段名）。

### 4. 修 DSH_HOME（这个坑埋得很深）

会话一直写旧目录。查了半天发现 `main.js` 第 24 行：
```js
const guess = pathm.join(__dirname, '..', '引擎数据', '.dsh');
process.env.DSH_CUSTOMER_HOME = guess;
```
而 `serverSpawnEnv()` 是 `DSH_CUSTOMER_HOME || path.join(DATA_DIR,'.dsh')`
→ **这个变量优先级更高，数据迁移等于白做**。

### 5. 端到端验证通过（严格，避免假阳性）

第一次验证报「✅ 注入成功」是**假阳性**（「架构梳理」来自我的问题）。
改用严格方法：从注入文件取独一无二的特征字符串，直接搜会话 record 全量 JSON。

```
✅ 会话存储在 数据/.dsh/sessions（正确位置）
✅ 未污染旧目录
✅ 场景注入 4/4 标记全部命中
```
