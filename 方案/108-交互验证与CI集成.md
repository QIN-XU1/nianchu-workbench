## 一、核心突破：交互不再靠模拟点击

### 1.1 问题的本质

上一轮我花了大量时间在**屏幕坐标点击**上，反复失败：

| 尝试 | 结果 |
|---|---|
固定坐标点击 | 打到桌面（DPI 1.25 缩放导致坐标偏移） |
`WindowFromPoint` 探测 | 永远返回 `FolderView` |
UI Automation | 只能看到窗口按钮（Electron 内容是 Chromium 渲染） |
CDP 连接 | `json/list` 只有 Host 进程，无渲染进程 |
窗口缩放/最大化 | 侧边栏折叠状态变化，坐标全失效 |
网格标定 | 能标对一次，窗口一变化就失效 |

**根本问题**：坐标点击依赖太多不稳定因素（DPI、窗口位置、侧边栏折叠、滚动位置），
每次界面调整都要重新标定，成本极高且不可复用。

### 1.2 正确的做法：用测试驱动状态

关键转变：**不模拟点击，而是直接调用组件的 props 回调。**

```js
// 从渲染树里找到 SceneCard 实例
const cards = findAll(el, (n) => n.type?.name === 'SceneCard', true);
const hubCard = cards.find((n) => n.props.scene.id === 'hub');

// 直接调它的 onPick —— 等价于用户点击
hubCard.props.onPick('hub');

// 重渲染，断言详情抽屉出现
el = render();
const detail = find(el, (n) => n.props?.className === 'mn-detail');
assert(detail !== null);
```

这比坐标点击可靠一万倍，因为：
- 不依赖像素/DPI/窗口状态
- 不依赖滚动位置
- 失败时能精确知道是哪一环断了
- 可以在 CI 里跑，不需要 GUI

### 1.4 写这个测试时踩的 4 个坑（都是 React 语义问题）

**坑 1：hook 状态没有跨渲染保存**
```js
// 错：每次 render 清空 hookState
function render() { hookState.length = 0; ... }
```
修正：全局保留 `hookState`，`render()` 只重置读取指针 `hookIndex`。

**坑 2：子组件污染主组件 hook 序列**
```js
// 错：walk 展开子组件时重置 hookIndex
if (typeof node.type === 'function') { hookIndex = 0; ... }
```
修正：按组件名分池 `componentHooks: Map<name, stateArray>`，每个组件独立索引。

**坑 3：useEffect 每次渲染都重跑，覆盖了 setState 的结果**
```js
// 现象：点击卡片 → setSelected → 重渲染 → useEffect 又跑 load() → 状态被覆盖
```
修正：模拟 React 的空依赖语义，用 `effectRan: Set<component#index>` 去重。

**坑 4：`find` 找不到函数组件节点**
```js
// walk 遇到函数组件时直接执行它，不访问节点本身
```
修正：加 `keepComponents` 参数，先 `visit(node)` 再展开渲染结果。

**这 4 个坑说明一件事**：简易 React 替身要能正确模拟语义，比想象中难。
但一旦做好，后续所有交互测试都能复用。

## 二、测试自己抓出的 2 个真实 bug

### 2.1 刷新没带 force=1（误报，已澄清）

测试报 `刷新请求带 force=1` 失败，读到的 URL 是 `/memory-neuron/overview`。

**排查**：代码里 `onClick: () => load(true)` 是对的。
**真相**：测试在点刷新后立刻读 `fetchUrls[length-1]`，但此时新请求还没发出（异步）。
**修正**：加 `await sleep(60)` 再断言。修完后测试通过，说明代码本身没问题。

**教训**：测试失败不一定是代码错，也可能是测试自己有时序问题。

### 2.2 详情不显示「输入依赖」（测试数据缺失）

测试报 `详情含「输入依赖」` 失败。

**排查**：真实数据里 hub 有 3 条入边（`incident-analysis → hub` 等），
但测试用的 mock 数据里 hub 只有出边、没有入边，所以详情走的是「无输入依赖」分支。

**修正**：给 mock 数据补一条 `build-plan → hub` 的边。修完后测试通过。

**教训**：测试数据必须覆盖真实数据的所有分支，否则断言的是错误前提。

## 三、界面细节修复

### 3.1 去掉原生 tooltip

`OpsRow` 原来给 `v` 加了 `title={v}`，鼠标悬停会弹出**浏览器原生 tooltip**，
与宿主的 Tooltip 组件风格完全不同（截图里抓到了那个突兀的黑底白字气泡）。

**修正**：移除 `title` 属性。宿主有自己的 Tooltip 组件，如果要做悬停提示应该用它而不是原生属性。

### 3.2 待办列表文案修复

**问题 1**：正则被吃掉了反斜杠
```js
// 错（实际文件内容）：
String(line).replace(/^s*-s*[[^]]*]s*/, '')
// 对：
String(line).replace(/^\s*-\s*\[[^\]]*\]\s*/, '')
```
这是编辑器/工具链处理反斜杠时出的问题。

**修正**：抽成独立函数 `cleanTodoLine()`，用 `match` 而不是 `replace` 更稳妥：
```js
function cleanTodoLine(raw) {
  let s = String(raw || '').trim();
  const m = s.match(/^[-*]\s*\[[^\]]*\]\s*(.*)$/);
  if (m) s = m[1];
  else s = s.replace(/^[-*]\s*/, '');
  return s || raw;
}
```

**问题 2**：待办文案被单行截断
```
显示：- [2026-11-09 10:52] 机制体检失败：越界哨兵（...
应该：机制体检失败：越界哨兵（1 项）
```

**修正**：
- 用 `cleanTodoLine` 去掉 `- [时间] ` 前缀
- 待办行加 `data-multiline="1"`，允许两行显示（`-webkit-line-clamp: 2`）

## 六、方法论总结

### 6.1 验证交互应该走代码路径，不走像素路径

| 方式 | 可靠性 | 可维护性 | 可 CI 化 |
|---|---|---|---|
坐标点击 | 低（DPI/窗口/滚动都影响） | 差（每次 UI 改动要重标定） | 否 |
CDP 注入 | 中（需要渲染进程可连） | 中 | 否 |
**prop 回调驱动** | **高** | **好** | **是** |

坐标点击只用于「证明界面确实渲染出来了」（截图），
交互逻辑一律用编程方式验证。

### 6.2 测试失败要先区分「代码错」还是「测试错」

本轮 2 个「失败」最后都查明是测试自身问题：
- 刷新 force=1：测试有时序问题
- 输入依赖：测试数据缺分支

**如果不做这个区分，很容易为了"让测试通过"而改坏正确的代码。**

### 6.3 简易 React 替身必须模拟这些语义

要正确驱动组件测试，替身至少要做到：
1. `hookState` 跨渲染保留（按组件名分池）
2. `useEffect` 空依赖只跑一次
3. `walk` 能访问函数组件节点本身（不只是展开后的结果）
4. hook 索引按组件隔离，不互相污染

少任何一条，测试结论都不可信。
