## 五条最硬的判断（v2 修订）

### 1. 权限在数据里，不在提示词里（**保留，但改实现点**）
> 实现点不是自造 Policy 引擎，而是官方的：
> `tools/pre-execute` waterfall（可 deny/ask，**参数不可改写**）→ **monotonic guards（`ctx.tools.guard()`，最终否决）** → `ctx.approval`（**closed outcome，fail-closed**）。
> 依据：`docs/tool-execution-pipeline.md`、`docs/subsystems/{tools,approval}.md`

### 2. 能自己"长"的只有 D 档（**保留，落点改为官方 seam**）
> 应用层 = `extensions/cordis-host-runner`（**沙箱化 host-half 生命周期**）。
> 回滚 = **注册即 effect**（`register()` 返回 disposer）——可回滚是官方架构的天然属性，不是我要设计的。

### 3. 没有"会失败的检查"的规矩 = 口号（**保留，改用官方更强的表述**）
> 官方原文：**"A guard only guards if the regression fails it."**
> 且必须**证明它**：引入回归 → 看它变红 → 回退。
> 依据：`docs/testing.md`

### 4. 只有非编码场景也能判定"做完了"，才算通用（**保留，这是唯一必须新造的概念**）
> **DoneSpec 三形态**：`check`（跑命令，输出**差异集合**）/ `evidence`（可复核物证）/ `review`（具名人）。
> 官方有 `deliverables`（声明交付物）与 `plan`（过程审批），但**没有"完成机器判据"**。

### 5. 【新增】模型可见 ⟺ 已记录
> **任何进入模型请求的东西，必须能从会话日志重建；新增模型可见输入必须是会话事件。**
> 这条**推翻了我 v1 的 SQLite 数据模型设计**：Ticket 阶段、Mandate 摘要若会进提示词，就**必须**是 `SessionEventMap` 扩展 + 纯消息投影，不能另起"影子表"。
> 依据：`docs/architecture.zh.md`、`AGENTS.md` 同名规则

```
L6 运维   Watchdog · 审计 · 预算闸 · 回滚 · 【自己写 SAFETY 声明】

L4 人机   approval · ask-user · actionCards · feedback/ · liveshare
L3 编排   ★ 本项目：场景契约层（若需要）
          [官方] preset/ · subagent/ · team/ · goal/ · workflow/
L2 领域   ★ 本项目：Ticket / Mandate / DoneSpec（**全部为会话事件**）
          [官方] core/session（事件溯源）· session/projection
L1 能力   tools/ · skill/ · spill/ · compaction/ · context/ · fs/ · shell/ · sandbox/ · credentials/ · deliverables/
L0 宿主   deepseek-harness（Cordis 全插件，**不 fork**）
```

**图上最重要的一句：★ 只有两处。其余全绿。**

## 三个必须承认的现实（v2）

1. **官方 API 是 pre-stable**（`AGENTS.md`）→ 方案架在它上面，**升级会破**（R-13）。
2. **证实"不需要造"是好结果**：若 P0 的 F-1 成功，方案瘦身到"约定 + DoneSpec"，可能显得不够深入，但这是正确的（R-14）。
3. **最可能失败的不是技术，是注意力**：价值 = `被采纳的工作 / 人类付出的注意力`。
