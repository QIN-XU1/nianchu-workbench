## 二、我补充的三个判断

### 2.1 边从哪来 —— 用真实契约数据，不编造

```
sceneboard/scenes/<id>.json 有：
  inputs:  ["feature-matrix", ...]                    ← 依赖的产物
  outputs: [{ id:"architecture-plan", to:["build-plan"] }]  ← 产物流向

→ 用 outputs.to 建边 = 真实的依赖关系
→ 契约没建出边时，兜底用同领域两两相连
```

实测建出 **10 条边**。

### 2.2 「多个球体」的正解 —— 单球面扇区，不是球中球

**我先做错了一版**：把小球的球心放在主球内部，导致节点全在球内。

**实测证据：**
```
R = 279
dist 范围: 109 ~ 279
在球面上的节点: 2 / 10     ← 大量节点在球内部
```

**修正：所有节点直接铺在大球面的扇区**
```js
每个领域分配经度扇区（宽度 ∝ 场景数）
节点在扇区内：经度均铺 + 纬度铺开（±0.72弧度）
```

**修正后：**
```
R = 158
dist 范围: 157.8 ~ 157.8
在球面上的节点: 10 / 10  ✓
```

### 2.3 「行星感」的真解 —— 领域轨道带

用户说要"行星之间的美感"。行星感的核心是**轨道**，但用户又明确不要画球体轮廓。

**我的折中**：不画球体轮廓，但画**领域轨道带** ——
每个领域按其节点平均纬度，在球面上画一条极淡的闭合弧（透明度 9%），
沿线加 8 个刻度点。多个领域 → 多条轨道交错 = 卫星系统观感。

截图可见：左侧那条弧线就是"内容领域"的轨道。

## 三、技术实现

### 3.1 数据层

```js
// 1. 只加载场景（filter !isHub）

  social:  ['关系','情感','沟通','军师','复盘','自我']
]
// 3. 边：从契约 outputs.to
// 4. 附属物：身份卡/私有记忆/面板数/能力/MCP（点击展开）
```

### 3.2 布局层

```
单领域  → spherePositions(n, R)   [黄金角球面螺旋]
多领域  → 扇区经度均铺 + 纬度铺开   [同领域聚集，全部贴球面]
```

**为什么这样能保证在球面**：
经度 lon + 纬度 lat 直接生成球面坐标：
```js
x = cos(lon) · cos(lat) · R
y = sin(lat) · R
z = sin(lon) · cos(lat) · R
→ 恒等式：x² + y² + z² = R²   （永远在球面）
```

### 3.3 交互层

| 操作 | 行为 |
|---|---|
拖空白 | 旋转（yaw += dx·0.008, pitch += dy·0.0058, pitch 限 ±1.40） |
拖节点 | 位移反旋转到世界坐标，标记 dragged |
滚轮 | 缩放 0.5~2.0 |
点击节点 | 展开详情（附属资源芯片） |
点「整理」 | 记录起点 → 清 dragged → 重算球面 → 420ms easeOutCubic 动画 |

### 3.4 视觉层

```
✓ 深空渐变背景 + 150 星尘（缓慢闪烁）
✓ 无经纬线，只有球形边缘散射光（暗示体积）
✓ 领域轨道带（9% 透明度弧线 + 8 个刻度点）
✓ 背面节点淡化（26%~56%）
✓ 透视投影（近大远小）
✓ 节点大小 ∝ 连接度数
✓ 边是弧线，选中时流动光点
✓ 标签只画朝前的（背面不画，避免杂乱）
```
