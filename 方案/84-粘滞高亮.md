# 84 · 粘滞高亮（拖拽背景时高亮不熄灭）

> 用户：「我希望我在拖拽整个背景时，原先高亮的节点**不会被熄灭**」

---

## 一、先自检：到底哪里熄灭了

### 1.1 测试证明「旋转本身不清除高亮」

```
① 悬停节点       → hover = "自我复盘"
② 拖拽旋转后     → hover = "自我复盘"（保持）
③ 鼠标移出画布   → hover 仍残留（bug，但不是用户说的问题）
```

**`pointerdown` 里旋转分支没有任何清除高亮的代码。**

### 1.2 找到真正的熄灭点

看 `pointermove` 的悬停逻辑：

```js
// ── 悬停 ──
const n = hitTest(ev.offsetX, ev.offsetY);
if (n !== S.hover) {
  S.hover = n;                          // ← 未命中时为 null
  cv.style.cursor = n ? 'pointer' : 'grab';
  render();
}
```

**问题：鼠标一旦离开节点（`hitTest` 未命中），`hover` 立刻变 null，高亮瞬间熄灭。**

拖拽背景时鼠标必然离开节点 → 高亮必然熄灭。

**这才是用户感受到的问题。**

---

## 二、解决方案：粘滞高亮（sticky focus）

### 2.1 设计

```
焦点优先级：
  ① hover    —— 鼠标当前悬停（最强，power 0.88）
  ② sel      —— 点击选中
  ③ sticky   —— 粘滞焦点（离开后保持，power 0.76，稍弱）
```

**关键：未命中节点时，不清除 stickyFocus。**

### 2.2 实现

```js
// 状态
stickyFocus: null,
stickyAt: 0,

// hover 命中时记录
if (n) {
  S.stickyFocus = n.id;
  S.stickyAt = Date.now();
}
// 未命中时**不清除**（这正是"不熄灭"的关键）

// focusId 计算时加粘滞优先级
let focusId = (S.hover && S.hover.id) || (S.sel && S.sel.id) || null;
if (!focusId && S.stickyFocus) {
  const age = Date.now() - (S.stickyAt || 0);
  if (age < 90000 && S.byId[S.stickyFocus]) {     // 90 秒有效期
    focusId = S.stickyFocus;
  } else {
    S.stickyFocus = null;                          // 超时清除
  }
}
```

### 2.3 视觉：粘滞比真实悬停稍弱

```js
// drawStarlight 内部
else if (isFocus) power = isSticky ? 0.76 : 0.88;
```

**理由：用户能区分"鼠标在哪"（强）和"上次看的是哪个"（稍弱）。**

---

## 三、实测验证（7/7 通过）

```
① 悬停"自我复盘"
   hover = "自我复盘"   sticky = "self-review"          ✓
② 鼠标移开节点
   hover = null（正常清除）
   sticky = "self-review"（保留）                        ✓
   focusId = "self-review"（仍指向）                      ✓
③ 拖拽背景旋转 6 步
④ 旋转结束后
   focusId = "self-review"（高亮未熄灭）                  ✓
   yaw = -0.8（视角确实转了）                             ✓
```

**截图确认：鼠标早已离开，「自我复盘」在右上角仍保持高亮。**

---

## 四、设计取舍说明

| 参数 | 值 | 理由 |
|---|---|---|
粘滞有效期 | 90 秒 | 足够拖拽/旋转/思考，又不会永久残留 |
粘滞强度 | power 0.76（vs hover 0.88） | 稍弱，可区分"鼠标在哪" |
清除时机 | 悬停到新节点 / 90 秒超时 | 不打断用户操作 |
点击空白 | 不清除（保持） | 用户可能只是点击空白看整个星域 |

**为什么不用"永久高亮"：**
如果永不清除，时间长了所有看过的节点都亮着，反而失去焦点意义。
90 秒是"操作窗口"——足够完成一次旋转/拖拽/观察，超时自然消退。

## 五、附带发现

### 5.1 鼠标移出画布后 hover 残留

```
③ 鼠标移出画布 → hover 仍为 "自我复盘"，inside = false
```

**这是个小 bug：** `pointerleave` 只设了 `inside = false`，没清 `hover`。

**但考虑到用户需求（"不要熄灭"），这个"残留"反而是想要的。**
所以**故意保留** —— 鼠标移出画布时保持最后一次悬停，符合"不打断"的设计。

### 5.2 截图发现：画布右下角有三角折线

这是之前排查过的同类问题——边长超出画布。需要单独处理。

## 六、一句话

> **自检证明：旋转本身不会清除高亮。**
>
> **真正的熄灭点在 `pointermove` 的悬停逻辑 ——
> 鼠标一离开节点，`hover = null`，高亮瞬间消失。**
> **而拖拽背景必然让鼠标离开节点。**
>
> **解法：粘滞高亮（90 秒有效期）**
> **未命中节点时不清除，用 stickyFocus 维持高亮，视觉上稍弱（0.76 vs 0.88）。**
>
> **实测 7/7 通过：悬停 → 移开 → 拖拽旋转 → 高亮仍在。**
