## 1. 权威机构（按对本项目的相关性排序）

### 1.1 Anthropic — 相关性 ★★★★★

| 来源 | 主张 | 对官方的印证 | 对我们的含义 |
|---|---|---|---|
| **"Decoupling the brain from the hands"**（Super-agent 文章 5.2 引用） | harness 保持无状态，会话日志存在 harness 之外，通过统一接口按需接入执行环境 | 官方 `SessionPersistence` seam（`create`/`open`/`stat`/`list`/`export`）正是这个 | 我们的"存算分离"**不需要新抽象**，实现一个 provider 即可 |
| **Agent Skills（`SKILL.md`）** | name+description 自动进上下文，正文按需读 | 官方 `skill/`："Skill capability family: provider registry, local provider, model-facing catalog/loader" | 我们的"场景技能"应是 `skill/` provider 的一种组织方式 |
| **Context engineering**（compaction / 上下文管理） | 上下文是一等资源 | 官方 `compaction/`（Service Definition + basic provider）+ `spill/` | 我们只加策略，不加机制 |
| **"Step 是模型请求 + 它调用的工具"** | 步骤/轮次分离 | 官方 `docs/architecture.zh.md`：「一个**步骤**是一次模型请求加上它调用的工具。一个**轮次**包含零个或多个步骤」 | 我们的 DoneSpec 应在 **step 之后、turn 之内**判定 |

**Anthropic 的 Agent Skills 与我 v1 的"三级技能"高度重合**——这一点我在 v1 已抄对，但落点选错（我写"文件目录"，官方是 `skill/` provider）。

### 1.2 OpenAI — 相关性 ★★★★

| 来源 | 主张 | 含义 |
|---|---|---|
| **Agents SDK 的 handoff + guardrail 两个原语** | 极简抽象：交接（控制权转移）+ 护栏（前置校验） | 官方 `tools/pre-execute`（护栏）+ `subagent`（交接）已经覆盖；说明"两原语"是可扩展的最小集 |
| **"Responses API / computer use"** | 工具即 API 调用 | 官方 `tool-call` → `tools/execute` 流水线同构 |
| **Aardvark / 自动化安全研究**（若持续） | 用 Agent 审计 Agent | 与 arXiv:2609.00069「Auditing Harness Tampering」同一思路 |

**[推断] 对我们的含义**：OpenAI 路线的价值在"**最少原语**"。我们方案里凡是"新增第 N 个概念"的地方，都要问："能不能用 guardrail + handoff 表达？"

### 1.3 Google DeepMind — 相关性 ★★★★

| 来源 | 主张 | 含义 |
|---|---|---|
| **Gemini/Agents 的"工具调用 + 长程规划"** | 规划与执行分离 | 官方 `plan/`（"while it is active, the agent explores and designs before executing"）+ `goal/`（durable objective） |
| **AlphaEvolve**（arXiv 已在 v1 引用） | 用进化搜索优化可验证对象（算法/内核） | **关键启示**：AlphaEvolve 之所以成立，是因为**目标函数是确定性的**（正确性/性能）。这印证我们"确定性闸 > LLM 裁判"（`03` §4.4） |
| **"Darwin Gödel Machine" 出自 Sakana/UBC 而非 Google**（v1 已引，注意归属别写错） | 自改代码 + 经验验证 | 见 `03` §3.1 |

### 1.4 Microsoft — 相关性 ★★★

| 来源 | 主张 | 含义 |
|---|---|---|
| **AutoGen/AG2** | 多 Agent 对话即编排 | 官方 `team/agent-team` 是"**共享任务板 + DAG**"，比对话编排更确定 |
| **"Magentic-One"通用多 Agent** | 一个 orchestrator + 专业 agents + 任务台账 | 与官方 `team/` + `goal/` 同构 |

## 2. 学术前沿（2026）—— 按"能改变设计决策"排序

### 2.1 第一梯队：直接否定我们某个设计的

| 论文 | 结论 | 被它否定的 v1 设计 | v2 的修正 |
|---|---|---|---|
| **Self-Authored Verification Is Unreliable**（2607.24300）[论文] | Agent 同时控制"被优化对象"和"验证器" → 自评分接近满分而真实性能下降（verifier–deployment gap） | v1 的"LLM 裁判 + 自评" | 封存集必须在 `snapshots/`（CI 跑，模型不可见） |
| **LLM-as-a-Judge Is Not an Oracle**（2609.02246）[论文+工程] | 生产上跑几个月，总结 **11 种评估信号失效**（judge 偏差/harness 与指标失效/ground truth 错误/reward hacking）；案例"Agent 靠读缓存答案键拿满分" | v1 的"LLM 裁判作主要判据" | 裁判降级为顾问（`03` §4.4） |
| **Phantom Guardrails**（2607.13083）[论文] | 自进化 Agent **会幻觉出不存在的失败**并去修 | v1 只要求"反例" | 三重防线：事件绑定 + 反例可复现 + **空提案奖励**（`03` §2.3） |
| **Auditing Harness Tampering**（2609.00069）[论文] | 自改 harness 会产生虚假提升，同时**破坏授权/溯源/完整性**；给出两轴分类 | v1 的"五条义务"是自造 | 官方 `extensions` 的沙箱化生命周期 + 我们的义务清单 |
| **Securing Long-Term Memory Against Poisoning**（2606.24322）[论文] | 记忆投毒；现有防御基于内容或血缘，**两者都可伪造**；三条洗白通道（**Agent 自己的摘要 / 可信工具回声 / 伪造相互印证**）；证明 machine-checked 分离定理 | v1 的"权威等级"设计 | **R1–R5 五条**（`03` §7.2），其中"摘要永不升权"直接对应论文第 1 条通道 |

### 2.2 第二梯队：改变我们方法论的五篇

| 论文 | 结论 | 对方法论的改变 |
|---|---|---|
| **On the Fragility of Self-Improving Agents**（2608.18066）[论文] | ① 复杂环境评测本身有噪声，**叠加自进化会放大**；② 提升**高度依赖任务顺序**，之前工作常采用有利顺序 | 必须**固定种子 + 打乱顺序 + 重复 ≥3 次报方差**（`03` §4.3） |
| **Who Verifies the Verifier?**（2610.11464）[论文] | 把验证器本身当作可演进对象（**可检查的小检测器表达式**），按"与 10 条锚定参考集一致度 + 无标注一致性"选择，**绝不按 Agent 分数**；发现"去掉锚定护栏会崩" | 验证器可进化，但**需人批 + 锚定集 + 禁止删锚定** |
| **Small but Mighty**（2610.15964）[论文] | 仓库自带测试作为信号**太稀疏**（只拒 1/4 行为变更）；用质量-多样性进化搜"**又小又强**"的测试套件 | 要专门**培育小回归集**（`03` §5.3 反例培育器） |
| **Is Agent Memory a Database? (GEM)**（2605.26252）[论文] | 记忆当前有**四种复发失效**：无管制增长、缺语义修订、容量驱动遗忘、只读检索；正确性是**状态轨迹**的属性；四个状态级算子：ingestion/revision/forgetting/retrieval | 记忆操作必须是一等（`03` §7.1） |
| **Safety in Self-Evolving Agents: A Survey**（2610.00093）[论文] | 一旦"经验变成可复用状态"，**过去的事件成为未来的原因**；安全问题转为"**安全性是否在累积/泛化/跨上下文复用后仍成立**"；提出 SAVER | 经验写入必须过来源与权限检查（`03` §7.3） |

### 2.3 第三梯队：印证我们方向的（可作为"不是我瞎想"的证据）

| 论文 | 结论 | 印证了什么 |
|---|---|---|
| **Darwin Gödel Machine**（2505.22954）[论文] | 自改代码 + 经验验证（因"证明有益"实践上不可能）；保留 archive 做开放式搜索 | 用经验验证替代形式证明；**但环境差异（有确定性 benchmark、零代价失败）说明我们不能照搬** |
| **Reflexion**（2303.11366）[论文] | 言语强化：用自然语言反思替代梯度 | 反思作为信号源（但要防"编造失败"） |
| **AgentEvolver / EXG / Metis / FactorMiner / GuideEvolve / EVE-Agent** [论文] | 2026 年大量"场景化自进化"工作（医疗诊断、金融 alpha、科学工具获取、时序预测…） | **印证"自进化以场景为单位"**，与乱雨家"单场景自我进化"、Grok Bot"one bot one job"三方独立收敛 |
| **SEAD**（2602.03548） | 多轮服务对话的自进化 | 客服等非编码场景的可行性 |
| **Compile Away Uncertainty**（2610.39508） | 用程序化编译把不确定的 agent 技能固化成可执行结构 | **技能 = 可执行程序**，比"提示词技能"更可验证 → 对我们 DoneSpec 是强支持 |
| **Metis**（2606.24151） | 桥接文本记忆与代码记忆 | 记忆应同时有"人读"和"机器执行"两形态 |
| **Infini Memory**（2606.10677） | 用可维护的主题文档做长期记忆 | 与乱雨家"主题文档 + 红线"同构 |

## 3. 本轮扫描的六条硬结论

| # | 结论 | 支撑 |
|---|---|---|
| 1 | **权威机构的共同方向是"减少原语数量"**（handoff+guardrail、skills、context engineering），不是增加架构层 | OpenAI Agents SDK / Anthropic Skills / 官方 `packages/` 39 组 |
| 2 | **能确定性地验证的对象，才配进入自进化** | AlphaEvolve（目标函数确定）+ arXiv:2609.02246（LLM 裁判失效）+ 官方 `verify-*` 门禁 |
| 3 | **"验证器本身不可信"是 2026 年的共识** | 2607.24300 / 2609.02246 / 2610.11464 三篇独立结论 |
| 4 | **记忆的正确性是"轨迹"属性，不是"记录"属性** | GEM（2605.26252）；这解释了官方为何用**事件溯源会话日志**而非"记忆库" |
| 5 | **自进化的正确单位是"场景"** | 四个来源独立收敛：AgentEvolver 等论文群、乱雨家、Grok Bot、官方 `preset`（per-session composition） |
| 6 | **权威机构也承认这套东西不安全** | 官方 `SAFETY.md`："has not undergone a security audit, must not be treated as secure or production-ready" |
