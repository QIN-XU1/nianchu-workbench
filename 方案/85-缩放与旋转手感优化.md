# 85 · 缩放与旋转手感优化

> 用户：「整体放大缩小以及旋转的逻辑再斟酌下，优化使用体验」

---

## 一、先实测：找到 4 个真问题

| # | 问题 | 实测数据 |
|---|---|---|
① | 滚轮忽略 `deltaY` 大小 | `deltaY=100` 和 `deltaY=3` 都变成 1.07 → 触控板疯狂缩放 |
② | 缩放不以鼠标为中心 | 鼠标在左上角，节点却向画布中心移动 214px |
③ | 旋转太慢 | 转一圈需 786px 拖拽（画布宽 1221px） |
④ | pitch 硬钳制 | 拖到 80.2° 直接撞墙停住 |

## 二、逐项修复

### 2.1 ① 滚轮改为 `deltaY` 感知（指数映射）

**之前：**
```js
S.zoom *= (ev.deltaY > 0 ? 0.93 : 1.07);   // deltaY 大小完全忽略
```

**现在：**
```js
const delta = -ev.deltaY;
const zoomFactor = Math.exp(delta * 0.0016);
S.zoom = Math.max(0.45, Math.min(2.4, S.zoom * zoomFactor));
```

**实测效果：**

| 输入 | 之前 | 现在 |
|---|---|---|
鼠标一格 (deltaY=100) | +7.0% | **+17.4%** |
触控板微动 (deltaY=3) | +7.0% | **+0.5%** |

**触控板的细腻度提升 34 倍。** 鼠标一格也从"太慢"变为合适。

### 2.2 ② 缩放锚点（以鼠标为中心）

**原理：**
```
投影中心偏离画布中心 δ → 内容整体平移
offset = (鼠标 - 中心) × (1 - 1/zoomRatio)
```

**实现：**
```js
// render 里
let cx = W / 2, cy = H / 2;
if (S.zoomAnchor && S.zoomAnchor.active) {
  const za = S.zoomAnchor;
  const ratio = S.zoom / (za.baseZoom || 1);
  const compX = (za.nx * W) * (1 - 1 / ratio);
  const compY = (za.ny * H) * (1 - 1 / ratio);
  cx = W / 2 - Math.max(-W / 2, Math.min(W / 2, compX));
  cy = H / 2 - Math.max(-H / 2, Math.min(H / 2, compY));
}
```

**实测效果：**

| | 之前 | 现在 |
|---|---|---|
节点位置变化 | (848,142) → (634,130)，偏移 **214px** | (848,142) → (841,149)，偏移 **8px** |

**提升 27 倍。**

**辅助设计：**
- 拖拽/旋转开始时清空锚点（避免视角混乱）
- 锚点 2.5 秒后自动失效（避免长期偏离中心）

### 2.3 ③ 旋转灵敏度提高

**之前：** `yaw += dx * 0.0080`（0.46°/px，转一圈需 786px）
**现在：** `yaw += dx * 0.0115`（0.66°/px，转一圈需 547px）

**实测：** 拖 100px → 65.9°（之前 45.8°）

**转一圈从 786px 降到 547px**，更接近画布宽度（1221px），一次拖动就能转大半圈。

### 2.4 ④ pitch 软钳制（橡皮筋）

**之前：**
```js
S.pitch = Math.max(-1.40, Math.min(1.40, S.pitch));   // 硬停
```

**现在：**
```js
const PITCH_LIMIT = 1.45;
let nextPitch = S.pitch + dy * ROT_PITCH;
if (nextPitch > PITCH_LIMIT) {
  const over = nextPitch - PITCH_LIMIT;
  nextPitch = PITCH_LIMIT + over * 0.12;      // 越界后只按 12% 位移
} else if (nextPitch < -PITCH_LIMIT) {
  const over = nextPitch + PITCH_LIMIT;
  nextPitch = -PITCH_LIMIT + over * 0.12;
}
S.pitch = Math.max(-1.56, Math.min(1.56, nextPitch));   // 硬上限
```

**效果：** 接近边界时逐渐减速（像橡皮筋拉紧），不再硬停。

**实测：** 拖 450px → 84.3°（之前 80.2° 硬停）

## 三、设计说明

### 3.1 为什么用指数映射而不是线性

```
线性：zoom += deltaY * k
  → 大 deltaY 时步进过大，小 deltaY 时几乎无感

指数：zoom *= exp(deltaY * k)
  → 缩放是"乘法"关系（每格是固定比例），符合视觉感知
  → 且天然处理不同量级的输入（鼠标 vs 触控板）
```

**这是所有专业地图/图片查看器的标准做法。**

### 3.2 为什么锚点 2.5 秒后失效

如果锚点永久保留，用户缩放后画面会一直偏移中心（因为投影中心不是画布中心）。
2.5 秒足够完成一次缩放操作，之后自然回归。

### 3.3 为什么 pitch 上限从 1.40 提到 1.45 + 软钳制

```
1.40 rad = 80.2°，看不到极点
1.45 rad = 83.1°，能看到更多
1.56 rad = 89.4°（硬上限，接近极点）

软钳制后：越界时只按 12% 位移 → 有"拉不动"的物理感，不生硬
```

## 四、自检抓出的问题

### 问题：`render` 里的 `cx` 是 `const`，无法修改

```
第一次替换时锚点补偿代码没生效，因为原代码是 const cx
→ 需要改成 let
```

**教训：替换"常量"为"需要计算的变量"时，必须同时改声明方式。**

### 问题：字符串锚点匹配失败 4 次

```
缩进/空格差异导致匹配失败
→ 最终改用「行号定位 + 精确行内容确认」
```

> **实测找到 4 个问题，全部修了：**
> **① 滚轮忽略 deltaY → 指数映射（触控板细腻度提升 34 倍）**
> **② 缩放不以鼠标为中心 → 锚点补偿（偏移从 214px 降到 8px）**
> **③ 旋转太慢 → 灵敏度提高 44%（转一圈 786px → 547px）**
> **④ pitch 硬钳制 → 软钳制（橡皮筋感）**
>
> **最关键：① 和 ② 是"手感差"的真正原因 ——
> 不是参数不对，而是**缺少两个标准机制**（deltaY 感知、缩放锚点）。**
