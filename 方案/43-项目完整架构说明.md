## 三、核心机制详解（技术原理）

### 3.1 场景机制

**一个场景是什么**（`scenarios/<id>.json`）：

```json
{
  "id": "research",
  "name": "调研",
  "description": "...",
  "layout": "grid",
  "panels": [
    { "id": "rs-web", "title": "网页", "type": "embed",
      "url": "https://...", "col": 1, "row": 1, "w": 3, "h": 5 }
  ]
}
```

**关键字段**：
- `type` → 决定用哪个渲染器（`APP_RENDERERS[type]`）
- `col/row/w/h` → 4 列网格坐标
- harness 面板还有 `sessionTitle` / `pinTarget`（会话绑定用）

**切换流程**（`renderer.js` L970-984）：
```
点击场景标签
  → loadScenario(id)
  → grid.innerHTML = ''（清空）
  → for 每个 panel: mkPanel(p) + renderers[p.type](body, meta, head)
  → packAutoGrid（自动排格）
  → applyBadges
```

### 3.2 面板渲染机制

**两种注册方式**（这是我在审计时误报的原因）：

| 方式 | 位置 | 数量 |
|---|---|---|
`renderers['xxx'] = fn` | renderers.js 内 | 36 种核心 |
`window.APP_RENDERERS['xxx'] = fn` | 独立 .js 文件 | 1 种（sf-board） |

**运行时合并后是 37 种。**

**渲染器签名**：`(body, meta, head) => cleanupFn | void`
- `body`：面板内容容器（DOM）
- `meta`：面板配置（含 `meta.type` / `meta.scene`）
- `head`：标题栏
- 返回值：cleanup 函数（切场景时调用，防泄漏）

### 3.3 webview 机制（官方不推荐，但项目核心）

**6 个 webview**：
- 2 个引擎界面（`persist:harness`）
- 4 个免费 AI 站（`persist:webai-<key>`）

**Electron 官方原文**：
> **We currently recommend to not use the `webview` tag** — 渲染、导航、事件路由都不稳定。

**我们的实测**：
- 每个 webview = 一个独立 renderer 进程
- 销毁元素才能真正释放（导航到 about:blank 无效）
- 实测释放：4 个站 = 4 进程 / 1113 MB

### 3.4 记忆机制（三层 + 红线）

```
① 注入层   每轮注入，必须极短
② 私有层   <场景>/场景私有记忆.md，含 §〇 交接 ≤4KB
③ 共享层   _共享记忆/ 四块板（通知/待办/索引/体检）
```

**§〇 五小节**（原项目定义，我们已对齐）：
```
1) 上次交接  2) 当前项目  3) 私有记忆变更  4) 下一步/卡点  5) 全貌
```

**红线**：主文件 25KB · §〇 4KB · 项目记忆 8KB

**工具链**：
| 命令 | 作用 |
|---|---|
`node prototype/mem.mjs handoff --scene 命令 --done ...` | 交接（覆盖写 §〇 + 自动快照） |
`node prototype/mem.mjs checkall` | 11 个场景体量体检 |
`node workbench/工具/mem-init.mjs --all` | 为新场景建骨架 |
`node workbench/工具/mem-map.mjs` | 从场景自动重建记忆地图 |

### 3.5 记忆神经元机制（数据怎么流进图里）

**数据源链路**：
```
preload.js: memRoot = DSH_CUSTOMER_HOME + '\场景记忆'
  ↓
renderers.js: MEM_ROOT = paths.memRoot
              ROOT = MEM_ROOT + '\_共享记忆'
  ↓
load(): 读 索引.json / 项目.json / 记忆地图.json
  ↓
组装节点：
  · core（根）
  · doc（_待办/_跨场景通知/冲突）
  · area（索引.json 的 areas → areas/<id>.md）
  · memory（记忆地图 的 privateMemory）
  · skill（skills 目录下的 SKILL.md）
  · project（项目.json 或目录扫描）
  · source（dataSources 对象）
  ↓
逐个 statOk() 校验 → missing 标红
  ↓
canvas 绘制（力导向布局 + 连线）
```

**关键数据结构**（`记忆地图.json`）：
```json
{
  "areas": [{ "panel": "cmd-chat", "scene": "命令",
              "privateMemory": ["命令\\场景私有记忆.md"] }],
  "dataSources": {                       // ← 必须是对象，不是数组！
    "tools": { "path": "绝对路径", "count": 9 }
  }
}
```

**踩过的坑**：
1. `DSH_CUSTOMER_HOME` 未设置 → `memRoot = ""` → 空图
2. `dataSources` 写成数组 → 代码用 `Object.keys` → 不生效
3. `META_DIR = MEM_ROOT` 但文件在 `_共享记忆\` 下 → 3 个节点永远失效

### 3.6 Sceneflow 机制（场景间传数据）

```
场景契约（sceneboard/scenes/<id>.json）
  inputs:  [需要一个什么产物]
  outputs: [{ id, name, to: [接收方场景] }]
      ↓ 发布
产物（产物/<名>-<日期>-<id>.md + index.json + events.jsonl）
      ↓ 自动路由（按 outputs.to）
下游收件箱（inbox --scene X）
      ↓ 领取
consumedBy 记录 + claim 事件
      ↓
管线进度（pipe --id build-software，DAG 算 ready/done）
```

**核心设计**：
- 产物不可变（要改就发新版）
- 事件流是唯一真相（index 可重放重建）
- 校验能发现坏数据（缺文件 / 环 / 未知场景）

### 3.7 容错机制（我加的）

**7 类事件**：
| 事件 | 处理 |
|---|---|
`render-process-gone` | 记录 + 通知 + 可恢复的自动重载 |
`child-process-gone` | 记录 + 通知 |
`unresponsive` | 记录 + 通知 |
`did-fail-load` | 记录 + 通知（跳过 -3） |
`preload-error` | 记录 + 通知 |
`uncaughtException` | 兜底记录 |
`unhandledRejection` | 兜底记录 |

**链路**：main.js `fault-handlers.cjs` → `server.log` + IPC `fault:event` → `fault-ui.js` 显示故障条。

**实测**：`crash-log.jsonl` 40 条真实记录。

### 3.8 引擎复用机制

`main.js` 的 `startServer()`：
```js
if (await probe()) {          // probe = http.get('http://127.0.0.1:' + DSH_PORT + '/')
  engineIsForeign = true;     // 端口已在监听 ⇒ 复用外部引擎
  return true;
}
```
**实测**：`probe('1996')` 返回 `{ok:true, status:401}`（401 也算连上）。

### 3.9 可观测性机制（我加的）

`--inspect-electron <port>` / `SEA_DEBUG_PORT` → `app.commandLine.appendSwitch('remote-debugging-port')`

**用途**：CDP 连上 9 个 target，量面板尺寸、内存、渲染状态。
