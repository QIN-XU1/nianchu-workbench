---

## 一、我用的这套体系是什么

**仓库**：`edisonmbli/refactoring-ui-skill`（371 星，Python，460 KB）
**来源**：Refactoring UI 一书（作者 Adam Wathan & Steve Schoger，Tailwind CSS 创始人）
**规模**：**151 条规则** + 16 篇参考文档（约 300 KB）

### 关键定位（SKILL.md 原文）

> This skill is the **constraint and diagnosis layer** for interface work.
> It supplies the rules a design must satisfy and finds where a design breaks them.
>
> It is deliberately **not a generator of aesthetics**.

**它不是教我"怎么做好看"，是给我"规则"和"诊断工具"** —— 这正是我前几轮缺的。

| # | 法则 | 我的问题 |

## 三、第一步：用它的算法生成色板（不手调）

### 3.1 生成器

```bash
python3 scripts/generate_palette.py --base "#7DA1DE"
```

**算法（§5.3.3 / §5.4 / §5.4.2 / §5.5.1）**：
```
base(500) → edges(900/100) → bisect(700/300) → bisect(800/600/400/200)
饱和度随亮度偏离 50% 升高
色相向更亮/更暗方向旋转，上限 20-30°
灰阶带温度并两端补偿
```

### 3.2 生成的五条 ramp（每条 9 档）


## 四、第二步：用它的检查器校准对比度（这一步抓到了真问题）

### 4.1 我原本的映射

```
正文  neutral-100  #f6fbfd
次要  neutral-400  #919eac
三级  neutral-600  #5c6479   ← 我认为够灰
```

### 4.2 实测结果

| 配对 | 对比度 | 判定 |
|---|---|---|
正文 / base | **14.68:1** | ✅ |
次要 / base | **5.61:1** | ✅ |
**三级 / base** | **2.59:1** | ❌ **不达标**（需 4.5） |
**次要 / raised** | **4.18:1** | ❌ **不达标** |
边框 / base | 1.86:1 | ❌（装饰性，可接受） |

**这就是"我觉得还行"和"实测不行"的差别。**

### 4.3 按数据修正映射

我逐档实测了 neutral ramp 在两种背景下的对比度：

```
对 base(#222435)：  对 raised(#35394c)：
  n-100  14.68       n-100  10.94
  n-200  11.18       n-200   8.33
  n-300   8.20       n-300   6.11
  n-400   5.61       n-400   4.18  ← 刚够
  n-500   3.55       n-500   2.64
```

**结论（数据决定的，不是审美决定的）**：
```
正文 = neutral-100  (14.68 / 10.94)
次要 = neutral-300  ( 8.20 /  6.11)   ← 比原来的 400 更安全
三级 = neutral-400  ( 5.61 /  4.18)   ← 升一档
```

## 五、第三步：按 Sweep 顺序审计（发现真问题）

**扫描顺序（固定，来自 13-audit-rubric.md）**：
```
hierarchy → layout & spacing → typography → color → depth → images → finishing
```

### 5.1 第一次审计（坏得很彻底）

| 指标 | 实测 | 规则 | 判定 |
|---|---|---|---|
文字色 | **10 种** | ≤3 | ❌ P1 |
字重 | **5 种** | 2 | ❌ P1 |
字号 | **11 种**，7 对间隔 <18% | 1.25+ 倍率 | ❌ P2 |
实心按钮 | 0 个 | 一页一个 | ✅ |
阴影 | 0 个 | 克制 | ✅ |
间距 | 全在 4px 基准 | 系统 | ✅ |

### 5.2 第一次修复失败（写了 enforce 但没生效）

我写了 `theme-rui-enforce.css` 用 `!important` 强制收敛，
**但审计结果没变** —— 还是 10 种色、5 种字重。

### 5.3 写诊断脚本定位真正的违反者

`find-violators.mjs` 输出：

```
rgb(230,232,238) × 3   .brand-name / .boot-title / .webai-title
rgb(152,161,181) × 11  .brand-tip-line / .scenebar-label
rgb(143,245,247) × 2   .panel-badge        ← 霓虹青
rgb(11,18,32)    × 1   .mcp-badge          ← 深色
rgb(92,100,121)  × 2   .tui-sep
rgb(145,158,172) × 7   .tui-clock / 底栏提示
字重 700 × 6、800 × ?
```

**根因：这些元素都在 `.panel-body` 之外**（顶栏、状态栏、品牌区、徽标），
我的第一条 enforce 规则只覆盖了面板内部。

### 5.4 第二次修复：写 enforce2 覆盖外围

`theme-rui-enforce2.css` 显式处理：
- `.brand-name` / `.boot-title` / `.webai-title` → 二级色 + 600
- `.brand-tip-line` / `.tui-sep` / `.tbs-k` → 三级色 + 400
- `.panel-badge` / `.mcp-badge` → 去掉霓虹，统一灰边框
- 全局兜底：`*:not(webview)` 先压成 400 + 主要色，再逐级覆盖
- 显式消灭 700/800/900/300/100 字重

## 八、诚实说明

### 8.1 做到什么程度

**从"不合规"做到了"合规"。**

但"合规"不等于"好看"。
- 现在界面**干净、层次清楚、配色统一**
- 但**还不精致** —— 缺品牌感、缺细节打磨、缺动效

### 8.2 没做到的

| 项 | 原因 |
|---|---|
**真正的视觉设计** | 这套 skill 明确说它"不生成美学"，只给规则 |
**块字符画（像素鲸鱼）** | 需要专门设计 ASCII art |
**上下文进度条 / TPS 仪表** | 需要 token 计数器支撑 |
**动效** | 未做 |
**移动端适配** | 未验证 375px |

### 8.3 最重要的认知

> **这套 skill 的价值不在于"教我怎么好看"，在于"让我能证明自己不合规"。**
>
> 我三次说"改好了"，用户三次说"不好看" —— 因为我在凭感觉。
> 现在我有：**151 条规则 + 自动审计 + 对比度实测**。
>
> 每次改完能跑 `rui-audit.mjs` 得到量化结果，而不是"我觉得这次行了"。

## 九、最后一个必须说的问题

**但它的根因不是设计问题，是 0 个会话。**
