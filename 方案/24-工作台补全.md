## 1. 能力开关（默认全关）

### 1.1 为什么必须先做这个

用户原话：
> "MCP工具如果默认使用就会每轮使用固定消耗的token，可以做开关控制，不用的时候默认关闭"
> "例如让他操作Blender，操作我这台电脑，都是外挂默认关着，要用的时候才开"

luanyujia 的真实数字：**MCP 全开约 58k token/轮，一个 cua-driver 就 26.8k**。

### 1.2 实现

```powershell
node prototype\capabilities.mjs list
```
```
能力开关 · 默认全关

桥（外包给免费网页 AI）  一次问答、要一段文字；不适合批量或必须准时的任务
  ○ 关  deepseek       DeepSeek 网页版  零 token（走浏览器）

MCP 工具  全开约 58k token/轮 —— 平时必须关着
  ○ 关  cua-driver     电脑操作（CUA）  约 26.8k token/轮
  ○ 关  blender        Blender 操作  按需

外挂插件  按需启用，不用时关闭

当前没有开着的额外能力（固定 token 消耗为 0）
```

### 1.3 成本提醒

开启高成本项时立刻显示代价：
```
✓ mcp.cua-driver → 开
  代价：约 26.8k token/轮
```
开启后首屏显示：
```
… · 外挂 2 项（约 26800 token/轮）
```

### 1.4 接入桥（默认关闭 → 必须显式开启）

```
✗ 桥「DeepSeek 网页版」是关闭状态。
开启：node prototype/capabilities.mjs on bridge.deepseek
（默认全关是为了不白花钱/不白占额度）
  code=CAPABILITY_OFF
```

**这是关键的"防意外花钱"设计**：桥本身零 token，但会掉登录、会触发风控，
所以必须显式开启。

## 2. 自动归纳（luanyujia 留白的"发动机"）

### 2.1 为什么这是战略级

luanyujia 公开版明确写了它**没公开**两件事：

> 1. **自动归纳**：从对话里提"候选写回"，再经人审并入记忆。
>    没有它，记忆要靠人手写 —— 这就是"越用越强"的速度差。
> 2. **验证闸**：硬判据 + 反例清单 + 检查脚本。
>
> **"开源不可逆 —— 图可以送，发动机和刹车不送。"**

**刹车（验证闸）我们已经有了**（门禁 24/24）。
**这一轮把"发动机"（自动归纳）也做出来了。**

### 2.2 五个设计原则（极其克制）

| 原则 | 为什么 |
|---|---|
**只提名不自动写** | 写错记忆比不写更坏 |
**每条候选必须有出处** | 否则时间一长不知道哪来的 |
**写回判据**（照 luanyujia 的表） | 只有实质工作才提 |
**量有上限**（≤10 条/次） | 照 luanyujia 的规矩 |
**去重** | 已经在记忆里的不再提 |

### 2.3 判据自检 8/8

```
✓ 修 bug 应记              期望=keep 实际=keep
✓ 搜索结果不记             期望=drop 实际=drop
✓ 临时路径不记             期望=drop 实际=drop
✓ 技术方案应记             期望=keep 实际=keep
✓ 新坑应记                 期望=keep 实际=keep
✓ 一次性约束不记            期望=drop 实际=drop
✓ 过长不记                 期望=drop 实际=drop
✓ 去重生效                 fresh=1 dup=1
```

### 2.4 用真实工作记录试一次

输入本轮真实做的事：
```
修好了 bridge 的输入框识别 bug
新增了能力开关 capabilities.mjs
踩坑：DeepSeek 用虚拟滚动，body.innerText 只有 207 字符
决定用 CDP 方案驱动浏览器，零依赖
搜索结果里翻到三篇博客
临时路径 C:\Users\15282\Temp\a.txt
```

输出：
```
提出 4 条候选（跳过重复 0 条，未采纳 2 条）
  [修 bug] 修好了 bridge 的输入框识别 bug
  [建/改应用或模块] 新增了能力开关 capabilities.mjs
  [新踩的坑] 踩坑：DeepSeek 用虚拟滚动，body.innerText 只有 207 字符
  [选定技术方案] 决定用 CDP 方案驱动浏览器，零依赖
```

**4 条有效候选精确归类，2 条噪声正确排除。**

### 2.5 它不会改记忆（这是关键）

候选写到 `scenes/<id>/.review/candidates-<时间>.md`，**等人确认后才并入**。
`N4` 指标专门验证这一点：`记忆未变=true 有候选文件=true`。

## 3. 共享层四块板

### 3.1 为什么必须分四块

照 luanyujia 的真实教训：
> "看板一天几十条，一周就把索引和体检顶到看不见的地方。之后没人再往下翻——读的那件事自然就停了。"

**判断"要不要拆"的判据**：两块内容的更新频率差一个量级，或读者不是同一批人 ⇒ 必须分开。

### 3.2 四块板

| 板 | 回答 | 更新频率 |
|---|---|---|
通知板 | 发生了什么 | 一天几十条 |
待办板 | 该做什么（**全机唯一落点**） | 一天几条 |
总索引 | 东西在哪 | 一周几条 |
体检结果 | 机器健康吗 | 一周一次 |

### 3.3 自检 5/5

```
✓ 待办同一件只许一行        第一次 added=true 第二次 dup=true
✓ 待办做完可关行           关闭=true 剩余=0
✓ 通知最新在上             第二条位置=80 第一条=134
✓ 索引同路径不重复          第一次=true 第二次=true
✓ 四块板文件独立           通知/待办/索引/体检 各一个文件
```

## 4. 场景间协作

### 4.1 三条纪律（照 luanyujia）

| 纪律 | 内容 |
|---|---|
**修改权五档** | 别人的地盘只许写"请求"，一个字都不许写别人内容 |
**派单 ≠ 公告** | 派单要指定承接者；公告是让大家知道 |
**请求四件套** | **现象 + 该谁做 + 怎么做 + 做完怎么验** |

> luanyujia 原话："空泛的请求 = 对方无法执行 = 等于没提。"

### 4.2 四件套是强制的

```
✗ 请求不完整，缺：现象, 该谁做, 怎么做, 做完怎么验
  空泛的请求 = 对方无法执行 = 等于没提。请补齐四件套。
```

### 4.3 自检 5/5

```
✓ 缺四件套必须拒绝
✓ 完整请求可发
✓ 对方信箱能收到
✓ 不能给自己发
✓ 不存在的场景拒绝
```

### 4.4 接入首屏

```
… · 待办 1 · 协作 1 待处理 · 外挂 0 项（全关）
  ○ 待办：data-reconcile→doc-consistency：自检：索引漏登
  ● 协作请求待处理：doc-consistency(1)
```

**"该做但没做"的活现在在首屏可见了。**

## 5. 工作台多面板界面

### 5.1 从"状态条"升级为"可展开工作台"

**折叠态**（默认，占一行）：
```
● 现在没事   6 场景  门禁 24/24  下限 4/4  认证 6/6     ⟳  ▾ 工作台
```

**展开态**：
```
┌─ 状态条 ─────────────────────────────────┐
│ ● 现在没事  6 场景  门禁 24/24  ⟳    ▴  │
├─ 场景标签栏 ────────────────────────────┤
│ 场景  ● 数据核对  ● 文档一致性  ● 文档索引 … │
├─ 场景摘要 ──────────────────────────────┤
│ 六件套 5/5  未绑定会话  completeness …    │
├─ 文档类型 ──────────────────────────────┤
│ [定位卡] [记忆] [技能] [配置]              │
├─ 文档预览 ──────────────────────────────┤
│ （Markdown 渲染：标题/列表/表格）          │
├─ 能力开关卡片 ──────────────────────────┤
│ 桥（外包给免费网页 AI）                    │
│ ● DeepSeek 网页版（零 token）              │
└────────────────────────────────────────┘
```

### 5.2 四条 API（全部实测 HTTP 200）

| 端点 | 返回 |
|---|---|
`/sea-workbench/pulse` | sea 首屏状态 |
`/sea-workbench/scenes` | 场景清单 + 六件套完备度 + 身份 |
`/sea-workbench/scene-doc?id=X&which=Y` | 某场景的定位卡/记忆/技能/配置内容 |
`/sea-workbench/caps` | 能力开关状态 |

### 5.3 设计取舍

| 决定 | 理由 |
|---|---|
**折叠优先** | 健康状态不该占空间（superagent 原则） |
**展开时才拉数据** | 省请求；不展开就不发 |
**扫描式 Markdown 渲染** | 不做完整解析器，够看就行 |
**场景标签带 ●/○** | 一眼看出六件套是否完整 |
