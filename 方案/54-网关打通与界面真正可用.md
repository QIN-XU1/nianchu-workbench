### 2.3 修复的三步

**第一步：克隆 desktop profile 成 web-gw**


**第二步：安装依赖**
```powershell
dsh plugin --profile web-gw install
# + dsh-our-free-model 2.8.0 <- ..\desktop\node_modules\dsh-our-free-model
```

**第三步：改 agent-default-model**
```yaml

  config:
    provider: raccoon
```

## 三、验证网关的方法论（修复了我的假证）

### 3.1 之前犯的错

我用 `text.includes('网关测试成功')` 当判据，
**但我发的提问本身就包含"网关测试成功"这几个字** ⇒ 永远为真 ⇒ 假证。

### 3.2 正确的判据设计

**关键原则：答案必须不可能出现在提问里。**

```javascript
// 提问只给两个数，答案不出现在提问中
const A = 8379, B = 4612;
const EXPECT = String(A * B);   // 38643948
// 提问： "请计算 8379 乘以 4612，只输出纯数字"
//        ↑ 只有乘数和被乘数，没有答案
```

**这样「38643948 出现在响应里」就只能是模型算出来的。**

### 3.3 三层验证


## 四、界面优化（对照 edex-ui 真实规范）

### 4.1 参考来源（GitHub 实搜）

`GitSquared/edex-ui` —— **45,044★**，科幻终端模拟器。

从它源码 `src/assets/themes/navy.json` 挖到的**真实值**：

```json
{
  "colors": {
    "black": "#282a36",  "light_black": "#222430",  "grey": "#222430",
    "red": "#ff5c57", "green": "#5af78e", "yellow": "#f3f99d",
    "blue": "#57c7ff", "magenta": "#ff6ac1", "cyan": "#9aedfe",
    "white": "#f1f1f0"
  },
  "terminal": {
    "fontFamily": "Fira Mono",
    "foreground": "#87b7cc",        ← 正文是带蓝的灰，不是纯白
    "background": "#222430",
    "cursorStyle": "block"          ← 块状光标
  }
}
```

**提炼的四条铁律：**
```
① 背景不用纯黑 —— #222430
② 正文不用纯白 —— #87b7cc
③ 字体必须等宽 —— Fira Mono
④ 光标是块状的
```

### 4.2 三个优化前实测的缺陷

```
【① 纵向布局】16% 框架占比
    tui-statusbar 30px + titlebar 38px + scenebar 52px = 120px
【② 头部层数】3 层（edex-ui 只有 1 层）
【③ 字体】fontFamily = -apple-system  ← 不是等宽！
```

### 4.3 优化后的实测

| 指标 | 优化前 | 优化后 |
|---|---|---|
**头部层数** | 3 层 | **2 层** |
头部总高 | 120px | **64px**（省 56px） |
**框架占比** | 16% | **10%**（优于 edex 的 15%） |
**内容占比** | 84% | **90%** |
**字体** | `-apple-system` | **`Fira Mono`** |
**背景** | rgb(34,36,53) | **rgb(34,36,48)** = edex `#222430` |
字符画/块光标 | 无 | 有 |

### 4.4 实现方式

**头部合并（`tui-header-merge.js`）** —— DOM 级真正合并：
```
把 statusbar 的 logo / 统计 / 主题选择器 / 时钟 搬进 titlebar
然后 statusBar.remove()   ← 删掉一整层
```

**CSS 主题（`theme-edex.css`）** —— 采纳 edex 配色 + Fira Mono + 块状光标 + ASCII 装饰。

## 五、第四个深坑：引擎页面文字竖排

### 5.1 症状

AI 面板里文字**竖着排列**（每行只能放 1-2 个字）。

### 5.2 逐步定位

```
① 工作台侧测量     pl-ai 面板 746px, webview 720px    ← 宽度正常！
② 引擎侧测量       win 722x734, centerCol = 96px       ← 根因在这
③ 对比正常实例     win 1536x822, centerCol = 1256px
④ 查 frame grid    gridTemplateColumns = "625.6px 96px" ← 分成两列
⑤ centerCol 在第 2 列，只有 96px
```

**根因：引擎在窄窗口（<900px）下把 grid 分成两列，主内容只分到 96px。**

### 5.3 修复

在 webview 内部执行：
```javascript
frame.style.gridTemplateColumns = '1fr';
center.style.gridColumn = 'auto';
window.dispatchEvent(new Event('resize'));
```

结果：`centerCol 96px → 722px`，文字恢复正常横排。

### 5.4 犯的错与纠正（do-no-harm）

**第一次修复时我写成了"无论多宽都强制单列"**，
结果把本来正常的 1536px 实例从 `centerCol=1256px` 改坏成 `508px`。

**纠正：只在 `centerW < 300` 时才动手。**

```javascript
if (before >= 300) {
  return { skipped: true, reason: 'already wide' };   // do no harm
}
```

改 CSS 后工作台**启动即退出，零输出**。

### 7.2 定位

`server.log`：

### 7.3 稳定的启动方式

```powershell
Start-Process electron.exe -ArgumentList @(
  ".", "--disable-gpu", "--disable-gpu-compositing", "--no-sandbox"
) -WorkingDirectory $PWD
```
