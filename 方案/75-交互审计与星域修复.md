### 1.3 但真正的问题是：一次像素测量

**我写了一个脚本，直接统计画布像素的亮度分布。**

```
画布 1529×986 = 150 万像素

纯黑 (<10)       79.8%      ← 绝大部分是纯黑
极暗 (10-30)     19.7%
暗   (30-60)      0.1%
中   (60-120)     0.2%
亮   (120-200)    0.2%
很亮 (>200)       0%

★ 有效可见像素: 0.5%
最大亮度: 201/255
```

**这才是「交互感差」的真正根因。**

用户在一块 150 万像素的画布上，只能看到 **0.5% 的像素**（约 7500 个）。
节点只是几粒微光，散布在巨大的黑色空间里。
**任何交互反馈（悬停光晕、选中环、连线）都被黑暗稀释到几乎不可见。**

**这不是交互逻辑的问题，是质量问题。**

## 二、修复过程（三次迭代）

### 2.1 第一次：加星尘 + 提亮背景

```
星尘 180 → 520，透明度提高
背景渐变从 #05070A 提亮到 #141C28
```

结果：
```
纯黑 79.8% → 4.8%   （改善）
极暗 94.3%           （但大部分还是暗）
可见像素 0.5% → 0.8% （几乎没改善）
```

**为什么没改善？** 因为星云透明度只有 0.12~0.20，
在 #05070A 的底上叠加后亮度只到 ~20，仍在"极暗"区间。

### 2.2 第二次：星云透明度 ×2.5

```
星云 0.12~0.20 → 0.34~0.52
背景 再提亮到 #1B2836
星尘更亮更大 + 加小光晕
```

结果：
```
纯黑      0%       ← ★ 不再有纯黑
极暗     24%
暗(30-60) 72.7%    ← ★ 有了大量中间调
中(60-120) 3%
可见像素  76%      ← ★ 从 0.5% 提升 152 倍
```

### 2.3 第三次：节点分布从"挤左上"到"铺满"

诊断发现：
```
节点 x 坐标全在 430~800（画布宽 1529）
→ 右边 40% 完全空着
```

根因：`R = min(W,H) * 0.46`
```
画布 1529×986 → R = 986*0.46 = 454
水平只用了 908px，浪费 621px
```

修法：**椭圆自适应**
```js
RX = W * 0.40   // 水平用 80%
RY = H * 0.36   // 垂直用 72%
```

结果：
```
节点 x 分布: 430~800 → 440~1039（铺满）
标签重叠:    3 对 → 0 对
最小间距:    211.9 → 287.4
```

## 四、审计脚本自身的三个误报

审计第一次报"详情面板 0px"、"悬停/选中无差异"、"暗态边 5.5%"，
**这三个都是脚本的问题，不是真实 bug：**

1. **详情面板 0px** —— 因为 `display:none` 时量不到
   → 改为先触发显示再测

2. **悬停/选中差异** —— 脚本里写死了旧值
   → 改为**采样画布像素亮度对比**

3. **暗态边 5.5%** —— 同样是写死旧值
   → 改为**点亮前后像素亮度差**

**教训：审计脚本本身也要验证，否则会误报。**

## 五、留下的教训

### 5.1 "交互感差"往往是质量问题，不是逻辑问题

用户说"交互感很差"，我第一反应是查交互逻辑。
**但真正的答案是：画面是黑的。**

判断方法：**不要靠感觉，要测量。**
```
测量画布可见像素占比
→ 0.5%
→ 找到根因
→ 修复到 76%
```

### 5.2 深色设计要有"中间调"

纯黑底 + 亮节点 = 视觉上极度空旷。
真实宇宙的观感来自：
- 星云（大面积暗物质辉光）
- 星际尘埃（细密微光）
- 层次（不止一个亮度级别）

**深色设计的关键不是"黑"，是"暗中有层次"。**

### 5.3 椭圆而非圆形（宽面板场景）

`min(W,H)` 做半径，在宽画布上会浪费一半宽度。
用 `RX = W*k, RY = H*k` 的椭圆分布，才能铺满。
