## 二、这些体系里真正值得借鉴的机制

### 2.1 紫微斗数：**固定槽位 + 可变的星曜填充**

这是我认为**最有借鉴价值的机制**。

**机制本质（我确定的部分）：**
```
十二宫是固定槽位：
  命宫 兄弟 夫妻 子女 财帛 疾厄
  迁移 交友 官禄 田宅 福德 父母

每宫内容由「安星决」填充：
  · 星曜有固定的宫位分配规则
  · 同一颗星在不同宫位，性质不同
  · 主星/辅星/煞星 有层级
```

**为什么值得借鉴：**

我们现在的问题正是「场景数量不可预估，但界面槽位有限」。
紫微斗数的答案是：**槽位固定，内容可变**。

```
紫微斗数              我们的场景编排
─────────────────────────────────────
12 个固定宫位    →    有限的视觉槽位（不是无限画图）
安星决填充       →    按规则把场景分配到槽位
星曜有层级       →    场景有重要度分级
同星不同宫性质不同 →   同场景在不同分组下语义不同
```

**具体移植方案：**
```
界面不用"无限扩展的星空"，而用「固定 12 宫布局」：
  ┌───┬───┬───┬───┐
  │巳 │午 │未 │申 │
  ├───┼───┴───┼───┤
  │辰 │       │酉 │
  ├───┤  核心  ├───┤
  │卯 │       │戌 │
  ├───┼───┬───┼───┤
  │寅 │丑 │子 │亥 │
  └───┴───┴───┴───┘

场景按规则填入 12 宫，超出 12 个的用"迁移"机制
（点击某宫 → 显示该宫内的多个场景）
```

**这比我的"二十八宿环形"好得多** —— 因为：
- 环形是无限扩展的伪命题（再多也挤）
- 12 宫是**有限容器 + 分层内容**，天然可扩展

### 2.2 奇门遁甲：**九宫 + 时空叠加的局**

**机制本质（我确定的部分）：**
```
九宫格是固定空间结构（洛书九宫）：
  4 9 2
  3 5 7
  8 1 6

叠加三才盘（天盘/地盘/人盘）：
  · 地盘 = 固定的九宫
  · 天盘 = 随时间转动（随时辰变化）
  · 人盘 = 八门（开休生伤杜景死惊）

再叠加九星、八神 → 形成"一局"
阴遁阳遁随节气切换
```

**为什么值得借鉴：**

**「同一空间，不同时间层叠加」** —— 这正是我们需要的：

```
奇门遁甲                我们的场景状态
─────────────────────────────────────
地盘（不变）     →    场景的静态配置（role/inputs/outputs）
天盘（随时间转） →    场景的实时状态（待命/执行/完成）
人盘（八门）     →    场景的当前操作（可读/可写/锁定）
```

**具体移植：**
```
每个场景节点有 3 层状态：
  静态层（配置）   —— 永久不变，来自 sceneboard/scenes/*.json
  动态层（运行态） —— 每轮更新，来自 session.list 的 running/asOfSeq
  操作层（权限）   —— 当前可做什么（调度/查看/编辑/归档）

渲染时三层叠加显示，就像奇门的三盘。
```

### 2.3 六爻：**用神体系 + 世应关系**

**机制本质（我确定的部分）：**
```
一卦六爻，每爻有：
  · 地支（纳甲）
  · 五行
  · 阴阳
  · 世应（世爻代表自己，应爻代表对方）
  · 六亲（父母/兄弟/子孙/妻财/官鬼）

关键机制「用神」：
  测不同事取不同爻为「用神」
  如测财取妻财爻，测官取官鬼爻
  → **同一个卦，问不同事，看不同的爻**
```

**为什么值得借鉴：**

**「同一份数据，按问题类型选取不同的焦点」**。

```
六爻用神              我们的场景导航
─────────────────────────────────────
测财取妻财爻     →    找"性能问题"场景，按性能标签筛选
测官取官鬼爻     →    找"架构问题"场景，按架构标签筛选
世应关系         →    主 Agent（世）↔ 子场景（应）的关系
```

**具体移植：**
```
中枢接到需求 → 先判断"用神"（这类需求该看哪类场景）
  · 性能类 → 焦点 = 性能标签的场景
  · 架构类 → 焦点 = 架构标签的场景
  · 记忆类 → 焦点 = 记忆标签的场景
→ 然后只高亮那类场景，其余淡化
```

**这比我现在的"全部平铺"有用得多** —— 它解决了「1000 个场景里，我怎么找到相关的」。

### 2.4 易经：**六十四卦的编码系统**

**这是你说"重中之重"的，我认为最关键的是它的编码机制。**

**机制本质（我确定的部分）：**
```
太极 → 两仪（阴阳）
两仪 → 四象（老阳/少阴/少阳/老阴）
四象 → 八卦（乾兑离震巽坎艮坤）
八卦 → 六十四卦（8×8 组合）

编码：每卦 = 6 个爻（阳爻=1, 阴爻=0）
      六十四卦 = 6 位二进制 = 0~63
      卦序（先天/后天）有严格排列
```

**为什么这才是"重中之重"：**

它提供了**一套完备的状态编码 + 状态转移规则**。

```
易经                    我们的架构
─────────────────────────────────────
6 爻二进制编码      →    6 位的状态位（组合爆炸但有结构）
64 卦 = 状态空间    →    64 种系统状态
卦爻辞 = 状态转移规则 →    每种状态的处置策略
错卦/综卦/互卦      →    状态之间的变换关系
```

**具体移植：**
```
场景的 6 位状态编码：
  bit 0: 是否存在（有/无）
  bit 1: 是否有 AI 会话（有/无）
  bit 2: 是否正在执行（动/静）
  bit 3: 是否有产物（有/无）
  bit 4: 记忆是否完整（全/缺）
  bit 5: 是否报错（正常/异常）

→ 64 种组合 = 64 种场景状态
→ 每种状态有对应的处置策略（就像卦爻辞）
```

**这解决了"状态机散乱"的问题** —— 现在我的状态判断是散落的 if-else，
用易经的编码体系可以统一成一张表。

**注意：我不是要搞"占卜"，是要借它的"完备状态编码"思想。**

### 2.5 梅花易数：**取象的即时性**

**机制本质（我确定的部分）：**
```
起卦方式灵活：时间/数字/声音/方位 都能起卦
核心是「随机中取必然」
体用关系：体卦（主体）用卦（客体），看生克
```

**借鉴点：** 「用当下信息立刻生成一个结构化视图」。
我们已有类似机制（时间戳、session 状态），可以借用"体用"概念表达主客体关系。

### 2.6 七政四余：**天文精度的计算**

**机制本质：** 以真实天文位置（日月五星 + 四余）排盘。
**借鉴点：** 它强调"数据源必须精确"。对应我们的「权威数据源」原则。

## 四、最重要的是：紫微斗数的 12 宫布局

这是替代我现在"二十八宿环形"的正解。

### 4.1 为什么 12 宫比环形好

| 环形（我现在） | 12 宫（紫微方案） |
|---|---|
无限扩展的伪命题 | **有限容器，天然可扩展** |
场景越多越挤 | **每宫可容纳多个场景（分层）** |
没有语义结构 | **宫位有明确语义（命/财/官/迁）** |
需要 LOD 降级 | **不需要降级，结构本身支持** |

### 4.2 12 宫与我们的场景如何对应

```
宫位        含义           对应我们的什么
──────────────────────────────────────────
命宫        核心/本性       中枢
兄弟宫      同辈协作        并行执行的场景
夫妻宫      紧密搭档        强依赖场景
子女宫      产出/衍生        产出型场景（文档/方案）
财帛宫      资源/价值        资源占用型场景（性能/存储）
疾厄宫      健康/隐患        故障诊断类场景
迁移宫      对外/移动        对外接口类场景
交友宫      人脉/外部        外部集成类场景
官禄宫      事业/职责        执行型场景（计划/实施）
田宅宫      基业/存储        数据存储类场景
福德宫      精神/沉淀        记忆/复盘类场景
父母宫      根源/约束        规则/配置类场景
```

**场景按 role 关键词自动归入 12 宫** —— 这比二十八宿更简洁（12 vs 28），
而且每宫语义更贴近"人的事务"，比星宿更实用。

### 4.3 布局方案

```
┌─────┬─────┬─────┬─────┐
│ 巳  │ 午  │ 未  │ 申  │   四角为四生位
├─────┼─────┴─────┼─────┤
│ 辰  │           │ 酉  │
├─────┤   ☯ 中枢   ├─────┤
│ 卯  │  （命宫）  │ 戌  │
├─────┼─────┬─────┼─────┤
│ 寅  │ 丑  │ 子  │ 亥  │
└─────┴─────┴─────┴─────┘

每宫显示：宫名 + 该宫内的场景数 + 主要场景
点击某宫 → 展开该宫内所有场景
```

**这解决了规模问题：**
- 场景 ≤ 12：每宫 1 个，清晰
- 场景 100：每宫平均 8 个，宫格显示"角标 8"
- 场景 1000：每宫平均 83 个，点击进入宫内的列表
- 场景 10000：同样，宫是固定容器，场景在宫内的列表里分页

**永远不需要"挤在一圈"的伪命题。**

## 五、易经 6 位状态编码

### 5.1 编码表

```
场景状态 = 6 位二进制 = 64 种

bit 0  有场景定义        1/0
bit 1  有 AI 会话        1/0
bit 2  正在执行          1/0
bit 3  有产物            1/0
bit 4  记忆完整          1/0
bit 5  有错误            1/0

例：
 111111 = 63  完全就绪（可调度）
 110111 = 55  有错但可执行
 101000 = 40  只是存在，什么都没配
 000000 = 0   空壳
```

### 5.2 用途

```
① 一次性判断状态（不用散落的 if-else）
② 状态转移有明确表（就像卦变）
③ 界面可根据状态码显示不同视觉
④ 监控可聚合统计（如"有多少个 111111"）
```

**这是真正的"完备状态机"，比我现在散落的 if 判断强。**
