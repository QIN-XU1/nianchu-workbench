## 2. 唯一写操作：能力开关

### 2.1 为什么只允许这一个写操作

界面**不改业务数据**（场景文档、记忆、板内容都只读）。
唯一允许写的是**能力开关**，因为：
- 它只改 `capabilities.json` 一个文件
- 它不涉及不可逆操作
- 用户需要能随时关掉烧 token 的东西

### 2.2 实测

```
1. 开启前：当前没有开着的额外能力（固定 token 消耗为 0）

2. HTTP 开启：
   GET /sea-workbench/toggle?target=bridge.deepseek&on=1
   → HTTP 200 | ok=True on=True

3. 开启后：当前开着 1 项：DeepSeek 网页版

4. HTTP 关闭：
   GET /sea-workbench/toggle?target=bridge.deepseek&on=0
   → HTTP 200 | ok=True on=False

5. 关闭后：当前没有开着的额外能力
```

**写操作完整闭环。**

### 3.1 三个视图

**① 文档视图**：选场景 → 选文档类型（定位卡/记忆/技能/配置）→ 预览内容

**② 注入预览视图**（这是"引力"的可视化）：
```
预算 8192 字节 · 实际 335 字节 · 在预算内

【身份】
- 场景：文档索引（docs-index）
- 负责：保证 README 索引覆盖全部文档…
- 不碰：⛔ 不改文档正文…

注入 identity   219B  来自定位卡
跳过 memory       0B  交接段为空
跳过 board        0B  无待办、无协作请求
跳过 capability   0B  外挂全关（不注入，省 token）
跳过 warning      0B  无告警（保持安静）
```

**这一屏让"引力注入"变得可审计**：每一类注入了多少、为什么跳过，一目了然。

**③ 授权视图**：
```
授权模式  observe  只记不干    已记录 2 条"想做什么"
```

## 4. 状态持久化

用 `localStorage` 记住两件事：
- `sea-workbench.expanded`（是否展开）
- `sea-workbench.scene`（当前选中的场景）

**刷新后不丢** —— 这是"打开就不需要重新切换"的基础。
