**不再接受 `--result improved` 这种自说自话。**

### 2.2 新增第 10 个哨兵：记忆召回哨兵

`workbench/工具/记忆召回哨兵.mjs`

它验的不是字节数，是**记忆里到底有没有该知道的事**：

```
指标（口径来自 LongMemEval 源码）:
  recall_all@k  —— 所有关键事实都被召回

```


## 四、调研给出的最终优先级（我采纳）

### P1 · 造真实会话 + 封存集，先跑 Raw-RAG 基线

**为什么**：arXiv 2610.30755 证明 naive RAG 在 LoCoMo/LongMemEval/MEME/MemoryAgentBench
四个基准七个设置里**赢六次**。不做这个基线，任何升级都可能是负收益
（2610.34073 Memory Tax：很多专用记忆系统净价值为负）。

**前提**：要有真实会话。现在 0 个。

### P2 · 把"只追加"改成"带失效的写入协议"

arXiv 2610.36308 实测：把一条无关证据换成一条**过期的竞争事实**，
准确率从 **100% 掉到 44.6%**。

我现在 AGENTS.md 里写的「§五 只追加」，**在结构性制造过期事实**。
这是唯一被两份调研同时点名的**架构级错误**。

### P3 · 记忆安全

arXiv 2611.01700 MemHarmBench：恶意指令存入记忆后，
即使原始攻击内容删除，仍然生效且 "behaviorally stealthy"。

我的 `发消息.mjs` → `_跨场景通知.md` 就是一条**无校验的记忆写入通道**。
