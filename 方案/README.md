## 3. 最有说服力的一个事实

**门禁不是"我说它可信"，而是：**

| 证明 | 内容 |
|---|---|
| 它拒绝了 `liar` | 永远说通过的 check → REJECT |
| 它拒绝了 `lazy` | 只查一类问题的 check → REJECT（捕获率 1/3） |
| 它拒绝了 `vague` | 会失败但说不清差在哪 → REJECT |
| **它抓到了我的 bug** | 我写的 3 条正式 check 一开始全被 REJECT，因为路径解析错误 |

> **最后这条最重要**：一个永远 ACCEPT 的门禁抓不到 bug。**它抓到了，说明它是真的。**

## 5. 我犯过的五次错误

| 版本 | 错误 | 正确说法 |
|---|---|---|
| v1 | 把"原型"当"地基" | 原型是**应用**，宿主是 harness |
| v2 | 把"仓库里有"当"能复用" | 仓库里有 ≠ 我的 profile 里装了 |
| v3 | 把"写进配置树"当"生效了" | 配置树里有 ≠ 会话用了它 |
| v4 | 把"架构正确"当"好用" | 架构完美但第一眼不知道干什么，差一个数量级 |
| **v5→v6** | **把"我自己写的 check"当"可信的 check"** | **可信不是承诺的，是被拒绝出来的** |
