## 一、它强在哪（我们确实不如的，逐条）

### 1. 记忆分层 + **硬性大小预算**（我们原来没有）

`总纲.md:28-33`「记忆怎么不丢」：

| 层 | 预算 | 原文 |
|---|---|---|
| 每轮注入 | 极短（铁律） | 「全局须知只放"不读就会白干"的铁律，必须极短」 |
| 场景私有 `§〇` | ≤4 KB | 「主文件 ≤25 KB」 |
| 项目记忆 | ≤8 KB | 「一个项目一份 `项目记忆\<项目id>.md`」 |

外加一条闸门：**「换会话前先写交接 → 跑 `场景记忆 check`，不过不许换」**（`总纲.md:33`）。

**我们原来**：只有「一个记忆库」，条目只增不减，每轮注入能全塞。
**这不是记忆，是垃圾桶**——而且越用越贵。

> ✅ **本轮已吸收**：`tools/agent/memory-budget.mjs`
> 四层（core 2KB / scene 4KB / project 8KB / misc 8KB）+ `planInjection` 超预算少注入 + `checkHandoff` 换会话闸门。
> 关键设计：**裁剪不删条目**（打 `outOfBudget`，还能检索到），避免为了省 token 把信息删掉。
> 验证：`verify-memory-budget.mjs` 20/20，含 4 条反例（缺交接 / 没写下一步 / 交接超预算 / core 超预算）。

### 2. 外壳侧 vs 热更新侧分离（架构决定，我们没做）

`07-顶栏与菜单栏/README.md:13-15`：

> 为什么刻意分成两侧：**外壳侧改一次要重启**（体验差），所以把"手感类"的东西（拖拽、收起、动画）全放到
> `renderers.js` 这一侧 —— 调手感不用重启。这是这套壳里最值得抄的一个**架构决定**

**我们的现状**：UI 是 Vite 整体构建（本轮实测 **46.72s**），生产环境改一行文案也要重新构建。
HMR 只在 `pnpm dev:web` 下可用 —— 那是开发态，不是产品态。

> ⬜ **待做**：把 agent 面板改成**运行时注入的插件**（`tools/plugin` 已有插件内核），
> 让"手感类"改动走热更新，外壳改动才重启。这是 P0 级架构债。

### 3. 派单状态机 + 「87% 的派单其实没送到」

`00-核心机制/README.md:21`：

> **[派单机制](四-派单机制.md)** —— 一条活从"我要交出去"到"确认干完"的完整状态机 + 台账 + 销账
> 「派单进黑洞；双方互等；**87% 的派单其实没送到**」

我们有 `tools/dispatch` + `tools/collab` + 台账，但**没有把"送达/回执"做成可判定的状态机**。
它点名了两个真实失败模式：**进黑洞**（没人接）和**双方互等**（都以为对方在做）。

> ⬜ **待做**：派单必须有 `已派 → 已接 → 执行中 → 已回执 → 已销账` 五态，
> 且**超时未接**要能自动升级告警。判据：伪造一个"没人接"的派单，系统必须报出来。

### 4. 消息九环（每条消息从产生到被记住的九道关）

`00-核心机制/七-消息与交付.md`（2.3KB）定义「一条消息从产生到被记住要过的九环 + 每环判据」。
我们只有「发出去」和「落盘」，**中间没有环**，所以「消息堆着没人读、账上写着办完实际没人办」这个失败模式我们没防。

### 5. 场景即人的一面（五字段口吻表）

`00-核心机制/六-场景即人的一面.md`：同一个机主在不同场景是不同的人，五字段口吻 + 六条边界。
我们的 agent 只有**一套腔调**打天下 —— 回话长度、顺序、雷区全对不上。

### 6. 六层里我们少一层：L3 个人层

它的 `总纲.md:17-24` 是 L0 宪法 / L1 共享 / L2 场景私有 / **L3 个人层（隔离，刻意不画线）** / L4 运行时 / L5 归档。
我们是 L0 宪法 / L1 共享 / L2 场景私有 / **L3 运行时** / L4 归档 —— **少了「个人层」这一层隔离**。

> 而且它点出一个我们没想到的原则（`总纲.md:26`）：
> **「每个东西只属于一层，只在一个地方是真源；其他地方只放指针。」**
> 我们的图谱里同一份数据经常既在配置又在场景，缺的正是这条。

## 五、诚实的边界

1. 它是**文档仓库**，很多能力是「文档里写了」而非「代码实现了」。我们的对比只能证明**它的设计意图**，
   不能证明它真的能跑（它自己也说跑不通）。所以 A 组维度大量是「部分」。
2. `12-源码照搬/` 里 96 个文件 17.7MB 是**照搬 DSH 外壳**，不是它自己写的 —— 不能算它的能力。
3. 它的规模数字（十余场景/二三十项目）是**单机现状**，不是产品能力。
4. 我们吸收的是**机制**，不是它的代码（MIT 但路径全是占位符，抄了也跑不起来）。
