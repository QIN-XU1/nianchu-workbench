# 改进方向 17：@ 文件引用（@ 菜单 + 行内高亮 + 点击查看）

## 动机

上一轮（方向 15/16）修好了 Ctrl+K 命令面板：能搜命令、能用「/」「>」前缀过滤、能打开「修改设置」。但它只覆盖「命令」这一类输入。日常对话里另一类高频输入是**指代文件**——用户想引用某个文件让模型去看，目前只能手打路径或粘贴内容：

- 打 `@` 没有任何反应，得自己记住路径前缀；
- 想引用的文件在深层目录（如 `packages/core/src/...`），手打成本高；
- 让模型「看看这个文件」时，只能贴相对路径，模型不一定能定位；
- 输入框里已引用的文件没有视觉区分，长 prompt 里混在正文中难以扫读。

**目标是给输入框加一个 `@` 文件引用层**：输入 `@` 弹出可搜索的文件菜单；选中后以 chip/高亮形式落进输入框；发送时把引用解析成绝对路径交给模型；已发送的消息里引用可点击查看。

## 现状证据

- `improve-at-panel.png`：输入框输入 `@packages/core/` 后弹出文件菜单，顶部有过滤词，列表项显示文件名 + 所在目录 + 类型图标，键盘上下选中高亮。
- `improve-at-file.png`：选中 `packages/core/src/loop/...` 后按回车，输入框里出现高亮 chip（带文件图标 + 相对路径 + 删除 ×），光标在 chip 后继续输入。

## 设计

### 1. 触发与过滤

- 输入框里**光标前紧邻**（或前面是空白）的 `@` 触发菜单；`@` 出现在词中间（如 `a@b.com`）不触发，避免误伤邮箱。
- 菜单打开后继续输入即为过滤词，按**路径模糊匹配**（子序列匹配，目录分隔符不参与惩罚），支持 `@core loop` 这类空格分段匹配。
- 上下键移动选中，`Enter`/`Tab` 插入，`Esc` 关闭；`Esc` 后再按 `Esc` 才退出输入框，避免一按就丢焦点。

### 2. 文件列表来源

- 数据来自已有的文件搜索能力（工作区遍历 + `.gitignore` 过滤），**只列文件不列目录**，目录通过输入路径前缀自然收敛。
- 首次 `@` 打开时按最近修改排序展示前 N 个（N=50），输入后按匹配度排序。
- 空结果时给「没有匹配的文件」，不弹错误。

### 3. 插入形式（两种模式，按配置）

- **chip 模式（默认）**：插入一个不可分割的行内节点，渲染为「图标 + 相对路径 + ×」。内部存绝对路径，显示相对路径；发送时序列化为绝对路径。
- **纯文本模式**：插入 `` `@相对路径` `` 形式的等宽文本。适合不想引入富文本编辑器的场景，也更方便手改。
- 两种模式都对**已发送消息**生效：消息里的引用渲染为可点击 chip，点击在侧边/预览面板打开该文件（复用现有的文件预览能力）。

### 4. 与其它输入能力的关系

- 菜单互斥：`@` 文件菜单与 `/` 命令菜单共用同一个 popup 容器，同一时刻只开一个；输入 `/` 时关掉 `@` 菜单，反之亦然。
- 与拖拽上传不冲突：拖进来的文件不进 `@` 引用（那是附件），两者在发送时都转成可读的路径/内容。
- 与 IME 组合输入：组合输入期间的 `@` 不触发（`compositionstart` 到 `compositionend` 之间跳过）。

### 5. 发送时的序列化

- chip 模式：把 chip 替换为 `` `@/abs/path/to/file` `` 的纯文本；同时**另附一份文件清单**给模型（路径 + 大小 + 语言），减少模型瞎猜。
- 纯文本模式：原样发送，服务端识别 `` `@...` `` 模式后按需读取，不自动全文注入（避免大文件撑爆上下文）。

## 验收

- 输入 `@` 弹出菜单；输入过滤词实时收敛；`Enter` 插入 chip。
- 光标在词中间输入 `@` 不弹菜单；邮箱不误触发。
- 发送后消息里引用可点击，点了能打开对应文件。
- 与 `/` 命令菜单互斥，不会同时弹两个。
- 组合输入期间不误触发。

## 落地清单

1. 输入框加 popup 状态机（`@` 菜单 / `/` 菜单 / 无），统一 trigger 检测（光标前字符 + 前面是否空白）。
2. 文件搜索接口（复用工作区遍历），加 `@` 的模糊匹配排序。
3. chip 节点（若走富文本）或 `` `@path` `` 文本插入（走 textarea）。
4. 消息渲染层识别引用并加点击预览。
5. 发送序列化 + 文件清单附加。
6. 单测：触发位置判定、模糊匹配、IME 跳过、菜单互斥。
