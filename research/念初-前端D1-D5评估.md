## D1 输入形态 —— 3/5（中级）

**证据**：单行 `textbox`（placeholder「问点什么，或 ⌘K 跳到能力 / 工具」）+ 模型选择器 + 技能/MCP 选择器 + 上下文计量 + 发送。

**能做到**：
- ⌘K 命令面板（跳能力/工具）
- 模型切换（mimo-v2.6-flash）
- 技能/MCP 显式挂载（6 技能 · 2 MCP）
- 上下文预算可见（38% · 64.2k / 168k）

**做不到**：
- 单行输入，无 Shift+Enter 多行编辑（长 prompt 只能一行滚）
- 无拖拽/粘贴图片（多模态断）
- 无 @ 文件提及（引用文件靠右栏点）
- 无语音

**具体改进**：
1. 输入框换 `contentEditable`，支持 Shift+Enter 换行 + 粘贴图片直接预览
2. `@` 触发文件/能力补全（复用 ⌘K 的搜索索引）
3. 右下角加「+」附件按钮（截图/文件）

---

## D2 信息密度 —— 4.5/5（高级，**强项**）

**证据**：
- 工具调用**单行折叠**：`● read_file  tools/approval_detection.py  0.04s`（dot 状态 + 名称 + 路径 + 耗时）
- **行内 diff**：行号 + 红/绿背景（terminal 输出、edit_file 的 + 行）
- **计量脚**：用时 2.4s / 入 12,841 / 出 486 / 缓存 76% / 成本 $0.0031
- **验证 4 态**：106 通过 · 6 待补 · 0 失败 · 2 判不了（还带「全部 →」）
- 右栏文件 + 行数

**这是全仓最强的一块**，密度接近 Cursor / Claude Code 的工具流。

**具体改进**：
1. 大 diff 默认折叠（>20 行只显示摘要 + 「展开」），避免刷屏
2. 工具行支持点开看完整参数/输出（当前只有摘要）
3. 加「耗时分布条」（横向时间轴，看哪步慢）

---

## D3 状态可见性 —— 3.5/5（中高级）

**能做到（执行层）**：
- 每个工具耗时（0.04s / 1.2s / 0.08s）
- Token 入/出/缓存、成本
- 验证计数（通过/待补/失败/判不了）
- 上下文占用（38%）

**缺（计划层）**：
- **无 todo / plan 图**——看不到「还剩几步、当前在哪步」
- 无「正在思考 / 正在调工具 / 等待审批」阶段指示
- 无任务进度条

**具体改进**：
1. 加 **plan 面板**（todo 列表 + 勾选 + 进度条），放在右栏「验证」旁
2. 会话头加**阶段徽章**（思考中 · 工具 · 等审批 · 完成）
3. 工具执行时显示**当前工具 + 已用时**

---

## D4 审批呈现 —— 1/5（**缺失**）

**证据**：markup 里「审批」是**会话主题**（接口审批链路加固），不是 UI 组件。没有任何批准/拒绝卡。

**风险**：工具已能 `terminal rm canary.txt && rmdir target` 这种破坏性命令，却没有审批闸——`accepted ≠ success` 的纪律在 UI 层是断的。

**具体改进（最高优先级）**：
1. **审批卡**：`命令 + 风险等级（低/中/高）+ 影响范围 + [批准] [拒绝] [永久允许] + 倒计时`
2. 高风险命令**默认拒绝**，需二次确认
3. 审批记录进右栏「变更」tab（谁批的、什么时候、批了什么）

---

## D5 中断恢复 —— 1/5（**缺失**）

**证据**：无检查点 / 无中断态 / 无恢复按钮。

**具体改进**：
1. **检查点列表**（每步工具调用后打点，可回滚到任意点）
2. 中断态 overlay（「已中断 · 从检查点 #3 恢复？」）
3. 恢复后保留上下文 + 工具历史

## 「推到」建议（按 ROI 排序）

1. **审批卡（D4）** —— 最高优先级。破坏性命令无闸，是安全缺口。
2. **plan/todo 面板（D3 计划层）** —— 让「还剩几步」可见。
3. **中断恢复（D5）** —— 检查点 + 回滚。
4. **输入增强（D1）** —— 多行 + 拖拽 + @ 提及。

> 先做 1（审批卡），再做 2（plan），3/4 跟进。每项都是 workbench-v7 里加组件，改动集中在 `workbench-v7.html` 的对应 section。
