## 五、行业空白区（我们的机会）

### 机会 1：没有一家把「不确定」当一等公民 ★最高优先

**现状**：
- ChatGPT：只有 `task_complete` / `turn_aborted` 两态，**没有「做了一半但判不了」**
- DSH：只有 PASS/FAIL 语境，无 UNKNOWN
- hermes：审批有 deny/allow，但「这个结论可靠吗」不表达
- **CL4R1T4S 里 Codex 已有严格四态证据判定**（「Treat uncertain or indirect evidence as not achieved」）—— 但那是**提示词级**，不是机制级

**我们的位置**：A7（记忆）+ A5（压缩）+ A15（能力边界）已把四态做成机制，UNKNOWN 永不并入通过。

**怎么验证超过**：构造「无法判定」场景，产品必须说「判不了」且不并入通过；对照组（如有 Codex）会给结论。

### 机会 2：成本可见性普遍弱

- DSH：**完全没有**（实证 0 命中）
- ChatGPT：有 `token_usage_record` 但 [推测] 无产品化仪表
- openclaw：有 manifest 内嵌单价 + usage kernel，是做得最好的

**怎么验证超过**：会话结束给可复算金额，两次展示一致，换模型后历史金额不重算。

### 机会 3：压缩后溯源普遍不清晰

- ChatGPT：压成「另一个模型的摘要」，原消息去哪了 [推测] 可查
- hermes：有 `absorbed_message_uids` 但正确性靠 **6 处重复 SQL 条件**维持

**怎么验证超过**：压缩+rewind+branch 三重叠加后，任意被吸收消息唯一反查到源行，且由**单点约束**（DB 约束/唯一索引）保证。

### 机会 4：配置演进普遍「升级即断」

- openclaw：明写不做兼容别名
- 闭源产品：通常也不提供迁移路径

**怎么验证超过**：保留最近两 minor 可读 + doctor 报弃用 + 旧配置真实启动测试作门禁。

### 机会 5：状态可见性只到「在做什么」，不到「证据在哪」

- ChatGPT：有上下文占用、步骤详略，但没有「这个结论的证据在哪」
- 我们：四态 + 每条记忆带来源 + 每个场景可追溯到 `tools/` 下哪个脚本

**怎么验证超过**：每个结论可点开看到证据来源（文件:行号 / 截图 / URL）。

## 八、诚实边界

1. **Cursor / Trae / CodeBuddy 无本机取证** —— 只有 [高置信] 与 [推测]，**不得当事实引用**。
2. **DSH 测试覆盖无法评估** —— production 安装，testkit 未装，全仓 0 个 `.test`。只能写「从这个产物无法验证」，不能写「DSH 没测试」。
3. **DSH 依赖方向无编译期强制证据** —— 无 tsconfig 工程引用，属文档+约定级。
4. **openclaw 运行时未实测** —— 结论来自源码与 docs。
5. **ECC hook 未实际运行** —— 只做静态阅读，拦截成功率是 [推测]。
6. **CL4R1T4S 是拼接产物** —— `CLAUDE-OPUS-5.5.md` 单文件含 12 段独立 prompt，1.9MB ≠ 1.9MB 提示词。
7. **luanyujia 部分文档未读** —— 06/08/13 及 105KB 规范未读；README 声称 2,717 行 vs 实测 3,164 行，无可信解释。
8. **open-design 快照缺 `packages/`** —— 1,599 处 import 无法解析，契约层读不到。
