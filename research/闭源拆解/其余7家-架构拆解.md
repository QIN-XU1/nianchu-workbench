## 二、重大发现：CodeBuddy 与 WorkBuddy 同源

- **CodeBuddy** 的内置扩展里有 **`genie 0.2.4`**。
- **WorkBuddy** 的依赖里有 **`@genie/agent-harness`**、**`@genie/im-channels-native`**。
- **WorkBuddy** 的插件目录是 **`.codebuddy-plugin`**。

→ **腾讯的 CodeBuddy 与 WorkBuddy 共享同一套 `genie` Agent 内核与 `.codebuddy-plugin` 插件协议**。
这不是两家独立实现，是同内核的两个产品壳。矩阵里把「CodeBuddy」和「WorkBuddy」当两家独立比较，**前提就不完全成立**（至少执行逻辑是同一套）。

## 三、WorkBuddy 的执行架构（119 文件里读出来的）

### 3.1 三种交互模式（模板）

`resources/app.asar.unpacked/resources/templates/` 下有：
- `workbuddy-ask-prompt.tpl` / `-ask-code-` / `-ask-coding-`
- `workbuddy-craft-prompt.tpl` / `-craft-code-` / `-craft-coding-` / `-craft-design-`
- `workbuddy-expert-prompt.tpl` / `-expert-code-` / `-expert-coding-`
- `workbuddy-quick-prompt.tpl`
- `system-reminder.tpl` / `ask-mode-reminder.tpl` / `craft-mode-reminder.tpl`

→ **ask / craft / expert 三种模式**，每种还有 code/coding/design 变体，外加 quick 模式。这是一种**按模式切换系统提示词**的架构。

### 3.2 插件与能力（`.codebuddy-plugin` 协议）

`resources/plugins/workbuddy-builtin/` 下：
- `skills/`（16 个，见 3.3）
- `hooks/high-credit-gate.cjs`（**积分门禁钩子**）
- `mcps/agently-cli`、`mcps/miora-mcp`
- `builtin-plugins/`：ardot · calendar · teams-todo · subscription-gate · tencent-docs · xmind · wecom-a2a-auth · weixinpay · workbuddy-creative/docx/pptx/sheetagent

### 3.3 Skills（16 个，SKILL.md 质量很高）

`buddy-image-processing` · `buddy-multimodal-generation` · `cloud-service` · `expert-manager` · `geo-map-compliance-guard` · `library` · `marketplace-skill-installer` · `mini-program-development` · `miora-brand-design` · `miora-creative-core` · `miora-image-generation` · `miora-video-generation` · `paper` · `recommend-connectors` · `recommend-experts` · `buddy-*`

`buddy-image-processing/SKILL.md` 的结构（**值得对照**）：
1. YAML frontmatter（name/description）
2. **Routing Rules**：什么请求用哪个 operation，什么请求**转交**别的 skill
3. **能力表**：capability → operation（erase/enhance/beauty/restore/matting）
4. **Input Rules**：禁止把本地图转 Base64 塞进 shell、4MB 上限、不打印大 payload
5. **Execution Flow**：`connect_cloud_service` 拿 `clientTempToken` → 跑脚本 → 轮询 → `present_files`
6. **Retry Rules**：**绝不自动重试**、**绝不伪造结果/文件路径**、超时报 `SUBMISSION_STATUS_UNKNOWN`
7. **Script Execution**：禁止猜安装目录、禁止手动拼 `app.asar` 路径

### 3.4 运行时依赖

`vendor/` 里带：`sandbox/5.11.4`（sandbox-cli/tsbx，**沙箱**）、`ripgrep`、`genie-trash`、`PortableGit`、`python.exe`、`node.zip`、`node-pty`（PTY）。

## 四、与念初逐维对比（诚实）

| 维度 | WorkBuddy | 念初 | 判定 |
|---|---|---|---|
| Agent 内核 | `@genie/agent-harness` | 自研 harness | 平 |
| 插件协议 | `.codebuddy-plugin` | `plugin.json` | 平 |
| **多模式（ask/craft/expert/quick）** | **有**（按模式切系统提示词） | **无**（单模式） | **WorkBuddy 领先** |
| Skills | 16 个 | 26 个 | **念初多** |
| Skill 质量（重试/禁伪造规则） | 写死在 SKILL.md | 有 trustBoundary，但没这么细 | **WorkBuddy 略领先** |
| Hooks | `high-credit-gate.cjs`（积分门禁） | 有 hooks | 平 |
| MCP | agently-cli / miora-mcp | 21 工具 | 平 |
| **云服务鉴权** | `connect_cloud_service` + clientTempToken | **无** | **WorkBuddy 领先** |
| 沙箱 | `vendor/sandbox` | 有 sandbox | 平 |
| 内置 Office 能力 | docx/pptx/sheetagent 插件 | 有（Office 三件套） | 平 |
| 积分/订阅门禁 | 有 | 无 | WorkBuddy 领先 |

**结论**：WorkBuddy 在 **多模式 / 云服务鉴权 / 积分门禁** 三项领先；念初在 **Skill 数量** 上更多。
「零落后」在 WorkBuddy 这一格也不成立。
