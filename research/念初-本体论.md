# 念初 · 本体论

> **这份文档回答一个问题：念初到底是什么。**
>
> 用户的定义是：「一个超越所有人的 agent，但他的概念不止于 agent，更像 AGI，
> 一份跨时代、真正带领人类发展的项目。」
>
> 这份文档不写口号。它把上面那句话**翻译成可检验的主张**，并且给出证据与边界。
> 立：2026-11-15

---

## 一、先把话说清楚：什么不该做

「像 AGI」这句话有两种接法，一种会毁掉项目，一种不会。

**接法 A（会毁掉项目）**：宣称我们在造 AGI，然后堆一堆看起来像 AGI 的功能。
这条路的问题不是难，是**它无法被证伪** —— 而用户明确禁止过「看起来有实际是空」。

**接法 B（本文件采用）**：找到**「AGI 与 agent 的真正分界」**，然后把分界做成可运行的机制。

分界是什么？看这 22 个拆解得到的证据。

## 二、证据：22 个项目共同缺的那一块

我对 18 份拆解报告的「缺点」章节做了关键词归类扫描（`tools/benchmark/find-common-gap.mjs`），实测：

| 共同缺点 | 提及份数 | 谁 |
|---|---|---|
| **多副本漂移** | **11 份** | closed · hermes-ecc · new3 · openbitfun · orca · spec · 补-cursor · 补-exec-1 … |
| **结论不可独立验证** | **7 份** | closed · dsh-openclaw · three · 补-cursor · 补-exec-1 · 补-luanyujia-2 · 补-trae |
| 单文件过大 | 6 份 | hermes-ecc · new3 · omp-aion · openbitfun · three · 补-exec-2 |
| **不会自己变强** | 3 份 | new3 · 补-luanyujia-2 · 补-luanyujia |
| 被供应商/平台锁住 | 3 份 | closed · dsh-openclaw · 补-cursor |
| **改进没有度量** | 2 份 | new3 · 补-luanyujia |
| 记忆不会老化 | 1 份 | hermes-ecc |
| 成本不可见 | 1 份 | dsh-openclaw |

### 2.1 三条共同短板的合取，正好是「会自己变强的系统」的最小条件

```
结论不可独立验证  +  改进没有度量  +  不会自己变强
        ↓                  ↓                ↓
   没法证明自己做对    没法知道有没有变好   改进靠人手工
        └──────────────────┴────────────────┘
                            ↓
              「闭环不成立」—— 没有人把这三件事接起来
```

**逐项实证**（不是归纳，是各自的原话）：

- **ECC**：314 skill / 71 agent / 98 command 的真源，但**0 行代码保证执行**；
  `validate-skill-host-compat.js` 只校验副本合法，不校验与 canonical 一致 →
  314 canonical 漂到 Codex 47 / Kiro 43 / Cursor 12，**没有任何机制会去补**
- **luanyujia**：写了 184.6KB 规范（三份），**0 行代码**；
  它自己承认「无对照实验、无前后发生率」→ 机制是否真减少事故**没有数据**
- **solo-to-team-skills**：有状态机但**全靠自觉**，明写「无对照实验、无前后发生率」
- **Cursor**：有 `disable_cursoreval`（自己的 eval 系统）与 `disable_ai_assert`（AI 断言），
  但**闭源、外部不可验证**，且只到「断言通过/失败」二态
- **DSH**：把「无特权内核」做到了极致（338 包全可替换），但
  `rg "usd|dollar|pricing"` 在 `*/src/**` **零命中** —— **完全不知道一轮花了多少**
- **hermes**：8 层审批闸、18 张表、6 后端 —— 工程上最强的一档，
  但**无记忆 TTL**（`rg ttl|decay|half_life` 四模块零命中），陈旧记忆永久污染 system prompt

### 2.2 所以分界不在「能力」，在「闭环」

| | agent（22 个都是） | 念初（主张） |
|---|---|---|
| 做任务 | ✅ | ✅ |
| 说自己做完了 | ✅ | ✅ **+ 证据 + 判不了的单独一列** |
| 记忆 | ✅ 存 | ✅ 存 **+ 来源 + 老化 + 冲突留痕** |
| 改进自己 | ⚠️ 靠人改配置/技能 | ✅ **自己提假设 → 改 → 量 → 留或退** |
| 证明改进有效 | ❌ 无 | ✅ **前后对比数字 + 独立验收方** |
| 成本 | ❌ 多数不可见 | ✅ 可复算 |

**一句话**：agent 是**执行器**；念初要做的是**一个能证明自己在变强的系统**。

这不是「更聪明的 agent」，是**换了一层**：从「执行」换到「改进执行」。

## 三、为什么这算「带领人类发展」

我不想把这句话说成空话，所以给一个**具体的、可被反驳的论证**：

**AI 帮不了人类，瓶颈不是能力，是信任。**

现状的证据（就在我们身边）：
- 公司把 AI 限制在低风险任务 —— 因为没人能核验它的输出
- 个人用它写草稿，不用它做决定 —— 因为错了没法追责
- 没人在无人监督下让它跑长周期任务 —— 因为不知道它什么时候开始瞎编

**每一次「不敢用」，代价都是人类时间的真实浪费。**

而解锁信任的东西不是「更强的模型」，是**可核验的主张**：

> 一个说「做完了」的系统，和一个说
> 「做完了 · 这是证据 · 这三项我判不了 · 这是第三方复核结果 · 这次比上次快了 X% 且错误少了 Y 个」
> 的系统 —— **不是同一类东西。**

第二种可以被**委托**。可委托，才谈得上「帮人类」。

所以「带领人类发展」在这个项目里的具体形式是：
**把「可委托」变成工程属性，而不是把「更聪明」当卖点。**

这个论证可以被反驳 —— 反驳方式是举出一个「不可核验但被大规模委托」的反例。
我目前想不出。**这就是我愿意把它写进规格的原因。**

## 四、可检验的主张（六条，每条给判据）

不写「跨时代」这种词。写成能被机器判定的六条：

| # | 主张 | 判据（怎么算达成） |
|---|---|---|
| **C1** | 每个结论都能追到证据 | 任意一条断言可反查到 `路径:行号` / URL / 截图；**无法追溯的断言数为 0** |
| **C2** | 判不了就说判不了 | 四态（PASS/WARN/FAIL/UNKNOWN）中 UNKNOWN **永不并入通过**；构造不可判定场景必须输出 UNKNOWN |
| **C3** | 记忆会老化且留痕 | 过期项不进结果但保留历史；冲突时旧值标 `superseded` 且**仍可查** |
| **C4** | 改进有前后度量 | 每次自我修改记录：改前指标 / 改后指标 / 样本量；**改前无度量则不许改** |
| **C5** | 改进会被独立验证 | 验收方与实现方**不是同一个**；自我修改若只被自己验证过，状态最高为 `部分` |
| **C6** | 成本可复算 | 任一轮任务可算出金额，且**两次展示一致**、换模型后历史金额不重算 |

C1–C3、C6 我们**已有可运行的实现**（见第六节）。
**C4 与 C5 是缺口 —— 也正是「跨时代」那一步。**

## 五、架构：五层，缺哪一层

```
┌─────────────────────────────────────────────────────────┐
│  L5 证明层   每个主张可追到证据 · 矩阵诚实性审计          │  ✅ 已有
│              矩阵 31 维 / 假绿审计 0 项                   │
├─────────────────────────────────────────────────────────┤
│  L4 改进层   假设 → 改动 → 度量 → 留或退 → 留痕          │  ✗ 缺 ← 核心
│              （这是「会自己变强」的物理位置）              │
├─────────────────────────────────────────────────────────┤
│  L3 记忆层   来源 + 冲突留痕 + TTL + supersede           │  ✅ 已有
│              无来源拒绝写入 · gc 只删「过期且被推翻」      │
├─────────────────────────────────────────────────────────┤
│  L2 验证层   四态 · 12 个验收器 · 300+ 断言              │  ✅ 已有
│              UNKNOWN 永不并入通过                         │
├─────────────────────────────────────────────────────────┤
│  L1 观测层   真实状态采集（进程/端口/网关/仓库/资源）      │  ✅ 已有
│              反假绿断言：PASS 必须有实观测                │
└─────────────────────────────────────────────────────────┘
```

**L4 是唯一缺的，也是全部差别所在。**

前四层的意义是**让 L4 成为可能**：
- 没有 L1，改进无从观测
- 没有 L2，改进无法判定对错
- 没有 L3，改进的结论会丢或会污染
- 没有 L5，改进的声明不可信

**所以这个项目的技术主线不是「加功能」，是「把闭环接上」。**

## 七、L4 的第一个可交付切片（具体到能开工）

**目标**：让系统**自己发现一个真实问题 → 提出改动 → 度量前后 → 决定留或退 → 留下可复核记录**。

**要做的东西**（都不新造概念，全用已有的）：

1. **`tools/evolve/hypothesis.mjs`** —— 假设登记
   输入：一条观测（来自 L1）+ 一个可度量的指标
   输出：结构化假设 `{ 观测, 假设, 指标, 基线值, 预期方向, 判据 }`
   **硬约束**：没有基线值的假设**不许登记**（对应 C4）

2. **`tools/evolve/measure.mjs`** —— 度量执行
   跑基线 → 应用改动 → 再跑 → 出 `{ 前, 后, 差, 样本量, 是否支持假设 }`
   **硬约束**：样本量 < N 时结论只能是 UNKNOWN（对应 C2）

3. **`tools/evolve/ledger.mjs`** —— 改进台账（只追加）
   每条：`日期 / 观测 / 假设 / 改动 / 前后值 / 结论 / 谁验的 / 留或退`
   **硬约束**：结论为「留」但验证方 == 实现方 ⇒ 状态降为 `部分`（对应 C5）

4. **`tools/evolve/verify-evolve.mjs`** —— 反例台
   **关键**：必须能证明「假改进会被拒」——
   造一个「改前无度量」的改动 ⇒ 必须拒绝登记；
   造一个「样本量不足」的度量 ⇒ 必须输出 UNKNOWN；
   造一个「自己验自己」的结论 ⇒ 必须降为部分

**验收判据（可机械判定）**：
- 跑 3 轮真实改进，台账有 3 条完整记录，每条前后值可复算
- 3 个反例全部被拒/降级
- **并且**：其中至少 1 轮是**系统自己发现的**问题（不是人指定的）

第三条是分水岭：**能做到，才叫闭环；做不到，就还只是「带度量的配置管理」。**

## 八、边界（我不承诺什么）

必须写清楚，否则这份文档就违背了 C1/C2。

1. **我不承诺造出 AGI。** 没有人能按需造出通用智能。本文件承诺的是**闭环** ——
   一个能被检验的、会度量自己改进的系统。这是 AGI 的**必要条件，不是充分条件**。
2. **「带领人类发展」是长期后果，不是近期指标。** 近期唯一可检验的是 C1–C6。
   如果 C1–C6 做不到，那句话就是空话 —— 所以我把它放在第七节之后。
3. **L4 闭环本身可能失败。** 风险是真实的：
   - 系统可能「改进」出一个只在度量里成立的假优化（Goodhart 陷阱）
     → 缓解：C5 要求独立验证方；反例台必须能拒掉假改进
   - 自我修改可能破坏已通过的 16 项验收
     → 缓解：每次自我修改后全量重跑 `verify-goal`，红线不许破
   - 度量本身可能是错的
     → 缓解：度量必须可复算（偏差 <5%，已有先例：密度度量 12 项断言）
4. **我不为「跨时代」这个词负责。** 我负责 C1–C6 能被机器判定。
   词是用户的，判据是我的。

## 九、和「超过 7 个参照系统」的关系

这两个目标不冲突，是同一件事的两面：

- **超过参照系统** = 在 31 维矩阵上，我们的格子有实证依据（横向）
- **闭环** = 这些格子会**自己变好**（纵向）

**没有闭环的超越是一次性的**：今天我们比 OpenBitFun 多 5 个维度，
但他们会更新，我们必须手工追 —— 这就是 11 份报告都提到的「多副本漂移」。

**有了闭环，超越是可复利的**：系统自己发现差距 → 自己提改动 → 自己量 → 留下有效的。

所以：**闭环不是加的第八个目标，它是让前七个目标不退化的机制。**
