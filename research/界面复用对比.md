# 界面复用对比（v4）

> 用户的判断：**「界面整体给人一种廉价感，请比对主流的几款开源项目，直接复用他们的做适量修改。」**
> 本文是多项目对比的结论，以及 v4 到底复用了什么、改了什么。

---

## 一、为什么之前会廉价（三个具体来源）

| 来源 | v1–v3 的做法 | 后果 |
|---|---|---|
| 图标 | 用字符当图标：`◧ ◉ ✳ ◷ ⛁ ⚒ ◎ ⚙` | Wingdings 观感，最像"没做完"的一处 |
| 控件 | 按钮 / 输入框 / 开关 / 表格**全部手搓** | 缺微状态（hover 过渡、focus ring、按下位移、禁用态） |
| 色阶 | 自己拼 30 个散 token | 灰与灰不同源，整屏发脏 |

**手搓组件是根因。** 一个成熟组件库在按钮内边距、圆角、过渡曲线、焦点环这些细节上累积了几百次调整，不是临时能画出来的。

---

## 二、多项目对比（源码级，不是看截图）

取依赖清单的方式：`api.github.com/repos/<repo>/contents/package.json`（`raw.githubusercontent.com` 被墙，`codeload` 与 `api` 可用）。

| 项目 | 设计体系 | 关键依赖 |
|---|---|---|
| **Cherry Studio** v2.2.2 | Tailwind v4 + **shadcn 约定** + **Lucide 图标** | `tailwindcss ^4.3.3`、`@tailwindcss/vite`、`@radix-ui/react-switch`、`@radix-ui/react-slot` |
| **LibreChat** v0.8.9 | Tailwind + 自研组件 | `prettier-plugin-tailwindcss` |
| **Open WebUI** v0.13.3 | Tailwind v4 + typography | `@tailwindcss/postcss`、`@tailwindcss/typography` |
| **LobeChat** v2.3.3 | 自研 UI 包 | `@lobehub/ui ^6.13.1`、`@emotion/react`、`next-themes` |
| **AionUi** v2.2.2 | **Arco Design**（唯一用完整组件库的） | `@arco-design/web-react ^2.66.1` |

补充证据：

- Cherry Studio `src/renderer/assets/styles/index.css` 里明确有 `.lucide:not(.lucide-custom) { color: var(--muted-foreground) }`，
  说明它**就是用 Lucide 图标集**，并且图标是个被统一着色的原子组件。
- 它有独立的 `packages/ui/src/styles/`：`contract.css` / `product.css` / `shadcn.css` / `theme.css`(18.4KB) / `tokens.css`，
  即**把设计系统当独立包维护**，而不是散在业务组件里。
- `shadcn.css` 就是 shadcn 的语义变量契约：`--background/--foreground/--card/--popover/--primary/--secondary/--muted/--accent/--destructive/--border/--input/--ring/--sidebar-*/--radius`。

### 结论

**五家里四家在 Tailwind 上手搓组件，只有 AionUi 用完整组件库。**
而我手搓的结果就是廉价 —— 所以 v4 走 AionUi 那条路，同时借 Cherry Studio 的两条做法：**用 Lucide 图标**、**把设计令牌单独成层**。

## 三、v4 复用了什么

| 资产 | 版本 | 许可 | 体积 | 用在哪 |
|---|---|---|---|---|
| Arco Design（`@arco-design/web-react` 的成品 CSS） | 2.66.1 | MIT | 657.5KB | 全部控件：按钮 / 输入框 / 开关 / 表格 / 标签 / 空态 / 弹层遮罩 |
| Lucide | 0.469.0 | ISC | 349.7KB | 全部图标（侧栏、能力分类、按钮、空态） |

两者都已 vendor 进仓库：`prototype/agent-ui/vendor/arco.css`、`vendor/lucide.js`，页面用相对路径 `<link>` 引用，**不依赖网络**。

### 我改了什么（「适量修改」的部分）

**一、配色覆盖（约 30 个变量）。** 不是改 Arco 的结构，只把它的暗色令牌换成中性灰阶 + 单一主色：

```css
body[arco-theme='dark'] {
  --color-bg-1: #0e0e10;  --color-bg-2: #141416;  --color-bg-3: #1a1a1d;
  --color-bg-4: #212125;  --color-bg-5: #29292e;
  --color-border: #26262b; --color-border-2: #303036; --color-border-3: #3a3a41;
  --color-text-1: #f2f2f4; --color-text-2: #b6bac2; --color-text-3: #8b9099; --color-text-4: #6b7079;
  --primary-6: #4f7cff;
  --border-radius-small: 4px; --border-radius-medium: 6px; --border-radius-large: 8px;
}
```

沿用自己的原则：**颜色只表示状态，不表示装饰** —— 主色只有一个蓝，其余颜色只给验证四态（通过 / 待补 / 失败 / 判不了）。

**二、开关的类名与配色（踩到的真坑）。** Arco 的小号开关类名是 `arco-switch-small`，不是 `arco-switch-size-small`；
且暗色下 `checked` 的轨道几乎看不见，必须显式给色：

```css
.arco-switch { background: var(--color-fill-4); }
.arco-switch.arco-switch-checked { background: var(--primary-6); }
.arco-switch .arco-switch-dot { background: #fff; }
.arco-switch-small { width: 28px; height: 16px; }
```

**三、信息架构（这部分是我们自己的，v3 已验证）。** Arco 只提供控件，不提供产品结构：

- 侧栏两级：一级导航（会话 / 智能体 / 能力 / 自动化）+ 随一级切换的二级列表
- 主区是**路由**：会话 / 能力 / 自动化 / 智能体 / 设置，支持深链接 `?view=capabilities&kind=mcp`
- 能力五分类（技能 / MCP / 工具 / 模型 / 智能体）用 Arco 表格承载
- 能力归属三条通道：能力页（全局配置）· 智能体详情（组合）· 会话内胶囊（这次用了什么）

**四、去掉了重复导航。** 侧栏已经列了「能力分类」五项，页面里原本又有一列同样的五项 ——
重复一列既浪费宽度，也让"我在哪"变含糊。已删除页内那列。

**五、表格列宽按比例分配**（名称 46% / 16% / 19% / 12% / 8%），而不是让名称列用 `1fr` 吃满、右侧空一大截。

# 追加：v5 转向 DSH + open-design 的设计语言

> 用户第二轮判断：**「Cherry Studio 类的设计我并不喜欢，他看起来像是很多年前的老产物，
> ChatGPT、claude code、deepseek harness 这些界面设计的我觉得就很好」**，
> 随后补充：**「https://github.com/nexu-io/open-design/ 项目的界面也具有很大的参考意义」**。

## 一、Arco 路线为什么被否

Arco / Cherry Studio 那一类是「企业后台」气质：卡片、表头、边框、拨动开关、彩色主按钮。
它**不算廉价**，但它**不算现代**。被嫌"像很多年前"的正是这套语言。

所以 v5 把 Arco 整个移除，改为读两个「被认可」的系统自己的样式。

## 二、DSH：从 app.asar 里抽出来的真实令牌

Web GUI 要鉴权（401），但本机有 `app.asar`（199MB），用 asar 头解析直接取文件：

```
dsh-client-ui-theme/src/styles/design-platform.css                    474 条变量
dsh-client-ui-sidebar/src/client/SidebarRoot.module.css               22KB
dsh-client-ui-conversation/src/client/skeleton/ConversationRoot.module.css  21KB
```

实测结论（与「老产物」逐条相反）：

| 维度 | Arco/我旧版 | DSH 实测 |
|---|---|---|
| 圆角 | 4 / 6 / 8 | xs4 / sm8 / md12 / lg16 / xl20 / panel28 |
| 边框 | 到处硬线 | `rgba(0,0,0,.04)`–`.16`，几乎看不见 |
| 边框数量 | 每个组件都有 | **侧栏 22KB CSS 只有 6 处非零 border；会话 21KB 只有 2 处** |
| 底色 | 暖褐 / 纯中性 | `--dsw-static-neutral-bluish-*` 中性偏蓝；暗色底 `#0f1115` |
| 阴影 | 堆叠 | `lv1 = 0 2px 4px rgba(0,0,0,.05)` |
| 分区 | 靠框线 | 靠间距 |

关键色值（逐字）：

```
neutral-bluish  00 #ffffff  50 #f9fafb  75 #f1f3f5  300 #cfd3d6  500 #979da6
                600 #81858c 700 #61666b 875 #232324 900 #1b1b1c 950 #151517 1000 #0f1115
deepseek-500    rgb(65,118,230) = #4176e6
border-l1/l2/l3/l4  rgba(0,0,0,.04 / .10 / .12 / .16)
radius          xs4 sm8 md12 lg16 xl20 panel28
```

## 三、open-design：又一整套语言，且更"墨"

仓库 31.7MB / 4826 文件（tar 在 assets 的 webp 处被 240s 超时截断，源码完整）。
Next 16 + React 18 + **Tailwind 4.3** + **lucide-react 1.16** + **motion 12.40**，
自带一层样式库：`tokens.css`(13.9KB) / `primitives.css`(17.1KB) / `shell.css`(75.9KB) / `chat.css`(141.6KB)。

它的令牌与 DSH 是两种气质：

```
字阶   --text #494949  --text-strong #202020  --text-muted #5c5c5c
       --text-soft #848484  --text-faint #bdbdbd
主色   --accent #353535（墨！不是蓝）  --accent-strong #202020
品牌   --brand #87ea5c  --brand-text #0d5400  --brand-surface #F2FFF2
       --send-ground #00ff08（只有发送按钮是荧光的）
圆角   small 2 / medium 4 / large 8 / xlarge 12 / 2xlarge 16
阴影   xs 0 1px 0 rgba(28,27,26,.04)   sm 0 1px 2px .05 + 0 1px 3px .04
玻璃   --glass-regular rgba(250,250,250,.66)  --glass-regular-blur 28px
动效   50/100/150/200/250/300/400/500ms + 四条命名曲线
正文   --prose-font-size 13px / line-height 1.7
z 序   --z-hint 4000 / --z-menu 9000（按用途命名，不是随手取大数）
```

**它给的启示，恰好治我 v2–v4 的病：结构用墨色，颜色只留给「状态」和「那一个动作」。**
我之前的界面到处是蓝（主按钮、选中态、图标），正是"配色很用力"的廉价来源之一。

## 四、v5 最终取谁的什么

| 取自 | 用在 |
|---|---|

# v6：把暗色令牌换成 DSH / open-design 的字面值

> 用户第三轮判断：**「配色太丑了，很廉价，一点都没有顶尖的水平，另外很多处细节也没处理好」**。

前五版我一直在**调色**，这一版改成**取证**：把两个被认可系统的暗色令牌逐字抽出来，直接照抄。

## 一、根因：我之前根本没读过它们的暗色值

- DSH 的 `design-platform.css` 我只读了亮色基础层，暗色覆盖在 `body[data-ds-dark-theme]` 块里，**255 条变量**没读。
- open-design 的 `tokens.css` 我只读了 `:root`，`[data-theme="dark"]` 块（52 条）没读。

读出来之后，我 v5 的三处错误一目了然：

| | DSH 暗色实测 | open-design 暗色 | 我的 v5 | 后果 |
|---|---|---|---|---|
| 底色 | `bg-base = neutral-bluish-950 = #151517` | `--bg #202020` | `#0f1115` | 太黑 |
| 层次步进 | 151517 → 232324 → 2c2c2e → 353638（**14/10/10**） | 202020 → 353535 → 494949 | 151517 → 1b1b1c（**只差 6**） | **整屏糊成一片，这就是"廉价"的物理原因** |
| 品牌主色 | `brand-primary = neutral-bluish-50 = #f9fafb` | `--accent #ededed` | 蓝 `#4176e6` | **暗色下塞彩色主色，第二个物理原因** |
| 状态色 | — | 绿 `#3BBF7D` / 琥珀 `#FFC740` / 红 `#FF5E5E` | 高饱和交通灯 | 第三个物理原因 |
| hover | `rgba(255,255,255,.08)` | — | 自己拼的 | 不到位 |

**结论：两个顶尖系统在暗色下，品牌主色都是近白，不是任何彩色。** 彩色只用来表示状态。

## 三、细节修复清单（用户说"很多处细节没处理好"）

## 四、验收：三条根因做成了可计算的指标

```

  —— v5 只有 6，所以糊
✓ 暗色主色 accent-ink 是近白 #f9fafb（RGB 最小值 249 ≥ 230）
✓ 主色不带明显色相（通道差 2 ≤ 12）—— 不是"塞了个蓝"
✓ 页面里已完全不引用 --ds-500（实际 0 处）
✓ 状态色 = open-design 的 #3BBF7D / #FFC740 / #FF5E5E
✓ 已启用状态不再逐行写文字（只标停用）
✓ 状态文字禁止换行（「已停用」曾被挤成两行）
✓ 会话视图顶栏扣掉右工作区宽度，与正文对齐
```

## 五、我仍然不敢说的

**「顶尖水平」这件事没法自我认证。** 我能做的是：把配色从"我调的"换成"两个被认可系统的字面值"，
并把可计算的三种廉价来源做成断言。至于整体是否达到那几家水平，需要你指具体位置。

前五版我都以为对了，所以这次不写"这次应该行了"。

# v7：照搬 BitFun（OpenBitFun）的设计系统

## 一、它有一个正规的设计系统包（这是能"直接照搬"的前提）

仓库 31.4MB / 5210 文件。顶层就有 `design-system/`，README 写明这是**独立可发布的边界**：

```
@openbitfun/design-tokens    令牌契约 + 密度模式 + 生成的 CSS/TS 产物
@openbitfun/theme-openbitfun 可替换的 light / dark / high-contrast 主题值
@openbitfun/ui               与主题无关的 React 原语与组件
@openbitfun/token-engine     构建期令牌解析
@openbitfun/design-lab       独立预览与令牌编辑应用
```

**两层色彩模型**：参考色用 `ref.color.neutral.950` / `ref.color.blue.400` 这种命名标尺，
语义色把它们映射到 UI 角色。参考色**不生成运行时 CSS 变量**，也不作为组件契约 ——
这条纪律比"一堆 CSS 变量"清晰得多。

令牌源文件是 JSON：

```
theme-openbitfun/src/reference.tokens.json      171 条（159 个 hex）
theme-openbitfun/src/dark.tokens.json           192 条
theme-openbitfun/src/light.tokens.json          192 条
theme-openbitfun/src/high-contrast-{light,dark}.tokens.json
design-tokens/src/system.tokens.json            740 条（版式/几何/动效/层级）
design-tokens/src/density-{compact,touch}.tokens.json
```

## 三、除了颜色，还照搬了行为

从 `design-system/packages/ui/src/flow-chat/` 读到的不只是色值：

| 行为 | 出处 |
|---|---|
| **composer 聚焦只改 border-color，不加焦点环、不加阴影** | `ChatComposer.module.css` `.surface:focus-within { border-color: var(--openbitfun-color-border-default) }` |
| **小图标按钮用 pill 半径** | `.actionButton[data-openbitfun-component="icon-button"] { border-radius: var(--openbitfun-radius-pill) }` |
| **状态色 = emphasis 10% 底 + 30% 边** | `color.status.*.surface / .border` 的 color-mix 规则 |
| **composer 有 compact / expanded 两种布局** | `.surface[data-openbitfun-layout="compact"\|"expanded"]` |
| **工具卡分 ambient / prominent 两类** | `AmbientToolCard` / `ProminentToolCard` —— 名字说明结果该留在对话背景还是值得用户注意 |

## 四、没能照搬的（说清楚，不装）

**BitFun 的应用外壳不在仓库里。** 它是 Rust + Tauri，前端编进二进制；仓库里只有
`design-system` 包、安装器 UI（`OpenBitFun-Installer`）和 MiniApp 示例。
所以外壳的 HTML 结构仍是我们自己的信息架构（侧栏两级 + 主区路由 + 能力五分类）。

能照搬的是它的**设计系统**——而那恰好决定了"看起来像不像"。
