## 一、三个「误报」逐条查：它们到底是不是验收器的错

| 用例 | 当时的表现 | 是验收器的错吗 | 我的处理 | 处理对不对 |
|---|---|---|---|---|
| **F04** typography:audit | 干净状态 exit 1 | **不是** —— 它因缺 Rust 侧 `typescript-owner` 文件（`missing-typography-owner`）**永久**非 0，那是**部分 fork 的结构性限制** | 加 `expectOutput: "raw-css-typography"`，要求输出里出现本次注入的具体违规类型 | **对**：它把「结构性失败」与「这次注入的违规」区分开了 |
| **F07** dirty git | 干净状态 exit 1 | **不是** —— 树脏时 R8 **本就应该红**，那是正确行为 | 加 `dependsOnCleanGit: true`，树脏时判 UNKNOWN | **对**：环境不满足是 UNKNOWN，不该算误报 |
| **F08** matrix dim count | 干净状态 exit 1 | **不是** —— `verify-goal` **根本没有 `--only` 参数**，所以跑全量，得到的是全量结论 | 给 `verify-goal` 加 `--only`（前缀匹配，跳过项不计入） | **对**：这是补一个缺失的功能，不是放松判据 |

**结论：三个都不是验收器的准确性问题。**

所以 `fpr 0.375 → 0.000` 这个变化，**度量的是「我的度量器算得对不对」，不是「验收器准不准」。**

---

## 二、我原来错在哪

我原来的说法（提交 `1a6f9e76` 之后的汇总里）：

> fpr `0.375 → 0.000` —— 误报率降到 0

这句话暗示「验收器的误报减少了」。**那是错的**，因为：
- 没有任何一个验收器的判定逻辑被改准
- 变的是**度量器对「什么算误报」的定义**

**这是把「度量口径修正」说成了「被测对象改善」。** 两者完全不同：
- 前者是我发现自己算错了
- 后者是系统真的变好了

独立验证方 R2 抓的就是这个偷换。

## 三、正确的说法（已写进度量器注释与台账）

```
fpr 这个指标，在当前实现里测的是：
  「度量器能不能正确区分『验收器真报错』与『验证环境不满足 / 工具缺功能』」

它不测：
  「验收器判断的准确性」
```

**真正测验收器准确性的指标应该是另一个**：拿**真实历史提交**里已知的缺陷，
看验收器当时有没有报。（本轮没做，记为缺口。）

## 四、这件事本身的价值

它证明了闭环的一个必要环节：**没有独立验证方，我会一直带着这个错误说法往下走。**

具体链条：
1. 我改了三处判据 → 数字变好 → 我写「误报率降到 0」
2. 如果没有独立验证方，这句话会进矩阵、进本体论、进给用户的汇报
3. 独立验证方对着 git 历史逐条核对，发现**0 处改验收器** → 判 `refuted`

**这正是 C5（独立验证）存在的意义 —— 它抓的不是「我造假」，是「我把自己没意识到的东西说成了结论」。**
