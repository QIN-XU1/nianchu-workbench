## 核心资产一：标准化规范（105KB 读完 → 32 条可执行条目）

来源：`05-协作与规矩/二-标准化规范.md`（777 行）。它回答的是**"加任何东西都有唯一正确的位置与固定格式"**（`:11`）。原文自带一句定位："层级：规范层（细则）——平时不读，按节号查"（`:3`）。

**A. 位置与根（§一 / §6.2）**
1. **全机只有一个根**，根下固定 7 个夹：`引擎\` `外壳\` `启动器\` `工作区\` `说明\` `备份\` `自我复盘\`；换机只搬这一个文件夹 + 改 `DSH_HOME`（`:17-33`）。
2. `DSH_HOME` 必须 = `<根>\引擎\.dsh`，否则引擎读旧会话库（`:32`；`一-全局铁律.md:46`）。
3. `自我复盘\` **不是软件的一部分**，是"人的"，换机跟着搬但不许塞程序（`:30`）。
4. 关键/不可再生的一律进 `备份\`；工作区只放过程件（`:115-117`）。

**B. 加东西的七种标准（§二 2.1–2.14）**
5. **加场景六步**：json → 定位卡 → 登记身份索引 → 专属技能 → 长期记忆 → 生效方式（改 json 切一次场景、新标签要重启 GUI）（`:39-46`）。
6. **加技能**：位置只认 `引擎\.dsh\skills\<名>\SKILL.md`；front-matter 只许 `name/description/whenToUse` + 两个布尔 + metadata；**驼峰旧写法会被引擎判错**；`SKILL.md ≤12 KB`；热加载（`:47-67`）。
7. **技能长大 = 拆子技能，不是硬压**：主技能只留"导航+判据+铁律+触发词"，子技能 `description` 必须写清"什么时候用它"（因为目录摘要只渲染 name+description）；**为压体积删判据 = 静默丢功能**（`:54-64`）。
8. **插件/MCP/驱动三目录只放本体**，不许丢脚本素材试验品；新增插件行要重启引擎（`:68-76`）。
9. **记忆四节必备**：`§〇 交接`(覆盖) + `§一 简介` + `§二 资产` + `§五 决策与坑`(只追加)；开场只读 §〇+§一+§二，§五先 grep（`:77-83`）。
10. **写回判据**：只有实质工作（建/改应用、修 bug、写文档、重构、定方案、宿主约定）才写；⛔ 不记搜索结果/临时路径/报错原文/一次性约束；**每会话 ≤10 行 / ≤2 KB**（`:83-87`）。
11. **体积红线**：场景记忆主文件 **≤25 KB**、`§〇` **≤4 KB**、技能 **≤12 KB**、定位卡 **≤25 KB**、注入层越短越好（`:88`、`:217`、`:605`）。
12. **拆分两条铁规**：① 能搬走=解释/背景/长清单/案例/排障经过；**绝不能搬走=判据·阈值·命令原文·执行顺序·红线·触发条件**（六样搬走就是功能静默丢失）② 移出内容必须留**触发句**「要 <做 X> 时，读 <文件> §<节>」，只留路径等于没写（`:93-102`）。
13. **临时目录**只准建在 `<工作区>\_临时\<会话名>-<YYYYMMDD-HHMM>\`；⛔ 盘根/桌面/`%TEMP%`（`:104-107`；后收紧为两处，`一-全局铁律.md:41`）。
14. **工作区顶层 = 白名单制**：新目录要**同时**改 `_目录地图.md` 表 + `梳理体检.mjs` 白名单，两处都改才算合规（`:109-121`）。
15. **文本/文档索引**：每场景一份 `_文件索引.md`，四列 `文件|是什么|状态|复核日期`；状态只有四个词 `活/常备(180天)/留档/待清(7天)`；新建即登记、删改同一步改行（`:125-135`、`:196-224`）。
16. **文档密集目录必须有索引（写死数字）**：常驻目录**直接子文档 ≥30**，或 **≥8 且合计 ≥500 KB**，或**同主题 ≥10 份** ⇒ 必须有 `_索引.md`；扫描深度 ≤4；豁免 `_临时`/`node_modules`/历史归档（但父目录索引要有"这里是什么"一行）；抓手 `索引体检.mjs --dense`（`:226-240`、`:581-584`）。**这条的起因是宿主实测投诉"规矩失效了"**（`:228-231`）。
17. **例外要机械判定**：项目自有成熟索引 ⇒ 台账只登记入口一行，但**三条全满足才算已登记**（白名单 json + 索引真实存在 + 台账有入口行），否则退回逐文件登记（`:243-248`）。
18. **源码直跑、永不打包**（宿主原话"不要让我的工作台受影响"）：靠两件事撑着——`resources\app` 是指向源码的**目录联接**、`启动器\*.exe` **一个字节都不许动**；实测用 rcedit 改版本资源 ⇒ 渲染进程全线 `launch-failed exit 57`、所有面板灰白、**壳此后起不了任何子进程，只能重启**；抓手 `入口哨兵.mjs` 比 exe SHA256 + 查联接（`:139-158`）。
19. **文件夹治理**：建之前弹卡片问（四样：建在哪/叫什么/装什么/为什么不塞已有夹）；命名=用途+时间（禁"新建文件夹/temp/最终版/副本"）；建完登记 `目录基线.json` + `_目录地图.md`；抓手 `目录哨兵.mjs`，**违规项不许进基线**（`:162-192`）。
20. **文档生命周期**：状态四词 + 到期四选一（更新/**合并优先**/归档/清）+ 归档落点写死；节奏：每周日 12:30 稳定体检、每月 1 日 05:00 文档整理（`:196-224`）。

**C. 四条业务规矩（§2.11–2.14，都是宿主原话驱动）**
21. **设计/图片活唯一对口 `design-misc`**：请求六项必填（要什么 / **用在哪** / 尺寸 / 格式 / 风格 / 何时要），缺 `--for` 直接拒发；**产物落点三级优先**（`--out` > `_临时\设计产物-<请求方>-<时间>\` > 项目自己的素材夹）；**交付回四件套**（绝对路径 + 尺寸/格式/体积 + 怎么用 + 还差什么）（`:252-286`）。
22. **免费 AI 顾问团**：默认 2 站、重要方案 3 站、⛔ 不超 3；一条命令收成**一份 `_汇总.md`**（不要自己写循环，那样 3 份回答各占一份上下文）；`--round2` 让一站读另外两站；**机密闸脚本硬拦，`--force` 也不放行**；采纳三原则"自己核过再落文件"（`:290-316`）。
23. **帮手会话**：触发信号=活重/可切片/要并行；命名 `<场景简称>助手N`；**不是新场景**（不进名册/不建卡/不建记忆），只有一份交接文档；登记走 `助手会话.mjs`，不登记=顶栏看不见=白开；**防无限对话**五条硬约束（见资产二）（`:320-372`）。
24. **整树部署铁律**：任何"把一整棵树推上去/盖过去"的动作，动手前先做**只读差异预检**；**差异集合 == 自己的改动集合**才可真做；冒出别人的文件 ⇒ 停手 + 通知主人；没有 `--check-only` ⇒ 先补开关再部署；部署后再打一次差异（`:373-382`）。

**D. 换机器（§三）**
25. **必须搬**：`引擎\.dsh\`（skills/sessions/storages/profiles/凭据/铁律/规范）+ 所有场景记忆 + 插件/MCP/工具本体 + 外壳全部源码与 scenarios + 根工具 + 工作区三入口文件；**不必搬**：node_modules（引擎 1,960.7 MB / 外壳 0.43 GB）、构建产物（须先 `pnpm run clean`）、electron-profile、`_临时`（`:388-410`）。
26. **换机复验五项**：引擎能起 / 配置零警告 / 场景全在（`sessions.mjs --check`）/ MCP 全活 / 技能全在 / 记忆能读（`:438-446`）。
27. **盘符不同只替换三串**：`<根>\引擎`、`<根>\外壳`、`<工作区>`；替换后必跑 `sessions --check` + `稳定体检` + `check-gui`（`:425-436`）。

**E. 血换来的铁律（§五）**
28. **绝不对引擎/工作台目录树做递归删除或搬移**；删移前 `Resolve-Path` 打印绝对路径；PowerShell 变量名大小写不敏感 ⇒ **禁用 `$e/$E/$p` 单字母变量**（2026-10-08 一次 `$e` 覆盖 `$E` + 递归删除，删掉 **1570 个源文件** + node_modules）（`:469-473`）。

**F. 下沉细则（§六，2026-10-17 把 46.8 KB 宪法瘦到 25 KB 的下沉区）**
29. **413 = `context_length_exceeded`，不是网络问题**；先 `/compact`，压完仍 413 才分叉/新开；**"到压缩线"绝不是换会话理由**；压缩线 = 模型 `contextWindow × 0.8`，**窗口是 per-provider 三档**（deepseek-official 1M/800k、qianwen·fwj·maben 262144/210k、codingplan 160k/128k）；**换模型＝换窗口**，从 1M 换到 160k 会让原本 30% 的会话瞬间 413（`:483-518`）。
30. **判压力只认 `ctx.mjs` 当场那一行**；`sessions.mjs` 百分比不含工具定义（**低估 2~3 倍**），`读会话尾巴 --usage` 是历史值（`:504-517`）。
31. **MCP 按需开**：全开实测 **58k/轮**，`cua-driver` 一个就 **26,801 token/轮**；关掉它其余 8 个只需 ~20.3k（`:520-522`）。工具结果 >12k token 自动 spill，出现 `[...]`+`stored at:` 就去读路径（`:524-527`）。
32. **落点唯一 + 三档法**：`§6.7` 三个新落点（全机待办板 / 语义检索缓存 `引擎\.dsh\cache\retrieval\` / **记忆注入插件 `引擎\插件\会话开场简报\`**），每个能力**只许一个落点**，插件必须 **fail-open**（注入失败不许阻断会话）（`:613-621`、`:749`）。

### 2.3 冲突怎么办：四条互不重叠的防线
1. **修改权五档**（A 共享宪法 / C 共享工具运行时 / B 板与台账 / D 自己专属 / E 别人的专属）：A/C 只有 `dg-dsh` 能在宿主指令下改；B 各写自己那些行、**不许删改别人的行**；D 自由但"改自己的规矩"要告知；**E 一个字都不许写，只许写请求**（`:200-214`、`00/一-协作机制.md:41-66`）。判据一句话："这份文件属于哪一档？"
2. **只提请求、不动手**：清理走 `清理请求.mjs`、设计走 `设计请求.mjs`，脚本本身**不许出现删除/改名调用**（`:46-49`、`:124`）。
3. **底层改动的"超级通道"**：改完引擎/外壳/规范/技能/清理规则 ⇒ `通知场景.mjs "<变了什么+要它们做什么>" --affected <标签>`，一次通知所有受影响方（看板 + 每个目标 §〇 顶部一行 + 台账去重），默认不唤醒（`:264-267`）。
4. **禁止无限对话（成本控制，不是洁癖）**：实测 5 条帮手与 `oa-ai` 互发技术小论文，一夜之间 助手2 **262 轮** / 助手4 **224 轮** / 助手5 **101 轮**，把余额烧到 `Insufficient Balance (ACCOUNT_QUOTA, 402)` 04:19 停摆 ⇒ 五条硬约束 + 成本闸（见 `402` 立即停派单）+ 抓手"同一会话**一小时内轮数增长 >30** ⇒ 怀疑循环对话"（`三-跨场景协作.md:190-198`、规范 `:763-771`）。

### 2.4 派单 ≠ 公告：一条最有价值的实测数字
> 某天发出 **36 条"通知"，只有 8 条真发进对方会话**，其余全躺在对方记忆文件里，要等宿主点开那个面板才看得见。宿主原话："**你这边派单他们没反应啊**"（`00/一-协作机制.md:111-113`；`00/四-派单机制.md:44-48`）。
> 修法：句子里有「请你改/派单/做完回一句/改完跑 xxx 复验」就是派单 ⇒ **必须 `--wake`**；`通知场景.mjs` 现在会自己判一次，只警告绝不自动改（防"偷偷花别人一轮 token"）。

## 核心资产三：三层记忆

来源：`00/二-记忆机制.md`(253 行) + 规范 §2.4/§6.7.1 + `02/六-记忆分三层.md` + 代码 `工具\场景记忆.mjs`。

### 3.1 分层：三层 + 一个"不进上下文"的细则层
| 层 | 放什么 | 谁读 / 何时 | 红线 |
|---|---|---|---|
| **① 注入层** = 全局铁律（每个会话自动注入） | 只放"不读就会白干"的铁律 | **每轮都读** ⇒ 每轮都付 | 引擎上限 **64 KB**，实际从 46.8 KB 瘦到 **15.8 KB**（`一-全局铁律.md:9-10`） |
| **② 私有层** = `引擎\场景记忆\<场景>\` | `场景私有记忆.md`（人写）+ `身份卡.md`/`场景画像.md`（**工具生成，手改即校验失败**）+ `项目记忆\<id>.md` + `归档\` | 每场开场读一次 | 主文件 **≤25 KB**、`§〇` **≤4 KB**、项目记忆 **≤8 KB** |
| **③ 共享层** = 板 / 台账 / 快照 | 通知看板（发生了什么）/ 待办板（该做什么）/ 总索引+文档台账（东西在哪）/ `_体检-latest.json`（健康吗） | 需要时查 | 看板 185.4 KB、台账 85.5 KB、体检 18.3 KB（规范 `:725-735` 实测） |
| **④ 细则层**（不注入） | 规范 102.8 KB / 技能 / 参考件 | 按节号查 | — |

**为什么不能合并**（原文给了真实数字）：注入 60 KB ≈ **每轮多付 20k token**；曾有一份场景记忆涨到 **40 KB**，结果没人读、交接形同虚设（`二-记忆机制.md:54-63`）。
**判据一句话**："**这东西谁会读？多久读一次？**"（同处）；`02/六:43-44` 把它翻译成"把'每轮都要付的成本'和'用的时候才付的成本'分开"。

### 3.2 注入：三条通道，两条自动一条靠规矩
1. **全局铁律**：引擎的 AGENTS 层级，每轮自动注入（`02/六:12`）。
2. **技能目录**：每轮注入 `<available_skills>`，但**只有 name + description**，正文要主动去读（`02/六:13`；规范 `:50-58` 明确 `whenToUse` 不进摘要）。
3. **场景记忆：引擎不注入** —— 只能靠"开场四步认领"（见资产四）；后来补了一个**插件**来做半自动注入：`引擎\插件\会话开场简报\`，在 `cordis.patch.yml` 用 `- insert:` 挂，且 **必须 fail-open**（规范 `:621`、`:749`）。该插件实际注入四块：`【本会话压力】`（≥80% 提醒、≥100% 明说该换会话）、`【回执】` 欠账、`【最新通知】`、`待办板` 前 8 条（`08/机制清单.md:83-104`）。

### 3.3 淘汰与容量：全部给了数字和动作
| 对象 | 红线 | 到线动作 |
|---|---|---|
| 场景记忆主文件 | ≤25 KB | 旧轮次/旧决策搬 `归档\§<节>-<名>-<YYYYMMDD>.md`，原位只留指针（`二-记忆机制.md:155-176`） |
| `§〇 交接` | ≤4 KB | 同上；历史搬走只留最新一份 |
| 技能单篇 | ≤12 KB | 拆"主技能 + 子技能/reference" |
| 项目记忆 | ≤8 KB | 只改对应字段，不整篇重写（`模板/项目信息-模板.md:53`） |
| 写回 | ≤10 行/≤2 KB | 超了说明在抄过程（`二:147`） |
| 30 天以上旧日志 | — | 按主题**蒸馏**进主文件后删旧（规范 `:86`，**蒸馏≠重写**） |
| 待办挂起 | >30 天 | 搬 `_待办-归档-YYYYMM.md`（规范 `:619`） |

**减肥四步（硬要求）**：① 先存"搬之前"快照 ② 搬 ③ 跑核对脚本逐行比对"搬前非历史行 == 搬后非历史行"，**命中 0 差异才算没丢** ④ 跑索引体检（`二:164-175`）。
**真实教训**："有一次没存快照就动手拆，结果**核对脚本根本跑不了** —— 你无法证明自己没丢东西。"**判据升级为：先快照，再动手。**
**代码落地**：`工具\场景记忆.mjs` 的 `check` 硬校验 `§〇` **4096 B**、主文件 **25600 B**、身份卡指纹（sha256 定位卡 + json）、项目记忆、归档、例外清单；`交接` 做"归档旧版 → 补 §〇 五小节 → stamp 重生成 → 登记索引"，通过才允许换会话（`12-源码照搬\工具\场景记忆.mjs:1-18, 130-186, 457-561`）。

### 3.4 `§〇` 只回答四个问题
> 原话："最常见的错误：把 §〇 写成**周报**……新会话读完之后**仍然不知道下一步该干什么**"（`二:99-101`）。
> **"§〇 的回答只有四个：我是谁 / 干到哪 / 下一步 / 卡在哪。"** → 固定五小节（上次交接 / 当前项目表 / 私有记忆变更 / 下一步与卡点 / 全貌-工具生成）。

### 3.5 失效模式（六条，都真发生过）
记忆越写越肥没人读（根因=抄过程）· 两份数字打架（单一权威）· 换场景失忆（sessionId 指旧会话）· 别人的判断进了我的记忆（跨场景直写）· **"体积正常但内容没用"**（判据改成"读完 §〇 30 秒内能不能说出下一步"）· **压力数字骗人**（拿会话占用百分比当压力，低估 2~3 倍）（`二:216-226`）。

## 核心资产四：场景体系与身份认领

### 4.1 场景是什么
> **"一个场景 = 一类活 + 一套资产 + 一套流程 + 一条常驻 AI"**（`00/三-场景体系.md:4`）。
> 切场景的本质：给每类活**独立的上下文 + 独立的记忆 + 独立的规矩 + 独立的资产边界**（`:20`）。
> 开场景判据："**半年后我还会为它单独打开一个窗口吗？**" 答不上来就别开（`:47`）。
> 三种切分逻辑（比"按项目切"稳定）：**按风险/权限切 / 按资产性质切 / 按对口关系切**（`:177-181`）。

### 4.2 最小可运行集：六件套（缺一件就某处失效）
`00/三:55-62` 的表是本仓库最值得抄的一张：

| # | 组件 | 缺了会怎样 | 最小版本 |
|---|---|---|---|
| 1 | **场景配置** `<id>.json`（面板布局+网格+会话绑定） | 标签栏根本不出现 | 有 `id/name/layout/cols/panels`，`panels` 可为空数组 |
| 2 | **定位卡** `<id>-context.md`（职责/资产地图/触发词/铁律/上次进度） | AI 不知道干什么、能碰什么 | 只要四节：职责/资产/触发词/铁律 |
| 3 | **场景记忆**（§〇 + 长期决策与坑） | 换会话就断片 | 只要一个 §〇 五条 |
| 4 | **专属技能** `SKILL.md` | AI 用通用办法硬干专业活 | 可先写 10 行流程骨架，没有就写"—"，⛔ 别硬造 |
| 5 | **专属面板**（可选） | 只能靠聊天 | 可先用通用面板（file/view/harness） |
| 6 | **常驻会话 + 身份索引一行** | **引擎不注入身份 ⇒ AI 会猜，一猜就串台** | 一行七列 |

> 其中 **2、3、6 不可省**（1、4、5 可退化成"共用"）；判断场景成不成立就看"卡（职责）、记忆（进度）、索引（身份）"（`:87-88`）。

### 4.3 `场景即人的一面` 是什么
来源：`00/六-场景即人的一面.md`（67 行）。核心事实：**同一个机主在不同场景是不同的人**（OA 运维语气急、个人站松、复盘认真）——"这不是心情，是场景决定了他以哪一面出现"（`:8-14`）。
落地=**五字段一张表**：场景 / 常见语气 / **典型原话（必须带日期与出处，无出处即删）** / 雷区 / 应对（`:18-26`）。开工前读自己那一行，决定三件事：**回多长 / 先说啥 / 别踩什么**（`:30-38`）。
**四条硬边界（2026-11-04 定稿）**：① 只记表达方式，**禁止从口气推原因** ② **一个场景是一个面，不是一个人**（禁写"他是什么样的人"）③ 原话必须带日期出处，无出处即删 ④ 禁区=健康/家庭/财务/证件/宗教，且**不做跨场景拼图**（`:40-45`）。
它明确与另两套机制分工：记忆记"发生了什么"，场景体系记"负责什么"，本表记"在这个场景里他通常怎么说话"（`:55-63`）。

### 4.4 身份认领：机制与代码位置
**前提（最关键的一句）**：`02/一-身份是怎么认领的.md:9-17` —— **"引擎本身不按场景注入任何东西"**；引擎只自动给两样：全局须知（AGENTS 层级）+ 技能目录（只有 name+description）。所以**卡与记忆能被读到，仅仅因为有人告诉 AI 去哪读**。

**四步认领（开场约 30 秒）**（`02/一:21-39`；`身份索引:60-72`）：
```
① $env:DSH_SESSION_ID                     拿本次会话 id
② 查「场景身份索引」表 → 场景/面板/定位卡/主技能/记忆文件夹
③ 读定位卡（职责·资产地图·触发词·标准流程·铁律·上次进度）
④ 读场景记忆（§〇 当前交接 + §一 + §二）
```
四个关键点：**必须当场认领**（不信会话记忆旧结论）· **以配置文件为准**（表与 json 不一致时表过期）· **一次读够不每轮重读** · **不在表里=普通会话**（`02/一:34-39`）。

**索引表七列**（`身份索引:22-40`）：场景 id / 面板 id / 面板标题 / 会话名(`pinTarget` 首项) / 会话 id / 定位卡 / 主技能。每列谁在用、缺了会怎样都写了；一句话"**身份必须是文件里的事实，不能是上下文里的印象**"（`:18`）。

**代码在哪（三层）**：
1. **绑定三字段**：`sessionTitle`（精确找，完全相等优先级最高）/ `sessionId`（验明正身 + 直达 + 决定独立分区）/ `pinTarget`（候选名列表，忽略大小写空格，先完全相等再包含）。三字段少写一个不报错，只悄悄退化成"随便显示一条"（`02/二-会话绑定三字段.md:13-55`）。
2. **注入实现**：`12-源码照搬\外壳\renderer\renderers.js:13946` 起 `renderers.harness`；`:14076` `HARNESS_PIN_JS`（幂等，`__pinGen` 防重复装定时器）；`:14010-14027` 读三字段；`:13969` 本面板绑定键 `app_pin_bind_v2:<panelId>`；**每 5 秒重注入**（`:13952` pinTimer）；主进程侧 `ipcMain.handle('harness:wv:inject', ...)`（`main.js:1137`）。
3. **核验实现**：`sessions.mjs --check` 逐面板校验标题是否命中真实会话（`10-源码/会话与切换/sessions.mjs:1-20`，文件头注释实测引擎会话行 DOM 是 `div[role="treeitem"][aria-selected]`，**行里没有 id，只有标题**）。

**为什么必须靠"注入+点行"**：AI 面板其实是一个 `<webview>`（`02/三-跟着窗口走.md:8-16`），面板重载后注入就没了 ⇒ 必须周期性重注入 ⇒ 脚本必须幂等。**判据只能是画面**：会话行 DOM 里没有 id，所以没有任何"读回来的值"能证明切过去了，只能看①标题行诊断小字 ②面板截图（`02/二:108-116`；`02/三:37-47`）。

**一个 AI 面板一个独立分区**（`persist:ai-panel-<面板id>`）：共用分区会导致"左右两个窗口都变成同一个会话""每隔 8 秒对刷一次"（`02/四-防串台.md:21-32`）。历史教训写死在注释里：早先"写 `dsh.sessions.current` + reload 直达"一度删除过（共用分区互抢），2026-09-19 三次定稿后按"一板一分区"重新启用（`renderers.js:14015-14023`）。

## 核心资产五：MCP 接免费 AI（技术方案 + 可靠性评估）

### 5.1 四层架构（不是破解接口）
```
A 会话层（决定问谁）→ B 本地桥（注入/主进程服务）→ C MCP 薄壳（每站一个）→ D 已登录网页
```
> 原话："**做法不是破解接口，而是复用一个已经登录的浏览器会话：把它当成人来用 —— 输入、等它说完、把话取回来**"（`03/整体架构.md:3-4`）。

**真实链路（代码级）**：`webai.mjs`（CLI）→ `http://127.0.0.1:31239`（main.js 的本地桥服务）→ 工作台渲染层 → **复用顶栏那个网页版 `<webview>`（登录态持久）** → 把回答文本带回来（`10-源码/免费AI桥/webai.mjs:1-30`）。
注意：**它不是 Playwright/Puppeteer 起新窗口**，而是驱动**已经开着的、登录着的** webview（`main.js:827` 注释：渲染器用 `partition="persist:webai-<key>"` 建窗；`main.js:4616`："主进程碰不到它的 DOM ⇒ 必须借渲染层的手"）。

### 5.2 三个决定性设计
1. **薄壳很薄**：站点差异只在一个对象里 —— `{ id,name,url,loggedIn,inputSel,send,answerSel,wait,profileDir }`；流程代码（输入→等第一段→等稳定→取文本）**所有站共用一份** ⇒ 加站成本从"半天"降到"十几分钟"（`03/怎么加一个站.md:32-42, 58-68`；`模板/MCP-站点薄壳.mjs:17-51`）。
2. **等待必须分两步**：先等"文本出现"（只是它开始说了），再等"`stableMs` 内不再变化"（才是说完了）。**只等出现会拿到半句话** —— 这是最常见的实现错误。参数：`firstTokenMs 20000 / stableMs 1200 / hardTimeoutMs 180000`（`03/整体架构.md:62-69`；`模板/MCP-站点薄壳.mjs:40-44`）。
3. **持久化 profile，不做自动登录**：第一次手动登录一次、之后复用 profile 目录；⛔ 代码里模拟登录几乎必触发风控，且出问题无法判断是谁的错（`03/整体架构.md:71-75`）。

### 5.3 可靠性评估（它自己诚实写了，我复核后同意并补三条）
| 维度 | 评估 | 证据 |
|---|---|---|
| **成本** | 真零 token，但付**时间**（一次问答几十秒）与**维护**（选择器会过期） | `03/整体架构.md:31-47`、`:96` |
| **脆度** | 对方改一次 DOM 选择器就过期；掉登录/风控全挂 | 同上；`03/排障.md:12-23` |
| **并发** | **同一个站不能并发**（两个页面问答几乎必然串话）；不同站可以并行 | `03/整体架构.md:44,97` |
| **失败模式** | 大量故障**不报错**：半句、上一轮的回答、空字符串——看起来都"成功" | `03/排障.md:3-6` |
| **对策①** | 空回答**必须抛错**，不许返回空串（否则上层当成"AI 说没有"，排查半天） | `03/整体架构.md:85-87`；`排障:16` |
| **对策②** | 取**最后一条**回答容器 `querySelectorAll(sel).pop()` | `排障:15` |
| **对策③** | 桥带**版本号**，版本不符拒绝回包（治"回包来自旧桥/别的站"） | `排障:17`；`webai.mjs:97,121` |
| **对策④** | 长回答**落盘，只回 600 字预览**（省上下文的关键设计） | `03/README.md:54-55`；`webai.mjs:359-371` |

**我的补充判断**：它最大的**架构价值**不是"省钱"，而是**把"网页 AI"抽象成一个 `ask(question)→text` 的工具**——会话层看到的是普通工具，不知道背后是网页（`03/整体架构.md:22`）。这个抽象让"5 个站轮询集思广益"变成一条命令（`顾问团.mjs`），也让"哪个站稳就用哪个"变成配置而不是改代码。

## 面板体系全表（24 种 / 7 族）

来源：`01-场景模式/面板类型总览.md`（149 行）。原文明确："下面 24 种全来自一台真跑着的机器"，且"**只有被真实使用逼出来的面板才活得久 —— 预造的面板通常用两次就没人点了**"（`:144-145`）。

| 族 | 类型 | 显示什么 | 关键字段 | 为什么需要 |
|---|---|---|---|---|
| 通用(8) | `view` | 预览/阅读器（文件/图片/文档/网页） | `home` `homeFolders` `filesPanel` | 需要"看内容" |
| | `file` | 文件管理（目录树+打开） | `mode` `drives` `viewPanel` | 需要"找文件"（与 view 天然一对） |
| | `embed` | 嵌一个网页（带独立登录态） | `url` `userAgent` `failHint` | 只是"要看那个网站" |
| | `web` | 内嵌浏览器（可导航刷新） | `url` | 要在面板里**操作**网页 |
| | `harness` | **AI 会话面板** | `sessionTitle` `sessionId` `pinTarget` `expand` | 每个场景至少一块 |
| | `reserved` | 预留占位 | `title` | 先定版式、功能后补 |
| | `combo` | 组合容器（一块地放几样） | 子块定义 | 省格子 |
| | `dash` | 仪表盘容器（KPI 卡片排一排） | 卡片定义 | 一眼看几个数字 |
| 流程图(1) | `flow` | 节点画布（可点可拖的工序图） | 节点/连线 JSON | 视频工作流把"素材→生成→剪辑"变工单；**最重的自定义面板** |
| 数据行情(3) | `chart` / `board` / `screen` | 趋势图 / 板块雷达 / 筛选结果 | 数据源 | 行情场景；**数据敏感度最高，公开版整组留空** |
| 电脑(4) | `pc-drives` `pc-toplarge` `pc-junk` `pc-ledger` | 各盘容量 · 大户排行 · 可清项 · 清理台账 | 系统调用+阈值分档 | 把"该不该清"从口头判断变成看板数字 |
| 站点(4) | `site-preview` `site-folder` `site-projects` `site-urls` | 预览/源码树/项目清单/网址清单 | 固定夹+刷新 | 一个站要"改完立刻看" |
| 复盘(2) | `review-doc` `review-files` | 长文档案（带目录）/ 文件清单 | 只读根 | 个人档案要看、不能改 |
| 三维(2) | `bl-folder` `bl-live` | 工程资源夹 / 外部软件实时连接 | MCP 端口 | 连外部软件 |

**三种最常用面板的最小实现要点**（`:85-113`）：
- `harness`：① 三字段绑定 ② **两条会话用同一场景时名字必须不同**（重名=串台）③ 切场景**不重建会话**只切显示 ④ 卸载解绑监听、重载幂等。
- `view`+`file`：① 互指（`viewPanel`/`filesPanel`）② `homeFolders` 一打开就在有用的地方 ③ **大文件只读前 N KB** ④ 路径不存在要**显式空态**，不许静默空白。
- `pc-drives`：① 10 秒级刷新 ② 阈值分档上色（90%/95%），别只给一个数字 ③ 点分区联动别的面板。

**加一种新面板六步**（`:117-126`）：起名（小写连字符）→ 在 `renderers` 表注册函数（返回 DOM、不碰全局）→ 场景 json 写 `{id,type,title,col,row,w,h}` → 想清数据从哪来（**别在渲染层直接读盘**）→ **空态与错误态**（90% 的人会漏）→ 自检三情况（切场景/⟳重载/拔掉数据源）。
> 判据："一个新面板如果没数据时一片白、不报错，它就不合格——白屏是最难排查的故障。"

**生长顺序（值得抄的节奏）**：第 1 天 `view+file+harness` → 第 1 周 `embed/web` → 第 1 月 `chart/board/screen` → 第 2 月 `pc-*` → 第 3 月 `flow` → 之后各场景 2~4 个专用（`:135-142`）。
**实际注册数比 24 多**：公开版 `renderers.js` 实注册约 **36 个**（多出 `shell/log/ctl/market/usboard/radar/neuron/wb-cards/app-window/code-urls/site-about/site-media`），`file` 还被注册了两次（见硬伤）。

## 界面骨架（顶栏 / 菜单栏 / 布局）

### 布局：一份 JSON + 一个 CSS Grid
- **默认 4 列**，列宽等分，行高 `grid-auto-rows: minmax(0,1fr)`；面板内容自己滚、整页不滚（`01/布局与网格.md:9-13`）。
- 坐标 = **起点 + 跨度**：`col/row` 从 1 开始，`w/h` 跨几格（默认 2/2）；只写 `w/h` ⇒ 进自动流；整份不写坐标 ⇒ **全场景自动排版，自动补洞拉伸填满**（`:31-45`）。
- **`cols` 是"比例的最小单位"**：4 列表达不了 2:3，要 12/20 + 8/20 就把 cols 调成 20（`:48-66`）。
- 常见版式六种（上3下1 / 左1右3 / 左右各半 / 2×2 / 上下通栏 / 主区+侧栏+底部工具条）；实践一条：**最大的那块留给 AI 面板**（`:70-82`）。
- **▲ 展开到最高**：在原格插一个占位格钉住版面，再把面板改成覆盖层，动画只改高度 ⇒ 其它面板位置完全不动（`:85-92`）。

### 顶栏（场景标签栏）：两侧分工是最值得抄的架构决定
| 文件 | 摘自 | 管什么 | 生效方式 |
|---|---|---|---|
| `1-建标签（外壳侧）.js` | `renderer.js` | 建 DOM、钉会话、图标、⧉ 新窗口 | ⚠ **必须重启 GUI** |
| `2-标签交互（热更新侧）.js` | `renderers.js` | 拖拽换位、未激活收成图标、固定组 | ⟳ 热加载 |
| `tabbar.css` | `styles.css` | 标签本体/激活态/收起态/拖拽态 | ⟳ 热加载 |

> 为什么刻意分两侧："**外壳侧改一次要重启**（体验差），所以把'手感类'的东西全放到 `renderers.js` 这一侧 —— 调手感不用重启"（`07/README.md:13-15`）。
> 数据流关键：交互层**自己不存顺序**，只把新顺序报给外壳，外壳交主进程持久化（`data\scene-tab-order.json`）⇒ **单一权威**；两份顺序同时存必打架（`:19-34`）。

**三个真会出事的地方**（`:40-66`）：
1. **不用 HTML5 DnD**：`dragstart` 会和 `click` 抢事件 ⇒ 拖完顺手切场景。改用**指针事件 + `setPointerCapture`**，拖动超阈值就把这次 click 在捕获阶段吞掉。判据：**拖完标签场景没被切走**。
2. **固定组不许被打乱**：`tabClampTarget()` 纯函数卡边界（固定标签只能组内换、别的标签插不到固定组前面）；`tabClampTarget`/`tabDropIndex` 都拆成**纯函数**以便脱开浏览器单测。
3. **重复初始化**：热加载会反复调同一 `init` ⇒ 用 `data-tabbar="<版本>"` 做**幂等标记**，否则监听器叠加，表现"拖一下跳好几下"。

**顶栏其余 6 个部件**（2026-10-25 补，`:97-115`）：① 网页端按钮×5（桥打开/收起内置窗）② **负载胶囊** `CPU 10% · GPU 9% · MEM 42%`（`kun.sys.load()`，位置在最右侧、紧挨最小化/最大化/关闭那组左边，**不是 ⟳ 旁边**）③ 场景刷新 ⟳ ④ 插件/技能/工具/模型目录图标 ⑤ 余额（密钥只留主进程）⑥ ⋯ 菜单 / 回退 #N。
> 通用原则："**接口不存在就隐藏或禁用，不许给假按钮**"；回退是可逆性承诺，没有真快照就别渲染可点数字，显示"回退：未接入"比点了没反应诚实（`:100,114`）。
> 「正在工作」光效现行版=**发光底条**（早先整圈光环 + filter 太吃 GPU）：光晕静态、**只有 opacity 在呼吸**（`:117-134`）。

**菜单栏与独立窗口**：场景可"分离"成独立窗口（URL 带 `?solo=1&scene=<id>`），主窗口留占位卡，关掉自动收回；**绝不在两边同时渲染**（"不要搞一模一样的会打架"）（`02/三:51-61`）。多窗口=多套壳 ⇒ "抢单必须认身份"：认领要核对发起方 id，交卷再核对一次，另加**版本申报**（`02/四:36-53`）。

## 最小可运行壳（能不能直接用）

**是什么**：`11-最小可运行壳/index.html` —— **单文件 434 行 / 23.2 KB / 零依赖，双击就能跑**。内含 5 个区段：0 模拟外壳桥 `app.*`（假文件树、假会话+`rotate()`）· 1 场景配置 `SCENES`（3 个：文件+预览 / 只留 AI / 空场景）· 2 渲染器表 `RENDERERS`（file 约 40 行 / view / harness / reserved）· 3 建壳（`buildTabs()` `buildGrid()` `enableDrag()` `dropIndex()` 纯函数）· 4 启动（`11/README.md:67-76`；`index.html:100-219`）。

**它演示对了什么**：切场景=整块重建 · 拖拽用指针事件不误切 · 文件→预览联动（`filesPanel`）· 换会话弹出"三处同步"提示 · 底部状态栏（引擎/场景/会话/面板数）。

**它明确不是什么**（`11/README.md:36-45` 自述）：❌ 不是真实工作台（数据全假）· ❌ 不接任何 AI（那两句是写死的）· ❌ 不持久化（刷新回初始）· ❌ 没有 Electron。
**已知简化**：拖拽只做换位没做 FLIP 让位动画；`view` 只渲染文本；换会话是模拟的；顺序不持久化（`:79-84`）。

**结论：不能直接当我们的基线，但它是极好的"行为规范测试床"。**
理由：① 它没有真实的会话/分区/IPC，而这三样恰是这套东西的难点（`harness` 只演示了长得像）；② 零依赖单文件意味着**放弃了 Electron 的能力**（真窗口、文件系统、托盘），而"源码直跑+热更新"这套形态恰恰依赖 Electron（`04/技术栈与启动链路.md:10-26`）；③ 它自己定位是"把机制长什么样压缩到 600 行内，让你先跑起来，再决定要不要读那 7,600 行真代码"（`11/README.md:45`）。
**若要用，正确用法**：把它当"壳的验收用例"——我们做的壳要能通过它演示的 5 个动作；或者反向：拿 `12-源码照搬/外壳`（真 Electron、119 行 index.html 引 5 个脚本）当参考，把 `renderers.js` 按面板拆开重写。

3. **"把规矩变成机制"的五步法，以及"反例验收"这条硬要求**

   它甚至把这条**用在自己的工具上**：`负载闸.mjs` 定义退出码 **0/10/20** 且"工具跑不了=退出码 3，调用方别把 3 当 0"（`10-源码/机制小工具/负载闸.mjs:15-42`）。

4. **派单/回执闭环把"隐形等待"变成可查的账，并给出了真实事故数字**
   36 条通知只有 8 条真送达（`00/一:111-113`）；5 条帮手一夜 262/224/101 轮把余额烧到 402 停摆（`三-跨场景协作.md:192-198`）；因此有"派单≠公告""回执必须投递""≤3 条消息""收到知悉一个字不回"（`:190-343`）+ 台账与两张单查询（`00/四:105-124`）+ 自动销账与超时催办（`08/机制清单.md:66-104`）。
   **这是多 Agent 系统里最贵、最少人写的一块**（"双方都在等对方"，而且它没有任何报错）。

5. **场景六件套 + "唯一对口"：用三条切分逻辑把混乱挡在源头**
   `00/三:55-62`（六件套 + 缺了会怎样）、`:177-181`（按风险/权限、按资产性质、按对口关系切）、`:195-197`（"唯一对口写进地盘说明，一条规矩消掉 80% 越界"）；落地成 10 行职能表 + 19 行判据表（`三-跨场景协作.md:20-31, 229-249`）+ 两把请求闸（`清理请求.mjs` / `设计请求.mjs`，脚本本身不许删改）。
   **它的洞见是"一件事只有一个对口人"**——不是靠共识，而是靠"别人只许提请求"的硬边界。

## 它的硬伤（5 条，带文件证据）

1. **前端是一个 18,294 行 / 1.09 MB 的单文件，且里面已有"注册两次=死代码"**
   `renderers.js` = 18,294 行 / 1,091.6 KB（实测）；24 种面板只是文档口径，**实注册约 36 个**；`renderers.file` 在 **L962** 定义（307 行），又被 **L15828** 的 `renderers['file']` **覆盖**（836 行）⇒ 前 307 行是死代码。超大块：`flow` 2,611 行、`screen` 2,321 行、`chart` 1,926 行、`app-window` 1,247 行、`view` 1,410 行、`harness` 862 行。
   连带**检查器也被代码排版绑架**：`check-gui.mjs` 第 4 项靠"本渲染器 → 下一个 `renderers[...]`"切片来认定时器泄漏，代码注释直接写"⚠ 显式 cleanup：check-gui 第 4 项按…切片认这个形状"（`renderers.js:12389`、`:12427`）——**换行位置一改，体检就失效**。

2. **主进程 4,722 行 / 257 KB 里塞了五套业务，公开版还留着死代码**
   `main.js` 实测 **172 个 `ipcMain.handle/on`**；段落标题就是业务清单：多窗口、OA（`:2139-2822`）、股票（`:3022-3480`）、Blender（`:1622-1944`）、自我复盘（`:1468-1532`）、个人站（`:1353-1467`）、本地电脑（`:1306`）。公开版 `renderer/index.html` 只引 5 个脚本，但 `renderers.js` 仍保留 `market/chart/board/screen/site-*` 等已被摘除业务的渲染器（`更新清单.md:16` 承认删了 `sector-data.js` 但 `renderers.js` 里"所有取数处本就 `typeof SECTOR_DATA!=='undefined'` 兜底"）⇒ **1 MB 里相当一部分是永远不会执行的代码**。

3. **强绑定 Electron + Windows + 端口 + 目录联接，不可 CI、不能移植**
   `12-源码照搬/外壳/package.json`：Electron **43.4.0**、engines `node >=24.9 <25`；端口写死 3080/3083/31238/31239/9876（`12-源码照搬/README.md:20-25`、`自检.mjs:13-16`）；形态依赖 `resources\app` **目录联接**与"exe 一字节不许动"（规范 `:139-158`）；换机必须"同路径 + 改 DSH_HOME"（`:33`）。`10-源码/README.md:63-74` 自认"没有测试与 CI"。

4. **会话绑定这一层最脆：靠注入 JS + 点 DOM 行 + 每 5 秒重注入，且只能靠截图证明**
   `renderers.js:14076` `HARNESS_PIN_JS` + `:13952` 5 秒 `pinTimer` + `:14299` `window.__pinDiag`；依赖引擎前端 DOM 形状（`sessions.mjs:1-20` 注释实测 `div[role="treeitem"][aria-selected]`，**行里没有 id**）；`02/二:108-116` 承认"判据只能是画面"。更麻烦的是**历史反复**：`:14015-14023` 记录该通道"一度删除过 → 09-19 三次定稿后重新启用"，说明这块改过至少三轮才稳。

5. **文档大量口径漂移，"公开版=跑着的实例"是错觉；且规范自身节号乱序**
   ① 06 说 11 个场景，实际 3 份（`06/README.md:3`）② README 说 24 种面板，代码 36 个 ③ `12-源码照搬` 的定位卡只有 **6 行**（`scenarios/bilibili-context.md` 全文），与"定位卡要有职责/资产/触发词/流程/铁律/进度"的规范要求不符 ④ 公开记忆骨架的 `_共享记忆/索引.md` 只有一行"（示例）" ⑤ 规范节号实际顺序是 6.1→6.5→6.7→6.10→6.9→6.8→6.7.1→6.6（见资产一的注）——**追加生长的痕迹** ⑥ 旧称与 v2 并存：文件头挂"2026-10-27 快照说明"说"本文里 `场景项目信息\…` 按旧称理解"（规范 `:5`）。
   工程后果：**读文档的人会以为拿到的是可运行系统，实际拿到的是"脱敏后的方法论 + 骨架"**。

> **公平地说**：这 5 条硬伤里，1/2/3 是"一个人边用边搭"的必然代价，4 是"寄生在别人前端上"的必然代价，5 是"公开脱敏"的必然代价。**它们都不影响方法论的价值，但决定了我们只能抄"规矩形状"，不能抄"实现"。**

## 对我们 12 条可直接继承的东西

> 判据统一为：**能变成我们的代码/检查，且不需要 Electron、不需要它的私有资产。**

| # | 继承什么 | 具体做法 | 落点 |
|---|---|---|---|
| **L1** | **三层记忆 + "谁会读"判据** | 注入层只放铁律、私有层 §〇 ≤4 KB、共享层四块板（看板/待办/索引/体检）；判据"每轮读/每场读/按需读" | 记忆目录 + 注入白名单 |
| **L2** | **§〇 五小节 + 四问** | 固定模板：上次交接 / 当前项目表 / 记忆变更 / 下一步·卡点 / 全貌（工具生成）；写不出"下一步"说明这轮白干 | 交接生成器 + check |
| **L3** | **体量红线 + 先快照再搬 + 只搬不丢** | 4096/25600/12288/8192 四个字节常数 + `archive()` 前快照 + `核对拆分` 逐行比对 + 索引体检 | 已有 `memory-guard` 可对齐这四个数 |
| **L4** | **写回判据 + 每会话预算** | 只记结论不记过程；≤10 行/≤2 KB；判据"三个月后还需要这一行吗" | 写回检查器（带 dry-run） |
| **L5** | **场景六件套 + 开场景判据** | json / 定位卡 / 记忆 / 技能 / 面板 / 索引行；判据"半年后还会为它单独开窗吗"；对象=一类活不是项目名 | 场景脚手架生成 |
| **L6** | **身份索引七列 + 四步认领** | 场景 id/面板 id/面板标题/会话名/sessionId/定位卡/主技能；开场 `$id`→查表→读卡→读 §〇；**冲突时以技能与记忆为准** | 会话启动钩子（我们不需要 webview，可直接注入） |
| **L7** | **三字段绑定 + 一板一分区 + 判据看画面** | 精确 id + 候选名 + 完全相等优先；每个面板独立状态分区；**"我写了值≠界面读了"** | 前端会话绑定层 |
| **L8** | **修改权五档（A/C/B/D/E）** | 共享宪法/工具只一处能改；板与台账各写自己行；别人地盘只许写请求；**判据"这份文件属于哪一档"** | 权限矩阵 + 写盘守卫 |
| **L9** | **派单≠公告 + 回执三件套 + ≤3 条** | 要动手必须真投递；回执=结论+证据（差异集合）+落盘路径；首行标记 + 末行【结束】；知悉不回；402/配额立即停 | 任务板 + 消息协议 + 成本闸 |
| **L10** | **把规矩变成机制五步法** | 违规可判定 → 唯一出处 → exit≠0 的检查 → **必造反例** → 挂节奏 + 失败进待办；"只说 0/1 不算，要说差异集合" | 我们的 check 框架（现在 20/20 元验证可复用） |
| **L11** | **MCP 薄壳 + 两步等待 + 机密闸 + 长答只回预览** | 站点差异收敛成一个对象；`stableMs` 等稳定；空答抛错不返空串；桥带版本号；正文含机密直接拒发；长答落盘只给路径 | 我们的外部模型桥（比它的 webview 方案更可控） |
| **L12** | **"一个能力只有一个落点" + 目录白名单 + 文档四状态** | 新能力先钉位置再写实现（板类→`_*.md`、缓存→`cache\`、引擎能力→插件）；工作区顶层白名单（改两处才算合规）；文档状态只用 活/常备180/留档/待清7 | 目录哨兵 + 索引体检 |

**明确不继承的**（避免踩它的坑）：Electron 单文件巨型 renderer、`main.js` 混业务、"每 5 秒注入 JS 点 DOM"的会话绑定、exe 不打包形态、`%TEMP%` 判据、把 24 种面板一次预造。
**可借用但要改造的**：`check-gui` 的五项思路（语法 / IPC 双向对齐 / **面板类型覆盖** / 渲染器 cleanup / 图标覆盖）—— 我们的版本应改成**按模块清单校验**，而不是按代码排版切片。

> 红线用字节数、判据用单一出处、检查必带反例、失败必进待办、地盘只给一个人进门。
