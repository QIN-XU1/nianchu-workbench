# 差异化优势：6 项参照系统都没有的能力

> 目标第 4 条要求「至少 5 项参照系统都没有的能力，每项附验证证据」。
> 每一项都写三件事：**是什么** / **凭什么说七家都没有** / **怎么验（命令 + 断言数）**。
> 「凭什么说没有」全部指向 `research/vs-*.md` 里的源码证据，不是印象。

## ① 产物契约式的多代理协作（不是任务队列）

**是什么**
场景之间不是「派个活儿」，而是**带契约的交接**：每个场景的契约里有
`inputs[]`（吃什么，谁给的）、`outputs[].to`（吐给谁）、`notDo`（越界清单）、`boundary`（验收判据）。
派单必须带 `subject / verify / createdAt / state`，落在 `派单台账.json`，可追溯、可算健康度。

**凭什么说七家都没有**（见 `research/对比矩阵.md` A9 行）

| 系统 | 现状 | 证据 |
|---|---|---|
| ChatGPT/Codex | 只有 `thread_spawn_edges`，无协商、无产物契约 | `~/.codex` SQLite `state_5.thread_spawn_edges` |
| Claude Code | 有 agents 列表 + attach，无协议 | `sdk.d.ts` 33 hook 事件，无协作契约 |
| DSH | `TeamService` 就是任务板 + 消息，无角色/投票/预算协商 | `dsh-agent-team/src/index.ts:48-49` |
| openclaw | 通道多，agent 间无协商协议 | 28 通道全表，无协作契约结构 |
| hermes | `kanban` 是任务看板不是协商协议；子代理**禁用 send_message**（不能横向通信） | `delegate_tool_toolsets.py:14-22` |
| ECC | 只有 agent 定义，无运行时 | 71 agents 全是静态配置 |
| luanyujia | **部分有**：产物契约 + 回执三件套 + ≤3 条消息 | `05/三-跨场景协作.md` |

→ 唯一的对手是 luanyujia（部分的产物契约）。其余六家都没有。

**怎么验**
```bash
node prototype/hermes-agents/verify-mechanisms.mjs      # 调度：6 断言
node prototype/hermes-agents/audit-neuron.mjs           # 31 边契约图：13 断言
```

## ② 独立可复算的验证闭环（含反例验证）

**是什么**
"做完了"不靠自称。三层：
1. **106 项机制守卫**（`工具/机制体检.mjs`）——每条都是可执行断言
2. **反例验证**（`工具/破坏性验证.mjs` 99KB）——**故意破坏**，证明守卫真的会红
3. **验收器三层**（数据/传输/界面）——`verify-starmap.mjs` 就是这样

第 2 条是关键：**只有证明"守卫会红"，绿才可信**。

**凭什么说七家都没有**（矩阵 C3 行）

| 系统 | 现状 | 证据 |
|---|---|---|
| ChatGPT | 同一模型自评 | 无独立判据 |
| Claude Code | `CONFIRMED/PLAUSIBLE` 由同一模型给 | `sdk.d.ts` |
| DSH | `concluded` 由模型给 | `dsh-agent-loop/src/agent.ts:596-604` |
| openclaw | `delivery proof` 不是独立验证器 | `src/agents/AGENTS.md:36-38` |
| hermes | **能力齐备但默认全关** | `verification_stop.py:1-3` 自称 `policy-only`、`never runs checks`；`verify_on_stop_enabled()` 默认 OFF |
| ECC | GateGuard 要求出示事实，**是七家里唯一做 A/B 的** | `docker/gateguard-effectiveness/` 119 文件 |
| luanyujia | 「必造反例」五步法，但无自动化 | `08/把规矩变成机制.md` |

→ **最接近的是 ECC**（有 A/B 实验），但它是静态配置层，没有运行时。
我们的是运行时 + 106 条 + 反例验证。

**怎么验**
```bash
cd workbench && node 工具/机制体检.mjs --check   # 91/106（今天实测）
node prototype/hermes-agents/verify-all.mjs      # 104 断言
```

> 本轮有个诚实的发现：`机制体检` 在引擎没起时会掉到 84/106。
> 那不是回归，是环境 —— 现在引擎起来就是 91/106。**判断前要先看环境**。

## ③ 单一权威源 + 漂移守卫

**是什么**
`工具/_场景清单.mjs` 是唯一权威。第 106 号守卫 `场景清单一致.mjs` 扫**全部 42 处**硬编码清单，
任何一处与权威不符就红。目标：**差异集合 = 0**。

**凭什么说七家都没有**（矩阵 B2 行）—— 这条是全矩阵里最集体的一块

| 系统 | 漂移实测 |
|---|---|
| ECC | canonical 314 skills → Codex 影子树 **47（15%）**、Cursor **12（3.8%）**；`agent.yaml` **171/314（45% 漂移）**；触发词 **34/314（10.8%）**；`CONTRIBUTING.md:429` 原文承认「Keeping these subsets in sync is **manual**」 |
| luanyujia | 文档 24 面板 vs 代码 **36**；文档 11 场景 vs 实际 3；规范节号顺序 6.1→6.5→6.7→6.10→6.9 |
| hermes | prompt surface 有 CI 快照门禁（这一块它最强），但场景/清单多处手写 |
| DSH | Typert 一份方法定义供三端复用（部分做到） |
| openclaw | TypeBox schema 单一源生成 validator（部分做到） |

→ **七家里没有一个在「业务清单」层做到单源 + 守卫**。ECC 有 `catalog.js` 对账 9 个文件，
但范围只到"文档数字不许撒谎"，管不到 314 个 skill 的派生副本。

**怎么验**
```bash
cd workbench && node 工具/场景清单一致.mjs   # 差异集合 0
cd workbench && node 工具/路由表.mjs --selftest  # 21/21
```

## ④ 神经元：把场景依赖图接进成熟可视化

**是什么**
12 个场景 + 31 条契约边 + 6 个领域，接进 hermes 自带的 StarMap：
力导向布局 + 时间轴 + **节点大小 = 真实派单次数** + 悬停卡片 + share code。

**凭什么说七家都没有**（矩阵 A9/D 各行）

- 七家里**没有一个有"场景依赖图"这个概念**。hermes 的 StarMap 原本只画技能 + 记忆卡；
  我们把场景图接了进去，它才第一次有了"业务结构"视图。
- **按真实使用次数决定节点权重**：`nodeRadius = 3 + sqrt(useCount)*0.55 + pinned*0.8`
  （`geometry.ts:22`），中枢 62 次派单 → 最大的点。七家里没有第二家把"使用强度"画进图里。
- **时间轴回放 + 分享码**（`playback-hotkey.ts` / `share-code.ts` 6.3KB）：七家全无。

**怎么验**
```bash
node prototype/hermes-agents/verify-starmap.mjs   # 13 断言（数据/传输/界面三层）
```
截图：`research/screenshots/hermes-星图.png`（DOM 里读到 `12 / 12`）

## ⑤ 可审计的进化（trigger 必填 + 回滚锚点 + 分级门槛）

**是什么**
每次自我进化必须登记：`id / scene / level / target / change / trigger`。
- `trigger` 记录**是什么 bug 驱动的这次改动** —— 没有 trigger 就不许登记
- `level` 分三级，门槛不同：L1 记忆（只追加）/ L2 技能（**回测必须全通过**）/ L3 身份（**必须人工确认**）
- `基线.json`（31 字段）是回滚锚点，`回滚.mjs` 29.8KB

**凭什么说七家都没有**

| 系统 | 现状 |
|---|---|
| hermes | `curator.py` 有 7/14/30 天节奏，`DEFAULT_CONSOLIDATE=False`，但**没有 trigger 字段、没有单条回滚锚点** |
| ECC | GateGuard 有 A/B 实验，但没有运行时进化登记 |
| DSH | 无自进化机制（无 memory 包） |
| ChatGPT/Claude | 无用户可见的自我进化 |
| openclaw | 有 dreaming 三阶段记忆整合，但不是"进化登记 + 回滚" |
| luanyujia | 「单场景自我进化-最小闭环」有留白（自动归纳 + 验证闸未做） |

**怎么验**
```bash
node prototype/hermes-agents/verify-mechanisms.mjs   # 自愈部分：9 断言
```
诚实记录：目前只有 **2 条 L1（记忆）** 进化，L2/L3 规则**从未被触发**。
机制在、门槛在，但高等级进化还没真跑过 —— 这条写在验证输出里，不隐藏。

## ⑥ 领域层 + 领域自动聚类

**是什么**
12 个场景分 6 个领域（中枢1 / 调研3 / 设计2 / 实现3 / 质量1 / 运维2），`domain` 只写在
`外壳/scenarios/<id>.json` 一处，星图按 `category` 自动聚成 6 个簇。

**凭什么说七家都没有**

- 参照系统里只有 **luanyujia** 有"场景体系"概念，但它**没有领域分组**（9 场景平铺）。
- DSH/openclaw/hermes 的插件有分类，但那是**技术分类**（ui/api/tool），不是**业务领域**。

**怎么验**
```bash
node prototype/hermes-agents/assign-domains.mjs --check   # 12 场景 → 6 领域
```
