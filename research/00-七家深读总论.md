## 二、七家共同的最大软肋：同一件事

**所有派生物靠手工同步，必然漂移。** 这不是巧合，是同一个结构缺陷的七种表现：

| 系统 | 漂移实测 |
|---|---|
| ECC | canonical 314 skills → Codex 影子树只有 **47（15%）**、Cursor **12（3.8%）**；`agent.yaml` 只列 **171/314（45% 漂移）**；触发词 **34/314（10.8%）**；`CONTRIBUTING.md:429` 原文承认「Keeping these subsets in sync is **manual**」 |
| luanyujia | 文档说 24 面板，代码实测 **36**；文档说 11 场景，实际 3 份；规范节号顺序 6.1→6.5→6.7→6.10→6.9→6.8 |
| hermes | 验证能力齐备但默认全关（`verification_stop.py:1-3` 自称 policy-only、never runs checks），`verify_on_stop_enabled()` 默认 OFF |
| DSH | 根本没有跨会话记忆（无 memory 包、无 embedding，grep 零命中） |
| openclaw | 记忆碎片化成 5 个方向的插件并存（`VISION.md:117` 自认要收敛）；68% surfaces 还是 Alpha |
| ChatGPT/Claude Code | 任务完成由同一模型自评，没有独立可复算的判据 |

**而我们恰好在做这件事**：`工具/_场景清单.mjs` 是唯一权威，第 106 号守卫 `场景清单一致.mjs` 扫全部 42 处硬编码清单，差异集合 = 0。

**我们不是最强的那个。** 但结构很特殊：

- 我们**赢在协作与验证**：A9 多代理协作协议（31 边场景图 + 产物契约 + 执行 DAG + 派单台账）—— 7 个里只有 luanyujia 部分有；C3 独立可复算验证闭环（106 守卫 + 验证闸 + 后置审查 + 必造反例）—— 7 个全是「自评」或「默认关」。
- 我们**输在执行骨架**：A1 代码编辑、A2 终端沙箱、A5 上下文压缩 **完全没有**；C1 agent 循环不自持（借 DSH）；B1 外壳仍是单体。
- 我们**输在界面成熟度**：D2 信息密度、D3 状态可见性（成本/完成度）都缺。

## 四、三条结构性机会（对打它们的理由）

### 机会 1：验收不再是自评

两家闭源都受「自己给自己判卷」的结构约束，短期不会自破。
我们的路：**DoneSpec + 独立验证器 + 证据账本**，让第三方只凭产物就能复算「完成/未完成」。
- 超过判据：任一任务输出 DoneSpec + 验证器结论 + 证据链，误判率 < 5%
- 已有基础：106 守卫、验证闸、后置审查（`--claim` / `--check --force`）

### 机会 2：压缩从「散文摘要」变成「结构化状态」

Codex 的 `compacted` 明写「另一个模型生成的摘要」，Claude 是 `isCompactSummary`。
摘要不可审计、丢决策、用户不知道丢了什么。
我们的路：目标/约束/决策/证据索引四张表替代摘要，压缩后关键决策丢失率 = 0。

### 机会 3：派生物从「手工同步」变成「编译器」

ECC 只做了 1/6 的 Agent IR（`SUPPORTED = { claude: ['pi'] }`）。
我们的路：一份源 → N 个确定性 emitter → CI 校验副本 hash。
- 超过判据：任意派生物与源不一致即 CI 红；已有 `场景清单一致.mjs` 的原型

## 五、明确不做（这一轮）

图像/视频生成、语音通话、computer use、自研沙箱、多通道 IM、第三方插件市场。
理由：这些是模型与系统工程密集型，大厂边际成本低，我们无法形成判据优势。
力气全押上面三条 + 补齐执行骨架（A1/A2/A5/C1）。

## 六、七个可直接继承的具体东西

1. **hermes 的「prompt cache 不可破坏」纪律**（`tests/ci/test_prompt_surface.py` 快照门禁）—— 有 CI 执法的第一性原理
2. **DSH 的「日志即真相」**（`deriveMessages()` 可重建模型所见）+ native/PTC 双形态工具呈现
3. **openclaw 的 append-only RPC 方法表**（549 行规格一张表驱动列出/鉴权/限流）+ 出网哨兵
4. **ECC 的 `agent-ir.v1` 数据模型**（tools 逐字无损 + frontmatter round-trip + stem 作稳定键）+ 选择性安装三件套
5. **ECC 的 hooks 指纹漂移检测**（任何「事件→动作」接线都该有）
6. **luanyujia 的「必造反例」五步法**（违规可判定→唯一出处→exit≠0→必造反例→挂节奏）
7. **openclaw 的输入队列四模式**（steer/followup/collect/interrupt）
