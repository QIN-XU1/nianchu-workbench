## 二、界面骨架的范式（原判「四种」，补入 omp-studio 后修正为五种）

> **修正记录**：本文第一版写的是「看完 25 个之后，骨架层面没有第五种」。之后拆解 omp-studio（`research/vs-omp-studio.md`）发现**第五种**——浮动/吸附窗口画布。原文保留不改，此处补入并说明为什么它是新范式而不是 A/B/C 的变体。

### 范式 A：单栏对话流（ChatGPT / Claude.ai / DeepSeek）

```
┌──────────┬────────────────────────────────┐
│ 侧栏      │  对话流（一条条消息）            │
│ 会话列表  │  ─────────────────────────     │
│          │  输入框（居中/贴底）             │
└──────────┴────────────────────────────────┘
```
**特征**：密度低（7–14%），分区多（10–22），靠留白和高行距撑气质。
**空态**：问候语 + 建议卡片 + 能力提示。

### 范式 B：侧栏 + 工具调用流（Kiro / Claude Code / Amp / Codex）

```
┌──────────┬────────────────────────────────┐
│ New      │  任务标题                       │
│ session  │  步骤化的工具调用（可折叠）       │
│ ───────  │  ✓ Applied steering files       │
│ Recent   │  Est. Credits 1.66 · 2m 4s      │
│ 会话…    │  ┌──────────────────────────┐   │
│          │  │ 输入框 + 上下文胶囊        │   │
└──────────┴────────────────────────────────┘
```
**特征**：密度 9–16%，分区 21–25（**最高**），把"做了什么/花了多少"逐轮摊开。

### 范式 C：编辑器 + Agent 面板（Cursor / Windsurf / Qoder / Trae / Zed / Cline）

```
┌──────────────────────┬───────────────┐
│  代码编辑器（主体）    │  Agent 侧栏    │
│                      │  ───────────  │
│                      │  计划/差异/审批 │
└──────────────────────┴───────────────┘
```
**特征**：Agent 是**副驾**，主舞台是代码。我们（hermes）不属于这类。

### 范式 D：Slot 树（DSH）—— 唯一把界面本身做成数据结构的

不是"布局长什么样"，而是"界面由哪些可替换的点组成"。见第三节。

### 范式 E：浮动/吸附窗口画布（omp-studio 0.2.0）★ 新补

```
┌─────────────────────────────────────────────────┐
│ ╔═══════════╗  ┌───────────────────────┐        │
│ ║ 对话 A     ║  │  对话 B（吸附右上）    │        │
│ ║ 拖顶栏变浮窗║  └───────────────────────┘        │
│ ╚═══════════╝  ┌───────────────────────┐        │
│                │  工具/浏览器（吸附右下）│        │
│                └───────────────────────┘        │
└─────────────────────────────────────────────────┘
```

**判定它不是 A/B/C 变体的三条理由**（都可回到代码验证，见 `vs-omp-studio.md` §4）：

1. **布局是用户状态，不是产品常量。** A/B/C 的骨架由产品定死（侧栏宽固定、编辑器在左）；这里布局是**持久化的数据**：`DockLayout { left, rail, right, bottom, floats, hidden, cards, presetId }`（`apps/renderer/src/dock/model.ts:14-29`），重启后恢复。
2. **同一类东西可以开多个实例。** 面板 ID 有三套命名空间：`files@2`（可重复）、`agent-detail:<agentId>`（按实体唯一）、`conversation:<viewId>`（按视图唯一）（`dock/types.ts:7-23`）。A/B/C 里「对话」永远只有一份。
3. **隐藏不是关闭，是可回退。** `hidden: { <panelId>: { region, groupId, index, rect? } }` 存的是**退回地址**（`dock/model.ts:20,29`）。A/B/C 的隐藏就是消失。

**代价（也是它为什么不常见）**：需要一套认真的手势工程——边缘 24px 触发、**停留 160ms 才吸附**、插入索引导引、拖拽预览、布局锁（`dock/gestures.ts:18,19,42,203`），并且光窗口系统就写了约 173KB 测试（`dock/*.test.*`）。**这是「窗口化」真正的门槛：不是画得出来，是不会误触。**

## 三、逐个产品的设计要点

### 3.1 Kiro（AWS）：状态可见性做得最好的一家

真界面截图（`research/ui-survey/docs-shots/kiro-docs-1.png`）里能直接看到五件事：

```
⊛ Cloned repo 5  ›                     ← 上下文动作，可展开
✓ Applied steering files               ← 注入了哪些规则文件
✓ Applied learnings                    ← 注入了哪些历史经验
Est. Credits Used: 1.66 · Elapsed Time: 2m 4s   ← 成本 + 用时
                                          7 tools ⌄   ← 工具调用数，可折叠
```

**这五行就是"在做什么 / 花了多少 / 还差什么"的完整答案。**
输入框底部还有 repo 胶囊（`jwdomb/csrf`、`jwdomb/handlers`…）—— **发送前就知道挂了哪些上下文**。

左侧会话列表的标题全是**有信息量的短句**（"fix SAML redirect on Safari"、"bump Node to 22, fix what breaks"），不是"Untitled"。

### 3.2 Windsurf（已并入 Cognition/Devin）：一屏只做一个决定

`windsurf-docs-1.png` 是开屏 Customize 页：
- 主题选择用**真实代码缩略图**（Light / Dark / Other 三张卡片里都是代码），不是色块
- `Install devin-desktop terminal command` 一个勾选框
- `Import settings ›` —— 一键从 VS Code 迁移
- 只有一个主按钮 `Next ↵`（带键盘提示）

**每个开屏只让用户做一个决定，且用"预览"代替"描述"。**

### 3.3 Qoder（阿里）：一套设计语言，十种界面形态

文档站顶部导航直接暴露了它的界面矩阵：

```
Qoder Series | Qoder | IDE | JetBrains Plugin | CLI | Agent SDK
             | Cloud Agents | Mobile & Web | QoderWake | Enterprise
```

**同一个产品家族覆盖 IDE 插件、独立 IDE、CLI、SDK、云端 agent、移动端、唤醒式常驻 agent。**
关键词 `QoderWake` = "works around the clock" —— 常驻型 agent 是一个独立界面形态。

主页正文里能读到它的界面骨架：
`Coding General / New Task / Projects Beta / Discussion Beta / Search Folders / Recent conversations / Knowledge Center / Sites / Automations / Extensions` + 空态 `What can Qoder help you with`。

**可抄的一点**：`Knowledge Center`、`Sites`、`Automations`、`Extensions` 是**四个平级的一级入口** —— 不是全塞进 settings。

### 3.4 Amp：用"录制回放"代替功能列表

主页板块 `WORKING DAY TO DAY IN AMP / Watch Thorsten Build in Amp`，下面是**带时间戳的章节**：

```
0:16  An agent that wakes itself to check production
4:07  Send a screen recording of a flicker
8:16  Ship changes and watch the rollout
11:46 Grant an orb production access from the terminal
16:24 Ask for screenshot proof
22:52 Cut a release, email the user, close the bug
```

**章节标题本身就是能力清单。** 比"我们有 X 功能"一格一格列强得多。

### 3.5 DSH：唯一把界面做成「类型化数据结构」的

活体解剖（`cordis_inspect_query`）拿到的是实时 Slot 树：

- **5 种 Slot 类型**：`single`（独占）/ `list`（有序多）/ `keyed`（按 key 分派）/ `chain`（选择链）/ `hoc`（包裹宿主内容）
- **每个 Slot 自带 `replaceRisk`**：`none` / `shadows-shipped-ui`（会盖住官方 UI）/ `wraps-owner-content`（包裹宿主内容）
- **`purpose` 字段写清版面位置和溢出行为**，例如：
  > "overflow is clipped and faded before the utilities, **so overlays must portal**"
- **18 种聊天节点类型**（keyed）：`assistant-step, command, command-input, compaction, context, manual-compaction, model-retry, question-reply, steering, system-prompt, tool-call, turn-error, turn-max-tokens, turn-process, turn-tail, turn-trigger, unknown, user, workflow-run`
- **空态有专门 slot**：`conversation.hero.brand.mark` / `hero.agentPreset` / `hero.options`
- **主题只有 14 个语义 token**，全部 `requiresLightAndDark: true`，不暴露原始色值

### 3.6 Pi：把设计约束写成代码

- 宽度按**可见列**算（ANSI、宽字符、emoji、组合字符都影响显示宽度）
- **容器必须把 `focused` 往下传**，否则中日韩输入法候选框会跑到错的位置
- 主题从终端色**算出**，body 文字强制 **WCAG 4.5:1** 对比度
- 三级降级：背景+ANSI / 只有背景 / 什么都没有

### 3.7 Claude / DeepSeek（对话范式基准）

- Claude 首页：12 面板 / 225 文字块 / 13.88% 密度 / 10 分区
- Claude 对话：11 / 290 / 7.70% / 22 分区
- DeepSeek 对话：9 / 310 / 7.89% / 21 分区

**共同点**：密度低、分区多、留白大。它们卖的是"读起来舒服"，不是"信息密度"。

### 3.8 omp-studio：把「窗口化」做成真的可用（范式 E 唯一实现）

**它是本调研里界面工程密度最高的一家**，而且密度不在像素上，在**状态模型**上。

| 设计要点 | 具体做法 | 证据 |
|---|---|---|
| 一切皆面板 | 21 个工具全是可停靠面板（`files/changes/git/browser/computer/agents/environment/context/terminal/jobs/problems/tests/output/logs/btw/token-counter…`） | `apps/renderer/src/dock/types.ts:4` |
| 面板身份派生而非存储 | 三套命名空间：`files@2`（可重复）、`agent-detail:<id>`（按实体）、`conversation:<viewId>`（按视图） | `dock/types.ts:7-23` |
| 隐藏可回退 | `hidden: { <panelId>: {region, groupId, index, rect} }` 存退回地址 | `dock/model.ts:20,29` |
| 吸附防误触 | 边缘 24px + **停留 160ms** 才吸附 | `dock/gestures.ts:18,19` |
| 插入有指引 | 命中测试返回插入**索引**，画 4px 指示条 + `插入${NAME}` | `dock/gestures.ts:42,91` |
| 布局可锁 | `preferences.locked` 时拖拽直接 return | `dock/gestures.ts:203` |
| 对话宽度四档 + 窄窗退让顺序 | 768/1024/铺满/自定义(640–1440, 32px 步进)；窄窗按「压右栏→隐右栏→隐左栏」顺序退让，**用户明确关闭的面板不会因变宽而自动打开** | `docs/conversation-width.md` |
| 上下文可下钻 | 9 类分解（system-prompt/skills/built-in-tools/custom-tools/user/assistant/thinking/tool-calls/tool-output），每条带 token+bytes+**脱敏预览** | `studio-protocol/src/contracts/context-view.ts:1` |
| 图像压缩记账 | `snapcompact { visionCapable, savedTokens }` | 同上 `:39` |

**对我们的直接价值**：8 条里有 6 条是我们现在完全没有的，而它们都**不依赖新产品形态**——上下文下钻、对话宽度档位、隐藏回退，都可以在我们的单窗口里先落地，不必一步跳到浮动窗口。

### 3.9 Orca：分屏面板派（与 omp-studio 的浮动派对立）

同样是「多任务并排」，Orca 选了**固定分屏**而不是浮动窗口，且把「跨类型并排」做成主卖点：

- **Split Anything**：agent / 终端 / 浏览器 / diff 并排，按任务形状分屏
- **Jump Anywhere**：一个快捷键跳到任何 workspace 或 tab，**跨所有 repo 和所有主机**
- **Chat ⇄ Terminal 互转**：同一场对话在结构化 Chat UI 和裸 CLI 之间来回换，**不丢上下文**（难点在把结构化消息和文本流双向映射）
- **Design Mode**：在它内建浏览器里点任意元素 → 复制 HTML/样式/选择器 → 粘进 agent 对话。**把「视觉问题」变成可执行的上下文**，省掉人的转述
- **在 diff 具体行上留批注**并回发 agent（不是「把整个 diff 丢回去让它自己找」）
- **Mobile Emulator**：在 agent 旁边跑 iOS/Android 模拟器，**让 agent 自己点、自己验收**

**工程上值得抄的两条**（不是界面本身）：
- `lint:design-system`——用 lint 规则**强制**设计系统用量（我们是靠人写判据）
- `check:zustand-selector-fanout`——**渲染扇出的性能闸门**，防止一次状态变更把整棵树重渲

**它没解决的**：因为要托管 40 个异构 CLI agent，界面状态只能靠**解析 PTY 输出**推断；omp-studio 在自述里明确拒绝这条路（`PTY bytes are not a control protocol`）。详见 `research/vs-orca.md` §4.4。

## 五、可以立刻抄的 12 条设计

按"性价比 × 可判定性"排序：

| # | 设计 | 出处 | 我们现状 | 成本 |
|---|---|---|---|---|
| 1 | **空态放可点入口** | ChatGPT 建议卡 / DSH `conversation.hero.*` | ❌ `intro.tsx` 是 `pointer-events-none` 死文本 | 低 |
| 2 | **每轮显示成本+用时** | Kiro `Est. Credits 1.66 · 2m 4s` | ❌ 只有全局 `hermes insights` | 低 |
| 3 | **上下文注入可见** | Kiro `Applied steering files / learnings` | ❌ 隐藏 | 低 |
| 4 | **工具调用数可折叠** | Kiro `7 tools ⌄` | 部分（transcript 有折叠） | 低 |
| 5 | **会话标题要有信息量** | Kiro `fix SAML redirect on Safari` | 部分（`Getting started`） | 低 |
| 6 | **发送前显示挂载的上下文胶囊** | Kiro repo chips | ❌ | 中 |
| 7 | **主题预览用真实内容** | Windsurf 代码缩略图 | ❌ 色块 | 中 |
| 8 | **一屏一个决定** | Windsurf 开屏 | ❌ 设置页一屏几十项 | 中 |
| 9 | **一级入口不塞进设置** | Qoder 四个平级入口 | 部分（侧栏有 5 个） | 中 |
| 10 | **用录制回放代替功能列表** | Amp 章节时间戳 | ❌ | 高 |
| 11 | **语义 token 层（14 个，不用 344 个变量）** | DSH | ❌ 344 个混合变量 | 高 |
| 12 | **扩展点标 `replaceRisk`** | DSH | ❌ contrib 只说"加了什么" | 高 |

### 中文界面的两项硬要求（来自 Pi）

- **宽度按可见列算**，一个汉字 2 列，按 `str.length` 排版必错位
- **焦点必须向下传播**，否则输入法候选框位置错

这两条不是"优化"，是硬伤级别的缺陷。

## 五、从「本机已安装的真实产品」取证的补充（v0 之后新增）

前面几节的参照来自开源仓库和截图。本节不同：**取证对象是用户机器上装着的商业产品本体**，
拆的是它们实际发布的资源文件。这是「本地源码 > 联网文档 > 二手描述」里最高的一级。

### 5.1 取证方法（可复现）

- **Qoder**（用户本机 `D:\file\software\Qoder`，版本 0.5.3）是 Electron 打包，
  界面在 `resources/app.asar` 里。asar 是 Chromium pickle 格式：
  `[0..4)` 固定值 4 / `[4..8)` header pickle 长度 / `[8..12)` JSON 长度 /
  `[12..16)` JSON 实际长度，之后按 header 里的 offset 排布文件内容。
  读取器在 `prototype/agent-ui/read-asar.mjs`（不依赖 `@electron/asar`）。
  实测 `app.asar` 188MB / 6435 个文件，主界面样式是
  `out/renderer/assets/index-BDkncoAI.css`（381KB）。
- **OpenAI Codex** 是 Microsoft Store 应用（`OpenAI.Codex_26.901.5003.0_x64`），
  本机路径 `C:\Users\<user>\AppData\Local\OpenAI\Codex`。

> 踩坑记录：asar 里用 offset 定位内容时，内容起点是 `8 + headerPickleSize`，
> 不是 `16 + headerJsonLen`。前者才算得对。

### 5.2 Qoder 的实证结论（**值可以读，名字被构建混淆**）

它的 CSS 变量名被压成 `--qbf1f6b` 这种不可读形式，但**值是真实的**，所以能反推设计决策：

| 观察 | 证据 | 说明了什么 |
|---|---|---|
| **10 套主题** | `data-theme` 取值：`light / forest-light / bee-light / mint-light / light-parchment / forest-dark / bee-dark / mint-dark / parchment-dark / dark` | 主题不是「明暗」两档，是**按情绪选的四种色相**（森林绿 / 蜂黄 / 薄荷 / 羊皮纸）再各配明暗 |
| **品牌色是深林绿** | `#316e50` `#358e62` `#2cb879` `#1c4432` | 不是蓝也不是紫 —— 中文 AI IDE 里少见的绿系品牌 |
| **中性色带品牌色相** | `#edf5f1` `#e2eee8` `#ddf8ea` `#f2f4f2` `#fbfcfb` | 灰不是纯灰，是**绿调灰**。品牌色渗进中性色，整屏才「是一个东西」 |
| **暗色底也带色相** | bee 主题底色 `#202116`（R32 G33 B22，偏橄榄） | 深色底不用纯黑/纯蓝黑，用主题色相压暗 |
| **不是纯扁平** | `0 0 0 1px #0000000f, 0 1px 2px -1px …`（多个同类 token） | **1px 环 + 极小阴影**（Tailwind `ring-1 + shadow-sm` 手法）。和 omp-studio 的 `shadow: none` 是两条相反路线 |
| **浮层用毛玻璃** | `blur(16px)` | 浮层靠背景模糊建立层级 |
| **高饱和语义色齐备** | 蓝 `#3b81e9` / 橙 `#ea873f` `#efb041` / 黄 `#f2c647` / 红 `#ec5b56` / 粉 `#da5597` / 紫 `#605ce5` / 青 `#55b5a6` | 语义色不是一两个，是一整族 |

**额外发现（产品形态层面）**：Qoder 的 renderer 里有
`DesktopPetSurface`（桌面宠物）、`DynamicIslandPanel`（灵动岛）、
`LiveVoiceOverlay`（实时语音浮层）、`CompanionActivitySurface`（伙伴活动）、
`QuickNoteWindow`（速记浮窗）。
也就是说它不只是一个 IDE 窗口，而是**「IDE + 常驻桌面伙伴」两套形态并存**。
这是我们之前完全没考虑过的形态维度。

### 5.3 omp-studio 设计系统的关键数值（重读 tokens.css 568 行带走的）

| 观察 | 证据（tokens.css 行号） | 说明了什么 |
|---|---|---|
| 字号 1.17 倍梯 | `:28-42`，注释写明「Removed --fs-13 (too close to 12px to be distinguishable)」 | 梯子的档位是按**能不能分辨**定的，不是按好看定的 |
| 圆角必须嵌套 | `:49-56`「Every tier moved up… nested corners still nest correctly (outer must exceed inner)」 | 圆角是有结构约束的，不是随手取值 |
| 文字梯算过对比度 | `:207-211`「--text-faint was #8f96a1 — only 2.95:1 on white」，改后 4.72:1 | 声称达标 ≠ 算过达标 |
| 非文字灰单独一档 | `:217-220`「they only owe 3:1, and using the text ramp there would make the chrome heavier than the content」 | 图标和文字的义务不同，共用一档会让装饰比内容重 |
| 动效按含义选曲线 | `:126-141` 七条曲线各有语义：state / arrive / leave / travel / follow / morph / settle | 曲线不是审美选择，是语义选择 |
| 离开比到达快一档 | `:106-107`「a 320ms surface leaves in 250ms, so dismissing never feels like waiting」 | 这条是体感优化的核心，很少人写出来 |
| 密度只缩放间距 | `:61-63, 184-187`「只缩放间距阶梯…字号与布局度量不动」 | 改密度不该改可读性 |
| 不用阴影堆假高度 | `:303-308`「Flat: depth comes from borders + surface steps, never shadow stacks」 | 界面干净的根本原因 |

### 5.4 这些观察怎么用到了我们自己的 v0 上

`prototype/agent-ui/workbench-v0.html`（单文件 42KB，无构建依赖）：

| 学自 | 具体做法 | 我们的代码位置 |
|---|---|---|
| omp-studio | 不用阴影堆假高度；深度 = 边框 + 表面阶梯 | 只有一个 `--shadow-float` token |
| omp-studio | 对比度算过而不是看着行 | `verify-agent-ui.mjs` 计算 WCAG 比值 |
| omp-studio | 圆角层级必须嵌套（外层 > 内层） | `--r-4/6/8/10` 注释写明用途 |
| omp-studio | 动效按「动的是什么」选曲线；离开比到达快一档 | `--ease-out`（到达）/ `--ease-in`（离开） |
| omp-studio | 密度只缩放间距，不动字号 | `--density-scale` 只进 `--sp-*` |
| Qoder | **中性色带色相** | 暖石墨（褐调灰），不是蓝黑 |
| Qoder | 浮层用 1px 环 + 微阴影 | `--shadow-float: 0 0 0 1px …, 0 10px 30px -14px …` |
| Qoder | 暗色底不用纯黑/纯蓝黑 | `--bg: #0e0c0b`（暖，非 `#0D1117`） |

| ChatGPT | 主操作不用品牌色，用高对比中性填充 | `.send { background: var(--text); color: var(--bg) }` |

### 5.5 我们刻意**不**跟的两条

1. **不做多套情绪主题。** Qoder 的 forest/bee/mint/parchment 很漂亮，但它是面向大众的编辑器；
   我们的界面是**验收仪表**，换主题等于换掉状态色的语义基准，反而削弱「状态可判定」这个核心。
   我们只做明暗两套，且两套的四态色都实测 ≥4.5:1。
2. **不用毛玻璃。** `blur(16px)` 在截图里好看，但它会让背景内容持续参与渲染，
   并且**降低文字与背景的可判定对比度**。我们的判据是「每个颜色都必须能被算出来」，
   模糊背景会让对比度依赖「背后是什么」，无法稳定计算。

### 5.6 本节还没做到的（如实写）

- ChatGPT 桌面版**没找到安装目录**（只找到 Store 版 Codex），所以针对 ChatGPT 的三条做法
  来自其公开界面形态的判断，**不是本机源码取证**。这条要补。
- Qoder 只读了 CSS token 层，**没读它的交互逻辑**（对话流怎么滚动、工具块怎么折叠）。
  那些在 JS chunk 里，还没拆。
- DesktopPet / 灵动岛这套「常驻形态」**只记录，没有消化**成我们的设计。
