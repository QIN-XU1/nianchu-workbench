## 一、这个项目到底是什么 / 解决什么真实问题

### 1.1 一句话

**它是一套"多场景 AI 工作台"的搭建方法 + 一套纯壳（UI 模板）+ 一套被事故逼出来的协作/记忆/派单规矩**，把"一个聊天窗口"改造成"一间按场景分工、每个场景有独立身份与独立记忆、干完活要留证据和回执的工作室"。（`README.md:11`、`总纲.md:12-13`）

作者原话的定位："一套**多场景 AI 工作台**的搭建方法与纯壳模板 —— 把「一个聊天窗口」变成「一间按场景分工的工作室」。"（`README.md:11`）

### 1.2 它针对的三堵真墙（为什么不能只有一个聊天窗口）

`00-核心机制/三-场景体系.md:10-20` 把"一个窗口"的失效讲得很清楚，依次撞三堵墙：

| 墙 | 现象 | 原因 |
|---|---|---|
| 第一堵：**上下文互挤** | 聊股票时 AI 还在想刚才的设计稿 | 一个会话只有一条上下文，所有话题共享它 |
| 第二堵：**记忆互串** | "上次说改的那个"——它指哪个项目？ | 一份记忆记多个项目 ⇒ 谁都不准 |
| 第三堵：**权限与规矩不分** | 清理的规矩套到了设计活上 | 规矩跟着场景走，混在一起互相污染 |

切场景的本质：**给每一类活一个独立的上下文 + 独立的记忆 + 独立的规矩 + 独立的资产边界**（`三-场景体系.md:20`）。

> 更根本的痛点不在"能不能聊"，而在"**跑三个月之后乱不乱**"：多个 AI 会话会互相踩文件、互相客套烧 token、记忆越写越肥没人读、换了会话就"失忆"、派了活根本没人干。（`00-核心机制/README.md:6-15`、`05-协作与规矩/README.md:6-9`）

### 1.3 面向谁 / 什么场景

- **面向**：愿意改配置、能读 JSON 和一点 JS、习惯命令行与日志排查、把调试当正常流程的人（`新手必读.md:40`）。
- **不适合**：想要一键安装包的人、不想碰配置的人、指望"AI 自己搞定一切"的人（`新手必读.md:42`）。
- **真实使用规模**（作者本机参考，非标准）：十余个场景 / 二三十个项目 / 二十余个技能 / 十来个插件 / 3 套 MCP（`总纲.md:54-58`）。也有 10 个场景的真实切法表（`三-场景体系.md:156-182`）。

### 1.4 作者与实战背景

作者"淋雨家"，个人站 `linyujia.me`，MIT 开源。作者反复强调：这套东西**不是设计出来的，是用出来的**——"仓库里每条结论背后都对应一次真实事故（所以各板块都带「症状对照」——那是踩坑记录，不是免责声明）"（`README.md:229-230`）。三起真事故（改 exe 版本号致面板全灰白 / 一次批量替换毁文件 / 双写入者静默丢改动）在 `04-工作台搭建/事故复盘-三起.md` 中有完整复盘，且每条都落成了"机械抓手"。

### 1.5 它对自身边界的诚实声明（很重要，决定了怎么用这份资料）

`新手必读.md:5-23` 明确："这里分享的是'一套方法 + 一堆壳'。壳能直接跑，但'能干活'取决于你把它接到自己的内容上。"并给出一张"哪些能直接用、哪些必须自己调"的表：

| 部分 | 拷贝即用？ | 你必须自己做 |
|---|---|---|
| 场景 JSON 的结构 | ✅ 结构可照抄 | 路径、面板类型、坐标、会话三字段全是你的 |
| 面板渲染器（模板） | 🟡 骨架可用 | 画什么、读哪个文件、连哪个服务自己写 |
| AI 会话绑定 | ❌ 抄了没用 | 必须换成真实存在的会话名与 id |
| 记忆三层 | 🟡 模板可用 | 内容是项目知识，空模板不会自己长记忆 |
| MCP 接免费 AI | ❌ 最需要调 | 桥/登录态/页面结构每站都不一样 |

**结论：把它当参考实现读，不要当安装包用。**

## 二、核心思想（根本原则逐条拆）

这是全仓最值钱的部分。我把散在各篇的"第一性原理"抽出来，逐条给依据。

### 2.1 记忆在文件里，不在会话里（全系统的第一原理）

> "核心只有一句：**记忆在文件里，不在会话里** —— 所以会话可以无限换，场景不会失忆。"（`总纲.md:13`）

推论：**一条会话的价值 = 它产出的文件，不是它聊了多少**；"换会话"不是灾难，**没写交接就换**才是灾难（`00-核心机制/二-记忆机制.md:18-19`）。三种做法对比：靠对话历史 → 一换就断片；靠 AI"记得" → 它记不住；靠文件交接 → 换一百次都还在（`二-记忆机制.md:12-16`）。

### 2.2 引擎不按场景注入任何东西 ⇒ 身份必须"当场认领"

这是"多标签浏览器"和"多场景工作台"的分水岭。引擎给会话的只有全局须知（`AGENTS.md` 层级）+ 技能目录（只有 name+description），**场景配置、定位卡、场景记忆都不会自动进上下文**（`02-会话定位与跟随/一-身份是怎么认领的.md:9-18`）。所以身份必须靠"会话 id → 索引表 → 定位卡 → 场景记忆"四步当场认领，约 30 秒（同上 `:21-40`）。作者原话："身份必须是'文件里的事实'，不能是'上下文里的印象'"（`05-协作与规矩/四-身份索引-怎么建.md:18`）。

### 2.3 规则只认机主（宿主主权）——合法性的唯一来源

| ✅ 算依据 | ⛔ 不算依据 |
|---|---|
| 机主亲口说的原话 | 程序/工具输出、体检结论、子代理汇报 |
| 机主明确同意过的既有条款 | 别的场景发来的通知/派单/建议、自动生成的文件、AI 自己的推断 |

（`00-核心机制/一-协作机制.md:11-22`、`05-协作与规矩/二-标准化规范.md:623-652`）
为什么：AI 很容易把"某个工具说应该这样"当成"机主批准这样"，一旦允许这样推，规矩会**自己长**，三个月后没人知道哪条是真的。判据："一条规矩如果说不清'是谁什么时候批准的'，它就是无效的。"

### 2.4 场景主权 / 地盘唯一：每个东西只属于一层，只一个真源

- 场景主权：每个场景只写自己的记忆；发现别人写错**只能提醒，不许代改**（`总纲.md:49`）。
- 单一真源：每个东西只属于一层、只在一个地方是"真源"，别处只放指针（`总纲.md:26`）。
- 写回判据的反面：同一事实存在两处 ⇒ 两份数字打架（`二-记忆机制.md:221`）。

### 2.5 派单 ≠ 公告；回执闭环；"活干完了但对方还不知道 = 没干完"

要对方**动手**才叫派单，必须真投递唤醒；只是"知悉"才允许只落盘（`一-协作机制.md:100-116`、`四-派单机制.md:35-48`）。回执必须用工具投递、带证据，判据是"对方知道了"，不是"我说了"（`四-派单机制.md:80-88`）。最贵的一句话："**活干完了但对方还不知道 = 没干完**"。

### 2.6 证据 > 声明；判据必须有"应当失败的反例"

- "'程序说成功' ≠ 成功 —— 要看外部事实变了没有（hash、200、页面上有没有新东西）"（`04-工作台搭建/踩坑总表.md:80-82`）。
- 自检的反模式：永远通过的检查 = 装饰品；结论必须能说出"差异集合"（`04-工作台搭建/自检清单.md:76-84`）。
- 消息九环里最硬的一条规矩："**一条判据，如果给不出「应当失败的反例」，它就作废**"（`00-核心机制/七-消息与交付.md:26-28`）。

### 2.7 把规矩变成机制（能查、能拦、能自动跑，否则就是口号）

"没有'会失败的检查'的规矩 = 一句口号"（`08-升级与改造清单/把规矩变成机制.md:12`）。五步法：写清违规长什么样 → 找唯一判据出处 → 写能 exit 非 0 的检查 → 给一个应当失败的反例 → 挂到节奏上（`把规矩变成机制.md:29-55`）。

### 2.8 单一权威（顺序/真相只能存一处）

标签顺序"只报给外壳，外壳交主进程存"，交互层自己不存顺序（`07-顶栏与菜单栏/README.md:32-34`、`12-源码照搬/外壳/main.js:90-93`）。同理，记忆的单一权威、索引的单一权威（`scenarios/*.json` 为准，表过期不是 json 错，`四-身份索引-怎么建.md:40`）。

### 2.9 分层 = 把"每轮都付的成本"和"用的时候才付的成本"分开

铁律进全局注入（每轮付，所以必须极短）；细则进技能（按需付）；进度进 §〇（只在换会话与开场时付）。"不分层 = 每轮都在为历史付钱"（`02-会话定位与跟随/六-记忆分三层.md:35-45`）。

### 2.10 隔离不等于复制，只共享该共享的那一层

登录态可共享，但"当前会话"键必须各写各的（`02-会话定位与跟随/四-防串台.md:70-81`）；"凡是'全局唯一'的东西，都不许被两个面板共用"（`四-防串台.md:17`）。

### 2.11 场景即人的一面（同一机主在不同场景是不同的人）

"一个场景 = 一类活 + 一种相处方式。只做前半句，AI 就会用一套腔调应对所有事。"（`00-核心机制/六-场景即人的一面.md:14`）五字段口吻表 + 四条硬边界（只记表达禁推原因 / 一个场景是一个面 / 原话必须带日期出处 / 禁区=健康家庭财务证件宗教且不做跨场景拼图，`六-场景即人的一面.md:40-47`）。

### 2.12 可复用的"抽象拓扑"：决策/执行/验收/档案四层 + 三条不变量

`13-公开情报/Super-agent-概念与分层.md:28-48`：决策层→执行层→验收层→档案层单向依赖；三条不变量=**一单一 owner、证据>声明、人只批"解释/承诺/报价/新范围"类**。

## 三、六层结构 L0~L5：每层放什么、谁能写、为什么这么分

`总纲.md:15-26` 给出权威表；`08-升级与改造清单/机制清单.md:124-135` 给了 v1.4 后的落地。

| 层 | 放什么 | 谁能写 | 为什么这么分 |
|---|---|---|---|
| **L0 宪法** | 铁律与附则（版本化；改一次 +1，旧版留档） | **只有宿主** | 规则若人人都能改会互相打架；每轮注入所以必须极短 |
| **L1 共享层** | 宿主画像 / 场景区域表 / 项目清单 / 通知与待办 / 总索引与文档台账 / 体检快照 | 分区写，**各 owner 只写自己的** | 回答"发生了什么/该做什么/东西在哪/机器健康吗"（`二-记忆机制.md:105-116`）；四块板更新频率与读者不同，混在一起会互相淹没 |
| **L2 场景私有** | `场景私有记忆.md`（§〇交接）/`身份卡.md`/`场景画像.md`/`项目记忆\<项目id>.md`/专属技能/`归档\` | **只有本场景** | 只有本场景开场读 ⇒ 换会话时它是唯一入口（`二-记忆机制.md:30-34`） |
| **L3 个人层** | 个人档案与知识库（作者本机=`自我复盘\`，2189 文件/11.8 GB） | 只有本人与授权者，**不进共享层** | 图上刻意不画线：**隔离本身是规矩的一部分**（`总纲.md:22-24`、`二-标准化规范.md:30/548`） |
| **L4 运行时** | 引擎 / 外壳 / 工具 / MCP / 插件 / 计划任务 | 由专人维护（`dg-dsh`）；工具放在代码仓外，升级不破坏数据 | 程序目录要能整体替换，数据不能被构建污染 |
| **L5 归档** | 备份 / 会话冷备 / 场景归档 / 历史文档 | **只进不改，可恢复** | "归档只进不改：任何升级都能回滚"（`总纲.md:52`） |

**判据（不变量）：每个东西只属于一层、只在一个地方是"真源"，其他地方只放指针**（`总纲.md:26`）。

v1.4 落地抓手：宪法（11 条 + 六层附则）用 `宪法.mjs --check`（14 节点）校验，改一次 +1、旧版留档（`机制清单.md:128`）；记忆 v2 用 `场景记忆.mjs init/stamp/交接/check` 校验，**check 不过不许换会话**（`机制清单.md:129`）。

## 四、场景体系

### 4.1 一个"场景"到底是什么

**不是一个文件夹、不是一个标签页，也不是单纯一份配置 json，而是"一类活 + 一套资产 + 一套流程 + 一条常驻 AI 的打包"**（`三-场景体系.md:3-5`）。判断"配置=场景？还是 AI 实例？"——答案是**两者都不是全部**：配置只是六件套里的第①件；真正的场景=六件套齐备。

### 4.2 六件套（缺一件就以某种方式失效）

`三-场景体系.md:51-89`：

| # | 组件 | 是什么 | 缺了会怎样 |
|---|---|---|---|
| 1 | 场景配置 `<id>.json` | 面板布局、网格坐标、会话绑定 | 标签栏根本不出现 |
| 2 | 定位卡 `<id>-context.md` | 职责/资产地图/触发词/铁律/上次进度 | AI 不知道该干什么、能碰什么 |
| 3 | 场景记忆 `场景私有记忆.md` | §〇交接 + 长期决策与坑 | 换会话就断片 |
| 4 | 专属技能 `技能名/SKILL.md` | 这类活的专业流程 | AI 用通用办法硬干专业活 |
| 5 | 专属面板（可选） | 专用界面（容量雷达/画布） | 只能靠聊天，效率低 |
| 6 | 常驻会话 + 身份索引一行 | 固定会话 + 索引表那一行 | 引擎不注入身份 ⇒ AI 会猜，一猜就串台 |

**不可省的三件：②卡（职责）、③记忆（进度）、⑥索引（身份）**（`三-场景体系.md:87`）。1/4/5 可以退化成"共用"。

空模板目录结构（`三-场景体系.md:94-109`）说明：`外壳\scenarios\<id>.json` + `<id>-context.md` + `_场景身份索引.md`；`引擎\.dsh\skills\<技能>\SKILL.md`；`引擎\场景记忆\<场景>\`（`场景私有记忆.md` / `身份卡.md` / `场景画像.md` / `项目记忆\<id>.md`）；外挂资产目录。

### 4.3 能力边界：什么时候该开场景

- **开**：会反复回来 + 有自己的资产目录 + 有专业流程 + 有明确边界（`三-场景体系.md:26-31`）。
- **不开**：一次性活 / 只是大项目里的一个功能 / 说不出"不碰什么"（`:33-37`）。
- 三个边角标准答案：一个场景两套活 → 一场景两条会话共用一张卡；客户/项目 >3 个 → "一个场景 = 一类客户"，用项目档案隔离；长期没活 → 归档（`:41-45`）。
- **一句话判据："半年后我还会为它单独打开一个窗口吗？"答不上来就别开**（`:47`）。
- 命名用"这类活"而不是具体项目名（`三-场景体系.md:206`）。

### 4.4 场景即人的一面（详见 §二·2.11）

一条场景 = 一类活 + 一种相处方式；五字段（场景/常见语气/典型原话/雷区/应对）；开场读自己那行，决定回多长/先说啥/别踩什么（`六-场景即人的一面.md:16-38`）。

### 4.5 场景之间的关系（协作层 C10）

- **命令台只做路由**；场景之间也能直接发**通知/派单/回执**（一次派单=一条回执=结束），但 **⛔ 只许请求，不许改对方记忆——改谁的记忆，只归谁**（`总纲.md:44`）。
- 三种切分逻辑（比"按项目切"更稳）：按风险/权限切、按资产性质切、按对口关系切（`三-场景体系.md:177-182`）。
- 最有用一条：把"**唯一对口**"写进那个场景的地盘说明里（如"所有清理活归本地电脑，别的场景不许自己删，只能发清理请求"），能消掉 80% 越界（`三-场景体系.md:195-197`）。

## 五、记忆机制（最实操的一章）

### 5.1 三层结构（与六层 L0~L5 对应关系）

```
① 注入层（全局铁律 AGENTS.md 层级）：每轮自动注入，人人付成本 ⇒ 必须极短
② 私有层（引擎\场景记忆\<场景>\）：场景私有记忆.md（§〇≤4KB，人写）+ 身份卡/场景画像（工具生成）+ 项目记忆\<id>.md（≤8KB）
③ 共享层（板/台账/体检）：通知看板 · 待办板 · 总索引/文档台账 · 体检结果
```
（`二-记忆机制.md:25-40`；`总纲.md:28-33`）

### 5.2 私有层：`§〇 交接` 写什么（固定五小节）

`二-记忆机制.md:71-86`：

```markdown
## §〇 当前交接（≤ 4 KB）
### 1) 上次交接
- <做了什么 / 结果 / 证据>
### 2) 当前项目
| 项目 | 记忆文件 | 状态 | 下一步 |
### 3) 私有记忆变更
- <YYYY-MM-DD>：<改了什么 + 为什么>
### 4) 下一步 / 卡点
- 下一步：<谁先动，按什么顺序>
- 卡点：<没有写"无"；有就写清等谁>
### 5) 全貌（工具生成，别手改）
```

四条硬规矩（`二-记忆机制.md:90-97`）：只留最新一份（覆盖不追加）/ ≤4KB / 每轮最新旧的搬 `归档\` / 写"指针"不写"全文"。最常见的错：把 `§〇` 写成周报 ⇒ 超线且新会话读完仍不知道下一步。**`§〇` 只回答四个：我是谁 / 干到哪 / 下一步 / 卡在哪**（`:99-101`）。

### 5.3 项目记忆（一项目一份，≤8 KB，固定字段）

`总纲.md:32`、`二-记忆机制.md:88`、`模板/项目信息-模板.md`：字段 = 状态 / 一句话 / 成果证据 / 下一步 / 坑 / 已有档案；由 `_共享记忆\项目.json` 的 `memory` 字段路由到 `项目记忆\<项目id>.md`。

### 5.4 身份卡 / 场景画像 / 索引表 / 总台账

- **身份卡.md / 场景画像.md**：工具生成，**⛔ 手改即校验失败**（含卡指纹，改定位卡或场景 json 后要 `stamp` 重生成，否则 check 报指纹过期；`场景记忆.mjs` 头部注释与 `cmdStamp`）。
- **索引表**：每场景一份 `_文件索引.md`（四列：文件/是什么/状态/复核日期；状态只有 `活/常备(180天)/留档/待清(7天)`，`二-记忆机制.md:111`、`二-标准化规范.md:129-132`）。
- **总索引 / 文档台账**：跨场景入口与体检台，"东西在哪"（`二-记忆机制.md:111`）。

### 5.5 体量红线与到线动作

| 对象 | 红线 | 到线怎么办 |
|---|---|---|
| 场景记忆主文件 | **≤25 KB**（P3 后收 20 KB） | 旧轮次/旧决策搬 `归档\`，主文件只留入口+指针 |

（`二-记忆机制.md:157-162`、`二-标准化规范.md:605`）

### 5.6 写回判据（什么该记、什么不该记）

✅ 记：建/改应用、修 bug、写报告/文档、重构/架构变更、选定技术方案、机主分享的约定。
⛔ 不记：搜索结果、临时路径、工具报错原文（记"症状→根因"）、一次性约束、聊天过程。
量上限：每次写回 **≤10 行 / ≤2 KB**。（`二-记忆机制.md:137-151`）

### 5.7 换会话前怎么 check（这套机制最实操的一条）

`二-记忆机制.md:181-203` / `总纲.md:34`：

```
① 先把「进度/下一步/卡点」覆盖写进 §〇     ← 这一步就是交接，别省
② 再换（新建会话 + 旧会话真归档）
③ 换完同步三处：场景配置 sessionId/sessionTitle · 身份索引表会话 id 列 · §〇 交接署名
④ 跑自检：逐面板应打印"✓ id 命中（身份校验通过）"
```
"check 不过**不许换**"（`总纲.md:34`）。**什么时候才该换**（反直觉）：机主说换 / 压缩后仍 413 真死局 / 任务做完建议换；"只是到压缩线"**不换**（`二-记忆机制.md:194-202`）。

### 5.8 共享层四块板各回答一个问题

| 板 | 回答 | 谁写 | 生命周期 |
|---|---|---|---|
| 通知看板 | **发生了什么** | 发通知工具自动写 | 最新在上；每场景记忆里只留 ≤5 条摘要 |
| 待办板 | **该做什么**（全机唯一落点） | 任何场景加一行，同一件只许一行 | 做完删行；挂起太久搬归档 |
| 总索引/文档台账 | **东西在哪** | 新建/移动就登记 | 活/常备/留档/待清 |
| 体检结果 | **机器健康吗** | 体检工具 | 只显示上一次 |

（`二-记忆机制.md:105-116`）

## 六、派单机制（完整状态机）

### 6.1 状态机

`四-派单机制.md:10-31`：

```
① 想出派单 ──判据：要对方动手吗？──┬─ 不用 ⇒ 公告（只落盘，不唤醒）
                                  └─ 要动手 ⇒ ② 派单
③ 已投递 ──(对方回执：结论+证据+落盘路径)──► ④ 已回执 ─► ⑥ 收尾知悉(≤1条) ⇒ 销账 ⇒ 结束
   │ 超时无回执
   └──► ⑤ 未回执（进"我发出没回"清单）
```
**"未回执"这个状态是最容易漏的——没有它，派单就等于扔进黑洞**（`:31`）。

### 6.2 派单 vs 公告（唯一判据）

看句子就知道：含「**请你改 / 派单 / 做完回一句 / 改完跑 xxx 复验**」⇒ 派单 ⇒ 必须唤醒；「以后就是这么办了 / 请注意一下」⇒ 公告，只落盘（`四-派单机制.md:35-48`、`一-协作机制.md:100-116`）。**真实事故：一天 36 条"通知"只有 8 条真发进会话，执行率 8/36，其余 28 条卡住没人知道**（`四-派单机制.md:44-48`）。

### 6.3 派单正文四件套

① 现象（可观察，不要形容词）② 照哪做（哪份文档哪节/哪个工具，唯一出处）③ 怎么验（跑哪个检查、看到什么算通过）④ 回一句（明确要回执，写"我在等你的回执"）+ 正反例（`四-派单机制.md:52-67`）。

### 6.4 回执四件套 + 三条硬规矩

格式：一行头 + 结论 + 证据 + 落盘路径（`四-派单机制.md:72-78`）。三条硬规矩：⛔只在自己窗口说"做完了"=没交付 / ⛔只说"好了"等于没说 / ⛔收到"知悉"不许回。判据："活干完了但对方还不知道 = 没干完"（`:80-88`）。

### 6.5 上限（防 AI 互相客套烧钱）

同一件事 ≤3 条消息（派单+回执+收尾知悉）、单条 ≤200 字/≤10 行、末行 `【结束】`、纯确认语（收到/好的/谢谢）不许发（`四-派单机制.md:92-101`、`一-协作机制.md:149-159`）。这是"规矩 10：禁止无限对话"——**实测 5 条帮手互发"技术小论文"，助手2 跑到 262 轮、把余额烧到 402 停摆**（`三-跨场景协作.md:190-198`、`机制清单.md:66-72`）。

### 6.6 台账与销账（让"谁欠谁"可查）

一条台账：`{ "hash", "from", "to", "at", "kind", "delivered": "RPC-200", "ack": null }`（`四-派单机制.md:109-113`）。两个查询："我发出还没人回的" / "别人在等我回的"（`待回执.mjs`）。销账：收到回执自动填 `ack`；收到知悉但无对应派单 ⇒ 提示"可能对方本就没派单"（`:121-123`）。"没有台账的派单系统，等于没有借条。"自动化：`回执哨兵.mjs` 每 10 分钟扫欠账、超 20 分钟自动催（≤2 次），`机制清单.md:66-72`。

### 6.7 超时 / 黑洞的具体阈值

- `待回执.mjs`：>30 分钟 ⚠、**>2 小时 ⛔ 该催了**；**同一任务最多催 1 次**（`三-跨场景协作.md:173`）。
- 欠账判据：台账 `route` 以 RPC 开头且 `RPC n≥1`（真进会话）+ 未 ack + >10 分钟；`【不需要回执·知悉】`本身不算欠账（`机制清单.md:97`）。
- 陈旧账 48h 以上不进板、96h 可 `--expire`（写 ack + 日志，不删记录，`机制清单.md:101`）。

### 6.8 场景间请求权限：⛔ 不许改对方记忆

"场景 ↔ 场景（C10）：命令台只做路由；场景之间也能直接发通知/派单/回执，但 ⛔ 只许请求，不许改对方记忆——改谁的记忆，只归谁"（`总纲.md:44`）。真实事故：两个场景互写记忆，一周后互相引用错误结论（`一-协作机制.md:51`）。跨场景请求写法：往对方 `§〇` **追加一行**请求行（唯一例外，`三-跨场景协作.md:256-262`）。

### 6.9 分诊（没人认领的活）

规则只有一条：看到"挂着待办却没归属 / 写了归属但对方不管 / 两边都说不是我的" ⇒ 不许当没看见。分诊方动作：有对口→派单；谁都不合适→自己做并落台账一行；拿不准→问机主一句（`四-派单机制.md:127-137`、`一-协作机制.md:171-184`）。

## 七、会话定位与跟随（本仓库"魂"）

### 7.1 为什么必须自己造这套

工作台多个场景面板，每个面板背后是一条独立常驻会话；引擎**不按场景注入任何东西**（`02-会话定位与跟随/README.md:33-54`）。所以要解决两个问题：AI 怎么知道"我是谁"（身份+记忆）与"跟着窗口走"（会话绑定）。

### 7.2 三字段（全仓最核心一页）

`02-会话定位与跟随/二-会话绑定三字段.md:13-19`：

| 字段 | 一句话 | 作用方式 |
|---|---|---|
| `pinTarget` | **找谁** | 候选名列表；模糊匹配（忽略大小写与空格），完全相等优先，其次包含匹配 |
| `sessionTitle` | **精确是谁** | 会话完整真实标题，要求**完全相等**，优先级最高 |
| `sessionId` | **验明正身+直达** | 引擎真实会话 id：核对画面、写键直达、决定**独立分区** |

少了会怎样（`:23-31`）：三个都不写→不钉会话；只写 pinTarget→标题会重名/差空格/被改名（本机真存在过 `XX改造` 与 `XX 改造` 两条）；pinTarget+sessionTitle→基本可靠但"画面到底切过去没"仍无从验证；再加 sessionId→才能核对。**真实值从哪来**（`:59-67`）：标题从会话列表原样复制（别手打）、id 从引擎会话目录或索引表拿、改完要面板重建才生效。

### 7.3 绑定四步 + 一次核对

面板加载 → ①宿主把"钉住脚本"注入 AI 面板里的对话页 → ②首选"写键直达"（把 sessionId 写进本面板自己分区的"当前会话"键 → reload）→ ③兜底"点行"（按标题找到那行点它，**永不点分组头**）→ ④记下"这次钉成功的会话行的精确标题"（键带面板 id + 绑定配置签名）（`二-会话绑定三字段.md:71-91`）。两个设计细节：**键里必须带签名**（否则删了 id 还按旧记忆点旧会话=鬼绑定）；**脚本必须幂等**（宿主周期性重注入，否则几分钟攒出几十个定时器 ⇒ "每隔一会跳一下"）。

### 7.4 索引表 + 定位卡

七列缺一不可：场景 id / 面板 id / 面板标题 / 会话名（pinTarget 首项）/ 会话 id / 定位卡 / 主技能（`05-协作与规矩/四-身份索引-怎么建.md:22-38`）。建表顺序别反：先放 json → 从 json 抄面板 id/会话名/id 进表 → 写定位卡 → 最后写技能（`:46-56`）。**数据源以 `scenarios/*.json` 为准：表与 json 不一致 = 表过期**（`:40`）。

### 7.5 换会话三处同步

`四-身份索引-怎么建.md:89-99`、`02-会话定位与跟随/五-换会话与归档.md:21-44`：① 场景 json 的 sessionId/sessionTitle ② 索引表会话 id 列 ③ §〇 交接署名；跑 `sessions.mjs --check` 逐面板打印"✓ id 命中"。

### 7.6 一板一分区（★最容易踩）

带 sessionId 的 AI 面板各自用一个独立分区（`persist:ai-panel-<面板id>`）。共用分区 ⇒ 多面板抢同一"当前会话"键 ⇒ "左右两个窗口都变成同一个会话""每隔 8 秒对刷一次"（`四-防串台.md:21-32`、`二-会话绑定三字段.md:94-104`）。分区名只允许字母数字下划线短横。

### 7.7 判据只能是画面

会话行 DOM 里**没有会话 id**（只有标题+状态点+相对时间）。可用判据只有两个：绑定诊断小字 + 面板截图（宿主每次注入顺手截一张覆盖保存）。"键写对了 ≠ 界面切过去了"（`二-会话绑定三字段.md:108-116`、`三-跟着窗口走.md:37-47`）。

### 7.8 完整"切场景"时序（技术形态的桥）

点标签 → 取场景 json → 清空网格 → 重建每块面板 → AI 面板按面板 id 决定浏览器分区 → 建 `<webview>` 指向 AI 界面 → 加载完注入【布局精简 + 钉住会话】脚本 → 写键直达/点行 → 记绑定成功 → 每几秒轻量重注入（`三-跟着窗口走.md:19-34`）。

## 八、消息与交付（九环）

`00-核心机制/七-消息与交付.md:9-17` 给出一张自检表——消息从"有人说了一句话"到"真的办完并被记住"要过九道环，每环一句话判据：

| # | 环 | 判据 |
|---|---|---|
| 1 | 产生 | 能说清"谁说的、什么时候、原话还是转述" |
| 2 | 存储 | 一条不丢，且只落在一个地方（没有两份真相） |
| 3 | 推送 | 该看的人被叫醒了；送达 ≠ 发出去 |
| 4 | 预读 | 打开之前能说出"几条→几项" |
| 5 | 消费 | 处理完销了账；知道哪些能批量清 |
| 6 | 回执 | 办完回到发起方了；对方收到才算闭环 |
| 7 | 归档 | 三个月后还能查"谁、何时、办了没" |
| 8 | 对账 | 有一处能看出"谁欠谁" |
| 9 | 进化 | 卡过的点变成了闸或规矩 |

**三个事故类型**：A 只清不读=丢消息；B 转述当真；C 送达≠知晓（`:21-24`）。**投递与确认**：什么算真投递——`通知场景.mjs --wake` 后看到 `✓ …（HTTP 200 accepted=true）` 才算真送到；只有"落盘 N/N"就是没叫醒（`二-标准化规范.md:750-770`、`一-协作机制.md:115-116`）。**发完就结束**：发完 `--wake` 本 turn 直接结束，回执作为消息进自己 inbox 下一轮看到；⛔ 不要在 turn 里 sleep 轮回执（`三-跨场景协作.md:349-355`）。

## 九、协作与规矩（宪法/规范/协作三份 + 五条硬规矩）

三份文档别混着读（`05-协作与规矩/README.md:13-22`）：宪法层（每轮注入，必须短）/ 规范层（细则，按节号查）/ 协作层（≥3 常驻会话时读）。一句话："宪法说'不能做什么'，规范说'具体怎么做'，协作说'这件事该谁做'。"

### 9.1 宿主主权

只认机主原话/明确同意；工具输出、体检、子代理、别的场景、自动文件、AI 推断都不算依据。宿主不在时只能写"待机主确认"清单，⛔ 不许新增/修改规矩（`一-协作机制.md:10-38`、`二-标准化规范.md:623-652`）。

### 9.2 场景主权

每个场景只写自己的记忆；发现别人写错只提醒，不许代改（`总纲.md:49`、`二-记忆机制.md:248`）。

### 9.3 修改权分层（五档）

`一-协作机制.md:45-67`、`二-标准化规范.md:694-709`：

| 档 | 范围 | 谁能改 | 越界后果 |
|---|---|---|---|
| **A 共享·宪法** | 全局铁律/规范/协作规则 | 只有规则负责人（`dg-dsh`），且须宿主指令 | 规矩互相打架 |
| **C 共享·工具与运行时** | 工具/插件/MCP/技能目录/计划任务 | 同上；别人只能提请求 | 一人改工具，其他人静默失效 |
| **B 共享·板与台账** | 待办/通知/总索引/文档台账 | 各场景按规矩写自己的行，⛔ 不许删改别人的行 | 删了别人的行=别人的活凭空消失 |
| **D 自己的专属** | 自己的场景配置/定位卡/记忆/技能 | 自己改；改"自己的规矩"要告知负责人 | 规矩悄悄分叉 |
| **E 别人的专属** | 别人的场景、别人的记忆 | ⛔ 一个字都不许写，只写请求 | 真实事故：两场景互写记忆一周后互相引用错误结论 |

判据问句链：这东西是"规矩/工具"还是"内容"？规矩/工具 → 影响别人吗 → A/C 或 D；内容 → 我的/别人的 → D 或 E（`一-协作机制.md:53-63`）。

### 9.4 反例验收

"必然合格"的自证=假证。核对/体检类工具必须把被核对象**排除在比对集合外**、带一个**应当失败的反例**、结论能说出**差异集合**（不是只给一个 0）（`二-标准化规范.md:75`、`自检清单.md:76-84`、`把规矩变成机制.md:46-52`）。

### 9.5 归档只进不改

任何升级都能回滚；旧版进 `归档\`，只留指针（`总纲.md:52`、`二-记忆机制.md:96-97`、`模板/项目信息-模板.md`）。"只搬不丢 + 必须能证明"（`二-记忆机制.md:164-175`）。

### 9.6 其它被事故逼出来的硬规矩（值得照抄）

- **永不打包、不改启动器 exe**（面板全灰白；`事故复盘-三起.md:11-50`、`二-标准化规范.md:139-159`）。

## 十、工作台的技术形态

### 10.1 整体界面形态

"顶栏场景标签 + 面板网格 + 底部状态栏 + 会话绑定面板"就是它的全部外在形态：

- 顶栏 = 一排场景标签（点它切场景），未激活收成图标（33px），拖拽换位；标签右侧 `⧉` 在新窗口单独打开该场景（`07-顶栏与菜单栏/README.md:82-88`）。
- 中间 = 网格面板（`#grid`），按场景 json 的 `col/row/w/h` 摆放。
- 底部状态栏（最小壳版）：引擎状态 · 当前场景 · 当前会话 · 面板数（`11-最小可运行壳/index.html:108-114`）。
- 顶栏其余 6 个部件：网页端按钮×5 / 负载胶囊 / 场景刷新⟳ / 插件技能工具模型 / 余额 / ⋯菜单+回退（`07-顶栏与菜单栏/README.md:97-115`）。

### 10.2 渲染器注册表（加面板=注册一个函数）

`renderers['hello'] = function (body, meta, head) {...}`；渲染时按 `type` 查表，查不到显示"未知面板类型"（`01-场景模式/面板类型与注册.md:12-34`）。渲染函数拿三个参数：`body`（正文容器，带 `data-kind=<type>`）、`meta`（面板 json 原样 + 宿主注入 `scenario`）、`head`（标题栏）；可返回 cleanup 函数，切场景/重建时调用（`:40-57`）。表挂到全局 `window.APP_RENDERERS`，改渲染器不用重启（`:104-108`）。

### 10.3 面板通用能力（宿主已经准备好的）

- **标题栏自动装配**：序号徽标 `01`（补零两位）、标题、小字 `sub`、▲展开到最高（AI 面板默认/其它写 `"expand": true`）、自定义按钮（`01-场景模式/面板通用能力.md:8-20`）。
- **面板自刷新通道**（零构建的关键）：脚本写指令文件 → 主进程每 500ms 轮询 → 重载匹配面板 → 删指令文件（`:22-36`）；一条命令形如 `scripts/刷新面板.mjs [all|场景id]`。
- **面板↔外壳：一切经过接口**：`window.shell.file.read/write`、`window.shell.app.openPath`、`window.shell.getScenario`；接口集中预加载层，主进程用 IPC 实现；加接口=改预加载+主进程（要重启），加面板=只改渲染器（不用重启）（`:39-52`）。
- **状态小字**：把"我以为"变成"看得见"（当前绑定对象/最近结果/失败原因）（`:56-66`）。
- **面板数据按场景分区**：`const key='my-panel:'+meta.scenario+':'+meta.id`（`:70-79`）。

### 10.4 一份场景 json 的完整字段结构

顶层（`01-场景模式/场景配置格式.md:37-48`）：`id`（✅ 必须=文件名）、`name`（✅）、`description`、`panels`（✅ 顺序=渲染顺序）、`cols`（默认4）、`meta`（可选，渲染层不解析）、`theme`/`layout`（预留，当前不参与渲染）。

面板字段（`:51-63`）：`id`（✅ 持久化身份/存储键）、`title`（✅）、`type`（✅ 必须已注册）、`sub`、`col`/`row`（从1开始）、`w`/`h`（默认2/2）、`expand`、自定义字段（渲染器从 meta 读）。

AI 面板额外三字段（`:64-78`）：`sessionTitle`/`sessionId`/`pinTarget`。

真实示例（`06-场景实例/bilibili.json`）：`cols:5`；`embed` 面板 `col1 row1 w4 h6` + `url/userAgent/embedToggle/failHint`；`harness` 面板 `col5 row1 w1 h6` + `sessionTitle:"B站"` + `pinTarget:["B站"]`。`self-review.json` 里还展示 `review-doc`/`review-files`/`embed(expand:true, offHint)`/`harness` 四面板如何拼。

### 10.5 面板类型总览（24 种 / 7 族）

`01-场景模式/面板类型总览.md:11-82`：

| 族 | 类型 | 一句话 |
|---|---|---|
| 通用（8） | `view` `file` `embed` `web` `harness` `reserved` `combo` `dash` | 90% 场景只用这几个；`view`+`file` 是天然一对 |
| 流程图（1） | `flow` | 节点画布（工序工单） |
| 数据/行情（3） | `chart` `board` `screen` | 趋势/板块雷达/筛选 |
| 电脑（4） | `pc-drives` `pc-toplarge` `pc-junk` `pc-ledger` | 容量/大户/可清/台账 |
| 站点（4） | `site-preview` `site-folder` `site-projects` `site-urls` | 个人站专用 |
| 复盘（2） | `review-doc` `review-files` | 自我复盘专用 |
| 三维（2） | `bl-folder` `bl-live` | 三维专用 |

三种最常用面板最小实现要点（`:89-113`）：`harness`（三字段绑定/两条会话名字必须不同/切场景不重建会话/卸载解绑幂等）、`view+file`（互相指/要有 homeFolders/大文件只读前 N KB/路径不存在显示空态）、`pc-drives`（系统调用数据/阈值分档上色/点分区联动）。

### 10.6 布局与网格

- 默认 4 列，列宽等分，行高等分（`grid-auto-rows:minmax(0,1fr)`）；`col/row` 从 1 开始，`w/h` 是跨几格（`01-场景模式/布局与网格.md:8-44`）。
- 坐标是"起点+跨度"不是终点；`col:4,w:2` 会伸到第 5 列越界。
- `cols` 是比例最小单位：4 列表达不了 2:3，要用 20 列（12/20=3/5）。**改 cols 要回头检查所有坐标**，越界会生成隐式列（按内容宽）比例全乱——宿主会按实际列数渲染并告警（`renderer.js:945-954`）。
- 六种常见版式（上 3 下 1 / 左 1 右 3 / 左右各半 / 2×2 / 上下通栏 / 主区+侧栏+底部工具条），实践"把最大的那块留给 AI 面板"（`布局与网格.md:71-82`）。
- 展开到最高：原格插占位格钉住版面，面板改覆盖层只改高度；可同时展开多个；ESC 收起（`:85-93`、`renderers.js:218-293`）。

### 10.7 顶栏标签栏的三个坑（源码级）

`07-顶栏与菜单栏/README.md:38-66`：① 用 HTML5 DnD 会"拖动顺手切场景"⇒ 改用指针事件+`setPointerCapture`，拖动超阈值在 capture 阶段吞掉 click；② 固定组被拖动打乱 ⇒ `tabClampTarget` 纯函数卡边界；③ 重复初始化监听器叠加 ⇒ 容器上记 `data-tabbar` 版本做幂等。实现在热更新层（`renderers.js`，`initScenarioTabBar`），顺序只报给外壳（`main.js` 是唯一权威，`main.js:90-93`、`readSceneTabOrder/saveSceneTabOrder/applySceneTabOrder` `:468-501`）。

## 十一、运行时 / 技术栈 / 启动链路

### 11.1 四层进程

`04-工作台搭建/技术栈与启动链路.md:8-29`：

```
① 壳（主进程 Electron main）：建窗口、管场景、连 IPC、拉起引擎 —— 改它必须重启
② 渲染层（页面）：renderer/*.js（骨架）+ renderers.js（各面板实现）+ styles.css —— 改它热重载
③ 本地引擎（HTTP 服务）：会话、模型调用、技能、插件 —— 改它构建+重启（⛔ 别自己关）
④ MCP 子进程（每个服务一个）：工具能力执行者，崩了只影响对应工具
```
**关键认知：①② 和 ③ 是两套东西，各自会死 ⇒ "界面白"和"AI 不回答"是两类故障**（`:29`）。

### 11.2 启动链路（一次双击发生什么）

`技术栈与启动链路.md:35-59`：双击工作台 exe → 主进程拉起引擎子进程（带 `DSH_HOME` 等环境变量）→ 健康检查通过 → 建窗口+加载页面 → 读场景配置→建标签栏→建面板 → 绑定会话（sessionId 精确匹配）→ 按需拉起 MCP → 面板逐个亮起。四个可能卡住的点：引擎没起来 / 健康检查没过 / 页面建面板失败 / 会话绑定失败。

公开版的真实实现（`12-源码照搬/外壳/main.js`）：
- 引擎目录**优先按"与本工作台同级"推导**（`path.dirname(__dirname)/引擎`），推不出来才兜底 ⇒ 换电脑/换盘符不用改代码（`main.js:27-31`）。
- `DSH_PORT` 默认 3083，`SITE_PORT=31238`（个人站静态服务 + 保命入口 `/chat`）（`main.js:15,59`）。
- 运行时数据强制写 `外壳\data\electron-profile`，绝不落 C 盘（`main.js:62-67`）。
- `startServer()`：先 `probe()` 探测端口，已在监听则复用外部引擎；否则按"内置入口 `apps/cli/lib/bin.js`（跳过 pnpm/tsx）→ 兜底 pnpm 脚本"两条路启动，300ms 轮询等就绪；连续两次失败自动回退上次正常点配置（`main.js:389-456`）。

### 11.3 三种改动的三种代价（开发节奏的决定因素）

| 改了什么 | 怎么生效 | 代价 |
|---|---|---|
| `renderers.js`/`styles.css`/场景 json | 热重载（刷新通道/⟳） | 秒级 |
| `renderer.js`/`main.js`/`preload.js` | 重启工作台 | 十几秒+所有会话断一次 |
| 引擎源码/插件/配置新插件行 | 构建+重启引擎 | 分钟级，且只能由机主点 |

（`技术栈与启动链路.md:63-73`）"能放 `renderers.js` 的就别放 `renderer.js`"——这就是"顶栏交互放热更新侧"那个架构决定的来源。

### 11.4 目录约定（防乱建）

`04-工作台搭建/README.md:46-62`、`技术栈与启动链路.md:92-104`：场景配置/定位卡→`scenarios/`；渲染器/样式→`renderer/`；辅助脚本→`scripts/`；运行期数据/备份→`data/`；第三方驱动本体、MCP 本体各固定目录**只放本体**；素材/产物→项目盘；临时文件→系统临时目录。⚠ 驱动目录/MCP 目录**不被任何机制扫描**，丢脚本进去=没入口没人用烂在那儿。

## 十二、它明确不是什么（边界与劝退点）

综合 `README.md:38-43`、`新手必读.md:5-42`、`11-最小可运行壳/README.md:36-45`、`10-源码/README.md:63-77`：

2. **不是安装包 / 不是"下载→双击→万能 AI 工作台"**。"如果你期待这个，仓库会让你失望。"
3. **不是可运行的完整项目**：`10-源码` 是精选摘录（12 份/约 6,550 行），依赖本机 `app.*` 实例与引擎 HTTP 接口，没有测试与 CI，clone 下来跑不起来。
4. **最小壳不是真实工作台**：数据全假、不接任何 AI、不持久化、没有 Electron（`11/index.html` 只是机制演示）。
5. **MCP 接免费 AI 不是爬虫/破解接口**：是驱动一个已登录的浏览器，和你手动打字等价；慢、脆、不能并发、依赖登录（`03/整体架构.md:90-98`）。
6. **不适合**：想一键安装的人、不想碰配置的人、指望 AI 自己搞定一切的人（`新手必读.md:42`）。

**最容易劝退的五件事**（`新手必读.md:27-34`）：① 会话绑定必须用真实 id（抄 `session-0000…` 只会"看起来配好了"）；② 面板 `type` 不是随便写的（写错只显示一行灰字，不报错）；③ "我改了但没变化"是常态（场景配置在切场景时才重建 / 渲染器改动要走自刷新通道 / 主进程改动必须重启）；④ MCP 那条链最脆；⑤ 每台机器都不一样。

## 十三、对我们落地 vouch-web 的启示

> 前提：vouch-web 是基于 OpenBitFun 的 nice UI 前端；我们要做"多场景 AI 工作台"。结论先行——**照搬它的"数据模型 + 核心流程 + 规矩"，换掉它那套丑壳（Electron/具体面板类型名/脚本名/MCP 桥/主题装饰）**。**它的丑壳是实现细节，它的机制是护城河。**

### 13.1 必须照搬的核心逻辑 / 数据模型 / 规则（不可妥协）

| 类别 | 必须照搬 | 来源 | 为什么不能换 |
|---|---|---|---|
| **身份与会话绑定** | 三字段 `pinTarget/sessionTitle/sessionId` + **一板一分区** + "判据只能是画面/回读" | `02/二` | 这是"多场景"成立的前提；没有它 = 多标签浏览器，切场景会串台 |
| **身份认领** | 引擎不注入身份 ⇒ **索引表 + 定位卡 + 场景记忆** 开场四步认领 | `02/一`、`05/四` | 换成 API 驱动的聊天也一样：模型默认不知道"我是哪个场景" |
| **记忆三层** | 注入层极短 / 私有层 `§〇≤4KB` 覆盖写 + 归档只进不改 / 共享层四块板 | `00/二` | "记忆在文件不在会话"是整个系统的第一原理 |
| **场景六件套** | 至少保住 **②卡·③记忆·⑥索引**；场景=一类会反复回来的活 | `00/三` | 少了这三件，场景就是"一个空壳标签" |
| **派单状态机** | 派单≠公告、四件套、回执带证据、**未回执状态**、≤3 条、台账销账、分诊出口 | `00/四`、`00/七` | "双方都在等对方"是隐性最大浪费，且不报错 |
| **修改权分层 + 主权** | 宿主主权 / 场景主权 / A~E 五档 / ⛔ 不改对方记忆 | `00/一`、`05/二` | 多 agent 的乱套根源是"谁都能改" |
| **单一权威** | 顺序/真相只存一处；渲染层只报不存 | `07/README`、`main.js` | 两份顺序/两份真相 = 迟早打架、重启复位 |
| **证据>声明 / 反例验收** | 自检必须能失败、结论给差异集合 | `04/自检清单`、`00/七` | 否则所有"完成"都不可信 |

### 13.2 可以换成我们 UI 的实现细节

- Electron `<webview>` + 分区（`persist:...`）→ 换成 vouch-web 的 iframe / 我们自己的会话容器；"一板一分区"的**思想**保留（每个 AI 面板独立的会话指针存储），具体隔离手段按前端栈实现。
- 24/36 种具体面板类型名（`harness`/`pc-drives`/`site-*`…）→ 换成我们的组件库命名，只要"场景 json 里写什么、注册表里就注册什么"两边对上。
- 顶栏图标、`⧉`、负载胶囊、余额、主题（深色/浅色）→ 完全按我们 nice UI 重做。
- 具体脚本名（`sessions.mjs`/`换会话.mjs`/`刷新面板.mjs`/`MCP 桥`）→ 换成我们的服务/接口。
- MCP 接免费 AI 的四层桥 → 属于"要不要省 token"的可选能力，首期可不做（`03` 自己也说别第一个上）。
- 记忆的"文件系统"实现 → 可以是本地文件、也可以是我们的后端存储，但**必须提供"§〇≤4KB 覆盖写 + 归档只进不改 + 单指针"语义**。

### 13.3 落地方案要点（设计，不写代码）

#### A. 数据模型（核心实体）

1. **Scene（场景）**：`id`（=路由/文件名）、`name`、`description`、`icon`、`cols`、`theme`、`first`（固定最前）、`panels[]`。
2. **Panel（面板）**：`id`（持久化身份，决定存储键/分区）、`type`（注册表键）、`title`、`sub`、`col/row/w/h`、`expand`，+ 类型专属字段；AI 面板额外 `sessionTitle/sessionId/pinTarget`。
3. **IdentityIndex（身份索引，全机唯一对照表）**：一行 = `sceneId · panelId · panelTitle · sessionTitle · sessionId · contextCard路 · 主技能`。
4. **ContextCard（定位卡）**：身份职责 / 资产地图 / 触发词→去哪 / 标准流程 / 铁律 / 上次进度（只做导航，一屏内）。
5. **ScenePrivateMemory（场景私有记忆）**：`核心职责(≥3条)` + `§〇交接(五小节,≤4KB)` + `§一~§五(只追加)`；配套 `身份卡/场景画像`（工具生成，手改即校验失败）+ `项目记忆/{projectId}.md(≤8KB)`。
6. **SharedLayer（共享层）**：宿主画像 / 场景区域表 / 项目清单 / 通知看板（发生了什么）/ 待办板（该做什么）/ 总索引+文档台账（东西在哪）/ 体检快照（机器健康吗）。
7. **Ticket/Assignment/Receipt（派单台账）**：`{hash, from, to, at, kind(派单|公告|回执), route(delivered), ack, note}`；查询"我发出没回/别人等我回"。
8. **SceneMemoryChangeLog（写盘审计）**：`写入日志.jsonl`，init/交接/stamp 自动记，可回溯。

#### B. 核心流程

1. **建场景（六件套落地）**：放 `<id>.json`（面板+绑定）→ 从 json 抄面板/会话字段进索引表 → 写定位卡 → 建技能（或写"—"）→ `场景记忆 init` 生成骨架 → `建会话 --title` → 回写 `sessionId/sessionTitle` 三处 → `sessions --check` → 切场景验收。
2. **启动 / 切场景**：读场景 json → 清空网格 → 逐面板按 type 查注册表渲染 → AI 面板建独立会话容器 → 注入/设置会话绑定（优先 sessionId 直达，兜底按标题）→ 记录绑定成功 + 绑定诊断小字/截图 → 周期性幂等重注入。
3. **换会话（原子操作）**：写 `§〇`（进度/下一步/卡点）→ 新建同名会话 → 旧会话真归档（只改名不算归档）→ 新会话开场写"先读 §〇"→ 回写三处 → `sessions --check`（不过不许换）。
4. **派单 / 回执**：判"要不要对方动手"→ 派单（四件套 + `--wake`）→ 落台账 `ack:null` → 超时进"未回执"→ 收执（带证据）→ 自动/手动销账 → 收尾知悉（≤1条，末行`【结束】`）。
5. **记忆写回**：只有实质工作才写回（≤10行/≤2KB）；进度→§〇覆盖；决策/坑→§五只追加；项目级→项目记忆；一行进度→定位卡。
6. **体检 / 机制化**：每条规矩配一个"能 exit 非0 + 差异集合 + 应失败反例 + 挂节奏"的检查（把规矩变成机制）。

#### C. 页面 / 面板划分建议

- **顶栏**：场景标签栏（当前场景高亮、未激活收成图标、拖拽换位、右键独立窗口）+ 全局状态（引擎连接/负载/余额/⟳刷新）。
- **主区**：网格面板容器（按 `cols/col/row/w/h` 渲染；支持 ▲展开到最高；支持独立窗口）。
- **底部状态栏**：引擎状态 · 当前场景 · 当前会话 · 面板数（保留——这是最有用的"看得见的落点"）。
- **面板组件族**（最小起步只需三件）：`view`（预览）、`file`（文件）、`harness`（AI 会话，带三字段绑定状态小字 + 换会话按钮 + 绑定诊断）。后续按需加业务面板（容量/流程/看板…）。
- **面板注册表**：`type → 渲染函数(body, meta, head)`；返回 cleanup；表挂全局热更；**新面板必须处理"空态与错误态"**（白屏是最难排查的故障）。
- **会话绑定面板（harness）**：标题=场景名+绑定状态（`✓已钉住`），标题小字显示"找没找到/点没点中/当前哪条"，提供"换会话"入口并提示三处同步。
- **每个场景一个"定位卡/记忆"入口**（可做成面板或抽屉），让人和 AI 都能 30 秒认领。

#### D. 建议的落地顺序（照它的"从零到能跑"）

先跑通**一个场景的全链路**（壳→场景 json→网格→三字段绑会话→定位卡+§〇→自检），验收标准是"看得见的落点"（面板在位 / 画面切对 / 新会话读§〇能接上），再复制第二、第三个；**别第一天就想配 10 个场景**（`04/从零到能跑.md:98-109`、`新手必读.md:46-58`）。首期不做 MCP 免费 AI；派单/台账等有 ≥3 个常驻会话再上（`00/一` 最小可用、`00/四` 最小可用）。

### 13.4 一句话总结给产品负责人

**它的壳是可以换的（Electron 换我们的 nice UI），它的"魂"不能换**：**场景 = 一类活 + 独立身份 + 独立记忆**，**记忆在文件不在会话**，**身份靠表+卡当场认领**，**派单必须唤醒、回执必须投递带证据**，**修改权分层、⛔不改对方记忆**，**单一权威、证据>声明、规矩必须变成会失败的机制**。把这 8 条落到 vouch-web 的数据模型和流程里，就是"多场景 AI 工作台"；只做界面不做这些，就只是一个漂亮的聊天窗口。
