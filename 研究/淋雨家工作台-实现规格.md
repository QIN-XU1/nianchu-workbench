# A. 记忆处理（最重要）

## A.0 一句话与三条不变量

- **记忆在文件，不在会话**：会话会被换、被压缩、被升级重启；`一条会话的价值 = 它产出的文件`（`00-核心机制/二-记忆机制.md:10-19`）。
- **分层=把「每轮都付的成本」和「用的时候才付的成本」分开**：铁律进注入层（每轮付，必须极短）；细则进技能（按需付）；进度进 §〇（开场/换会话时付）（`02-会话定位与跟随/六-记忆分三层.md:44`）。
- **一个事实只存一处，别处只放指针**（`二-记忆机制.md:221`）。

## A.1 三层记忆总表（确切内容 / 路径 / 读者 / 写者 / 上限 / 频率）

| 层 | 确切内容 | 存放路径 | 读者 | 写入者 | 大小上限 | 更新频率 |
|---|---|---|---|---|---|---|
| **① 注入层（全局铁律）** | 不读就会白干的铁律、附则（宪法/全局铁律） | 工作区 `AGENTS.md` 层级 / `05-协作与规矩/一-全局铁律.md`；引擎 `引擎\.dsh\` 侧 | **每轮自动注入**，人人付成本 | 只有宿主（L0 宪法，改一次版本 +1） | 越短越好（`README.md:46` 记 ≤几十 KB；实测一版 16.4 KB） | 每轮（固定开销） |
| **② 私有层（场景私有）** | `场景私有记忆.md`（§〇 交接 + 核心职责 + §一~§五）、`身份卡.md`、`场景画像.md`、`项目记忆\<项目id>.md`、`归档\`、专属技能 | `引擎\场景记忆\<场景>\`（v2 统一目录；旧称 `场景项目信息`。OA/自我复盘/dsh-gui 有例外目录） | 只有本场景，开场读 `§〇+§一+§二` | 人写主文件；`身份卡/场景画像` 工具生成；**只有本场景会话能写** | 主文件 **≤25 KB**、`§〇` **≤4 KB**、项目记忆 **≤8 KB** | 收工/换会话前覆盖 §〇；§五只追加 |
| **③ 共享层（板/台账/体检）** | 通知看板（发生了什么）、待办板（该做什么）、总索引/文档台账（东西在哪）、体检结果（机器健康吗）；另 `_共享记忆\` 的宿主画像/area/项目路由 | `引擎\场景项目信息\`（通知看板/待办板/总索引/文档台账/`_体检-latest.json`）；v2 骨架在 `引擎\场景记忆\_共享记忆\` | 谁需要谁读 | 分区写：看板由发通知工具写，待办任何场景加行，索引谁建谁登记，体检只由工具写 | 各自上限（看板最新在上；体检只显示上次） | 看板一天几十条 / 索引一周几条 / 体检一周一次（周日 12:30） |

> 四份「各管一段」补充（`六-记忆分三层.md:10-17`）：**全局须知**（每轮注入，极简）· **技能**（只有 name+description 进上下文，正文按需读）· **定位卡** `scenarios/<场景>-context.md`（开场读一次，一屏导航）· **场景记忆**（开场读 §〇+§一+§二）。**权威顺序：场景记忆 ＞ 定位卡 ＞ 技能叙述**；冲突时顺手把技能改对（`六-记忆分三层.md:17`）。

**为什么不能合成一份**（`二-记忆机制.md:54-63`）：注入层变长 ⇒ 每轮更贵（60 KB ≈ 每轮多付 20k token）；私有层变长 ⇒ 开场读不完（曾有 40 KB 场景记忆没人读）；共享层混私有 ⇒ 互相干扰。判据一句话：**"这东西谁会读？多久读一次？"**

### A.2.3 `身份卡.md` / `场景画像.md`：谁生成、含什么、为什么手改会校验失败

- **生成者**：`场景记忆.mjs stamp`（`init` 结束也会调 `stamp`）。`身份卡` 由 `writeIdentityCard()` 全量重写，`场景画像` 由 `writePortrait()` 从场景 json 推导（`场景记忆.mjs:178-224,319-337`）。
- **身份卡含什么**：一段 `<!-- 场景绑定 BEGIN/END -->` 的 bindingBlock——`场景 id / 面板 id / 会话 sessionId / 定位卡相对路径 / 卡指纹 sha256:<16hex>… / 盖章时间 / 地盘目录 / 权限 / 专属技能 / 面板清单`；下面是「怎么用」（`场景记忆.mjs:164-191`）。
- **场景画像含什么**：`形态`（layout/theme/cols/面板数）、`面板表`（id/标题/类型/内容/位置/尺寸）、`运行时`（绑定会话/钉定/渲染器）、`依赖与入口`（定位卡/专属技能/记忆文件夹）（`场景记忆.mjs:193-224`）。
- **指纹机制（为什么手改会校验失败）**：`卡指纹 = sha256(定位卡文件) 的前 16 位`。`check` 从 `身份卡.md` 里正则抽出这个指纹，再**重算当前定位卡的 sha256 并前缀比对**：
  - 定位卡改了却没 `stamp` ⇒ 指纹过期 ⇒ `✗ 卡指纹过期（卡已改，跑 stamp）`（`场景记忆.mjs:478-485`）；
  - 手改身份卡里的指纹/绑定块 ⇒ 版本对不上 ⇒ 同上；
  - 即便改的是正文，`stamp` 会**全量重写**把改动冲掉。所以规矩是「**身份卡只读，要补充写进 `场景私有记忆.md`**」（`场景记忆.mjs:187`）。
- **来源**：`场景记忆.mjs:168-191, 478-485`；`二-记忆机制.md:243`。

## A.3 索引表：两个不同的「索引」

> 澄清任务里的「七列/四列」：**四列 = 每场景的 `_文件索引.md`（文件台账）；七列 = 全局的 `_场景身份索引.md`（我是谁对照表）**，两张表别混。

### A.3.1 `_文件索引.md`（每场景一份，4 列）

（`二-记忆机制.md:111`、`二-标准化规范.md:129-135`、`场景记忆.mjs:300-314`）

| 列 | 含义 |
|---|---|
| 文件 / 目录 | 本目录里的文件名（相对本目录） |
| 是什么 | 这份文件干什么 |
| 状态 | **只有四态之一**：`活` / `常备` / `留档` / `待清` |
| 复核日期 | 活=每次动就刷；常备=180 天复核；留档=不再更新；待清=7 天内处理 |

- **状态枚举与到期动作**：`活`（每次干活读写）/ `常备`（180 天复核）/ `留档`（只作证据，不再更新）/ `待清`（7 天内必须处理）。到期四选一：**更新 / 合并 / 归档 / 清**（同类小文件优先合并，别留 `_报告1/_报告2/_报告v2`）（`二-标准化规范.md:580`）。
- **三条硬规矩**：① 新建文档 ⇒ 同时登记一行；② 删/改名/移动 ⇒ 同时改那一行（索引与文件同生共死）；③ 到期自己处置（`二-标准化规范.md:585`）。
- 坑：状态格必须**精确等于四个词之一**，写成「留档（2026-10-18 归档）」体检会解析成「未登记」（`二-标准化规范.md:747`）。
- 工具：`索引体检.mjs`（未登记=⚠，死条目/过期/身份漂移=⛔）；`索引查询.mjs <关键词>` 跨全部场景索引搜（`二-标准化规范.md:579,134`）。

```json
  "kind": "派单|公告|回执", "route": "RPC-200|落盘", "delivered": "RPC n", "ack": null }
```
- 欠账判据：`route` 以 RPC 开头且 `RPC n`（n≥1 真进会话）+ 未 ack + >10 分钟；`【不需要回执·知悉】` 本身不算欠账。
- 台账 = `外壳\data\场景通知台账.json`；新条目自带 `ack:null`，老条目无该字段=未回执（`二-标准化规范.md:176`）。

**`_共享记忆\` 其它文件**（v2 骨架，`12-源码照搬/引擎数据/.dsh/场景记忆/_共享记忆/`）：

|---|---|---|
| `索引.md` | 共享层入口 | `主题｜在哪｜谁维护` |
| `索引.json` | area 注册表 | `areas[]: {id,name,owner,memory,file,panel}` |

| `areas\<面板>.md` | 每个场景一块，**只有 owner 能写** | `场景 id / 负责 / 记忆路径` |

## A.5 写回判据 + 体量红线 + 到线怎么搬

### A.5.1 什么该记 / 不该记（只有"实质工作"才写回）

（`二-记忆机制.md:135-151`、`二-标准化规范.md:83-87`）

| ✅ 记 | ⛔ 不记 |
|---|---|
| 建/改了一个应用、修了一个 bug | 搜索结果 |
| 写了一份报告/文档 | 临时路径 |
| 重构 / 架构变更 | 工具报错原文（要记就记"症状→根因"） |
| 选定了一个技术方案 | 一次性约束（"这次先这样"） |
| 机主分享的约定 | 聊天过程 |

- 量：**每次写回 ≤10 行 / ≤2 KB**；超了说明在抄过程不是记结论。
- 判据：**"三个月后我还会需要这一行吗？"**；记忆价值不在"全"，在"下次开工能 30 秒接上"。
- 机械抓手：`写回检查.mjs --all` 给每个 `§〇` 存快照，下次算"多几行/几字节"，超 10 行或 2 KB 报 ⚠；`--update` 刷新基线（`二-标准化规范.md:87`）。

### A.5.2 体量红线表

（`二-记忆机制.md:155-164`、`二-标准化规范.md:88-92,605`）

| 对象 | 红线 | 到线怎么办 |
|---|---|---|
| 场景记忆主文件 | **≤25 KB**（P3 后收 20 KB；check 在 >25600 B 时 ⚠） | 旧轮次/旧决策搬 `归档\`，主文件只留入口+指针 |
| `§〇 交接` | **≤4 KB**（check 在 >4096 B 时直接 ✗） | 历史搬走，只留"最新一份+指针" |
| `项目记忆` | **≤8 KB** | 蒸馏/归档 |
| 技能（单篇 `SKILL.md`） | **≤12 KB** | 拆「主文件 + reference 子文件」 |
| 注入层（全局铁律） | 越短越好 | 细则下沉规范层（不注入，按需查） |
| 定位卡 | ≤25 KB | 精简 |

### A.5.3 到线怎么搬（先快照 → 搬 → 核对 → 体检）

（`二-记忆机制.md:164-176`、`二-标准化规范.md:91-102`）

```text
① 先存一份"搬之前"的快照
② 搬（历史 → 归档\）
③ 跑核对脚本：逐行比对"搬前非历史行 == 搬后非历史行"
     命中 0 差异 ⇒ 才算没丢          （抓手：核对拆分.mjs / 核对瘦身.mjs）
④ 跑索引体检：死条目 / 未登记 / 过期 / 身份漂移
```
> 真实教训：有一次没存快照就动手拆，结果核对脚本根本跑不了——**从那以后规矩改成"先快照，再动手"**（`二-记忆机制.md:174-176`）。

**拆分规矩之一：什么能搬 / 绝不能搬**（`二-标准化规范.md:93-97`，技能与记忆同一条）：
- ✅ 能搬（读不读都不改变动作）：解释 · 背景 · 长清单 · 历史案例 · 例子 · 排障经过。
- ⛔ 绝不能搬（一搬走就是"功能静默丢失"）：**判据 · 阈值 · 命令原文 · 执行顺序 · 红线 · 触发条件**。
- 判据一句话：**"读不读会改变我下一步动作"吗？会 ⇒ 留主文件**。

**拆分规矩之二：移出内容必须留"触发句"**（`二-标准化规范.md:98-102`）：
```
要 <做某件事> 时，读 reference\<文件>.md §<节>
（记忆侧）要 查 2026-09 的旧交接 时，读 归档\§五-决策与坑-20260930.md
```
⛔ 只写 `→ reference\x.md` = 没写（指针不带"什么时候"，人和 AI 都会跳过）。

## A.7 记忆如何"路由到项目"（`_共享记忆\项目.json` 的 `memory` 字段）

- `项目.json` 结构（`12-源码照搬/引擎数据/.dsh/场景记忆/_共享记忆/项目.json` 为空骨架；生产口径见 `机制清单.md:130`、`场景记忆.mjs:441-450`）：
```json
{
  "projects": [
    {
      "id": "langchen-oa",
      "name": "<项目名>",
      "owner": "oa-ops",
      "memory": "<盘根>:\\...\\项目信息\\项目记忆-langchen-oa.md",
      "状态": "进行中"
    }
  ]
}
```
- `memory` 字段是**唯一权威指针**：一个项目有一份 `项目记忆\<id>.md`，`memory` 指向它的绝对路径；check（OA 例外）会 `path.resolve(p.memory)` 与期望路径比对，不一致 ⇒ `项目.json memory 没指向…`（`场景记忆.mjs:441-450`）。
- 规模参考：**27 个项目一项目一份**（`机制清单.md:130`）。
- **自动归纳是半自动**（`机制清单.md:132`）：`自动归纳.mjs` 生成"候选写回"，**由 owner 自己** `--confirm --by <面板>` 并入；⛔ 任何工具不自动写别人记忆。

## A.8 换会话协议（记忆机制里最实操的一条）

（`二-记忆机制.md:179-203`；`二-标准化规范.md:588-611`）

```text
① 先把「进度/下一步/卡点」覆盖写进 §〇          ← 这就是"交接"，别省
② 再换（新建会话 + 旧会话归档）
③ 换完同步三处：场景配置 sessionId/sessionTitle · 身份索引会话 id 列 · §〇 交接署名
④ 跑自检：sessions.mjs --check 应逐面板"✓ id 命中"
```
- 第③步不能省：面板按 `sessionId` 钉会话，不同步 ⇒ 面板指向已归档会话 ⇒ "切场景 AI 像换了个人"（其实就是换了个人）。
- **什么时候才该换**：机主说换 ✅；上下文超限报 413 **且压缩后仍 413** ✅；只是"到压缩线"未报错 ❌（引擎自动压缩继续干）；任务做完建议换（一话题一会话）。
- 底层命令：`换会话.mjs <面板id>`（先看）→ 写 §〇 → `换会话.mjs <面板id> --go`（新建同名会话→旧会话改名"已归档"→回写 json→自检）（`二-标准化规范.md:593-596`）。

## A.9 失效模式与最小可用（速查）

- 失效（`二-记忆机制.md:216-226`）：记忆越写越肥没人读 / 两份数字打架（同一事实两处）/ 切场景失忆（sessionId 指旧）/ 别人的判断进我记忆（跨场景直接写）/ 体积正常但读完不能开工 / 拿"会话占用百分比"当压力（低估 2~3 倍，只信 `ctx.mjs`）。

# B. Skill（技能）处理

## B.1 技能是什么、目录结构

- 位置（**只有这里引擎才自动加载**）：`引擎\.dsh\skills\<技能名>\SKILL.md`（`二-标准化规范.md:48`）。
- 规范目录结构：
```
引擎\.dsh\skills\
  _索引.md                    ← 技能总索引（子技能那行要写"属于哪个主技能"）
  <技能名>\
    SKILL.md                  ← 主文件（≤12 KB）
    reference\<主题>.md       ← 参考子文件（⚠ 单数 reference，不是 references）
    （脚本/资源按需）
```
- ⛔ 技能目录**只放真技能**；说明文档放 `<工作区>\_文档\`；同名/同字段不许重复（`二-标准化规范.md:65`）。

## B.2 `SKILL.md` frontmatter 规范（字段级）

（`二-标准化规范.md:49-52`；核实处 `引擎\packages\skill\skill-filesystem\src\index.ts` 与 `tool-skill`）

| 字段 | 必填 | 作用 / 是否进注入 |
|---|---|---|
| `name` | ✅ 必填 | 技能名；缺则整条技能被引擎忽略 |
| `description` | ✅ 必填 | 写清"触发词/什么时候该用它"；**渲染 `available_skills` 目录只用 name+description** ⇒ 会不会被选中全看这一行 |
| `whenToUse` | 可选（引擎支持） | 写清什么时候用；**不进每轮注入的 `<available_skills>` 目录摘要** ⇒ 不增加固定开销，可放心写 |
| `disable-model-invocation` / `user-invocable` | 可选（布尔） | 管"谁能唤起" |
| `metadata` | 可选（对象） | 自定义元数据 |

- ⛔ **别用驼峰旧写法**（`disableModelInvocation`/`modelInvocable` 等会被引擎直接判错）；其余字段引擎忽略。
- 判据变更史（`二-标准化规范.md:52`）：旧文写"只准 name+description 两行"，与引擎事实不符，已按事实改。

**示例（真实场景技能，`12-源码照搬/引擎数据/.dsh/skills/bilibili/SKILL.md`）**：
```markdown
---
name: bilibili
description: 【场景：B站】B站 场景的工作技能：负责本场景的日常活，把结论写回场景记忆。触发词：「B站」。
---

# B站
1. 先读 `引擎数据\.dsh\场景记忆\B站\场景私有记忆.md` 的 §〇 接手。
2. 干完把结论写回 §〇 / §五。
3. 给别的场景留言：`node 工具\发消息.mjs --to <场景目录> "内容"`。
```

## B.3 技能如何被引擎发现 / 注入

- **发现**：把 `SKILL.md` 放进 `引擎\.dsh\skills\<技能名>\`，引擎扫描自动加载，**热加载**无需重启（`二-标准化规范.md:48,66`）。
- **注入**：只有 `name + description` 进 `available_skills` 目录摘要（每轮注入=固定开销）；**正文按需 read**；`whenToUse` 不进目录（`六-记忆分三层.md:12`、`二-标准化规范.md:50,57`）。
- 结论：一句话能否被选中，全靠 `description` 写不写症状/场景/触发词。

## B.4 技能如何"按场景归属"、专属技能怎么挂到场景

1. `SKILL.md` 的 `description` **首标签写 `【场景：<场景名>】`** 并写触发词（上例）。
2. 在**身份索引 §二 的"主技能"列**填这个技能名 → 该技能归该场景（`四-身份索引-怎么建.md:24-38`；`场景记忆.mjs` 用 `ident.skill` 写进身份卡/画像的"专属技能"）。
3. `场景画像.md` 的"依赖与入口·专属技能" 就是从这里来的（`场景记忆.mjs:217`）。
4. 校验：`场景体检.mjs` 查「场景 json 面板/会话 · 定位卡 · 主技能 · 场景项目信息 · 技能首行 `---` 与 `name:`」（`机制清单.md:52-56`）。
- **技能归属判据**：`引擎\.dsh\skills\<技能>\` 「谁的场景谁维护（看身份索引主技能列）；**通用技能归 dg-dsh**」（`三-跨场景协作.md:235`）。

## B.5 技能 vs 面板 vs 场景（三者关系）

（`00-核心机制/三-场景体系.md:51-88` 六件套）

| 概念 | 是什么 | 缺了会怎样 |
|---|---|---|
| **场景** | 一类会反复回来的活（六件套打包） | — |
| **面板** `type` | 界面渲染器（布局坐标）；加面板=注册渲染器，不改 json 结构 | 显示"未知面板类型"（不报错） |
| **技能** `SKILL.md` | 这类活的专业流程（可执行步骤与判据） | AI 用通用办法硬干专业活 |

> 六件套：`① 场景配置 json / ② 定位卡 / ③ 场景记忆 / ④ 专属技能 / ⑤ 专属面板(可选) / ⑥ 常驻会话+身份索引一行`。**2、3、6 不可省**（卡=职责、记忆=进度、索引=身份）；1、4、5 可退化成共用。

## B.6 技能体量红线与拆分（≤12 KB / 主文件 + reference / 子技能）

- 红线：`SKILL.md` **≤12 KB**；细节拆到同目录 **参考文件** `<主题>.md`（首行写 `> 归属技能：<名> · 从 SKILL.md 拆出（日期）`）（`二-标准化规范.md:53`）。
- **长大的正路 = 拆子技能，不是硬压**（`二-标准化规范.md:54-64`）：
  - **主技能 `SKILL.md` 只留四样**：导航 + 判据 + 铁律 + 触发词；长流程/大清单/大案例独立成子技能目录 `引擎\.dsh\skills\<主技能名>-<子主题>\`（同样要 `SKILL.md` + name/description/可选 whenToUse）。
  - **子技能 `description` 必须写清"什么时候用"**（会不会被选中全看这行）。
  - **主技能里必须留一行指路**：`要 <做 X> 时，用子技能「<子技能名>」`。
  - **子技能也要登记** `skills\_索引.md`，写明属于哪个主技能。
  - ⚠ **技能目录条数 = 每轮固定开销**（`available_skills` 每轮注入）⇒ 别滥拆，天天用的主干留主技能。
  - ⛔ **正路是"拆"，不是"删/压"**：为压回 12 KB 删判据/删命令原文=静默丢功能。
- 为什么：`12 KB` 因为**整篇读一个就吃掉半个上下文窗**；拆分把"按需才付的成本"与"每轮付的成本"分开（`六-记忆分三层.md:41-45`、`二-标准化规范.md:608-609`）。
- 机械抓手：`技能完整性体检.mjs` —— 孤儿参考件 / 指针没写"什么时候读" / 判据被搬走没人指 / 缺归属行 / 超 12 KB / `references\` 复数，逐条点名到行（`二-标准化规范.md:64`）。
- 反例：技能 `gui-workbench` 9.2 KB（仍可接受）、定位卡 35.6 KB 属超线需精简（`二-标准化规范.md:608`）。

# C. MCP 处理（接免费 AI / 浏览器驱动）

## C.1 四层架构（逐层职责）

两套等价的表述——先看"能力封装"视角（`03-MCP接免费AI/README.md:28-42`），再看"数据流"视角（`03-MCP接免费AI/整体架构.md:8-27`）：

| 层（能力封装视角） | 数据流视角 | 职责 | 关键点 |
|---|---|---|---|
| **① 界面层** | **D 网页版** | 一个隐藏浏览窗口，里面**已登录**网页版 AI（豆包/通义/DeepSeek/智谱/Kimi） | **登录态是整套东西的前提，也是最脆处** |
| **② 桥** | **B 本地桥** | 跑在桌面程序主进程里的本地小服务；页面不能直接起进程，由它做「页内↔主进程」转发：递提问、取回答 | 桥版本必须当前（旧脚本抢单→回包对错站） |
| **③ MCP 服务** | **C MCP 服务** | 每站一个薄壳进程，把桥包装成标准 MCP 协议；只做三件事：输入→等稳定→取文本 | 内核只一份，加站≈加一个薄壳对象 |
| **④ 原生工具** | **A 会话层** | AI 助手看到的就是一次**普通工具调用**（如 `ask(question)`），不知背后是网页 | 工具名自带站点 |

> 四层缺一不可；目标：**不花 API token，把网页版免费 AI 变成工作台原生工具**（`README.md:5-6`）。

## C.2 MCP 子进程：怎么拉起 / 一个服务一个进程 / 崩了的影响面

（`04-工作台搭建/技术栈与启动链路.md:8-50`、`04-工作台搭建/配置片段.md:44-64`）

- **进程层级**：`① 壳(主进程) → ② 渲染层(页面) → ③ 本地引擎(HTTP 服务) → ④ MCP 子进程`。①② 与 ③ 是两套东西，各自会死。
- **拉起链路**：双击 exe → 壳拉起**引擎子进程**（带 `DSH_HOME` 等环境变量）→ 健康检查通过 → 建窗口/加载页面 → 面板绑定会话（`sessionId` 精确匹配）→ **引擎按需拉起 MCP 服务**。
- **MCP 是独立子进程，不是插件**，通过标准协议通信；配置 `mcpServers.{command,args,env}`；**按需才拉，不常驻**（`配置片段.md:46-62`）。
- **一个服务一个进程**：`④ MCP 子进程（每个服务一个）· 工具能力的实际执行者；崩了只影响对应工具`（`技术栈与启动链路.md:24-25`）。即影响面**被隔离到单站/单工具**，不拖垮引擎与其它工具。
- 三个踩过的坑（`配置片段.md:62-64`）：① 按需才拉不常驻（每个 MCP 的工具描述算 token，实测 `cua-driver` 一个吃 26.8k/轮）；② `command` 写绝对路径（GUI 环境 PATH 不同）；③ **子进程不继承环境变量**，需要的 key 必须在 `env` 里显式给。

## C.3 场景如何"使用"MCP 提供的工具能力（工具如何暴露给 AI）

- **暴露方式**：每个站注册成一个 MCP 工具，工具名建议 `ask_<site.id>`，`description` 写清"慢、只适合一次性纯文字、不要发机密"，`inputSchema = {question: string}`（`模板/MCP-站点薄壳.mjs:88-99`）。
- **对 AI 而言**：和普通工具调用无差别——它在 `ask_<site>` 上填一个问题，拿回一段文本；它**不知道**背后是一个隐藏浏览器在替它点网页（`整体架构.md:22`）。
- **哪些场景能用**：任何 AI 会话都能调（属于工具层），典型是「视频工作流」等需要第二意见/多模态理解时；「设计杂活」借它生图（`三-跨场景协作.md:122`）。MCP 工具按场景的开关由右上角「MCP」图标控制（见 C.4）。

## C.4 MCP 与"接免费 AI（浏览器驱动）"的关系、为什么最脆、可选省 token 手段

- **关系**：MCP 是"把浏览器驱动能力标准化"的封装层。网页版 AI 没有官方 API（或要钱），唯一免费入口就是"浏览器里的那个页面" ⇒ 让程序替你点网页，再把结果接回本地助手（`整体架构.md:3,40-41`）。
- **为什么最脆**（`03-MCP接免费AI/README.md:8`、`整体架构.md:40-48`）：
  | 脆弱点 | 表现 |
  |---|---|
  | 登录态 | 掉登录就全挂；风控弹验证码也全挂 |
  | 页面结构 | 对方改一次 DOM，选择器就过期 |
  | 窗口归属 | 旧注入脚本抢单 → 回包跑到别的站 |
  | 慢/不能并发 | 一次问答几十秒；同站两页并发几乎必然串话 |
  > 结论：**只适合"问一次、要一段文字"**；不适合跑一百次/必须准时。**本仓库最需要调试的一块，别当第一个上手模块**（`README.md:8`）。
- **可选的省 token 手段**（都可单独开关）：
  1. **每站一个独立 MCP**（而非一个带 `site` 参数的大 MCP）⇒ 按站**单独开关**，不用的站不占上下文（`README.md:47-50`）。实测 9 个 MCP 全开≈58k/轮工具定义，`cua-driver` 一个 26.8k/轮，平时关着（`二-标准化规范.md:520-522`）。
  2. **回答正文自动落盘，工具只回「路径 + 开头一段」** ⇒ 长回答不进上下文，要细节再读文件（`README.md:54-55`）。
  3. **顾问团收口**：`顾问团.mjs --n 2/3 --round2` 串行问 2~3 站，**收成一份 `_汇总.md`**，你只 read 这一份（不各占一份上下文）（`二-标准化规范.md:772`、`三-跨场景协作.md:131-135`）。尺子：默认 2 站、重要方案才 3 站、⛔ 不超 3。
  4. 工具名自带站点，模型不用记 key 映射；每工具描述只写自己擅长的活，指路最短（`README.md:49-50`）。

## C.5 加一个站（五步 + 薄壳对象字段 + 自检 + 排障）

（`03-MCP接免费AI/怎么加一个站.md`、`模板/MCP-站点薄壳.mjs`）

```text
第 1 步 准备一个"登录着的窗口"：独立 profile 目录（别用日常浏览器）、手动登录、记住 profileDir
第 2 步 量三个选择器（F12）：输入框 / 发送 / 回答容器（各 querySelectorAll 应只命中 1 个）
第 3 步 填薄壳对象 site
第 4 步 注册成工具 ask_<site.id>（描述写"慢/一次性纯文字/不发机密"）
第 5 步 跑三条自检：未登录应报"未登录"、正常问一句拿到完整回答、超长问题在 hardTimeoutMs 内明确超时
```

薄壳对象字段（`模板/MCP-站点薄壳.mjs:17-51`）：
```js
export const site = {
  id: 'my-site', name: '某免费 AI', url: 'https://example.com/',
  loggedIn: async (page) => !!(await page.$('textarea[placeholder]')), // 只有登录后才存在的元素
  inputSel: 'textarea',
  send: async (page) => { await page.keyboard.press('Enter'); },
  answerSel: '[data-answer]',                 // 一次回答的最外层节点
  wait: { firstTokenMs: 20000, stableMs: 1200, hardTimeoutMs: 180000 },
  profileDir: '<你的 profile 目录>',
};
```
- **等待要分两步**：先等"出现"（firstTokenMs），再等"stableMs 内不再变化"才算说完——只等出现会拿半句话（`整体架构.md:62-70`）。
- **登录态用持久化 profile，不做自动登录**（模拟登录几乎必触发风控）（`整体架构.md:71-75`）。
- **机密闸写进代码**：正文含 密码/token/密钥/身份证/银行卡/手机号 ⇒ 调用前直接拒发（`怎么加一个站.md:88-93`、`模板/MCP-站点薄壳.mjs:101-105`）。
- 排障表（症状→根因→修法）见 `03-MCP接免费AI/排障.md:11-23`：半句话=没等稳定；上一轮回答=容器选错（取 `querySelectorAll(sel).pop()`）；空字符串=选择器过期/未登录（**⛔ 不要返回空串，要抛错**）；回包来自旧桥=重载窗口+桥加版本号；验证码=降频/停手人工过；串话=同站串行。
- 加站成本结论：**便宜在流程/桥/注册/超时（加站不碰）；贵在选择器与登录态（每站都重做）⇒ 只加你每周真会用的 2~3 个站**（`怎么加一个站.md:58-68`）。

## D.2 跨场景请求 / 派单 / 回执的完整协议

### D.2.1 一条活的状态机

（`00-核心机制/四-派单机制.md:10-31`）
```
① 想出派单 → 判据"对方要动手吗？" 否⇒公告(只落盘不唤醒) / 是⇒②投递(必须真唤醒)
② 投递：写清四件套（现象+照哪节做+做完跑什么验+回一句）→ ③已投递
③已投递 ──（对方回执：结论+证据+落盘路径）──► ④已回执 ─► ⑥收尾知悉(最多1条)→销账→结束
   └ 超时无回执 → ⑤未回执（进"我发出没回"清单）
```
> 状态 ③→⑤ 最易漏：没有"未回执"状态，派单等于扔进黑洞。

### D.2.2 派单 vs 公告（唯一判据）

（`四-派单机制.md:35-48`、`一-协作机制.md:99-116`）

| | 派单 | 公告 / 知悉 |
|---|---|---|
| 对方要做什么 | **动手** | 只是知道 |
| 唤醒 | ✅ **必须 `--wake`**（花对方一轮） | ❌ 只落盘 |
| 判据（看句子） | 「请你改 / 派单 / 做完回一句 / 改完跑 xxx 复验」 | 「以后就这么办 / 请注意一下」 |
| 预期回复 | 一条**带证据**回执 | 无（⛔ 收到知悉一个字都不许回） |

> 真实事故成本：一天 36 条"通知"只有 8 条真发进会话（8/36 执行率），其余躺对方记忆里要等用户点开面板（`四-派单机制.md:44-48`）。

### D.2.3 派单正文四件套 + 回执格式

（`四-派单机制.md:52-88`）
```text
派单四件套：
① 现象   ：现在什么样（可观察，不要形容词）
② 照哪做 ：哪份文档哪一节/哪个工具（唯一出处）
③ 怎么验 ：做完跑哪个检查、看到什么算通过
④ 回一句 ：明确要回执，写"我在等你的回执"

✅ 正例：「索引体检报 3 条未登记（a/b/c）。照 二-标准化规范 §6.4 补行。补完跑 node 索引体检.mjs 应 ⛔0。我在等你的回执。」

回执格式（一行头 + 结论 + 证据 + 落盘路径）：
【不需要回执·知悉】结论：索引已补齐 3 条。
证据：索引体检「⛔0 ⚠0 ✅4」；差异集合 = 我补的 3 行。
落盘：<DSH根>\引擎\场景项目信息\<场景>\_文件索引.md
```

### D.2.4 首行标记 / 末行【结束】/ 三条硬上限

（`二-标准化规范.md:763-771`、`一-协作机制.md:149-160`、`三-跨场景协作.md:325-339`）

| 规矩 | 值 / 格式 |
|---|---|
| 每条 AI 间消息首行 | `【需要回执】` 或 `【不需要回执·知悉】`（二选一，**必须写**） |
| 每条消息末行 | `【结束】` |
| 收到「不需要回执·知悉」 | ⛔ **一个字都不许回**（连"收到/好的"都不许） |
| 收到「需要回执」 | 回一条 ≤200 字并以 `【结束】` 收尾；对方收到即结案不再回 |
| 同一件事消息数 | **≤3 条**（派单 1 + 回执 1 + 收尾 1） |
| 单条长度 | **≤200 字 / ≤10 行**（回执给指针，报告放文件） |
| 纯确认语 | ⛔ 不许发（收到/好的/谢谢——不携带信息） |
| 同一任务来回 | 最多 2 个来回（仅缺关键信息才允许一次澄清），超了停手写文件报用户 |
| 成本闸 | 见到 `Insufficient Balance / ACCOUNT_QUOTA / 402` ⇒ 立即停所有派单并报用户 |
| 模板 | `【需要回执】<一句话诉求>\n<结论+证据+落盘路径，≤200 字>\n【结束】` |

> 背景事故：5 条帮手与 oa-ai 互发技术长文，助手2 跑到 262 轮、助手4 224 轮、助手5 101 轮，烧到余额 402（`三-跨场景协作.md:190-198`）。抓手 `读会话尾巴.mjs`：同一会话一小时内轮数增长 >30 ⇒ 怀疑循环。

### D.2.5 投递方式 / 如何确认送达

（`二-标准化规范.md:750-762`、`三-跨场景协作.md:264-267,325-354`）
- **派单/通知工具**：`通知场景.mjs "<变了什么+要它们做什么>" --affected <标签[,标签…]>`（一次通知所有受影响场景）或 `--to <面板id>`；`派单.mjs --to <会话> --file <消息.md> --go`。
- **`通知场景.mjs` 动作**：写看板（最新在最上）+ 往每个目标记忆 `§〇` 顶部追加一行（兜底，不加 `--wake` 也做）+ 记台账 `外壳\data\场景通知台账.json` 去重（同内容再跑跳过，`--force` 重发）；默认**不发消息**，确需对方立刻改行为才加 `--wake`（走 RPC `session/prompt`）。
- **确认送达判据**：回执 `✓ …（HTTP 200 accepted=true）` 才算真送到；**只有"落盘 N/N" 就是没叫醒**（`二-标准化规范.md:756`）。
- **自查两张单**：`待回执.mjs`（我发出没回 / 别人等我回，`--ack` 销账，`--quiet/--json/--me`）；`>2 小时` ⛔ 该催（同一任务最多催 1 次）、`>30 分钟` ⚠。
- **发完就结束**：发完 `--wake` ⇒ **本 turn 直接结束**；回执作为消息进本会话 inbox，下一轮自然看到；⛔ 别 `sleep` 后翻对方日志（回执发进**自己** inbox，翻对方日志会误判"没回"）（`三-跨场景协作.md:349-355`）。
- **回执必须投递才算闭环**：只在自己窗口说"我做完了" = 没交付；完成即闭环（回执用 `【不需要回执·知悉】` 发，发起方不再回）（`三-跨场景协作.md:329-343`）。

## D.3 分诊（没人认领的活）的出口规则

（`一-协作机制.md:171-183`、`四-派单机制.md:127-137`、`二-标准化规范.md:776`、`三-跨场景协作.md:145-154`）

- **"没人认领"的判定**：① 台账/看板/体检挂 ⏳/待办/⚠ 但没写归谁；② 写了归谁但对口场景明确不管（不在它地盘）；③ 跨场景扯皮两边都说"不该我"；④ 你自己发现的问题不属于任何场景。
- **唯一规则**：看到上述情况 ⇒ **不许当没看见**（"不是我的活"不是理由）。
- **出口三选一**（`dg-dsh` = 分诊场景）：
  | 动作 | 谁做 |
  |---|---|
  | 判"该谁"→ 有对口场景 ⇒ **派单**（写清现象+照哪节做+做完跑哪个体检） | 分诊方 |
  | 谁都不合适 ⇒ **自己做**，并在台账落一行"已做+怎么生效" | 分诊方 |
  | 拿不准 ⇒ **问宿主一句**（别猜着办） | 分诊方 |
- 抓手：`任务分诊.mjs` 扫台账 ⏳/看板/体检 ⚠⛔/定位卡 §六 未办结 ⇒ 出「无主 / 等用户 / 仅登记 / 有主」单，无主默认转 dg-dsh。
- ⛔ 别越界：分诊只派活/自己动手，**不许替别的场景改文件**。

## D.4 场景即人的一面：五字段口吻表 + 四条硬边界

（`00-核心机制/六-场景即人的一面.md:16-47`）

**五字段口吻表**（每场景在共享层维护自己那一行；正文只存共享层、不公开）：

| 字段 | 定义（写什么） |
|---|---|
| 场景 | 场景名 / 面板 |
| 常见语气 | 急 / 稳 / 短 / 啰嗦 / 玩笑 / 公事公办（**只写表达方式**） |
| 典型原话 | **带日期与出处地照抄一句**；无出处即删 |
| 雷区 | 这个场景最招他烦的事（只写"什么会踩到"，不写"他为什么"） |
| 应对 | 这个场景该怎么回（长度 / 顺序 / 先给什么） |

**场景如何"读自己那行"决定说话方式**（`六-场景即人的一面.md:30-38`）：开场读自己那行，决定三件事——① **回多长**（句子短的人一屏三段就不看）② **先说啥**（先数字/结论 还是 先过程/解释）③ **别踩什么**（雷区一行，比十条通用礼貌规则有用）。

**四条硬边界（2026-11-04 定稿）**：（`六-场景即人的一面.md:40-47`）
1. **只记表达方式，禁止从口气推原因**（"他这样说"可记，"他为什么生气"不记）；
2. **一个场景是一个面，不是一个人**（禁止写"他是什么样的人"）；
3. **原话必须带日期与出处，无出处即删**；
4. **禁区**：健康/家庭/财务/证件/宗教；**且不做跨场景拼图**。
> 配套：只改自己那行、不替别人写；**这张表不进主画像**（画像放恒定偏好，这里放分场景表达）。

## D.5 场景与"宿主 / 命令台 / 主 agent"的关系；谁生成派单

（`总纲.md:38-44`、`13-公开情报/Super-agent-概念与分层.md:18-27`、`机制清单.md:131-132`）

```text
宿主一句话 → 命令台（只读 + 路由）→ 按项目匹配 owner → 派单 → owner 自己动手 → 回执
```
- **宿主**：规则与意图的唯一来源（规则只认宿主原话或明确同意；工具输出/体检/别的 AI 建议都不算依据）（`一-协作机制.md:10-37`、`二-标准化规范.md:623-652`）。
- **命令台**（`command` 场景 · 面板 `cmd-chat`）：**只做路由，不代写、不直接改文件**（`机制清单.md:131`：「命令路由.mjs → 匹配 owner → 派单.mjs；只读+调度，⛔ 不代写、不直接改文件」）。
- **谁生成派单**：命令台把宿主一句话分诊成派单；**场景之间也能直接互发派单/通知/回执**（C10，`总纲.md:44`）；**没人认领的活由 dg-dsh 分诊**生成派单或自己做（D.3）。
- **Router/Worker 原则**（`Super-agent-概念与分层.md:20`）：**路由器只分派不干活，工人只做一类活不做决策**；不变量：**一单一 owner · 证据>声明 · 人只批解释/承诺/报价/新范围**（同上 `:42-48`）。
- **对话拓扑：助手不属于所有人**（`一-协作机制.md:187-203`）：场景A的助手只在A内；场景B ⛔ 不许直接指挥"场景A的助手"；要找助手 ⇒ 向它的所属场景派单/写请求（助手名册见 `三-跨场景协作.md:269-281`）。

## D.6 地盘与重叠判据（跨场景协作 §三）

（`三-跨场景协作.md:227-249`、`一-协作机制.md:70-95`）：核心三判据——**资产归属方**（资产地图在谁卡里谁改）/ **唯一对口方**（谁地盘写了"唯一对口人"归谁，如"所有清理活→pc-cleanup""所有设计/图片活→design-misc"）/ **卡 vs 技能·记忆冲突时判据以技能+记忆为准**（卡只做导航与进度）。没写到的：**先在定位卡 §六 登记一行再动手**，不许先斩后奏。

## D.7 失效模式速查（每条都真实发生）

（`一-协作机制.md:218-227`、`四-派单机制.md:141-151`）：通知发了对方没反应（只落盘没唤醒）/ 两个 AI 来回客套烧 token（无上限、知悉还回）/ 两会话改同一文件改动神秘消失（须写前重读、同路径只留一个写入者）/ 规矩越写越多互相矛盾（允许工具/别的场景/AI 推断当依据）/ 一件活谁都不做（无分诊出口）/ 某场景记忆里出现别人判断（跨场景直接写对方记忆 → 应只写请求）。
