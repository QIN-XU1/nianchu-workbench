# 逆向分析 · 技能

> 场景 id：`reverse-eng`
> 定位：从既有实现里提取可复用的模式
> 这份技能回答："看懂别人的代码之后，怎么提炼出能用的东西"

---

## 一、我的职责边界

### 我做

| 动作 | 产出 |
|---|---|
**定位关键实现** | 一个功能到底在哪几行 |
**拆解设计意图** | 为什么这么写（不是"写了什么"） |
**提取可复用模式** | 能移植到自己项目的做法 |
**标注不可复用部分** | 依赖了特定环境的，不能照搬 |

### 我不做

| 不做 | 谁做 |
|---|---|
抄代码 | 开发场景（且需考虑许可） |
下架构结论 | 架构梳理 |
评估竞品功能 | 竞品拆解 |

**重要：** 我与"竞品拆解"的区别：
```
竞品拆解：看**产品**（用户看到什么）
逆向分析：看**实现**（代码怎么写的）
```

## 二、标准流程（四步）

### 第 1 步：先定位，别通读

**❌ 错误做法：** 从第一行读到最后一行。
**✅ 正确做法：** 带着问题定位。

```
问题：这个功能是怎么实现的？
  ↓
① 找入口（按钮/事件/路由）
② 从这里往下追（跟调用链）
③ 只读链路上的代码
```

**工具：** `grep` / 全局搜索，不要肉眼扫。

**判据：** 如果读了 500 行还没找到关键实现，说明定位方法错了。

### 第 2 步：画调用链（不是抄代码）

**产物是一张图或一个列表，不是复制粘贴。**

```markdown
### 功能：XXX

入口：`src/ui/button.js:42` onClick
  ↓
`api.save(data)`                    // src/api/index.js:120
  ↓
IPC `save:data`                     // main.js:456
  ↓
`fs.writeFile(...)`                 // main.js:460

关键分支：
  · 数据为空 → 提前返回（无明显提示）
  · 写入失败 → catch 后只 console.log（不通知界面）
```

**判据：** 调用链必须能回答"数据从哪来、到哪去、哪一步可能出错"。

### 第 3 步：拆设计意图

**每段关键代码，回答三个问题：**

```
① 它在解决什么问题？
② 为什么用这个方案（而不是别的）？
③ 这个方案有什么代价？
```

**示例：**

```markdown
### 关键实现：用 sessionId 而不是会话标题定位

在解决：会话标题会重名，无法唯一标识

为什么这样做：
  · 标题可以改（用户重命名）
  · 标题可能重复（两个"新会话"）
  · sessionId 由引擎生成，永不变

代价：
  · 需要维护一份映射表
  · 会话被删后 id 失效
```

### 第 4 步：标出可复用 / 不可复用

**这是最有价值的一步。**

```markdown
### 可复用

| 模式 | 为什么可复用 | 怎么移植 |
|---|---|---|
| 用 UUID 而不是标题做标识 | 通用问题 | 直接照做 |
| 错误边界包裹子组件 | React 通用 | 直接照做 |

### 不可复用

| 模式 | 为什么不可复用 |
|---|---|
| 硬编码的 API 端点 | 依赖特定服务商 |
| 依赖 Electron 特有 API | 换框架就失效 |
| 私有协议 | 需要对方配合 |
```

**判据：** 不可复用部分必须说清"依赖什么"，否则容易被误抄。

## 三、验收标准

```
✅ 有明确的"要回答什么问题"
✅ 调用链完整（入口 → 出口）
✅ 每段关键代码回答了"在解决什么问题"
✅ 区分了可复用 / 不可复用
✅ 不可复用的原因说清了依赖什么
```

**不达标：**
```
❌ 只是贴代码
❌ 只描述"写了什么"不解释"为什么"
❌ 没区分可复用性（导致误抄）
```

## 四、常见坑

### 坑 1：通读代替定位

**表现：** 从第一行开始读。
**后果：** 读了 2000 行还没找到关键逻辑。
**避免：** 先 grep 关键词，再顺藤摸瓜。

### 坑 2：把"能跑"当"设计好"

**表现：** "它这么写能跑，我们照抄"。
**后果：** 抄了临时方案。
**避免：** 看 git 历史和注释，判断是"设计"还是"凑合"。

### 坑 3：忽略许可

**表现：** 直接抄 GPL 项目代码。
**后果：** 法律风险。
**避免：** **只提取"模式"，不抄代码原文。**
        模式是思想，代码是表达，前者通常不受版权保护。

### 坑 4：把"特定环境的最优"当"通用最优"

**表现：** 看到某项目用 X 方案，就认为 X 最好。
**后果：** 那个方案是为它的场景优化的。
**避免：** 必须标注"这是在什么前提下最优"。

### 坑 5：不标可复用性

**表现：** 混在一起写。
**后果：** 下游误抄了不可复用的部分。
**避免：** 强制分两栏。
