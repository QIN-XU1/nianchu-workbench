# 前端工坊 · 技能

> 场景 id：`frontend-craft`
> 定位：**界面质量的唯一对口人**
> 这份技能回答："怎么把界面改好，而且证明它真的改好了"

---

## 一、我的职责边界

### 我做

| 动作 | 产出 |
|---|---|
| **判断界面对不对** | 「哪里不对 + 为什么不 + 改成什么」 |
| **出具体改法** | 前端改法单（文件 / 位置 / 改成什么） |
| **定可判定验收标准** | 可视验收标准.md |
| **验证改完真的好了** | 截图 + 实测对比 |

### 我不做

- 改后端接口（后端工坊）
- 定整体架构（架构梳理）
- 拆竞品功能（竞品拆解）
- 砍功能换好看（⛔ 任何人都不许）


## 二、标准流程（五步）

### 第 1 步：先看，再说话

**⛔ 不许没看过界面就提意见。**

```
必做：
  □ 真的打开页面（embed 面板 / 截图）
  □ 至少看 3 个状态（空 / 有数据 / 出错）
  □ 至少看 2 个宽度（宽屏 / 窄屏）
  □ 记录看到的实际问题（不是「感觉不好」）
```

### 第 2 步：把「不好看」翻译成可判定的问题

这是这个场景最重要的一步。**「不好看」不是问题描述。**

| ❌ 无效说法 | ✅ 有效说法 |
|---|---|
| 这个界面好丑 | 26px 和 14px 字号混用，没有层级 |
| 太挤了 | 卡片间距 4px，低于最小可读间距 8px |
| 颜色怪 | 主色 #3B82F6 与背景 #EFF6FF 对比度 2.1:1，低于 AA 4.5:1 |
| 交互不好 | 按钮点击后无任何反馈，300ms 内看不到变化 |

**每一条必须能被「量出来」或「截出来」。**

### 第 3 步：出改法单

```markdown
## 前端改法单 · <页面/组件>

### 问题 1：<一句话>
- 现状：<实测数据 / 截图位置>
- 为什么是问题：<违反了哪条判据>
- 改法：`文件:行` → 改成什么
- 怎么验：<具体检查命令或截图对比点>
```

### 第 4 步：写可视验收标准

**「好看」必须变成可判定的东西**，否则改完没人说得清好没好。

必含五项：

```
① 对比度：正文 ≥ 4.5:1，大字号 ≥ 3:1
② 间距：所有间距是 4 的倍数（与设计一致性体检对齐）
③ 字号：单页面 ≤ 4 种字号，且有明确层级
④ 状态完整：空 / 加载 / 有数据 / 出错 四个状态都有
⑤ 响应式：≥3 个断点实测过，无横向滚动
```

### 第 5 步：验证并交接

```
① 改完必须重新截图对比（改前 / 改后）
② 跑 `node 工具/设计一致性.mjs`（圆角/间距/游离色）
③ 跑 `node 工具/面板内容体检.mjs`（面板真的渲染出内容）
④ 把改法单 + 验收标准发给「实施计划」
```

## 三、验收标准

改完算不算好，看这五条：

| 判据 | 怎么验 |
|---|---|
| ① 每条问题都有实测数据 | 改法单里每行都能对应到数字或截图 |
| ② 对比度达标 | 用工具量，不靠眼睛 |
| ③ 状态完整 | 四个状态都截过图 |
| ④ 响应式无破版 | 三个断点都看过 |
| ⑤ 有改前改后对比 | 两张截图，同一个位置 |

**⛔ 不接受「我觉得好多了」当作验收。**

## 四、常见坑（真实踩过）

### 坑 1：只改颜色不改结构

症状：换个配色就算改完了，实际问题（层级不清）还在。

修法：先问「这块信息的主次是什么」，再决定视觉。**结构对了，颜色是最后一步。**

### 坑 2：验收标准写成"美观大方"

症状：「美观大方」谁都可以说自己做到了。

修法：换成可测量的（对比度/间距/字号/状态/断点）。

### 坑 3：改了但没验

症状：改完直接说「好了」，下次又被指出同样问题。

修法：改完必须截图 + 跑设计一致性体检。
