## 五、坑与决策（只追加）

- 2026-11-14 **白底白字：加亮方向错了**：makeCard 里 ink 无条件加亮 0.78，浅色 seed 亮度约 0.96 被 clamp 到纯白。根因是「往亮走」只在深色底成立，浅色必须往暗走，且步长要乘 1.35 否则落在低对比黄区（实测 ink-3 只有 2.76:1）。

- 2026-11-14 **CSS 优先级：后加载不等于会赢**：`:root[data-theme="light"]` 权重 (0,1,1) 高于 `:root` (0,1,0)，所以后加载的 tokens-hermes 压不过前面的 tokens。教训：权重高一级就永远赢，用 DevTools 的 CSS.getMatchedStylesForNode 才能看出真正命中的规则。

- 2026-11-14 **color-mix 的 alpha 陷阱**：color-mix(in srgb, #17171a 74%, transparent) 的 alpha 不是 74% 而是 36%。根因是 transparent 是「透明黑」会与前景色分别插值并被拉向黑色。教训：文字色应直接用 rgba 写 alpha。

- 2026-11-14 **内联样式压过一切**：frame.js 用 style.cssText 内联了 color:var(--t4)，导致改 CSS 全部无效。教训：颜色与字号这类主题相关的值不该内联。更深一层，--t1..t4 在 compat.css 和 guoxue-tokens.css 各定义一份，后者覆盖前者。

- 2026-11-14 **判据要能从用户原话翻译过来**：用户说「界面一言难尽」不是可执行反馈，前端工坊的价值是把它翻译成「哪个元素、哪个值、应该是多少、改前改后截图」。根因：所以 check 里禁用「好丑」这类词、要求必须带可测值。

- 2026-11-14 **面板读不到目录会显示失败文案**：review-doc 与 review-files 面板依赖 docDir 配置，缺这个字段会显示「列目录失败」。教训：新场景的 panels 必须写 docDir，否则面板是空的但不会报配置错误。

- 2026-11-14 **面板渲染不出来会拖慢所有验证**：一个面板等满 15 秒超时，4 个面板就是 60 秒；3 个场景就是 180 秒。根因：检查工具的等待预算过大，掩盖了「面板根本没内容」这个真问题。

- 2026-11-14 **浅色主题的截图取证方式**：Page.captureScreenshot 返回的 PNG 大小可作白屏检测：面板丰富时小于 100KB 基本可疑。教训：截图不只看内容，也看体积。

- 2026-11-14 **传统色板与 hermes 色板并存会打架**：国学色板（gu-su 系列）与 hermes token 同时存在时，后加载的覆盖前面的，导致「改了没效果」。根因：同一个语义在多个文件里各定义一份，必须收敛到一处。

- 2026-11-14 **字号阶梯要来自实测而不是感觉**：正文 11px 是扫了 2111 个 tsx 文件统计出来的（text-xs 出现 425 次），不是凭审美定的。教训：设计规范要能从代码统计里推出，不能凭印象。
