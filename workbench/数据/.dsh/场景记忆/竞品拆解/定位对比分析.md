# 定位对比分析

> 拆解对象：本项目与主流 AI Agent 产品的核心差异——**找准自己的定位**，而不是继续拆自己的功能。
> 素材：全项目 scenarios / 工具 / 数据（机制清单 46 项、派单台账 32 单、进化台账、封存集、sceneboard、9 场景记忆）。
> 生成：2026-11-12

---

## 〇、一句话定位（先给结论）

**主流 Agent 在做"让单个大脑更聪明 / 让多 agent 编排更省事"，本项目做的是另一件事——给一群有地盘、有记忆、会越界的"场景"装一套可执行、可自测、可回滚的治理机制（哨兵 + 台账 + 盲测封存集），把"AI 可不可信"从一句 prompt 变成一个能跑、能证、能退的工程问题。**

---

## 一、本项目独有的设计（逐个定性）

### 1. 多场景 = 9 个有"地盘"的持久化 agent

- **本项目**：9 个场景（调研/竞品拆解/逆向分析/架构梳理/实施计划/故障分析/自我复盘/本地电脑/中枢），每个有自己的 `场景私有记忆.md`、身份卡、画像、边界。铁律"只写自己的地盘，别人的只许写请求"。
- **主流**：CrewAI/AutoGen/LangGraph 的多 agent 是**一次任务内临时编排**的多个 worker，任务结束即散；Claude Code 的 subagent 也是临时 spawn。
- **定性**：**部分创新**。多 agent 编排不新，但"场景 = 持久化的文件地盘 + 跨会话长存 + 文件级隔离边界"这个把 agent 和目录绑死的做法，主流产品没有。它的价值是给 agent 一个"归属"和"不许越界"的物理约束，而不是靠 prompt 求它"别乱改"。

### 2. 管线 = scene→scene 产物 DAG

- **本项目**：`sceneboard/pipelines/*.json` 声明 9 条产物边（research→competitor-analyze 交 competitor-list 等）。
- **主流**：LangGraph 的 graph + edges、Flowise/Dify 可视化工作流、CrewAI 的 sequential process，都是 DAG 编排。
- **定性**：**换个说法**。DAG 编排是行业标配。且上一轮我已实测：本项目的管线是"静态声明 + 写入记忆文档"，**没有任何运行时真执行**（竞品拆解/逆向分析 32 单里 0 派单）。它是"意图的图纸"，不是"跑起来的引擎"。

### 3. 进化 = 三级（L1记忆/L2技能/L3身份）+ 回滚 + 冻结 + 安全阀

- **本项目**：`进化.mjs` 分 L1(自动只追加)/L2(回测通过才写)/L3(人工确认)，每条带 version+changelog，观察期跌 >15% 判退化、连续 2 次退化自动冻结该场景。
- **主流**：Voyager（技能库自我扩充）、Reflexion（口头强化）、MemGPT/Letta（自我编辑记忆）、Claude Code 自动更新 CLAUDE.md。都算"自改进"，但多停在"记忆/技能"单层，且用 LLM 自我判断成败。
- **定性**：**部分创新**。三级分层 + 版本化 + 回滚 + 冻结这套"带刹车的加速"，比主流"无限自我更新"更收敛。但诚实说：进化台账目前只有 1 条 L1，且 trigger 是度量 bug 逼出来的（自我复盘场景已记），所以"设计独特、落地未验证"。

### 4. 封存集 = Agent 不可见的盲测集 + 判分 + sealed-delta

- **本项目**：`封存集.mjs` 从真实记忆生成"Agent 看不到的评估用例"，`封存集判分.mjs` 考场景算分，`进化.mjs --observe` 用 **sealed-delta（封存集得分变化）** 判进化是 improved/stable/degraded，拒绝"人指定结果"。
- **主流**：held-out test set 是 ML 标配；LLM 评测有 SWE-bench/MMLU。但**没有一个主流 agent 产品用"自己生成的、自己看不到的盲测集"来回测自己的进化是否退化**。
- **定性**：**最接近真创新**。把"自证"从"LLM 自说自话"变成"机器可读的盲测得分变化"，直接呼应 AGENTS.md 第 5 条"自证必须是真证、必须带应当失败的反例"。但落地有硬伤：封存集 3 次 run 全 100 分 0 退化（自我复盘已记）——**满分零退化的盲测没有区分度，等于没测**。概念真创新，验证还没到位。

### 5. 哨兵/机制体系 = 46 项机制，每条带"不变量 + 自测 + 已知盲区"

- **本项目**：`机制清单.mjs` 生成 46 项，每项四栏：抓手(.mjs)、不变量(4~26 条)、自测(.selftest)、**已知盲区(46/46 都写了)**。8 个哨兵（记忆/身份/派单/越界/健康/进化/内容/中枢调度卡）+ 记忆召回哨兵，全部带 .selftest。
- **主流**：guardrails（护栏）多在 prompt 层；Claude Code 有 hooks/pre-commit，但那是让用户自定义，不是 agent 自带一套"可执行断言 + 反例自测"。
- **定性**：**较真创新**。把"可靠性"从"prompt 里写一句要小心"变成"跑得起来的断言 + 必须带反例的自测 + 公开承认盲区"。最特别的是"已知盲区"这一栏——主流产品从不会在文档里写"我的检查哪里会漏"。

### 6. 派单台账 = 四件套 + 状态机 + 回执 + 销账/作废 + 闭环

- **本项目**：`派单.mjs` 派单要四件套(subject/phenomenon/howto/verify)，状态机 created→acked→delivered→closed/cancelled，回执带证据、一次一条 ≤200 字，`派单闭环验证.mjs` 用真实台账验 5 状态 7 拒收。
- **主流**：CrewAI/AutoGen 的任务分发是**一次性**的，发完即散；没有"台账、销账、超时、冻结、闭环验证"这套**运营账本**。
- **定性**：**部分创新**。任务分发不新，但"给多 agent 配一套带状态机、有账本、能超时冻结、能闭环验证的工单系统"较独特——更像给 agent 团队上了一套 ERP。

## 二、逐条对比表

| 本项目设计 | 主流做法 | 差异 | 是否真创新 | 价值 |
|---|---|---|---|---|
| 多场景（9 场景 + 文件地盘隔离 + 跨会话长存） | CrewAI/AutoGen 一次任务临时编排多 worker；Claude Code 临时 subagent | 主流 agent 任务结束即散；本项目场景是**持久化、按目录隔离、有归属**的"部门" | 部分创新 | 用文件级隔离做"物理边界"，比 prompt 求它"别越界"更硬 |
| 管线（scene→scene 产物 DAG） | LangGraph/Flowise/Dify 的图编排、CrewAI process | 本项目管线是静态声明、写入记忆文档，**无运行时执行** | 换个说法（且没真跑） | 作为"意图图纸"可读，但当前只有文档价值 |
| 进化（三级 + 回滚 + 冻结 + 安全阀） | Voyager 技能库、Reflexion 口头强化、MemGPT 自编辑记忆 | 主流多是单层、靠 LLM 自判成败；本项目三级分级、版本化、跌 15% 判退化、连续 2 次冻结 | 部分创新（落地未验证） | 给"自我改进"装刹车，防止变蠢停不下来 |
| 封存集（Agent 不可见盲测 + 判分 + sealed-delta） | ML 的 held-out test set；SWE-bench/MMLU 评测 | **无主流 agent 用"自己看不到的盲测集"回测自身进化** | **最接近真创新** | 把"自证"从 LLM 自说自话变成机器可读得分，防自欺 |
| 哨兵/机制（46 项 + 不变量 + 自测 + 已知盲区） | prompt 层 guardrails；Claude Code hooks（用户自定义） | 主流是"一句提醒"；本项目是"可执行断言 + 反例自测 + 公开盲区" | 较真创新 | 可靠性从"求它小心"变成"跑得起来的证" |
| 派单台账（四件套 + 状态机 + 回执 + 销账 + 闭环） | CrewAI/AutoGen 一次性 task 分发 | 主流发完即散；本项目是带账本、超时、冻结、闭环验证的运营系统 | 部分创新 | 让多 agent 协作有账可查、能追责、能销账 |
| 身份卡/越界哨兵（边界 + 只写自己地盘） | 所有 agent 的 system prompt 角色定义 | 主流角色定义是软的；本项目有越界哨兵监控身份卡被改、文件级隔离落地 | 部分创新 | 把"身份边界"变成可监控、可告警的硬约束 |

---

## 三、结论：本项目最独特的一点

**最独特的一点是"封存集"——一套 Agent 自己看不到、从它真实记忆生成的盲测用例，用来考它、给它的进化打分、判它有没有退化。**

一句话说清：

> **"别人在教 Agent 变得更聪明，本项目在给 Agent 出'它自己看不到的考卷'——考不过就回滚、连续退化就冻结，把'AI 会不会变蠢、会不会自欺'变成一个能实测、能退、能停的工程问题。"**

为什么是它而不是别的：多场景、管线、进化、哨兵，主流都能找到"换个说法"的对标；唯独"用 Agent 不可见的盲测集 + 机器可读得分变化来做自进化的回测"这件事，主流 agent 产品里找不到等价物。它精确回答了当前 Agent 最棘手、也最没人认真做的那个问题——**AI 的自我评估会自欺**（"满分零退化"恰恰是自欺的典型症状）。

---

## 四、诚实补注（避免自嗨，这段是拆自己的定位）

判断"真创新"不能只看概念新不新，还要看**有没有真的 work**。上一轮 + 自我复盘场景已记的证据，这里必须摆出来：

1. **封存集概念真创新，但当前零区分度**：3 次 run 全 100 分、0 退化，历史里从没出现过 score<100。一个"满分零退化"的盲测，等于没测——它还没有"应当失败的反例"，所以还抓不住真的退化。
2. **进化台账只有 1 条 L1**，且 trigger 是"健康度把 closed 误算成未回执"这种度量 bug，不是真实任务失败。三级进化的 L2/L3 从没触发过。
3. **管线上一轮已证是"纸上画的"**：9 条产物边 0 条真执行，竞品拆解/逆向分析 32 单里 0 派单。

所以更准确的定位表述是：

> **本项目不是"已经做到可信"的成品，而是一套"把可信做成可验证"的独特方法论 + 脚手架；它的封存集/进化/哨兵是最有辨识度的创新点，但目前大多还停在"设计画出来了、验证没跑起来"的阶段。**

这是它的真实位置：**概念上差异化最清晰、工程上验证最欠账**。
