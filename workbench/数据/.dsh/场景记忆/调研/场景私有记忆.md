- 2026-11-12：**三份机制清单数字对不上要交叉核对** — 症状：机制清单.md 46 项、盲区.json 48 条、机制体检.mjs 注册表 49 项，三处各差 1～3。根因：机制体检.mjs 的 GUARDS 数组才是「唯一清单」，自动生成的机制清单.md 滞后 3 个（界面回归/三方一致/文档命令体检没进去），盲区.json 又漏了文档命令体检这条。修法：凡涉及「机制数/盲区数」，先读机制体检.mjs 的 GUARDS 数组当基准，再对另外两份，不能只信自动生成的机制清单.md。
- 2026-11-12：**检查检查者的工具自己也会走过场** — 症状：机制审计.mjs 专门揪「口号/装饰」，但它默认（不加 --strict）永远 exit 0，连自己刚查出的「口号」都不判失败；自测里还有一句 `|| true` 恒真断言（L254），等于永远通过。根因：退出逻辑写成 `exit(has('--strict') && 口号>0 ? 1 : 0)`，默认不红；那行 `|| true` 是凑数，让断言失效。修法：判断任何工具是否真检查，看三件套——有没有 diffs.push、退出码是否随差异集合变 0/1、自测带不带「必须失败的反例」，别信名字带「审计/体检」就默认它是真的。
- 2026-11-12：**文档工具清单里藏着幽灵命令，顶部改了底部没同步** — 症状：pc-cleanup/SKILL.md 顶部已醒目标注「清理根目录/清理临时目录/梳理清理三个命令不存在」，但文件末尾「工具清单」表仍原样列出这 3 个 + 目录哨兵，4 个工具在工具目录里都不存在，照抄只会报 Cannot find module。根因：更正只改了开头一段，没同步改结尾的汇总表，文档自己跟自己矛盾。修法：核对文档命令真伪时直接 glob 工具目录逐个 Test-Path，别信「工具清单/命令示例」这类汇总表；发现「顶部说没有、底部还列着」就是没改干净的幽灵命令。
- 2026-11-12：**验证要回读代码真身，别假设上轮报过就修了** — 症状：上轮报告列出 pc-cleanup 4 个幽灵命令，这轮逐条 Test-Path 复查，4 个文件仍全部不存在，SKILL.md 的工具清单表原样未动，等于上轮白报。根因：报告只是「记录问题」，没有任何机制驱动修复，文档不会自己变好。修法：写「是否已修」这类验证结论时，必须重新 glob/Test-Path 拿实时证据，不能凭「上轮报过了」就默认已修；验证表和首次调研共用同一套证据手段，不能偷懒。
- 2026-11-12：**判断乱码先换 read 工具复核，别信 Get-Content 默认编码** — 症状：用 pwsh Get-Content 读 场景画像.md/身份卡.md/问答.json 全是乱码（「鎴戠殑」），一度误判成项目编码 bug。根因：这三个文件是「无 BOM 的 UTF-8」，Windows PowerShell 的 Get-Content 默认按系统 ANSI（GBK）解码，把 UTF-8 字节误读成乱码；换成 read 工具（按 UTF-8 读）就正常。修法：判断文件是否真乱码，先用 read 工具或 Get-Content -Encoding UTF8 复核，别拿默认 Get-Content 的结果当证据。
- 2026-11-12：**盘点文档先剔除副本快照与外部克隆，否则被上千冗余淹没** — 症状：全量列 .md 时 research/631 + 备份/670 + 参考项目/93 + 回滚快照/58 共 1452 个副本/外部素材冲进结果，真正的产出（研究素材 21 + 数据.dsh 正文 160 + 方案 122）反被淹没，一眼看去像「产出上千篇」。根因：备份/参考项目是历史副本、research/是克隆的外部仓库，都不是「产出」却和正文同列统计。修法：盘点前先按「产出桶 vs 副本/快照/外部克隆桶」分开计，只对产出桶判断价值，否则总量和占比全失真。
- 2026-11-13：**扫外部依赖必须排除内嵌浏览器用户数据目录** — 症状：递归 grep `外壳` 下所有 js/json 找外部域名，命中的不是代码而是 Chromium profile 的 LevelDB/Cache 文件（bing、msn、广告域上千条），真实调用被淹没且输出被截断成 14KB。根因：`外壳/data` 是内嵌浏览器的用户数据目录，和源码混在同一棵树里，递归时被当成源码扫。修法：只在 `外壳/*.js`、`工具/*.mjs` 这种扁平源码层 grep，递归前先排除 data/Cache/LevelDB/Network Persistent State；另外 `refs` 有凭证 ≠ 有依赖，必须按键名逐个回 grep 代码，零命中的记孤儿凭证。

### 场景 cwd 与命令可执行性（本轮最大发现）

- 场景会话的 cwd = `数据/.dsh/场景记忆/<场景>/`（9 个场景全部如此，已实测）

- `工具/命令可执行体检.mjs` — 从每个场景的 cwd 出发解析技能里引用的每条命令
- `AGENTS.local.md` 的 `## 命令执行目录` 一节 — 必须是所有场景都有（基础设施，非按需）
- 修法两处：`工具/场景注入.mjs`（8 个通用场景）+ `工具/中枢调度卡.mjs`（hub，因为场景注入会跳过它）
- 判据：不只看「文件存在」，要看「从实际运行环境出发能不能跑通」

### 面板验证

- `工具/面板内容体检.mjs` — 29 个面板 / 10 种类型 / 73 项自测
- `外壳/ui/panels/_generic.js` — 58KB 的实现文件，20 个面板共用；改面板判据前必读
- `review-doc` 的标题是 `rvMd()` 渲染的 `div[style*=font:600]`，不是 `<h1>`
- `sf-board` 是 DOM 卡片 `.sf-node`，不是 svg/canvas
- `embed` 是 Electron `<webview>`，不是 iframe
- 判据必须**对得上真实数据**：review-doc 去磁盘读文件确认标题文字出现；embed 查 CDP targets 确认 webview 真起来了
- `工具/界面功能体检.mjs` — 只覆盖 harness 类型（8 个 AI 面板），其余 21 个非 AI 面板归面板内容体检

### 并发互斥

- `工具/_ui-lock.mjs` — `withUiLock(name, fn)`，文件锁 + pid 存活检测
- `DSH_UI_LOCK_HELD=1` — 父进程持锁期间设置的环境变量，`execFileSync`/`spawn` 起的子进程继承后跳过拿锁
- 会切场景的 4 个工具：界面功能体检 / 面板内容体检 / 会话绑定验证 / 整体体检
- 踩坑：只允许「同 pid 重入」不够，因为子进程 PID 必然不同 → 必须用环境变量传递

### 文件引用盘点

- 575 条路径引用里 223 条找不到（39%），但**绝大多数不是问题**
- 分类：占位符 35 条（`工具/xxx.mjs`、`sceneboard/pipelines/*.json`）、只写文件名 130 条、模式描述 26 条、真正的幽灵命令只有 2 条（都是历史计划文档的待办）

### 盘点口径

- 副本来源：`备份/`（670）、`research/`（631，外部克隆）、`参考项目/`（93）、`回滚快照/`（58）
