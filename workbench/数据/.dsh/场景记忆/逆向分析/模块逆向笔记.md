## 一、模块职责

一句话：把「场景之间的关系」画成一个可 360° 旋转、可拖拽、可整理的**三维星盘**。

具体落点（来自文件头部 7 条设计意图，L7-31）：

- 只有**场景节点**，没有技能/记忆节点；附属物（记忆/身份卡/技能/MCP）点击时才展开（L25）
- 场景**平等**，无中心-边缘层级；但按「领域」做**双层结构**（领域层 + 场景层，L19-21）
- 支持拖拽节点、360° 旋转视图、滚轮缩放、「整理」按钮复位（L27-31）
- 边是「场景 ↔ 场景」的真实关联，不编造（L37-41）

## 四、关键算法

1. **球面/体积布局** `layout()`（L656-928）：密度因子 `densityFactor = 1 + log10(n/10)*0.62`（L677）；领域聚类中心 `clusterCenters`（L754）；每节点用 `seededRandom(id)` 生成确定性方向，立方体拒绝采样到单位球（L806-818），再施加**最小间距约束**（`MIN_SEP=0.30`，最多重采样 20 次，L853-890）。
2. **整理复位** `tidy()`（L944-999）：清 `dragged` → 调 `layout()` 取目标 → 420ms `easeOutCubic` 插值动画。
3. **3D 数学**（neuron-math.js）：`rotate3d`（先 yaw 后 pitch）、`inverseRotate3d`（逆序：先 -pitch 后 -yaw）、`project3d`（`fov/(fov+z)` 透视）。
4. **渲染分层** `render()`：边按两端 z 和排序（画家算法，L1177）；焦点优先级 hover > sel > dragSnapshot（L1148-1156）；选中节点相关边**永不裁剪**（L1213-1217）。
5. **星空系统**：`makeStar`（近/远分层，L1869）、`updateStars`（归一化坐标移动 + 生命周期重生 + 闪烁 + 鼠标微亮，L1911-1977）。

## 六、可复用的设计模式

1. **工厂函数 + 闭包私有状态**：`createNeuron3D` 返回 `inst`，`S` 只活在闭包内，外界只通过接口操作。
2. **纯函数拆分**：把 3D 数学抽到零依赖的 `neuron-math.js`，可单测（文件头 L1-8 自述拆分理由）。
3. **分级降级策略**：`getTier` 四档 + `densityFactor`，节点数增长时从「全细节」平滑过渡到「聚类聚合」。
4. **确定性伪随机**：`seededRandom(id)` 用字符串哈希做种子（LCG），保证同一 id 每次布局位置相同。
5. **单一数据源**：`tidy()` 直接复用 `layout()` 计算目标位，避免两套算法导致跳变。
6. **世界坐标/投影分离**：`zoom` 只进投影 fov，不进世界坐标；2D 缩放用独立的 `viewScale`。
7. **生命周期防御**：`destroy()` 清理动画帧、定时器、ResizeObserver，并从 `window.__NEURON3D` / `__WB.neuron3d` 全局数组移除自己。

## 七、它怎么做到的（结论 + 代码证据）

### 结论 1：场景关系不靠猜，靠契约 `outputs.to` 建边 + 分级兜底

边不是随机连的。L1（flow）直接读场景契约的 `outputs[].to`：

```js
// L446-458
for (const sid of Object.keys(contracts)) {
  const c = contracts[sid];
  if (!c || !Array.isArray(c.outputs)) continue;
  for (const out of c.outputs) {
    const targets = Array.isArray(out && out.to) ? out.to : [];
    for (const t of targets) {
      if (byId[t] && t !== sid) {
        edges.push({ a: sid, b: t, kind: 'flow', label: out.name || out.id || '' });
      }
    }
  }
}
```

L2 用「共同邻居」补间接关系（L473-533），L3 同领域（≤8 个才加，L538-565），L4 关键词交集（≤40 节点，L567 起）。每级都有明确依据，且逐级限流（L2 只留最强 30 条 `MAX_INDIRECT=30`，L522-523），防止「全连线」退化成蜘蛛网。

### 结论 2：拖拽 1:1 跟随靠「正确的逆旋转顺序」+ 抓取偏移

旧实现偏差从 2px 累积到 21px（L2349 注释）。根因是逆旋转顺序错。正确逆变换必须**反序**（先撤销 pitch 再撤销 yaw）：

```js
// neuron-math.js L34-46
export function inverseRotate3d(x, y, z, yaw, pitch) {
  const cp = Math.cos(pitch), sp = Math.sin(pitch);
  const y0 = y * cp + z * sp;      // ① 先撤销 pitch
  const z1 = -y * sp + z * cp;
  const cy = Math.cos(yaw), sy = Math.sin(yaw);
  const x0 = x * cy - z1 * sy;     // ② 再撤销 yaw
  const z0 = x * sy + z1 * cy;
  return { x: x0, y: y0, z: z0 };
}
```

配合按下瞬间记录的「抓取偏移」`dragGrab`（鼠标与节点投影中心的差值，L2305-2308），避免节点跳到鼠标中心。

### 结论 3：节点数量变化靠「分档 + 密度自适应 + 最小间距约束」三重兜底

- 密度因子随数量用 **log10** 而非线性放大空间（10→100 是 10 倍，但空间只需 1.55 倍）：

```js
// L677-680
const densityFactor = Math.max(1.0, Math.min(1.85, 1 + Math.log10(Math.max(1, nodeN)/10) * 0.62));
```

- 最小间距约束防止少量节点视觉重叠（事故 AC-014「9 个只画出 7 个」的根因，L841-852）：

```js
// L853, L870-877
const MIN_SEP = 0.30;
// 与已放置节点比较，太近就重采样（最多 20 次）
for (const other of placed) {
  const ddx = ux - other.ux, ddy = uy - other.uy, ddz = uz - other.uz;
  if (Math.sqrt(ddx*ddx + ddy*ddy + ddz*ddz) < MIN_SEP) { tooClose = true; break; }
}
```

### 结论 4：「整理」不跳变靠单一数据源 —— tidy 直接复用 layout

旧 bug：`tidy` 用 `spherePositions`、`layout` 用立方体采样，两套算法 → 整理后与重排结果不一致 → 缩放触发 layout 时坐标跳变 909px（L936-939）。修法是把 `layout()` 作为「目标位置唯一来源」：

```js
// L956-960
for (const n of S.scenes) n.dragged = false;
layout();                    // ③ 与渲染完全一致的目标位置
```

### 结论 5：确定性布局靠字符串哈希种子（同 id 永远同位置）

```js
// L765-775
function seededRandom(seedStr) {
  let h = 0;
  for (let i = 0; i < seedStr.length; i++) { h = (h << 5) - h + seedStr.charCodeAt(i); h |= 0; }
  return function () { h = (h * 1103515245 + 12345) & 0x7fffffff; return h / 0x7fffffff; };
}
```

用 `n.id` 作种子（L792），所以刷新/重排后节点位置稳定，不闪跳。
