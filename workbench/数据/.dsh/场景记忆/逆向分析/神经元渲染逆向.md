# 神经元渲染逆向笔记

> 对象：`workbench/外壳/ui/panels/neuron.js`（2933 行）+ `neuron-math.js`（57 行纯函数）
> 只记「怎么做到的」，每条带行号证据；不抄整段源码，只提取模式与关键公式。

## 一、3D 坐标如何投到 2D 屏幕

手写透视投影，没有矩阵库。核心在 `neuron-math.js` 的 `project3d`（L48-51）：

```
denom = fov / (fov + p.z)      // p.z 是旋转后的深度
sx  = cx + p.x * denom
sy  = cy + p.y * denom
scale = denom                  // 供节点半径等比缩放用
depth = p.z
```

要点（模式）：
- 用「焦距分母」做透视除法，不是齐次矩阵；`fov` 越大越接近正交（变形越小）。
- `fov = (S.radiusX || R) * 2.6 / S.zoom`（render L1080）。`S.zoom` 升高 → fov 变小 → 物体放大，属于透视缩放。
- 投影得到的 `sx/sy` 还要再套一层 2D 仿射：`屏幕 = 投影 × viewScale + pan`（render L1039-1042、hitTest L2121-2122）。所以完整管线是「3D 旋转 → 透视投影 → 2D 仿射」。

## 二、节点布局算法

不是力导向、不是分层，是**确定性伪随机 + 体积采样**的「星云分布」：
- 每个节点用 `seededRandom(id)` 得到固定种子（同 id 永远同位置，layout L765-775）。
- 在单位立方体内随机取点，拒绝采样保证落在单位球内（L806-818）。
- 半径用**幂律**做「中心密、边缘疏」：均匀模式 `rScale = 0.30 + pow(rr2, 0.45)*0.70`（L860），聚类模式 `inBall = 0.28 + pow(rr2,0.5)*0.72`（L834）。
- **领域聚类**：M/L/XL 档按领域聚成星团，团心球面均匀分布（黄金角经度 `2.39996`），团半径 ∝ sqrt(团内节点数)，上限 0.26 防重叠（L706-760）。S 档（≤24）不聚类，改加最小间距约束 `MIN_SEP=0.30`（L853）。
- 档位自适应密度：`densityFactor = clamp(1, 1.85, 1 + log10(n/10)*0.62)`（L677-681），节点越多整体半径越大、单个节点越小（tierCfg 的 `nodeScale` L1094-1097）。

关键模式：**「同一语义单一数据源」**——`tidy()`（整理动画）直接调 `layout()` 取目标位置，不再另写一套球面采样（L933-939）。

## 三、缩放与旋转如何实现

**旋转**（拖背景，pointermove L2399-2444）：
- 增量按 OrbitControls 公式：`yaw += π·dx/H`，`pitch += π·dy/H`，拖过画布高度 = 半圈（L2421-2423）。
- pitch 软钳制在 `[-1.42, 1.42]`，靠近边界渐进减速（L2429-2439）。
- 每帧把 yaw 归一到 `[-TAU, TAU]`（L1056-1057）。
- 旋转本体是 `rotate3d`：先绕 Y（yaw）再绕 X（pitch），手写三角、无矩阵（neuron-math.js L15-23）。

**缩放**（滚轮，wheel L2547-2601）：
- 是**画布级 2D 缩放**，不是改 fov：`newScale = oldScale * exp(deltaY*0.0016)`，`viewScale ∈ [0.25, 5]`（L2576-2577）。
- 锚点补偿让光标下的投影点不动：`pan = mx - (mx - pan0)/vs0 * vs1`（L2589-2590）。
- 注意 `S.zoom`（fov 透视）与 `S.viewScale`（2D 仿射）是**两套缩放**，滚轮现在只动 viewScale；`S.zoom` 仍影响投影与命中半径。

## 四、点击命中测试

`hitTest(mx,my)`（L2097-2133）用的是**逐节点反投影比距离**，不依赖事件目标：
- 对每个节点重新 `rotate3d` + `project3d`，得到屏幕坐标（L2115-2116）。
- 撤销视图变换：`screen = pr.sx*viewScale + pan`（L2121-2122）。
- 命中半径 `rr = max(6, (baseRp*pr.scale + 6)*viewScale)`（L2124）。
- 距离 ≤ rr 且取 `p3.z` 最大者 = 最靠前的节点（L2127-2130）。

**拖拽反解**（pointermove L2358-2389）是把上面的链倒过来：
- 保持旋转空间深度 z 不变，用 `denom` 反解出「要投到目标屏幕位置所需的旋转坐标」，再用 `inverseRotate3d` 逆回世界坐标（L2381-2385）。这是「直接指定目标屏幕坐标」而非「增量换算」，实现 1:1 零累积误差。

## 五、节点亮起为何「断断续续」

亮度分两路：**透明度 alpha** 和**颜色亮度 brightMul**，闪烁主要出在 alpha 上。

透明度计算（render L1392-1426）：
```
zw = 投影深度 / R
depth01 = clamp((zw+1)/2, 0, 1)
zw<0：  alpha = 0.38 + 0.32*depth01   // 背半球 0.38~0.70
zw>=0： alpha = 0.70 + 0.30*depth01   // 前半球 0.70~1.00
searchMiss → alpha*=0.22, 下限 0.10
isDimmed   → alpha*=0.40, 下限 0.26
```

根因：**分段公式在 zw=0 处有一处硬跳变**。同一节点在赤道面附近，`zw` 稍正稍负会让 alpha 在约 0.54 与 0.85 之间来回跳（差值约 0.31）。节点只要随旋转/拖拽跨过赤道面，亮度就瞬间明暗跳变，视觉上就是「断断续续」。

叠加两个加剧因素：
- 点亮/聚焦节点的呼吸脉动用**固定步长时钟**：`S.t += 0.016`（每帧加常数，L1053），`breathe = 0.5+0.5*sin(t*1.4)`（drawStarlight L1773），新节点脉冲 `0.5+0.5*sin(S.t*2.0)`（L1516）。这是「帧计数」而非真实时间，帧率不稳时呼吸忽快忽慢，节律不匀。
- 亮节点经 Bloom「降采样 + lighter 叠加」二次放大（L1813-1862），alpha 的小波动被泛光放大成明暗差。

颜色亮度 `brightMul`（L1444-1449）只做一次性乘算（焦点 1.9、邻居 1.25、搜索不命中 0.22、淡化 0.45），不随时间变，不构成闪烁源。
