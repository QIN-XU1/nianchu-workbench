> 本轮逆向分析沉淀的接口与机制事实。经验里提到过的实体在这里留一条，方便回查。

### 引擎 RPC 端点

- 打包位置：`workbench/引擎/node_modules/@deepseek-ai/dsh-api-remotes/lib/client.js` — 所有端点的 `jsonSchema` 都在这里，调之前先 dump
- 请求格式：`POST /api/{channel}/{endpoint}`，body `{type:'client-request', rpcId, method, payload:{args}}`
- `session/list` — args `{ _request: {} }`
- `session/page` — args `{ request: { address: { kind:'session', sessionId } } }`
- `session/state` — args `{ request: { sessionId } }`（**注意与 session/page 结构不同**）
- `session/projections` — args `{ request: { sessionId } }`
- `session/create` — args `{ request: { cwd } }`
- `skills/list` — args `{ request: { sessionId } }`
- 共 25 个 session 相关端点，完整清单见 `client.js`

### 会话事件类型

- `agent/inbox/spliced` — 投递的消息（含 `target`/`start`/`inserted`）
- `user/message` — 用户消息
- `assistant/attempt` — AI 尝试，`data` 只有 `{ turn, step, stream }`
- `step/start` / `step/end` / `turn/start` / `turn/end` / `compaction/start` / `compaction/end`
- **没有 system/context/prompt 类事件** —— 上下文是引擎调模型时直接拼的，不落事件流
- `turn/end` 的 `data.reason` 才是成败判据（`kind: completed|error|interrupted`），402/400 错误在这里，不在 `system/message`

### Electron / CDP

- 渲染进程 target：`type: 'page'`，URL 含 `ui/index.html`
- `<webview>` 是独立 CDP target（OOPIF），父页面 `querySelectorAll` 到不了里面
- `工具/界面功能体检.mjs` 的 `cdpConnect` — 已正确处理 WebSocket 掩码和 126/127 长度分支，可直接复用
- CDP 端口 9333（`SEA_DEBUG_PORT`），引擎端口 3083

### 重复实现的教训

- `工具/界面功能体检.mjs` — 真实发消息的唯一实现
- `工具/整体体检.mjs` — 改成 `execFileSync` 调上面那个并解析输出，不再自带一份实现
- 死锁解法：`DSH_UI_LOCK_HELD=1` 环境变量，父子进程共享「已持锁」状态
