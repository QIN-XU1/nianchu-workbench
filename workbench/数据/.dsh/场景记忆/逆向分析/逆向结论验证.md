# 逆向结论验证

> 对上轮 `神经元渲染逆向.md` 的结论做实测，用真实数值验证（不是重读一遍代码）。
> 验证方式：node 不在 PATH，改用 PowerShell 直接复算原函数公式，数值见下。

## 验证表

| 结论 | 验证方法 | 验证结果 | 是否成立 | 修正 |
|---|---|---|---|---|
| 投影公式 `denom=fov/(fov+z)`，`sx=cx+x·denom` | 用 `project3d` 原函数代入 R=500、cx=500、前节点 z=+250、背节点 z=-150，算 fov=1300/650/433 三档 | 前节点 denom=0.8387→0.7222→0.6341（变小）；背节点 1.1304→1.3→1.5294（变大） | 公式成立；但「S.zoom 升高→物体放大」**不成立** | 方向写反了，且 S.zoom 是死参数（见下） |
| 逆旋转必须「先转的后逆」顺序 | 用 `rotate3d`/`inverseRotate3d` 原函数，yaw=0.6、pitch=0.4、v=(1,2,3)，对比两种还原 | `inverseRotate3d` 还原误差=0（精确回到 1,2,3）；`rotate3d(v,-yaw,-pitch)` 误差=0.9228（明显错） | 成立 | 无 |
| alpha 在 zw=0 处硬跳变 | 按 render 的分段公式，zw 取 -0.0001/0/0.0001 算 | alpha = 0.53998 → 0.85000 → 0.85002，跳变约 0.31 | 成立 | 无 |

## 发现的不准确结论（至少 1 处）

**结论「`S.zoom` 升高 → fov 变小 → 物体放大」是错的，两处问题：**

1. **方向错**：实测前半球节点随 zoom 升高反而**缩小**（denom 0.8387→0.6341），背半球节点才放大（1.13→1.53）。它根本不是均匀放大，只是把 fov 当透视参数在调，前后方向不一致。笔记里「放大」是照注释语义猜的，没拿数字验证。

2. **S.zoom 是死参数**：grep 全量赋值点，`S.zoom` 只在 `btnReset`（L2684）和 `reset`（L2884）里被赋 `1`，滚轮（L2592）只改 `S.viewScale`。也就是说「S.zoom 透视缩放」这条路径在日常交互里**从不生效**，笔记把它当成活跃的透视缩放来描述，不准确。真正的缩放是 `viewScale` 这套 2D 仿射。

## 结论：看懂 vs 猜

- **看懂（有代码+数值双重证据）**：投影公式本身、逆旋转顺序、alpha 分段跳变、布局是「确定性伪随机+体积采样」、命中测试是「逐节点反投影取 z 最大」——这些公式我都是照着原函数算的，数值对得上。
- **猜错（只有命名/注释推断，没验证）**：`S.zoom` 的语义。我按变量名「zoom」和 render 里 `fov=…/S.zoom` 这一处，推断它是「活跃的透视缩放、升高放大」，既没查它是否真被用户改，也没验证缩放方向，结果方向和活跃性都错。

教训：逆向里「某参数干什么、方向如何」这类语义，光看命名和单处引用会猜错；要 grep 它所有赋值点判断是否活跃，再用具体数字跑一遍变换才能定方向。
