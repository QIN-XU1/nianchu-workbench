## 五、坑与决策（只追加）

- 2026-11-14 **TDZ 崩溃：常量定义在立即执行函数之后**：打包版报 Cannot access before initialization。源码版不崩是因为 IIFE 第一行 `if (!_IS_PACKAGED) return` 走不到那行。教训：「源码跑得好好的」不能证明打包版没问题。

- 2026-11-14 **UI Automation 读原生错误框**：查打包版崩溃优先用 UI Automation 读原生错误框文案，能拿到完整堆栈，比反复猜测快十倍。进程活着但无窗口时尤其有效。

- 2026-11-14 **USER_ROOT 与 DSH_USER_ROOT 分叉**：两处独立计算会分叉：%APPDATA% 在 Electron 里 mkdir 失败后 userData 落到 exe 同目录，dirname 覆盖了环境变量但常量仍指向不存在的路径。根因是「同一个事实存两处 = 两份结论」，最终 server.log 写 ENOENT 导致 API 一律 403。

- 2026-11-14 **__dirname 在 asar 内的连锁失效**：打包后 resolve(__dirname,"..") 等于 resources 而不是 workbench，全库 9 处全部失效。根因难查是因为错得很安静：handler 都 catch 了返回空数组，前端只显示「没有读到任何管线」。修法是引入 _WB_ROOT 与 USER_ROOT 两个明确常量。

- 2026-11-14 **打包清单必须自检**：asar 里只有 9 个条目，漏了 scenarios 与 sceneboard，症状是左侧一片空白且控制台只报「取场景列表失败 null」。教训：清单式打包必须自检，现在离线打包会扫 __dirname 引用，目录存在但没进包就报警。

- 2026-11-14 **构建产物目录名带空格与中文**：路径含空格和中文（如 dist3\win-unpacked）时，spawnSync 传参必须用数组形式不能拼字符串，否则参数被空格切断。教训：所有子进程调用一律用 execFile/spawn 的数组参数形式。

- 2026-11-14 **工作台数据根要能回退到可写位置**：USER_ROOT 的候选链必须逐个 mkdir 并实测写文件才算成功（mkdir 成功不等于可写）。根因：受管环境下某些目录能建不能写，只判断 existsSync 会漏掉这种情况。

- 2026-11-14 **引擎 token 抓取依赖日志落盘**：server.log 写不进去时引擎 token 永远为空，表现为所有 API 返回 403 而不是连不上。教训：把「日志能不能写」当成启动自检的一部分，而不是等出错才发现。

- 2026-11-14 **打包后原生模块要单独处理**：asar 不能装 .node 原生模块，必须走 unpacked 目录并从那里 require。node-pty 缺失会导致 TUI 终端不可用，但主界面不受影响，属可接受降级。

- 2026-11-14 **启动器要给用户可双击的文件**：用户只会双击文件，不会开终端敲命令。START-DSH.cmd 用纯 ASCII 内容加通配符匹配 exe 名，避免中文目录与编码问题。
