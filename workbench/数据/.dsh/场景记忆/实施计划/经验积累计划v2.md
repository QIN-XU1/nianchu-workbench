## 四、瓶颈与风险

### 瓶颈 1（最硬）：场景疲劳 → 经验涨不到 +9/轮
- 证据：`场景历练.mjs:460-462` 注释写明「重复派同一任务时，场景 agent 会判断『任务已完成，无需重做』→ 不再积累经验」。
- 后 4 个任务（`-9`~`-12`）是「成熟度评分 / 自我检验」类，同一场景连跑 8 轮主题会枯竭，产出重复/水经验被 `_经验识别.mjs` 去重。
- **应对**：每轮 `--list` 若某场景经验没涨（该 +1 却 +0），就是疲劳信号 → 停下，给该场景**新增任务**而不是硬派；优先用前 8 个高质量任务，`-9`~`-12` 作兜底。

### 瓶颈 2：轮次虚增 bug 仍在 → 任务被跳过、提前耗尽
- 证据：`场景历练.mjs:640` 和 `:669` 都是 `rounds[scene] = done + 1`，**在「投递成功 r.ok」后就推进轮次**，而不是「确认经验真 +1」后推进。
- 后果：投递成功但场景拒绝重做时，经验不涨、轮次却 +1 → 任务被跳过，12 个任务轮完就重头循环，加速疲劳。
- **应对**：开工前先修这个 bug（`rounds[scene]` 改为「经验数真增加」才推进），否则时间表会漂。

### 风险 3：余额不足 / 负载
- 硬规矩：见余额错误立刻停；负载 >90% 不派活。
- **应对**：每轮前 `node 工具/成本闸.mjs --status` 看一眼，欠费就停。

## 五、结论

- 任务库**不再是瓶颈**（108 任务 ≥ 108 目标）。
- 真正的瓶颈是**场景疲劳** + **轮次虚增 bug**，两者都会让「+9/轮」打折。
- 时间表 8 轮是**理想下限**；若疲劳打折，需靠「新增任务」而非「硬凑轮次」来补齐，否则经验会变水、封存集不过检。
