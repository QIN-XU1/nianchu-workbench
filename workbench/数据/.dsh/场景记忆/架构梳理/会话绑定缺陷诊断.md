## 二、已确证的事实（不需要重查）

### ① 配置是对的

`外壳/scenarios/*.json` 里每个面板的 `sessionId` 都正确指向自己的会话：

```
arch-review.json         session-2585d3ae
build-plan.json          session-0c91b59a
competitor-analyze.json  session-32bfa7a6
incident-analysis.json   session-c433a410
pc-cleanup.json          session-f89a8e74
research.json            session-8e710372
reverse-eng.json         session-587c9493
self-review.json         session-9e898c80
hub.json (meta.hubSessionId) session-34f35b09
```

### ② 引擎里会话也确实存在（28 个）

`数据/.dsh/sessions/<编码cwd>/<sessionId>/` 目录都在。

### ③ 每个场景都有独立 webview（1 个，随场景重建）

切场景时 webview 会重建，不是共用一个。

### ④ 症状规律：只保留「上一次成功 pin 的值」

```
arch-review  → 2585  ✓
build-plan   → 2585  ✗（沿用 arch-review 的）
...
research     → 8e71  ✓（突然又对了）
reverse-eng  → 8e71  ✗
```

放回读 `localStorage['dsh.sessions.current']` 得到的是**旧值**，
说明 `pinSessionToScene` 执行失败后**静默保留了上一个值**。

### ⑤ pin 失败的直接原因：目标会话行不在 DOM 里

实测 DOM 里只有 14 个 `session:` 行，目标会话大多不在：

```
OK 架构梳理   session-2585d3ae  ✓ 在 DOM 里
XX 实施计划   session-0c91b59a  ✗ 不在 DOM 里
XX 竞品拆解   session-32bfa7a6  ✗ 不在 DOM 里
...（其余 6 个都不在）
```

### ⑥ 为什么不在 DOM 里：引擎按 workspace 分组

`localStorage['dsh.workspace.view.v5']`：

```json
{
  "groupBy": "workspace",
  "orderBy": "updated",
  "groupExpansion": { "<9 个 workspaceId>": true, "": true },
  "archivedFilter": "default"
}
```

侧栏把会话按 workspace 分组，DOM 里 9 个 workspace 分组头都在：

```
workspace:cca4cefa  自我复盘
workspace:4fc65d9d  逆向分析
workspace:d3bc876e  调研
workspace:ccfc57e4  本地电脑
workspace:dd7852a3  故障分析
workspace:21c5e892  竞品拆解
workspace:fa6c3d13  实施计划
workspace:5d6b7923  架构梳理
workspace:73207011  中枢
workspace:          未分组
```

**但分组头下面没有子会话行**（除了少数挂在「未分组」下的历史会话）。

### ⑦ 根因：`workspace.json` 的 `sessionIds` 指向已删会话

`数据/.dsh/storages/workspace.json` → `tables.workspaces.<id>.sessionIds`：

```
中枢 (73207011)      [dde1feee(已删), 9ed65a6a(已删)]  ← 全幽灵
架构梳理 (5d6b7923)  [2585d3ae ✓, 70990ee0(已删)]
实施计划 (fa6c3d13)  [14fa543d(已删), 095af732(已删)]  ← 全幽灵
竞品拆解 (21c5e892)  [2d14c953 ✓, 32bfa7a6 ✓]
故障分析 (dd7852a3)  [15a1f611, f66c6447]  ← 都可能已删
本地电脑 (ccfc57e4)  [34ca4af3]            ← 已删
调研 (d3bc876e)      [e4f02282(已删), 5d3bae9b(已删)]  ← 全幽灵
逆向分析 (4fc65d9d)  [587c9493 ✓]
自我复盘 (cca4cefa)  [9e898c80 ✓]
```

**引擎认为该 workspace 下没有会话可渲染 → 分组不渲染子行 → pin 脚本找不到 DOM → 失败 → 保留旧值。**

这个根因是**我上一轮清理会话时造成的**：
我用「按文件大小最小」的判据删了 47 个会话，
但没同步更新 `workspace.json` 的引用。

## 三、已尝试但失败的修法（不要再试）

### ❌ 试法 1：给每个面板独立 partition

改 `harness.js` L165：

```js
// 原来
wv.setAttribute('partition', 'persist:harness');
// 改成
wv.setAttribute('partition', 'persist:harness-' + _panelKey);
```

**结果：从 2/8 变成 1/8，更差。**
推测：独立 partition 导致登录态不共享，引擎前端认证失败，行为更混乱。
已回滚。

### ❌ 试法 2：直接改 `workspace.json` 的 sessionIds

写了脚本把每个 workspace 的 `sessionIds` 替换成「配置里的期望会话 + 仍存在的会话」，
清掉 10 个幽灵引用，写入。

**结果：重启后 webview 完全不出现（targets 从 4 个降到 1 个）。**
推测：`workspace.json` 有更严格的内部约束（version 2 / unit 结构），
直接改字段可能让它进入不一致状态，引擎拒绝渲染任何会话。

**已回滚**（备份在 `workbench/备份/workspace-备份-033555.json`）。
但回滚后 webview 仍然没回来 —— 见第四节。

### ❌ 试法 3（思路）：改 `sceneInjectDir` 返回真实 cwd

改 `外壳/main.js` 的 `sceneInjectDir`，让它返回 `数据/.dsh/场景记忆/<中文名>`
而不是旧的 `数据/.dsh/场景注入/<sceneId>`。

**结果：binding 仍是 2/8，没变化。** 已回滚。

## 五、下一轮建议的做法

### 优先级 1：不要在 `workspace.json` 上硬改

引擎对它有内部约束。**正确做法应该是通过引擎 RPC 或前端 UI 来组织 workspace**，
而不是直接改文件。

值得先探测：
- 引擎有没有 `workspace/*` 相关的 RPC 端点？（我只试过 `session/*`）
- 前端有没有暴露 workspace 切换的 API？（`window.__WB` 上没看到）

### 优先级 2：换一个角度 —— 不依赖「侧栏点击」

现在的 pin 方案是「在侧栏找到会话行并 click」。
如果会话不渲染，这条路就断了。

替代思路：
- **URL/hash 路由**：旧注释说引擎前端没实现，但可以再确认一次（引擎可能升级过）
- **直接调 RPC 切换会话**：`session/selectModel` 能切模型，有没有类似的 `session/select`？
- **让引擎重新扫描 sessions 目录**：如果 workspace.json 的 sessionIds 能由引擎自己重建，
  就写个工具触发重建，而不是自己改文件

### 优先级 3：接受现状，把这个 bug 记录为「已知缺陷」

如果以上都不通，就在 `机制清单.md` 里明确记一条：
**「会话绑定 2/8 —— 已知缺陷，根因是 workspace.json 与 sessions 目录不同步」**，
并让 `会话绑定验证` 报「已知缺陷」而不是「未知失败」。

## 七、为什么这轮没修好（诚实复盘）

三个错误的判断：

**① 我以为「改对配置就够了」。**
实际上 `workspace.json` 和 `外壳/scenarios/*.json` 是**两套独立的会话引用**，
我只同步了后者。

**② 我以为「直接改文件」是安全的。**
`workspace.json` 是引擎的运行时状态文件，有内部约束。
改它导致引擎完全不渲染会话 —— 这比原来的 bug 更糟。

**③ 我上一轮清理会话时，只想着「删掉多余的」，没想到「删掉之后谁还引用它们」。**
这就是项目铁律「两处判据 = 两份结论 = 早晚打架」的又一次实例：
会话的存在性同时记在 `sessions/` 目录和 `workspace.json` 里，
删了目录不同步 json，立刻不一致。

**教训：删数据之前，先找出所有引用它的地方。**
