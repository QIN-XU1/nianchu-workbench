## 一、现状与问题

### 1.1 事实 A：调研的 7 个产出全是对本项目的自查，零外部来源

`数据/.dsh/场景记忆/调研/` 下 7 个产物，逐个看被调研的对象：

| 文件 | 实际在问什么 | 对象 |
|---|---|---|
| `外部依赖调研.md` | 我们引了哪些外部包、各自什么状态 | 本项目 |
| `工具真实性调研.md` | 我们的工具脚本是不是真在检查东西 | 本项目 |
| `数据目录调研.md` | 我们的 `数据/.dsh/*` 各是什么 | 本项目 |
| `文档代码一致度.md` | 我们的文档和代码对不对得上 | 本项目 |
| `文档价值盘点.md` | 我们哪些文档该留该删 | 本项目 |
| `文档修复验证.md` | 我们改了文档之后修没修好 | 本项目 |
| `机制体系索引.md` | 我们的机制怎么分类、三份清单数字为什么对不上 | 本项目 |

7/7 的对象是本项目。实测 URL 数（`[regex]::Matches('https?://')` 逐文件扫）：**6/7 个文件 URL = 0**；唯一有 URL 的 `外部依赖调研.md` 有 21 处，但全是「本项目调用了哪些外部接口」（`api.deepseek.com` / `qt.gtimg.cn` / `127.0.0.1:3425` 之类）——**对象仍是本项目**，问的是「我们的依赖是什么」，不是「外部有什么值得学」。

这些活的正确归属是：`逆向分析`（拆自己）、`架构梳理`（评自己）、`自我复盘`（盘自己）。调研把它们干了 = 占了调研的名额，干的是别人的活。

对照用户原话：「网络搜集，去调研优秀项目或是想法是必要的」——现有产物里**一个外部项目都没有**。这就是「名不副实」的第一层。

### 1.2 事实 B：两个技能的 check.mjs 实测只差 6 行

```
数据/.dsh/skills/research/check.mjs            225 行  MD5 4738BE34C6A6E520357DB465FE5A4C85
数据/.dsh/skills/competitor-analyze/check.mjs  225 行  MD5 8B04B99D66AF7903783B49992749220E
```

逐行 diff（`Compare-Object` / node 逐行比对，两侧行数相同）：**只有 3 个行位置不同** —— 第 3 行注释里的场景名、第 40 行 `const SCENE`、第 41 行 `const SCENE_NAME`。按「双侧计」是 3×2 = **6 行**。剩下的 222 行逐字相同。

两个 check.mjs 的第 105-111 行都留着同一句未兑现的 TODO（`check` 函数体末尾，`return` 之前）：

```js
//  TODO: 这里是通用底线检查。
//        请按「${SCENE_NAME}」的具体职责补充专有检查。
//  参考该技能应产出什么：
//   （未提取到）
```

也就是说：**「可执行验收」是抄的**。两个语义完全不同的场景，用同一把尺子量 5 条通用底线（非空 / 无占位 / ≥2 标题 / 不复述需求 / 有路径数字或引用）。这 5 条里，竞品拆解交出「一份把本项目当竞品的矩阵」能通过，调研交出「一份纯内部自查」也能通过 —— 因为它们根本不看对象是谁。这是「名不副实」的第二层：**验收不区分场景，所以场景做什么都能过**。

### 1.3 事实 C：skill.json 的 does / doesNot 解析为空

实跑 `parseSkillMd()`（`工具/技能执行器.mjs:83`）读两个 SKILL.md：

```
research            | does= []  | doesNot= ["--"]  | verify= ["*不达标：**","--"]
competitor-analyze  | does= []  | doesNot= ["--"]  | verify= ["*不达标：**","--"]
```

两个字段都是空的，`doesNot` 里那条 `"--"` 是垃圾。**根因已定位到行**（不是"格式不统一"这种含糊说法）：

| 现象 | 位置 | 原因 |
|---|---|---|
| `does` 恒为空 | `research/SKILL.md:19-21`、`competitor-analyze/SKILL.md:19-22` | 「我做」表格的行**没有行首竖线**：写成 `**查证事实** \| 带出处的结论 \|`，而 `parseSkillMd:103` 的正则是 `^\|\s*\*\*(.+?)\*\*\s*\|\s*(.+?)\s*\|`，要求行首必须是 `\|` |
| `doesNot` 抓到 `--` | `research/SKILL.md:31`、`competitor-analyze/SKILL.md:32` 的 `---` 分隔线 | `parseSkillMd:115` 的正则 `^[-*]\s*(.+)` 把 `---` 拆成 `--`；而 `inNot` 要等下一个 `##`/`###` 才退出（`:113`），正好跨过了这条分隔线 |
| `verify` 抓到垃圾 | `research/SKILL.md:102-116`、`competitor-analyze/SKILL.md:127-144` 的 `## 三、验收标准` 节 | 该节正文是 ``` 代码块 ```（分别开于 `:104` / `:129`），不是列表；`parseSkillMd:127` 的同一正则 `^[-*]\s*(.+)` 于是先吃到 `**不达标：**`（被截成 `*不达标：**`），再吃到节末的 `---`（被截成 `--`） |

> 三行都指向同一类病根：**Markdown 里差一个 `|`、多一条 `---`，解析器就静默返回空**。这类失败不报错、不抛异常，只在 `skill.json` 里留下空的 `does`。所以修的时候不能只改内容，必须同时补一条断言（§4.3 第 4 条），否则下次重写 SKILL.md 会复发。

后果：**技能系统读不到「这个场景做什么、不做什么」**。中枢判断归属只能退回 `场景路由.yaml` 的 `does_not`（那份是对的），但技能本身没有自述边界 → 干着干着就漂。

### 1.4 三层叠加的结论

> 对象错了（A）+ 尺子一把（B）+ 边界没写（C）= 两个场景挂着「调研 / 竞品拆解」的牌子，实际在做「内部自查」和「功能罗列」，且**任何产出都能通过验收**。

用户要的是「网络搜集优秀项目 + 拿来主义（claude / codex / workbuddy 之类）」，现有实现一条都没给。

### 1.5 顺带核实：竞品拆解同病，但表现不同

同一把尺子扫 `数据/.dsh/场景记忆/竞品拆解/` 的 7 个产物：**外部 URL = 0**（`项目功能矩阵.md` 表头明写「拆解对象：本工作台」）；只有 `定位对比分析.md`、`交互模式分析.md` 里出现了真实外部名字（Claude Code / CrewAI / AutoGen / Cursor / LangGraph 等），且都是**一句话带过**当背景，没有一条挂来源、没有一条给出版本或证据锚点。

也就是说：竞品拆解的 7 个产物 7/7 对象还是「我们自己」——**它把工作台自己当竞品拆了**。这解释了 `项目功能矩阵.md` 为什么 14 行全在夸自家成熟度（4–5 分），而不是在比外部差距。用户要的「拿 claude / codex 的长处」这件事，一次都没发生过。

> 补一句口径：这两节不是要把现有 7+7 份产物判死刑 —— 它们本身质量不差（`机制体系索引.md` 甚至抓出了「49 / 46 / 48 三个数字对不上」这种真问题）。问题是**放错了场景**，且顶替了本该做外部情报的名额。处理方式见 §5.2：迁走，不删。

## 二、调研 → 情报站：新职责

> 定位改写：**「把项目外部的不确定事，变成有时效标签、有可证伪条件的结构化情报」**
> 一句话判据：**情报的对象必须是项目外部的东西。** 写「我们自己」的一律不算。

### 2.1 新职责边界

| 我做 | 产出 |
|---|---|
| 外部采集（开源项目 / 论文 / 标准 / 厂商文档 / 社区讨论 / 行业动态） | 情报卡 |
| 交叉验证与置信度定级 | 每条卡的置信度 + 来源分级 |
| 从公开线索推断未公开实现 | 开源猜想（带推理链） |
| 时效管理（TTL / 复检 / 过期降级） | 情报卡索引的时效列 |
| 给下游挑「值得逆向 / 值得拆」的候选 | 开源项目候选清单 |

| 我不做 | 谁做 |
|---|---|
| 判我们自己的东西对不对（依赖 / 工具 / 目录 / 文档一致性 / 机制分类） | 架构梳理、逆向分析、自我复盘 |
| 拆竞品功能矩阵、操作路径 | 竞品拆解 |
| 下架构结论、选型拍板 | 架构梳理 |
| 编造出处、把 L3 传闻写成结论 | —— 硬禁止 |

**边界的一条可执行判据**：情报卡的 `对象:` 字段出现 `[A-Z]:\`、`本项目`、`workbench`、`数据/.dsh` 任一 → 不是情报，拒收（check R2）。

### 2.2 标准流程（5 步，每步一个判据）

| 步 | 做什么 | 判据（不满足就停） |
|---|---|---|
| 1 立题 | 写清「这条情报若成立，我们会改什么」 | 填不出具体改动对象（要指到文件或模块名）→ 不立项 |
| 2 采集 | 按 L1（官方文档/源码/spec）/ L2（技术博客/社区）/ L3（传闻）分级取源 | 每条事实至少挂 1 个可点开的 URL 或 repo 路径；L3 单独出现时置信度封顶「低」 |
| 3 交叉验证 | 关键结论找第二个独立来源 | 标 `关键: 是` 的卡，来源去重后 < 2 个 → 置信度不得为「高」 |
| 4 成卡 | 按 2.3 的六字段写 | 六字段缺一 → 不进索引 |
| 5 登记 + 定时 | 进索引、定 TTL、写复检日期 | 索引里出现「无 TTL」或「无复检日期」的卡 → 本轮不通过 |

### 2.3 新产物定义

全部落 `数据/.dsh/场景记忆/调研/` 顶层（原因见 D5）：

| 产物 | 文件名 | 内容规格 |
|---|---|---|
| 情报卡索引（主产物） | `情报卡索引.md` | 顶部一张总表：`ID \| 对象 \| 一句话结论 \| 关键性 \| 来源数 \| 置信度 \| 采集日 \| TTL \| 复检日 \| 状态`；下面按 ID 分节展开六字段。单次 ≤ 12 卡 |
| 开源猜想台账 | `开源猜想台账.md` | 每条 5 行固定格式（见 2.4）。单次 ≤ 5 条 |
| 开源项目候选 | `开源项目候选.md` | 表：`项目 \| repo/官网 \| 版本或 commit \| 许可证 \| 定位 \| 值得逆向的模块 \| 给谁`。单次 ≤ 8 个 |
| 情报周报 | `情报周报.md` | 滚动覆盖，≤ 5 卡摘要 + ≤ 2 猜想 + 1 行「本轮推翻/修正了什么」 |
| 来源存证（非 md） | `来源存证.jsonl` | 每行 `{id, url, fetchedAt, type:L1/L2/L3, sha256(正文前2KB), 摘要}`。供 check 核对「URL 是否真抓过」 |

**情报卡六字段（缺一不进索引）**：

```
ID:      INT-YYYYMMDD-NN
对象:    外部项目/组织/标准名（禁止本地路径、禁止「本项目」）
事实:    ≤3 条，每条结尾挂 [S1]/[S2]
来源:    S1=<URL 或 repo@commit> (L1|L2|L3, 抓取 2026-11-13)
关键性:  关键 | 参考     （关键 ⇒ 来源去重 ≥2）
置信度:  高 | 中 | 低     （高 ⇒ ≥2 独立 L1；中 ⇒ 1×L1 或 2×L2；低 ⇒ 仅间接/L3）
时效:    T1|T2|T3 + TTL 天数 + 复检日期 + 状态
```

### 2.4 「架构开源猜想」怎么写才不是造谣

这是本方案风险最高的一块。用户要「架构开源猜想」，但猜想和造谣只差一步。**五条硬格式，缺一条不进台账**：

```
猜想: <一句话，必须能被判真假。例：Codex 的沙箱靠容器而非进程内 seccomp>
已知事实:
  F1: <事实> [S1]
  F2: <事实> [S2]
  F3: <事实> [S3]
推理链: F1 表明 A；F2 表明 B；因为 <机制 C 是公开且确定的>，A+B ⇒ D
        （每步只能「事实 → 推论」，不许跳步；≥2 个 → 才算链，1 个 → 直白猜测，不收）
置信度: 中（判据：2 个 L1 事实支撑，但缺直接佐证；若有官方源码级证据可升「高」）
可证伪条件: 若在 <具体可搜的关键词 / 具体文件名 / 具体版本号> 处看到 <什么>，本猜想即错。
            例：若在 openai/codex 仓库 `sandbox/` 目录或 v0.4x 的 CHANGELOG 里出现 seccomp 字样，本猜想推翻。
反方证据: 我找到的与结论矛盾或不利的线索 —— 无则写「已检索 X 处，未找到反证（检索词：…）」
```

四条禁令（可直接正则判）：

| 禁令 | 为什么 |
|---|---|
| `可证伪条件` 为空或写成「有待验证」 | 「有待验证」不是条件，是免责声明 —— 这就是造谣 |
| `推理链` 里出现「很可能 / 大概率 / 应该就是」代替机制 C | 情绪词替代因果 = 编造。机制 C 必须是可查的公开事实 |
| 猜想结论出现在 `事实:` 栏 | 事实栏只许放已证实的外部信息 |
| `反方证据` 栏留空 | 没有反证检索的猜想 = 只想证明自己对 |

### 2.5 情报时效性管理

| 档 | 适用 | TTL | 例 |
|---|---|---|---|
| T1 快变 | 版本号 / API 签名 / 定价 / 组织变动 / 模型能力 | 30 天 | 「claude-code v2 的 hook 机制」 |
| T2 中变 | 架构模式 / 工具能力 / 生态格局 / 交互范式 | 90 天 | 「codex 的审批流设计」 |
| T3 慢变 | 协议 / 标准 / 论文结论 / 数学性质 | 365 天 | 「MCP 规范的分层方式」 |

状态三档（脚本可算，不靠人记）：
- `新鲜`：今天 < 复检日 − 7 天
- `临期`：复检日 − 7 天 ≤ 今天 < 复检日
- `过期`：今天 ≥ 复检日

过期处理（三条：标注、降级、收敛）：
1. 过期卡在索引里状态列写 `过期`，标题前加 `⚠`；
2. 下游产物引用过期卡时**必须**写成 `[[INT-20260801-03]]（已过期，仅作历史）`，check 会拦；
3. 过期超过 30 天未复检的卡，从索引正文移入末尾 `## 过期归档` 一节 —— **索引不增反减**，防无限膨胀。

工具：**新增** `工具/情报时效.mjs`
```
node 工具/情报时效.mjs --check     # 扫 情报卡索引.md，列临期/过期，有过期未复检则 exit 1
node 工具/情报时效.mjs --stale 30  # 列出过期超 30 天、待移入归档的卡
node 工具/情报时效.mjs --selftest  # 反例：造一张复检日已过的卡，必须判「过期」
```

### 2.6 验收标准（全部可判定）

| # | 标准 | 判定方式 |
|---|---|---|
| V1 | `对象:` 字段 0 处命中本地路径/本项目关键词 | check R2，正则 |
| V2 | 每卡 ≥1 个 `http(s)://` 或 `repo@commit`，且 `来源存证.jsonl` 有对应抓取记录（URL 存在） | check R3，读 jsonl 比对 |
| V3 | 标 `置信度: 高` 的卡，卡内 URL 去重 ≥2 | check R4 |

| V5 | 每卡有 TTL 与复检日；索引内 0 条「过期且未标 ⚠」 | check R6 + `情报时效.mjs` |

## 三、竞品拆解 → 拿来主义：新职责

> 定位改写：**「把外部优秀项目的设计决策，变成一份带代价和许可结论的拿来决策单」**
> 一句话判据：**每条「拿」都必须有数字代价和许可证归属。** 写不出代价 = 不批。

### 3.1 新职责边界

| 我做 | 产出 |
|---|---|
| 选对标（1 标杆 + 1 同类，≤3 家）并声明「不比什么」 | 对标差距表 |
| 拆设计思想：从可观察行为 / 官方文档 / spec / 公开代码推出设计决策 | 差距表证据列 |
| 出「拿来决策」：拿 / 改着拿 / 不拿，各带代价 | 拿来决策单 |
| 判许可与合规：什么能借鉴、什么不能碰 | 许可台账 |
| 拆操作路径（步数级），不拆视觉 | 交互模式分析 |

| 我不做 | 谁做 |
|---|---|
| 搜集资料（找候选、查来源、定置信度） | 调研（情报站） |
| 下架构结论、定分层 | 架构梳理 |
| **搬运竞品源码（一条都不搬）** | 谁都不搬 —— 我们重写 |
| 从反编译 / 去混淆产物取证 | —— 硬禁止（法律风险最高） |
| 评估价格与商业模式（除非派单要求） | 派单方 |

### 3.2 标准流程（5 步）

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 定题 | 写「这次要补我们哪个具体坑」+「不比什么」 | 说不清坑（须指到文件或模块）→ 不拆 |
| 2 取证 | 证据只取两类：**可观察行为**（我操作/看文档看到的）和**公开文本**（docs / spec / README / LICENSE / 论文） | 每条结论必须挂 `证据类型` + `证据锚点`（URL / 文档小节 / 操作步骤） |
| 3 填差距表 | 同一维度横比，写「做到什么程度」 | 格子必须是 1–5 分或 有/无/部分，出现「好/一般/差」→ 不通过 |
| 4 出决策单 | 每条：拿 / 改着拿 / 不拿 + 为什么 + 代价 + 落到哪个文件 | 代价列无数字 → 不批；0 条「不拿」→ 视为没做取舍，不通过 |
| 5 合规过闸 | 查许可证、判「思想 vs 实现」、写隔离说明 | GPL/AGPL/无许可项出现在「拿」列 → 必须降级为「仅行为观察」 |

| 产物 | 文件名 | 内容规格 |
|---|---|---|
| 对标差距表 | `项目功能矩阵.md`（沿用） | 列：`维度 \| 我们 \| 竞品A \| 竞品B \| 差距方向 \| 证据类型 \| 证据锚点`。行 ≤ 20；每格必须填，空 = 没拆 |

### 3.4 「拿来决策」的格式

```markdown
| # | 拿什么（设计思想，不是代码） | 出处 | 动作 | 为什么 | 代价（必须有数字） | 落到我们哪个文件 | 许可证 | 隔离说明 |
|---|---|---|---|---|---|---|---|---|
| 1 | 审批流用「一次授权、范围显式」而非「逐动作确认」 | codex 的审批模型 | 改着拿 | 逐动作确认在我们场景下会打断心流，且中枢已能自判归属 | 改 3 个文件约 260 行；多出 1 个状态（待授权）；每次规则变更要同步 2 处 | `工具/派单.mjs`、`数据/.dsh/场景路由.yaml` | Apache-2.0 | 只读官方 docs 与行为观察，未看源码；实现由我自己写 |
| 2 | 会话内工具调用的重试退避曲线 | workbuddy | 不拿 | 我们的工具调用都是本地秒级，重试只会掩盖真错 | —— | —— | —— | —— |
| 3 | GPL 项目的插件加载协议 | 某 GPL 项目 | 不拿（降级为仅行为观察） | 协议本身是思想，但该项目文档把协议与实现强绑定，取证成本高于收益 | —— | —— | GPL-3.0 | 只读 README 与运行行为，不读不写其源码 |
```

四种动作的判定口径：

| 动作 | 什么时候用 | 硬约束 |
|---|---|---|
| 拿 | 思想清晰、我方无同类、代价可算 | 必须有数字代价 + 许可证允许 |
| 改着拿 | 思想对但边界条件不同（最常见） | 「为什么改」必须写清我方哪个边界不同 |
| 不拿 | 我方不需要 / 代价大于收益 / 许可不允许 | **必须 ≥1 条**，且「为什么」非空 |
| 不拿（降级为仅行为观察） | 许可受限但思想值得参考 | 后续任何产物不得出现该项目的代码片段 |

**代价列的四类具体化（至少写一类，且必须带数字）**：
- 工程量：`改 N 个文件 / 约 M 行`
- 维护成本：`每次 X 变更要同步 K 处`
- 复杂度：`多出 K 个概念 / 状态 / 开关`
- 反向损失：`会丢掉我们现有的 <某项能力>`

### 3.5 许可与合规：怎么区分「可借鉴的设计思想」和「不该抄的具体实现」

**思想层（可借鉴，自己重写）**

- 交互流程、状态机、错误处理策略、数据模型、命名体系、分层方式
- 可观察行为（我看到了这个行为 → 我自己设计实现）
- 公开 spec / RFC / 论文 / 官方文档里写明的方法
- 竞品 README / 架构博客里作者主动公开的设计取舍

**实现层（不碰）**

- 逐行复制代码；含「变量名/注释/控制流结构几乎一致的翻译」——**翻译也算复制**
- GPL-2.0 / GPL-3.0 / AGPL-3.0 / SSPL 项目的代码进入我们仓库
- 反编译、去混淆、脱壳得到的实现（法律风险最高，且技术上不可信）
- 商标、品牌名、icon、插画、字体、截图
- 受专利保护的具体机制（拿之前先查专利，查不到就写「未检索专利」并降级）

**许可证 → 允许动作映射（写进 `许可台账.md` 的「允许动作」列，check 会验）**

| 许可证 | 允许动作 | 禁止 |
|---|---|---|
| MIT / BSD-2 / BSD-3 | 参考重写 | 去掉原版权声明（若参考程度高） |
| Apache-2.0 | 参考重写 + 可引用片段并署名 | 用其商标背书 |
| MPL-2.0 / LGPL-2.1 / LGPL-3.0 | 参考重写；不链接、不改其文件 | 把其文件并入我们仓库 |
| GPL-2.0 / GPL-3.0 / AGPL-3.0 / SSPL | **仅行为观察** | 读源码后照写、链接、并入 |
| 无 LICENSE / 商业闭源 | 仅公开文档与行为观察 | 任何形式的代码、素材、反编译 |

**隔离说明怎么写才不是走过场**：写清三件事 —— ① 我取证用了哪些材料（docs / 行为 / 源码）；② 我有没有读过其源码（读了就不能声称独立实现）；③ 我的实现从哪个文件开始是自己的。做不到双人 clean-room（本项目就一个 agent），就用**四项差异法**兜底：落地实现必须与参考在 `函数名 / 变量名 / 注释 / 控制流结构` 四项上都不同，并在决策单「隔离说明」列记录对照范围。

## 六、风险与防护

**核心风险（必须正面回答）**：扩职责会不会变成「什么都能干 = 什么都干不好」？

会。而且这个项目已经有先例 —— 调研现在就在干逆向分析和架构梳理的活（§1.1 的 7 个产物）。根因不是能力不够，是**没有一条硬门槛把「别人的事」挡在门外**。所以防护不是「加强边界意识」（那是空话），是六道可执行的闸。

| # | 防护 | 具体机制 | 判据（能不能真判） |
|---|---|---|---|
| P1 | **外部性闸（最关键）** | 情报对象必须是项目外部。这条一刀把「调研」和「自我复盘/架构梳理/逆向分析」劈开 —— 职责膨胀的最大来源（占现有 7/7 产物）被物理关掉 | check R2，一条正则。命中本地路径/本项目词 → 拒收 |
| P2 | **配额闸（防注水）** | 单次调研 ≤12 卡 / ≤5 猜想 / ≤8 候选项目；单次竞品 ≤3 家 / ≤15 决策行；**单次交付只能有 1 个主产物 + ≤3 个附属产物** | check R7 / C8 + 产物清单白名单。超了直接 exit 1，不许"下次注意" |
| P3 | **接单前置闸** | 派单的 `verify` 字段必须能从该场景 `场景路由.yaml` 的 `verify_hint` 里落到具体一条 check 项。填不出 = 不接单 | `工具/派单.mjs` 四件套校验（已有，`派单.mjs:145-156`）加一条：verify 文本须命中该场景 verify 白名单关键词，否则 `⛔ 派单缺四件套` 同款报错 |
| P4 | **时效自动收敛（防只增不减）** | 过期卡 30 天未复检 → 移入 `## 过期归档`；归档区不参与 check R7 计数，但从索引正文移除 | `工具/情报时效.mjs --stale 30`，有输出即须处理，否则 exit 1 |
| P5 | **双源 / 反方制（限速也是质量闸）** | 高置信度必须 ≥2 独立 L1；每条猜想必须写反方证据；每条「拿」必须写数字代价 | check R4 / R5 / C4。这三条是强制的**信息成本**，天然压住"什么都想调研一遍"的冲动 |
| P6 | **越界哨兵覆盖** | 情报站/竞品拆解不得写别的场景目录（迁移那 7 个文件必须由目标场景自己接） | `工具/越界哨兵.mjs` 的 INV-2（E 档写）/ INV-3（A 档写）已在跑，无需新增 |

**回退判据（升级失败就退回去，别硬撑）**：
升级上线 2 周后跑一次审计，若满足任一条，说明防护失效，**回退到窄职责**（调研只做外部采集、不出猜想；竞品只出差距表、不出决策单）：

| 失败信号 | 阈值 | 检查方式 |
|---|---|---|
| 情报对象仍指向本项目 | 新产物中 ≥30% 的卡 `对象:` 命中 R2 正则 | `grep` + R2 正则全量扫一遍 |
| 猜想无实质可证伪条件 | ≥1 条猜想的 `可证伪条件` 命中 `/有待\|待验证/` | check R5 |
| 许可风险 | ≥1 处 GPL 族项目进了「拿」列 | check C5 |
| 产物爆炸 | 任一单次交付产物数 > 4 | 数目录里本轮新增 md |
| 时效失控 | 索引里过期卡 > 新鲜卡的 1/3 | `工具/情报时效.mjs --check` |
