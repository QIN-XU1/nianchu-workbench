## 引擎启动问题（2026-11-09 诊断完成）

### 现状
本项目的 `workbench/引擎数据/` 只有数据（`.dsh` / `.dsh-tui`），**没有引擎源码**。

### 实测诊断
```
harnessDir:      workbench/引擎数据
hasDsh:          true       （数据目录存在）
hasCliBuilt:     false      （apps/cli/lib/bin.js 不存在）
hasPackageJson:  false      （没有 package.json，pnpm 无法启动）
pnpmCmd:         D:\file\env\nodejs\pnpm.cmd  （已修复，原来写死了错误路径）
```

### 结论（架构事实，不是 bug）
本项目设计为**复用外部引擎**：
- 引擎由 DeepSeek Harness 主程序拉起
- 通过 `DSH_ENGINE_TOKEN` 传入 token
- 代码里保留的"自己 spawn 引擎"路径在本项目环境走不通

### 已做的改进
1. **修复 pnpm 路径硬编码**
   原：`C:\Users\<user>\AppData\Roaming\npm\pnpm.cmd`（不存在）
   现：动态解析（NODE_HOME / PATH / 常见位置）

2. **引擎启动失败时给出可诊断提示**
   原：只打印 "startServer failed"，重试 34 次
   现：打印完整诊断 JSON + 修复建议

### 需要用户介入
```
① 让 DeepSeek Harness 主程序拉起引擎
② 或安装引擎源码到 workbench/引擎数据/apps/cli/
③ 确认 DSH_ENGINE_TOKEN 是最新的
```

### 影响
- **不影响**：机制体检、派单台账、场景记忆、备份、归因等所有本地功能
- **影响**：engine.rpc 不可用（无法通过 API 创建会话）
- 故障分析场景的会话绑定因此待定
