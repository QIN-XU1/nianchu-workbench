## 二、标准流程（五步）

### 第 1 步：先定"跟谁比、比什么"

**不要一上来就拆。**

```
① 这批竞品要回答什么问题？
     例："我们的 X 功能该做成什么样"
     
② 该选哪几个竞品？
     判据：至少一个"标杆"（做得最好的）+ 一个"同类"（规模相近的）
     
③ 不比什么？
     判据：明确写出"这次不评估价格/不考虑移动端"等
```

**判据：** 如果说不清"要回答什么问题"，先别拆 —— 会拆出一堆用不上的细节。

### 第 2 步：框架先行（关键）

**先定维度，再填内容。**

**常用维度（按产品类型选）：**

| 类型 | 建议维度 |
|---|---|
工具类 | 核心动作步数 / 学习成本 / 可定制程度 / 出错恢复 |
内容类 | 内容密度 / 发现机制 / 消费体验 / 互动形式 |
协作类 | 权限粒度 / 实时性 / 通知策略 / 历史追溯 |
平台类 | 扩展方式 / 生态成熟度 / 上手门槛 / 迁移成本 |

**判据：** 维度必须是**可对比的**（能给出 ABC 三家的具体值），
不是"体验好不好"。

### 第 3 步：填矩阵（不是填功能列表）

**反例（功能列表）：**
```
❌ 竞品 A 有：搜索、筛选、排序、导出
   竞品 B 有：搜索、筛选、导出、分享
```

**正例（功能矩阵）：**
```
✅ | 能力 | 竞品A | 竞品B | 我们 |
   |---|---|---|---|
   | 搜索 | 全文，即时 | 标题，需回车 | ? |
   | 筛选 | 6 个维度 | 3 个维度 | ? |
   | 排序 | 4 种 | 2 种 | ? |
   | 导出 | CSV | 无 | ? |
```

**关键区别：** 矩阵写的是"**做到什么程度**"，不是"有没有"。

### 第 4 步：拆交互（同一功能怎么做）

**每个关键功能，记录"操作路径"：**

```markdown
### 功能：批量删除

竞品 A：
  选中 → 勾选多个 → 点删除 → 确认弹窗 → 完成
  步数：4 步
  亮点：支持 Shift 连选
  
竞品 B：
  长按 → 进入编辑模式 → 勾选 → 删除
  步数：4 步
  亮点：删除后 5 秒内可撤销
```

**判据：** 必须写出"步数"和"亮点"。
只写"都能批量删除"等于没拆。

### 第 5 步：找差异的真正来源

**不要停在"竞品 A 有这个功能"。**

要回答：**为什么 A 这样做，B 那样做？**

格式：
```markdown
| 差异 | A 的做法 | B 的做法 | 差异来源（推测） |
|---|---|---|---|
| 删除确认 | 弹窗确认 | 直接删 + 可撤销 | A 面向谨慎操作（财务场景），B 面向高频操作 |
```

**判据：** 差异来源必须能解释"为什么"，不能只描述"是什么"。

## 三、验收标准

```
✅ 说清"要回答什么问题"
✅ 选竞品有理由（至少一个标杆 + 一个同类）
✅ 维度可对比（能填出具体值）
✅ 矩阵写"做到什么程度"而不是"有没有"
✅ 关键功能有操作路径和步数
✅ 差异有来源解释
```

**不达标：**
```
❌ 只是功能罗列
❌ 维度全是"好/一般/差"
❌ 没有"不评估什么"的声明
❌ 结论是"竞品比我们强"（没有可执行信息）
```

## 四、常见坑

### 坑 1：拆成功能清单

**表现：** 罗列竞品所有功能。
**后果：** 看完不知道该怎么办。
**避免：** 每个功能都要写"做到什么程度"。

### 坑 2：选太多竞品

**表现：** 一次拆 8 家。
**后果：** 每家的深度都不够。
**判据：** 一次最多 3 家（1 标杆 + 1 同类 + 1 跨界参考）。

### 坑 3：只拆表面

**表现：** "竞品 A 的按钮是蓝色的"。
**后果：** 抄了颜色没抄逻辑。
**避免：** 只拆"解决了什么用户问题"，不拆视觉细节。

### 坑 4：没有"不比什么"

**表现：** 什么都想比。
**后果：** 范围失控，交付延期。
**避免：** 明确写出本轮不评估的项。

### 坑 5：结论空泛

**表现：** "我们应该学习竞品 A"。
**后果：** 无法执行。
**避免：** 结论必须是"具体做什么"，可派单。
