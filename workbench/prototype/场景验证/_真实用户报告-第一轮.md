## 二、🔴 P0-1：主 Agent 终端全黑，界面却显示「就绪」

### 用户看到 vs 实际

| 界面显示 | 实际 |
|---|---|
| 状态栏绿点「终端就绪」 | 进程启动了（pid=12848） |
| 状态栏「待命」 | — |
| 终端区域 | **57 行全空，只有一个光标** |

### 实测证据

```json
// 终端内容
{ "totalRows": 57, "nonEmptyRows": 0,
  "firstRowHTML": "<span class=\"xterm-cursor\"> </span>" }

// 发送 /help 后
{ "afterInput": "（全空）", "nonBlank": 0 }

// 模拟敲字后
{ "afterTyping": "（仍然全空）", "charCount": 0 }

// 错误卡片
{ "hasFallbackCard": false }
```

### 根因（已定位）

手动跑 TUI 拿到真实报错：

```
dsh: warning: 1 entry did not activate
spill-local (@deepseek-ai/dsh-spill-local):
  Error: EPERM: operation not permitted,
  mkdtemp 'C:\Users\15282\AppData\Local\Temp\dsh-spill-XXXXXX'
```

**链路：**
```
spill-local 插件 EPERM 失败
  → cordis 报「1 entry did not activate」
  → TUI 进程起来了但不工作
  → 不输出任何 PTY 数据
  → 前端 xterm 一片空白
  → 但 api.tui.start() 返回 ok:true（进程确实起来了！）
  → harness 判断「就绪」→ 绿点
```

### 为什么致命

1. 这是**核心功能**（主 agent 调度其他场景）
2. 用户**完全无法察觉坏了**（界面说就绪）
3. 没有错误提示、没有降级卡片
4. 用户会以为「我不会用」

### 修复方向

1. **`tui.start` 要做「启动后健康检查」** —— 起进程 3 秒内没收到任何 PTY 输出 ⇒ 判失败
2. **`showTuiFallback` 触发条件要改** —— 不能只看 `res.ok`，要看「有没有真的输出」
3. **`spill-local` EPERM 要处理** —— `%TEMP%` 下 mkdtemp 失败（可能沙箱/杀软）
4. **状态栏要区分「进程起来了」和「能用了」**

## 三、🔴 P0-2：搜索框是死的（写了但没人读）

### 现象

```
输入「调研」 → 星盘 9 个节点一个不少
输入「zzzz不存在zzzz」 → 星盘还是 9 个节点，无任何提示
输入框有 X 清除按钮（说明设计过）
```

### 根因（已定位，非常确定）

`neuron.js` 第 2540 行：

```js
search.addEventListener('input', function () {
  S.filter = search.value.trim();   // ← 写了
  render();                          // ← 重绘
});
```

**`S.filter` 在整个 2700 行的文件里只出现这一处！**
**没有任何地方读它来过滤场景。**

这是典型的「写入但无人读取」的死代码 —— 和我之前修的
「内容哨兵永远不失败」是同一类问题（**装饰**）。

### 用户感受

输入框有、能打字、有清除按钮，**看起来像个正经功能**，
但输入任何东西都没用。

## 四、🔴 P1-1：AI 面板没有绑定场景会话，全是同一个空白首页

### 现象

在「本地电脑」场景点开 AI 面板，看到的是：

```
探索未至之境  预览版
选择工作区
选择一个工作区开始
```

**这是引擎的空白首页，不是「本地电脑」的专属对话。**

### 实测证据（进了 webview 内部）

```json
{
  "url": "http://127.0.0.1:3083/",
  "sessionItems": [],
  "mainText": "新会话 / 插件 / 自动化任务 / 工作区 / 未分组 / 探索未至之境 / 选择一个工作区开始",
  "inputs": [{ "placeholder": "搜索会话名称" }]
}
```

场景 json 明明配了：
```json
{ "id": "pc-ai", "type": "harness",
  "sessionId": "session-2e314473-69eb-426e-a4ea-909cfcdcb196" }
```

### 根因（已定位）

`harness.js` 的 `pinScript()`：

```js
var nodes = document.querySelectorAll('[class*="Session"] [role="listitem"], ...');
for (...) {
  var txt = nodes[i].textContent.trim();
  if (txt && txt.indexOf(needle) >= 0) {   // needle = sessionId
    nodes[i].click();
  }
}
```

**三个假设全错：**

| 假设 | 实际 |
|---|---|
选择器 `[class*="Session"] [role="listitem"]` | 实际类名 `wtg9ga_newSession`（哈希前缀） |
界面上能找到 `session-2e314473-...` 文字 | 界面只显示「新会话」 |
失败会有提示 | `catch(function(){})` **静默丢弃** |

### 为什么这是 P1

**这违背整个项目的核心设计**：

> 「每个场景有自己的 agent、自己的记忆、自己的身份卡」

如果 9 个场景的 AI 面板都是同一个空白首页，**场景就是空壳**。

### 参考项目的判据（我这次真懂了）

luanyujia 在 `02-会话定位与跟随/二-会话绑定三字段.md`：

> **「三个字段少写一个不会报错，只会悄悄退化成『随便显示一条』」**
> **「判断到位了没有**只能看画面**」**

**我看到的正是「随便显示一条」—— 引擎首页。**

这条判据本来就在我的资料里，但我是**作为用户走了一遍才真正理解它**。

## 六、P2：启动后 `getCurrentScene()` 返回 null

### 现象

```json
{ "currentScene": null }   // 启动完成后应是 'hub'
```

### 根因

两套状态机：

| 路径 | 更新什么 |
|---|---|
启动 `commands.run('scene.switch')` | `state.set(SCENE_ACTIVE)` + `renderScene()` |
神经元切换 `__WB.switchScene()` | `renderScene()` + `currentSceneId = sceneId` |

**互不同步。**

**实测 `switchScene('arch-review')` 本身完全正常**，所以这只是「启动路径没走同一个函数」。

## 八、⚠️ 工具问题：`工具/点击.mjs` 坐标偏移 8px

### 现象

我的点击工具点不中节点，但 CDP 派发事件能命中。

### 根因

```
innerW: 1540   outerW: 1556   差 16px（左右各 8px 边框）
innerH: 914    outerH: 920    差 6px
screenX: -7    screenY: 0
```

`GetWindowRect` 返回含边框的完整 rect（1554 宽），
但实际内容只有 1540 宽（**窗口 x 是 -7，边框被裁了一部分**）。

`点击.mjs` 用 `r.Left + w*百分比` 算屏幕坐标，
**比实际内容坐标偏了约 8px**。

对于命中半径 6px 的星盘节点，**8px 偏移足以错过**。

### 影响

这是**验证工具的缺陷**，不是产品缺陷。但它让我误判了「点节点没反应」，
浪费了时间。

## 十、本轮最重要的体会

### 「检查通过」和「用户能用」差得很远

我上一轮的检查报告：

> 9/9 场景全部通过，零错误特征
> 面板体检 15/15，机制体检 48/48

**但作为用户走了 35 分钟，发现 2 个 P0 级问题：**
1. 核心功能（主 Agent 终端）是死的，界面却说「就绪」
2. 搜索框写了但没人读 —— 纯装饰

**我的检查全都在查「有没有报错」，没查「能不能用」。**

### 具体盲区

| 我查了 | 我没查 |
|---|---|
面板有没有渲染内容 | **内容对不对**（终端全黑也算"渲染了"） |
有没有错误文字 | **该做的功能能不能做**（点不动也算"无错误"） |
面板数量对不对 | **布局有没有空洞** |
API 返回 ok | **返回 ok 但实际没生效**（pinScript 静默失败） |
代码有没有那段逻辑 | **那段逻辑有没有人调用**（S.filter 写了没人读） |

### 一条新判据

> **「没有报错」不等于「能用」。
> 要验「能用」，必须走一遍用户的路：看画面、点一下、敲一下、看结果变不变。」**

上一轮我写过「截图没变化 ≠ 功能坏了」，
**这次是它的反面：「截图看起来正常 ≠ 功能正常」。**

### 第二条判据

> **「代码里有这段逻辑」不等于「这段逻辑生效了」。
> 必须查：写入的值有没有被读取、绑定的监听器有没有被触发、算出的结果有没有被使用。」**

`S.filter` 是最典型的例子：一行代码，写了 3 年了，从来没生效过。
