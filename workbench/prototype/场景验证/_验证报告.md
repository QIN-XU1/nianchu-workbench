## 二、🔴 缺陷 1：`review-doc` / `review-files` 不区分场景

### 现象

| 场景 | 面板标题 | 副标题说它该显示什么 | 实际显示 |
|---|---|---|---|
架构梳理 | 架构文档 | 沉淀下来的方案 | **目录: 自我复盘** |
实施计划 | 计划文档 | 里程碑与验收 | **目录: 自我复盘** |
故障分析 | 崩溃分析报告 | `workbench/产物/崩溃分析报告.md` | **目录: 自我复盘** |
逆向分析 | 源码预览 | 看拆解出来的文件 | **目录: 自我复盘** |
自我复盘 | 预览 | 点右上的文件就在此预览 | 目录: 自我复盘 ← **这个是对的** |

### 根因

`preload.js` 里：
```js
reviewDir: DSH_SHELL_DIR.replace(/[\\/]外壳$/, '') + '\\自我复盘'
```

**`reviewDir` 是全局固定的一个目录，永远是 `workbench/自我复盘`。**

而 `_generic.js` 的 `createReviewDoc`：
```js
const p = await api.reviewDir();
emptyState(body, '▤', '审查文档', '目录: ' + dir);
```

**它只拿全局 reviewDir，没有「场景自己的文档目录」这个概念。**

### 判定

**架构层面缺一个概念：场景级文档目录。**

现在的模型：
```
reviewDir（全局一个） → 所有场景共用
```

应该是：
```
每个场景自己有一个文档目录（场景配置里声明）
  review-doc 优先读 scene.docDir
  没有才回退全局 reviewDir
```

## 六、工具问题：截图被 Windows 开始菜单遮挡

### 现象

多次截图里出现 Windows 开始菜单盖在界面上。

### 尝试过的方法

1. `SetForegroundWindow` → 无效
2. 按两次 ESC → 无效
3. 点击窗口内部（400,300）→ **反而可能点到开始菜单上**

### 根因（推测）

开始菜单是独立窗口（`Windows.UI.Core.CoreWindow`），
`GetForegroundWindow` 可能仍返回工作台句柄，但视觉上开始菜单在最上层。

### 影响

部分截图不完整，但**核心信息仍可读**（标题栏、面板标题、部分内容）。

### 待解决

需要更可靠的方法：枚举所有窗口，找到并关闭开始菜单；
或者用 Electron 的 `webContents.capturePage()` 而不是屏幕截图。
