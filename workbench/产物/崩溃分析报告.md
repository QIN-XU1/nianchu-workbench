### 模式 2：18 条 uncaughtException 全是 EPIPE（置信度：高）

**证据：**
```
18 条 uncaughtException，message 全部是 "EPIPE: broken pipe, write"
```

**归因：应用 bug（置信度：高）**

**机制解释：**
EPIPE = 向一个已关闭的管道/流写入数据。

在 Electron 里最常见的场景：
```js
// 危险写法
webContents.send('channel', data)   // 如果 webContents 已销毁 → EPIPE

// 正确写法
if (webContents && !webContents.isDestroyed()) {
    webContents.send('channel', data)
}
```

**另外**：相邻崩溃分析显示 `uncaughtException → uncaughtException` 出现 16 次，
说明这类异常会**连续发生**（一次没处理好，后续还会继续）。

**可观察的验证方法：**
```powershell
# 看崩溃日志里 EPIPE 是否还有新增
Select-String -Path crash-log.jsonl -Pattern "EPIPE" | Measure-Object
```

### 模式 3：child-process-gone 可分四类（置信度：高）

**证据：**
```
type=Utility  service=network.mojom.NetworkService     19 条
type=GPU      service=GPU                               9 条
type=Utility  service=audio.mojom.AudioService          7 条
type=Utility  service=video_capture.mojom.VideoCaptureService  3 条
```

**归因：环境/平台层（置信度：中）**

**分类判断：**

| 进程 | 是否正常 | 理由 |
|---|---|---|
`NetworkService` (19) | **正常** | Electron 网络服务崩溃后自动重启，通常无感 |
`GPU` (9) | **需关注** | GPU 进程崩溃可能导致渲染异常（白屏/花屏） |
`AudioService` (7) | **正常** | 音频服务同理自动重启 |
`VideoCaptureService` (3) | **需关注** | 摄像头相关，可能有功能中断 |

**关键判断：** 38 条里，**26 条（68%）是正常可忽略的**。
只有 GPU（9）和 VideoCapture（3）的 12 条需要关注。

### 模式 4：相邻崩溃有重复模式（置信度：中）

**证据：**
```
render-process-gone → child-process-gone   20 次
child-process-gone  → render-process-gone  19 次
render-process-gone → render-process-gone  18 次
child-process-gone  → child-process-gone   18 次
uncaughtException   → uncaughtException    16 次
```

**发现：** 同类崩溃经常连续发生。

**解释：**
- 渲染进程崩溃 → 页面重建 → 又崩溃（循环）
- 子进程崩溃 → 重启 → 又崩溃

**这说明：** 崩溃不是孤立的，而是**成簇发生**。
一次崩溃往往会引发连锁。

**需要：** 崩溃时间间隔数据来确认（同簇内间隔应该很短）。

### 8.4 一个特殊错误码

```
2026-11-07 04:50:56  exitCode = -2147483645 = 0x80000003
```

**0x80000003 = STATUS_BREAKPOINT（断点异常）**

这是 Windows 的断点异常，含义：
- 进程收到了一个断点指令
- 通常是调试器相关，或程序主动触发
- **不是普通的崩溃**

**其余 9 条 exitCode = -1**，是进程被强制终止。

**归因（置信度：中）：**
```
0x80000003 那条可能是：
  ① 开发时附加了调试器，然后断开
  ② 程序遇到了不可恢复状态，主动中断
  ③ Electron 内部断言失败

需要：查看该时间点的其他日志才能确认。
```
